## New Features & Practical Usage

### `claude -p` now tells you in stderr what it's waiting on when it hangs (v2.1.295)

**When a `claude -p` run doesn't exit after its last turn finishes, and stderr is a terminal, a new line now reports what it's currently waiting on.** Until now, there was no way to tell why a process wouldn't finish when a background task or pending notification was holding it open, so CI scripts could appear to hang for no apparent reason.

```bash
claude -p "Check the deploy script" --output-format text
# If the process stays alive after the last turn finishes, stderr prints what it's waiting on
```

**If you've noticed `claude -p` occasionally running longer than expected in a CI pipeline or an unattended automation script, just leaving that stderr output in your logs means you can immediately see what caused the wait next time.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### `claude plugin` commands now warn when the settings file they'd write to never loaded (v2.1.295)

**`claude plugin install`, `enable`, `disable`, and `marketplace add` now print a warning at run time if the settings file they're about to modify isn't actually loaded.** Until now, changes could be written silently into a settings.json with a syntax error or other corruption, ending up with no real effect.

**If you've got plugin install or enable commands baked into CI or onboarding scripts, it's worth checking whether this warning fires, to confirm settings.json is actually in a valid, loaded state.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Developer Workflow Tips

### When server load spikes, check per-endpoint logs before guessing why (10/14)

**After featuring a custom feed reader on Hacker News, a site owner watched the site slow to a crawl, with heavy server load persisting for days despite only a handful of real logged-in users.** Pulling per-endpoint request logs revealed that most requests weren't coming from the human-facing news-browsing API at all, but from AI bot traffic. Requests that actually rendered a page were rare; repeated, crawler-like background calls accounted for most of the load.

**When you ask Claude Code to investigate "the site got slow," rather than letting it jump straight to a fix like caching or scaling up, have it pull per-endpoint request logs first to see where the load is actually coming from — it'll save you from wasting time on a remedy aimed at the wrong cause.** [GeekNews](https://news.hada.io/topic?id=35313)

### A better Big-O doesn't guarantee a faster program in practice (10/13)

**The core critique of OpenAI's newly announced FFT (Fast Fourier Transform) result is that an asymptotic speedup doesn't necessarily translate into faster computation on a real machine.** The constant factor hidden inside the Big-O notation is large enough that, even though the improvement is real in theory, you'd need an input size that's practically impossible to reach before it actually outruns the existing algorithm.

**If Claude Code proposes an optimization during code review or refactoring on the grounds that "this algorithm has better Big-O," it's safer not to take that claim at face value until you've run a benchmark at realistic input sizes and confirmed the perceived performance actually improved.** [GeekNews](https://news.hada.io/topic?id=35295)

## Security & Limitations

### Claude service status — Console degradation resolved after six days, everything Operational (10/14)

**Checking status.claude.com directly, the usage-data loading delay in Claude Console (platform.claude.com) that had been ongoing since 10/7 was resolved at 18:00 UTC on 10/13, and as of 10/14 claude.ai, the Claude API, Claude Code, Claude Console, Claude Cowork, and Claude for Government are all Operational.** This performance degradation, covered daily in the 10/9 through 10/13 briefings, is now fully closed out after six days, and no new incidents have been reported as of 10/14.

**If your Claude Console usage dashboard numbers looked delayed recently, it's worth checking now whether they're updating at normal speed again.** [Claude Status](https://status.claude.com)

### A theoretical proof shows AI models can hide arbitrary capabilities (10/13)

**By embedding an encrypted neural network inside a model's weights and building a backdoor that only decrypts and runs it when a secret trigger is supplied, researchers showed that the assumption that adversarial evaluation can always surface a model's hidden capabilities doesn't hold.** Under a digital-locker construction and stated cryptographic assumptions, the key finding is that a model can be built to look safe throughout evaluation while revealing a hidden capability only on a specific trigger.

**If you're designing safety evaluations or red-teaming for a model, this research shows that capability-hiding undetectable by standard evaluation is theoretically possible, so passing an eval shouldn't be over-trusted as proof a capability is absent.** [GeekNews](https://news.hada.io/topic?id=35287)

### An 11-year-old soundness bug was found in Rust's borrow checker (10/13)

**A reproduction was found that uses covariant field assignment to bypass a struct's lifetime constraints, confirming that code which should be rejected by the compiler instead compiles cleanly, letting a short-lived reference inside `Drop` be treated as a `'static` reference.** The original repro works by putting a reference to a local variable whose lifetime has already ended back into global storage — notable because this class of soundness bug went undetected for 11 years.

**If any of your Rust dependencies contain low-level code that directly manipulates lifetimes or variance, this discovery is a good prompt to re-examine the lifetime assumptions sitting near your unsafe boundaries.** [GeekNews](https://news.hada.io/topic?id=35294)

## Ecosystem & Plugins

### Anthropic replaces Git with its own version control system, Scion, to handle AI-driven code volume (10/14)

**As AI coding pushed source control, builds, and CI into becoming bottlenecks, Anthropic built its own version control system, Scion, and migrated its entire monorepo off Git within five months.** The company reports that daily merge volume grew from an average of roughly 2,500 in May 2026 to over 30,000 by September, with CI alone generating about 25 million checkouts a day. The sheer volume of change AI agents generate has outgrown what a traditional Git-based workflow can handle.

**If running multiple Claude Code sessions or subagents in parallel is driving a sharp rise in your own code change volume, it's worth keeping in mind that the bottleneck Anthropic hit internally could become a real problem for your own Git infrastructure too, depending on your organization's scale.** [GeekNews](https://news.hada.io/topic?id=35309)
