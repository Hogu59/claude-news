## New Features & Practical Usage

### Computer Use, the Browser Use Tool, the Skills API, and the Files API reach general availability (8/20)

**Anthropic has taken Computer Use — previously beta on the Claude Platform — along with the newly added Browser Use Tool, Skills API, and Files API, and shipped them all to general availability (GA) together.** **Computer Use can now handle multiple actions in a single turn**, which **cuts task completion time and cost by roughly 30%**, and **can run under a BAA for HIPAA compliance in regulated industries**. **The Browser Use Tool adds page-structure analysis on top of screenshot-based interaction**, giving it a more reliable way to target web elements than relying on pixel coordinates alone. **The Skills API lets you upload versioned folders of instructions that run inside Claude's sandbox**, while **the Files API offers 1TB of storage per organization, automatic expiration, and rate limits 5x higher than before.**

**In practice**, this means you can now read files from the Files API, run procedures defined as Skills, automate web tasks with the browser and computer use tools, and write results back out as files — all **stitched together on the Claude Platform alone, without standing up separate self-hosted infrastructure.** All three features are **also available on Microsoft Foundry, with Google Cloud Vertex AI support in progress.** If you've been building your own file-upload or browser-automation pipelines on top of the Claude API, this GA release is worth checking out for **stable endpoints you can now use without beta headers.** [Source](https://claude.com/blog/computer-use-skills-api-files-api)

### Claude Academy opens its doors (8/20)

**Anthropic has opened Claude Academy, a free learning hub that makes the same training approach it has used internally for employees available externally.** It spans **everything from introductory courses like Claude 101 to deep technical tracks on building agents with the Claude API and Claude Code**, with **separate tracks for developers, students, educators, and nonprofits.**

**If you've struggled to put together onboarding material for rolling Claude Code out to a team, official curriculum like Claude Code 101 is now ready to use as-is.** [Claude Academy](https://academy.claude.com/)

### `/claude-api upgrade` migrates Python projects to anthropic 1.x (v2.1.239)

```bash
# Use the claude-api skill to migrate a Python project's anthropic dependency from 0.x to 1.x
/claude-api upgrade
```

**The `claude-api` skill has gained a command that migrates Python projects from `anthropic` 0.x to 1.x**, and **the skill's Python reference docs have also been updated for 1.x** (for example, timeouts now use `anthropic.Timeout` instead of `httpx.Timeout`).

**If you've been putting off upgrading to the `anthropic` SDK 1.x, this command gives you a first pass at automatically finding and fixing the spots that need to change.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Developer Workflow Tips

### The retry watchdog no longer waits forever on spend-limit errors (v2.1.239)

**Persistent retry mode enabled via `CLAUDE_CODE_RETRY_WATCHDOG` now fails immediately when it hits an organization spend-limit or credit-exhaustion error, instead of blindly waiting for the limit to reset.**

**In practice**: when overnight CI or background automation runs into a spend limit, the retry watchdog used to keep retrying and holding its spot until the reset time arrived. Now, **these kinds of errors fail fast, so a pipeline stuck in this state gets noticed sooner and can move on to the next step — alerting, requeuing, or whatever comes next.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Traces for tool execution delayed by PreToolUse hooks no longer get split apart (v2.1.239)

**When a `PreToolUse` hook delayed tool execution, that execution used to start a new OpenTelemetry trace instead of continuing the original turn's trace — this has been fixed.**

**If you've been piping Claude Code's OpenTelemetry output into an observability tool like Datadog or Honeycomb to analyze per-turn latency, hook-intercepted tool calls used to get sliced off into their own separate trace, making it hard to reconstruct a turn's full latency.** With this fix, **tool execution delayed by a hook now shows up correctly within the same turn's trace.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Even in a software factory, human judgment doesn't disappear — it just moves (8/21)

This piece argues that **even as software-factory models automate code generation, responsibility for product intent, system design, quality bars, and final deployment decisions still rests with humans.** The core point is that **Claude Code or Codex alone may be enough for implementation itself, but building the infrastructure to actually run work through event-driven queues repeatedly and reliably pass state, context, and evidence between agents remains a separate challenge.**

The **loop-engineering principle the 8/16-8/20 briefings have repeatedly touched on — that completion criteria and the judgment calls humans keep should be defined up front** — gets sharpened here into a **concrete architectural pattern: event queues and evidence handoff between agents.** If you're chaining multiple agents into a pipeline, it's worth noting that **defining what state, context, and evidence gets handed to the next stage is the central design question for your queue.** [GeekNews](https://news.hada.io/topic?id=32737)

## Security & Limitations

### Bedrock proxy streaming bug — every turn was silently billed twice (v2.1.239)

**A bug has been fixed where, behind a proxy that strips the Content-Type header from responses, Bedrock streaming would silently re-run every turn in non-streaming mode — resulting in the API call actually being billed twice.**

**If you've been running Bedrock behind an internal proxy or gateway, this bug may have inflated your billing history above your actual usage.** After updating to v2.1.239, **it's worth cross-checking your recent billing against actual request counts.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Data-residency workspace cost premiums now display correctly (v2.1.239)

**Cost estimates in `/cost`, the status line, and `--max-budget-usd` now factor in the 1.1x US-only-inference premium applied to data-residency workspaces.**

**If you've kept a workspace pinned to a specific region for data-residency requirements, the cost estimates shown on screen may have looked slightly lower than your actual bill.** With this fix, **budget alerts (`--max-budget-usd`) and the status line's cost estimate now line up much more closely with actual billing.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Claude service status — no new incidents as of 8/22, reports keep falling

**Checking the official Claude Status API (status.claude.com) directly**, following the **Google connector outage (Minor) from 18:32-19:42 UTC on 8/20 and the multi-model request error (Major) covered in the 8/21 briefing**, **no new incidents have been registered as of 8/22, and all services are operational.**

**As of the StatusGator check (2026-08-21 23:53 UTC), user reports over the past 24 hours stood at 7** — **down for a third straight day, from 18 on 8/19 to 9 on 8/20 to 7 on 8/21** — meaning **the elevated report levels that followed the authentication outage on the evening of 8/16 have now fully settled back to normal.** [Claude Status](https://status.claude.com/history) · [StatusGator](https://statusgator.com/services/claude)

## Ecosystem & Plugins

### Plugins synced from claude.ai now display as `name@synced` (v2.1.239)

**Plugins synced from claude.ai in cloud sessions now display in the `name@synced` format**, and **can be managed directly with `claude plugin enable/disable <name>@synced`.** Most importantly, **if you already have a plugin installed locally under the same name, the synced version will no longer overwrite it.**

**If you've been using plugins managed from claude.ai alongside ones installed locally, this change clears up the confusion over which one actually runs when names collide.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Feature request — AGENTS.md support in Claude Code (8/21)

**A community request asking Claude Code to read AGENTS.md — the project instructions file shared across multiple coding agents — directly, rather than duplicating it separately from CLAUDE.md.** **The proposed approach is dual-file support: load CLAUDE.md first, and fall back to AGENTS.md only when it's absent.**

**For teams running Claude Code, Codex, and other agents in the same repo, this could cut down on the hassle of maintaining separate instruction files per tool** — worth keeping an eye on. Note that it hasn't been implemented yet. [GeekNews](https://news.hada.io/topic?id=32716)

## Minor Changes

All of the following are from **v2.1.239**.

- **Cross-session messaging now works on Windows** — Claude Code sessions on different machines can send each other messages via `SendMessage` and discover each other via `ListAgents`, just as on macOS and Linux.
- **`ListAgents` now reports the session's own name** (the one other sessions use to message it), so sending `SendMessage` to your own name now tells you that instead of returning "no agent named …".
- **`ListAgents`/`/list-agents` now also show live teammates** — previously only subagents and other sessions appeared, and reachable teammates were missing from the list.
- **`keybindingFlavor: "readline"` now applies to word-wise movement and deletion keys too** — Alt+F and Ctrl/Option+Right now stop at word boundaries, Alt+D deletes a word (undoable with Ctrl+Y), and punctuation is treated as a word boundary.
- **Native image paste, clipboard, and audio capture addons now load correctly on Alpine/musl builds** — musl runtimes were rejecting glibc-built binaries, which is now fixed by shipping musl-built binaries instead.
- **The usage-limit message shown once your monthly spend limit is exhausted now also tells you when session and weekly limits will reset.**
- **A one-time full-screen renderer notice has been added for previously excluded environments like Bedrock, Vertex, and Foundry** — new installs in these environments now start in full-screen mode.
- **In Claude in Chrome, `/clear` now closes the session's Chrome tab group**, and empty tab groups are also cleaned up on `/resume` and when Claude Code exits.
- **Images uploaded from mobile now carry their stored file path along with them**, so Claude can copy it directly into newly created files.
- **[VSCode] The "View usage" link in the usage-limit banner is now placed inline next to the warning text instead of floating in the middle of the banner.**
