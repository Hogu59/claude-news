# Claude Code Daily Briefing - 2026-10-24

## Release Summary

| Version | Date | Key Changes |
|------|------|----------|
| **v2.1.310** | 10/23 | Monitor tool and plugin monitors extended to Bedrock/Vertex/Foundry, a Windows hook bypass flaw fixed, Cloud sessions and Remote Control permissions added to Enterprise custom roles, and roughly 25 other changes |
| v2.1.309 | 10/22 | Multiple sandbox/worktree isolation bypass fixes, `claude ultrareview` now requiring workspace trust, and roughly 80 other changes (covered in the 10/23 briefing) |
| v2.1.308 | 10/22 | Bug fixes and stability improvements (detailed changelog not public) |

**v2.1.310 landed on 10/23, just a day after v2.1.309 on 10/22.** The Monitor tool and plugin monitors can now be used through Bedrock, Vertex, and Foundry gateways, as well as in sessions with telemetry or non-essential traffic disabled. Alongside that, a security flaw was fixed where PreToolUse and PermissionRequest hooks on Windows would let tool calls through without inspection when Git Bash wasn't installed and the hook command was just a quoted string.

[Full release notes](https://github.com/anthropics/claude-code/releases)

## New Features & Practical Usage

### The Monitor tool and plugin monitors now reach Bedrock, Vertex, and Foundry gateways (v2.1.310)

**You can now use the Monitor tool and plugin monitors whether you're running Claude Code through Bedrock, Vertex, or Foundry, or in a session with telemetry and non-essential traffic turned off — and long foreground sleeps are blocked the same way in these environments too.** Previously, plugin monitors and the long-sleep block didn't always apply in sessions going through these gateways or with telemetry disabled.

**If your organization has telemetry turned off by policy, or you run Claude Code through Bedrock, Vertex, or Foundry and have been going without plugin-monitor-based observability as a result, v2.1.310 lets you extend the same monitoring coverage to those environments.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Enterprise custom roles can now govern Cloud sessions and Remote Control permissions per role (v2.1.310)

**Claude Code cloud sessions and Remote Control permissions have been added to Enterprise custom roles, letting Owners control access to each feature independently by role.** Until now, neither feature had role-based, granular access control.

**If your organization manages permissions through custom roles on an Enterprise plan, it's worth revisiting your permission matrix now to open up or restrict cloud sessions and Remote Control for specific roles.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Anthropic and Theorem formally verified 123 open source libraries using Claude (10/23)

**Anthropic and Theorem used Claude to formally verify 239 fuzzing entry points across 123 open source libraries, fixing the bugs they found and then proving that the compiled code doesn't crash under specific execution environments and input-size conditions.** Unlike traditional fuzzing, which runs large volumes of random inputs, this approach mathematically guarantees no crashes for any input under 64MB.

**If you're working with security-critical C/C++ libraries in Claude Code, it's worth watching how far this kind of approach can be automated — moving beyond fuzzing's sampling to formally proving safety across an entire input range.** [GeekNews](https://news.hada.io/topic?id=35855)

## Developer Workflow Tips

### On Linux, `/sandbox` now names the specific Ubuntu AppArmor restriction at play (v2.1.310)

**When Ubuntu's AppArmor restricts user namespaces and prevents bubblewrap from starting the sandbox, `/sandbox` and the sandbox-startup warning now name the specific restriction and explain how to lift it.** Previously, you sometimes had to track down the cause of a sandbox startup failure yourself.

**If you've hit a bubblewrap startup failure while using Claude Code's sandbox mode on Ubuntu, v2.1.310 lets you see how to lift the AppArmor restriction directly from the `/sandbox` guidance.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Auto mode now shows a clearer warning before blocking its first read outside the working directory (v2.1.310)

**The prompt auto mode shows before its first read of a file outside the working directory has been improved to also warn that blocking such reads can cause subsequent shell commands to ask for permission too.** Previously, this prompt alone made it hard to tell that denying it could spill over into shell commands.

**If you run unattended sessions with auto mode and block reads outside the working directory, this warning is worth keeping in mind — shell commands may unexpectedly start asking for permission as a result.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Security & Limitations

### Claude service status — ongoing request errors for Claude Fable 5.1, Sonnet 5.5, and Haiku 5.5 (10/24)

**Checking status.claude.com directly shows an investigation notice posted at 08:37 KST on 10/24 reporting elevated errors on requests to Claude Fable 5.1, Sonnet 5.5, Haiku 5.5, and Opus 5.5 fast mode, followed by an update at 08:54 KST saying success rates for the affected models were recovering and being monitored.** As of this writing, the incident has not yet been marked "resolved," and the same page shows claude.ai, the Claude API, Claude Code, and Claude Cowork all in Degraded Performance status.

**If requests you've sent today in Claude Code to Fable 5.1, Sonnet 5.5, Haiku 5.5, or Opus 5.5 fast mode are erroring out or running slow, suspect this ongoing incident before your local setup, and check status.claude.com for resolution.** [Claude Status](https://status.claude.com)

### A flaw letting hooks wave tool calls through on Windows when Git Bash is missing has been fixed (v2.1.310)

**A bug has been fixed where PreToolUse and PermissionRequest hooks would pass tool calls through without inspection when Git Bash wasn't installed and the hook's command was just a quoted string (e.g. a quoted path).** This flaw meant that in environments where you believed hooks were enforcing permission checks, those checks could actually have been silently skipped.

**If you rely on PreToolUse or PermissionRequest hooks as a security boundary on Windows, it's worth upgrading to v2.1.310 — depending on whether Git Bash was installed and how the hook command was written, checks could have been silently bypassed.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Sweden's government offices are blocking access to ChatGPT and Claude on work computers (10/23)

**Sweden's government offices (Regeringskansliet) are blocking access to ChatGPT and Claude on employees' work computers, steering staff toward approved AI services like Microsoft Copilot instead.** Some approved use cases are reportedly being left as exceptions, however.

**If you work with government or public-sector customers, or are evaluating Claude Code adoption in that kind of environment, it's worth building into your go-to-market strategy the assumption that any AI service not on an agency's own approved list can be blocked outright on the work network.** [GeekNews](https://news.hada.io/topic?id=35866)

## Minor Changes

All of the following are from **v2.1.310** (10/23).

- **Fixed background cleanup wiping out recent files, such as pasted images, when `cleanupPeriodDays` was set to a very large value.**
- **Fixed compaction after a "Prompt is too long" error leaving behind too much of a conversation with dense text like base64 or SVG, which could make the next request fail again too.**
- **Fixed the file-read permission prompt not showing where a symlink actually points.**
- **Fixed the auto-advance timeout on a question firing immediately when an external editor closed right after a long edit.**
- **Improved memory usage during compaction for non-interactive sessions (`-p`, Agent SDK) when the transcript file is very large.**
- **[Cloud sessions] Fixed the cloud environment edit dialog not showing an error inside the dialog when saving or archiving failed.**
- **[Cloud sessions] Added a Choose file button for loading a cloud environment's setup script from a file.**
- **[Claude Tag] Fixed `!` commands like `!restart` and `!help` being treated as plain messages when sent in bold, italic, or strikethrough formatting.**
- **[Code Review] Fixed a completed review failing to add a check to the PR after a failed first attempt — the final attempt now adds the completion check.**
