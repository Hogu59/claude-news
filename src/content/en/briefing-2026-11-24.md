# Claude Code Daily Briefing - 2026-11-24

**v2.1.331 shipped on 11/23, just three days after v2.1.330 landed on 11/20.** The standout changes are Code Mode's platform expansion, stronger `claude doctor` diagnostics, and new productivity features in VS Code, alongside hundreds of stability fixes — including a bug where MCP tool calls could hang for up to 30 minutes and another where interrupted plugin updates left skills and other components missing from the plugin folder.

## Developer Workflow Tips

### Code Mode now extends to terminal sessions on Bedrock, GCP Agent Platform, Microsoft Foundry, and AWS Claude Platform (v2.1.331)

**Until now, Code Mode — where Claude writes tool calls as code instead of calling them directly — was mostly limited to the standard Claude Platform environment. Starting with this release, it's also available in terminal sessions opened on Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry, and Claude Platform on AWS.** The same release also exposes Code Mode's `gen_ai.usage.*`, `gen_ai.response.model`, and `gen_ai.operation.name` trace spans through OpenTelemetry, so token usage and model information can be observed the same way no matter which platform you're running on.

**If your organization's policy has kept you running Claude Code on Bedrock, Foundry, or Claude Platform on AWS instead of the standard environment, and you've been missing out on Code Mode, upgrading to v2.1.331 is worth it just to get its speed and token savings on those platforms too.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### `claude doctor` now surfaces API connectivity status directly (v2.1.331)

**Previously, when Claude Code couldn't reach the API, figuring out whether the cause was the network, a proxy, or credentials meant digging through logs yourself. Starting with this release, `claude doctor` includes an API connectivity section that shows right away whether the API is reachable, what HTTP status or error came back if it isn't, or why the check couldn't run at all.**

```bash
claude doctor
# → Check reachability, HTTP status, and error causes directly in the "API connectivity" section
```

**If you've been asking users to send logs every time a connection issue comes up while running Claude Code behind a corporate proxy or gateway, running `claude doctor` once in v2.1.331 is a good first step to narrow down where the connection is failing.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### VS Code adds Fix with Claude Code and a merge-conflict resolution button (v2.1.331)

**Previously, getting Claude to fix an error or failing test in VS Code meant copying the details yourself and pasting them into the chat. Starting with this release, a Fix with Claude Code option appears in the Quick Fix menu for errors, warnings, the Test Results view, and failed-test previews, sending the problem straight into chat.** Files with merge conflicts also get a new Resolve Merge Conflicts button in the editor title bar and in the Source Control view's Merge Changes group. On top of that, an Add to Chat option was added to the right-click menu for changed files, and notebook cells got an Add Cell to Chat option that includes outputs and errors.

**If you've been copying error underlines or failing tests out of the editor to explain them to Claude by hand, v2.1.331 lets you just hit Fix with Claude Code from the Quick Fix menu, or Resolve Merge Conflicts on a conflicted file, to send it straight to chat.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Security & Limitations

### Claude service status — a 17-minute multi-model error incident on 11/23 (resolved), no new incidents today (11/24)

**According to the official status.claude.com, following three incident-free days from 11/20 to 11/22, there was a 17-minute incident between 09:39 and 09:56 UTC on 11/23 during which error rates rose across several models, including Claude Mythos 5.2, Fable 5.2, Opus 5.5, Sonnet 5.5, and Haiku 5.5.** The cause was identified, a fix was deployed, and the incident was resolved shortly after; no new incidents have been reported today (11/24). Every component — including claude.ai, Claude Console, the Claude API, Claude Code, Claude Cowork, Claude for Government, and Claude on AWS, Microsoft Foundry, and Google Cloud — currently shows as Operational.

**If you saw response errors across several models yesterday morning (11/23), it was a transient issue resolved within 17 minutes and nothing to worry about — today (11/24), every component is running stably.** [Claude Status](https://status.claude.com)

### Managed plugin marketplaces will auto-update by default starting November 30, 2026 (v2.1.331)

**Until now, plugin marketplaces registered under `extraKnownMarketplaces` in managed settings had no default auto-update behavior defined. According to this release's announcement, starting with releases after November 30, 2026, these marketplaces will auto-update by default.** If there's a marketplace you don't want auto-updated, you'll need to explicitly set `autoUpdate: false` on that entry.

```json
// Under extraKnownMarketplaces in managed settings
// To prevent a specific marketplace from auto-updating
{
  "extraKnownMarketplaces": {
    "my-marketplace": {
      "autoUpdate": false
    }
  }
}
```

**If your organization runs a plugin marketplace through `extraKnownMarketplaces` in managed settings, releases after November 30 could turn on auto-updates you didn't intend — it's worth setting `autoUpdate: false` now on any marketplace whose version needs to stay pinned.** [Full release notes](https://github.com/anthropics/claude-code/releases)

Both the paper and its Lean 4 formalization were written by AI and haven't yet been reviewed by human mathematicians — this doesn't resolve P vs. NP itself. Following the 11/20 quantum gravity claim and the 11/21 Riemann hypothesis proof announcement, this is another case of pointing Claude at an unsolved math or theoretical-CS problem, with both the formal verification and the lack of human review being emphasized. ## Minor Changes

All items below are from **v2.1.331** (11/23) and weren't covered above.

- **Added `oidc.groups_jsonpath` to the Claude apps gateway**, letting group info be read out of a list of objects using a subset of RFC 9535 JSONPath syntax.
- **Added the `CLAUDE_CODE_DISABLE_RESPONSE_COMPRESSION` environment variable** to request uncompressed responses behind proxies that cut off compressed responses mid-stream. It's not yet recommended for self-hosted runners or Remote Control.
- **Added the `CLAUDE_GATEWAY_IDP_CONNECT_BY_HOSTNAME=1` environment variable** so that, in environments using `oidc.use_proxy: true`, login requests pass the IdP hostname through to the proxy as-is even when `NO_PROXY` is set.
- **Added `optionalDependencies` to the plugin manifest**, letting an installed plugin individually disable or remove optional dependent plugins listed there.
- **Fixed a bug where some malformed responses from local or WebSocket MCP servers could hang MCP tool calls for up to 30 minutes.**
- **Fixed a bug where a plugin folder left with missing components (such as skills) after an interrupted or failed update kept loading that way on subsequent runs** (anthropics/claude-code#102186).
- **Added a notification for tab-mode voice input** that lets you know when it stops itself after 15 seconds of no detected speech or after hitting the 2-minute cap.

## Recommended Reads

- **AI gives everyone the same advice (11/23)**: an experiment asking 65 AIs from 30 companies roughly 128,000 questions found that everyday, financial, and career advice given without any personal context converges heavily on the same answers. 73% of life-changing book recommendations were *Man's Search for Meaning*, and 76% of business idea suggestions were subscription-box services — but duplication dropped sharply once specific preferences and circumstances were provided. Commenters pointed to duplication in training data and to reinforcement learning as factors that amplify pretraining bias. If you've been asking Claude Code or other models for recommendations without giving context, this is worth a read for understanding why you keep getting similar answers and how much giving specific context actually changes that. [Original](https://a90.com/experiments/same-advice/) · [GeekNews](https://news.hada.io/topic?id=37639)
- **Why you shouldn't keep SSH keys on disk (11/24)**: SSH private keys left on disk can be exfiltrated by malware scanning the filesystem, the author writes, sharing their experience moving keys into a password manager via the Bitwarden SSH agent and deleting the key files from disk. Commenters noted this isn't a complete fix since an attacker with the same user's privileges could just click through the approval prompt themselves, countered that most threats are malware that automatically scrapes credentials, so adding a defense layer still has real value, and suggested hardware keys like YubiKey or short-lived SSH certificates as better alternatives. Concerns were also raised about agentic LLMs potentially attempting authentication without approval — worth a look if you're letting an agent like Claude Code handle SSH access. [Original](https://jola.dev/posts/you-cant-afford-ssh-keys-disk) · [GeekNews](https://news.hada.io/topic?id=37734)
- **I'm pretty happy with my art site's technical architecture (11/22)**: describes a personal site structure that looks and feels like a fast static site to visitors while giving the owner a web-based CRUD UI for managing the artwork. Server-rendered HTML is cached on Cloudflare for 30 days, and any write invalidates the entire page cache — notably, the author explains choosing full invalidation over per-page dependency tracking as a tradeoff favoring correctness and simplicity. It's a practical pattern for low-traffic content sites that want both the benefits of static deployment and a dynamic management UI; worth a look if you're spinning up personal sites quickly with Claude Code and thinking about how to simplify cache invalidation. [Original](https://klauria.tech/klauria-art/) · [GeekNews](https://news.hada.io/topic?id=37607)

## Interesting Projects & Tools

- **Heirloom — a plugin for Claude Code and Codex that lets you verify AI-changed code's actual behavior before merging (11/23)**: it runs the agent's changes before and after in separate Git worktrees, compares the real output, and lets you roll back the work with a written reason if it doesn't match intent. Design decisions get saved and linked to the relevant code and tests, so another agent editing the same files later can reference that context. It's focused on actually running and verifying agent-made changes before code review, making it a lightweight, plugin-sized version of the verification-loop and chaos-loop design covered for the Claude Code team in the 11/19–20 briefings. [GitHub](https://github.com/cheongfish/heirloom) · [GeekNews](https://news.hada.io/topic?id=37703)
- **iphone-cli (iph) — a Rust-based CLI and MCP server that lets AI agents control a real iPhone (11/23)**: using Apple's developer services to read the iPhone's accessibility tree directly, this single-binary tool lets an AI agent control apps wirelessly over the same Wi-Fi network after a one-time USB connection — no Xcode or screen OCR required. It also runs on Windows, but only works against real devices running iOS 27 or later, and the author notes the range of verified device configurations is still limited. An early-stage tool worth trying if you want to connect it to Claude Code over MCP so an agent can check how a mobile app actually behaves. [GitHub](https://github.com/HyunSeob/iphone-cli) · [GeekNews](https://news.hada.io/topic?id=37674)
