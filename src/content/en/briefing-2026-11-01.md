## New Features & Practical Usage

### `CLAUDE_CODE_SUBAGENT_EFFORT` lets you set a default effort for subagents separate from the main session (v2.1.316)

**Until now, subagents without an explicit effort setting simply inherited the main session's effort; this new environment variable lets you set a separate default just for subagents.** It only applies to subagents that don't have effort specified elsewhere — it has no effect on subagents with an explicit setting or on the main session itself.

```bash
# Keep the main session on ultrathink while capping subagents at a cheaper default effort
export CLAUDE_CODE_SUBAGENT_EFFORT=medium
```

**If you've bumped the main session's effort up to xhigh or ultrathink for complex work but winced at dozens of spawned subagents burning tokens at that same level, this variable is an effective way to pin subagents to a cheaper effort and keep costs in check.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### The Claude apps gateway now supports a shared monthly budget pool for groups (v2.1.316)

**On top of each member's individual limit, you can now set one additional monthly budget shared across the whole group.** This is configured via the `pooled_budget` field in the spend limits admin API, and it works so that even if individual members still have room under their own limits, further spending is blocked once the group's shared budget runs out.

```json
// Example spend limits admin API configuration
{
  "group_id": "eng-team",
  "pooled_budget": 5000
}
```

**If your organization has struggled to control overall Claude spend using individual limits alone, it's worth checking the admin settings for this new group budget pool as an additional team-wide ceiling.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Developer Workflow Tips

### `CLAUDE_CODE_DISABLE_ULTRATHINK` can turn off the `ultrathink` keyword entirely (v2.1.316)

**Just days after `ultrathink`'s scope was widened so that typing it mid-turn immediately raises the effort for the rest of the turn, a new switch lets organizations disable the keyword altogether.** This is useful when multiple people share an environment, or when you want to prevent the word from accidentally appearing in docs or commit messages and unexpectedly spiking effort.

```bash
export CLAUDE_CODE_DISABLE_ULTRATHINK=1
```

**If you're running Claude Code in a shared environment or CI where costs need to be tightly controlled, this environment variable is worth setting to head off anyone habitually typing `ultrathink` and spiking effort.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Fixed a bug where scripts run via the Bash tool would stall after their first command if `SHELLOPTS` was exported (v2.1.316)

**Shell configs or CI environments sometimes export `SHELLOPTS` to pass `set -o` options down to child processes, but when this variable was exported, scripts run through the Bash tool would execute only their first command and then hang.** Without knowing the cause, it was easy to mistake this for a bug in the script itself.

**If you've hit scripts mysteriously stalling partway through and couldn't pin down why, check whether your shell config exports `SHELLOPTS` and consider upgrading to v2.1.316.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### `/diff` now runs one fewer full-repo git command on every refresh in large repositories (v2.1.316)

**`/diff` now typically skips one of the full-repository git scans it used to run on every redraw, and it automatically backs off the refresh interval when git responds slowly.** Previously, leaving `/diff` open on a large monorepo meant git commands piling up with each refresh, making the experience feel sluggish.

**If you work with `/diff` open on a monorepo with tens of thousands of files, it's worth checking whether refreshes feel noticeably lighter starting with v2.1.316.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Security & Limitations

### Claude service status — no incidents on 10/31 or 11/1, everything operational

**A direct check of the official status.claude.com shows "No incidents reported" for both 10/31 and 11/1, with claude.ai, Claude Console, Claude API, Claude Code, Claude Cowork, and Claude for Government all showing Operational status.**

**If you ran into errors recently, they appear to have already been resolved — so if something goes wrong today, it's more likely worth checking your local setup or network first.** [Claude Status](https://status.claude.com)

### Users report account restrictions tied to work resembling large-model training (11/1)

**One user reported that after using Claude to automate research, Anthropic classified the work as training a competing model, restricting their account and force-downgrading Opus 5.5 to Opus 5.** They claimed the actual output was a rollout of a different open-source model and that Claude was only used for submitting and analyzing tasks, but the restriction stayed in place — and commenters chimed in with similar reports of restrictions tied to RFT, SFT, or other large-model training work, regardless of location or VPN use. That said, this is a user-side account, and Anthropic's official position hasn't been separately confirmed.

**If you're running workflows that automate reinforcement learning or fine-tuning research through Claude Code or the Claude API, it's worth keeping in mind that work classified as training a competing model could get your account restricted or your model force-downgraded — and lining up a fallback accordingly is the safer bet.** [GeekNews](https://news.hada.io/topic?id=36358)

### A Linux kernel TCP flaw exposed a CVSS 9.8 use-after-free vulnerability (10/29)

**CVE-2026-98432 is a use-after-free triggered during IPv4 TCP handshake processing, affecting every unpatched Linux kernel since 4.4; because it fires before application-level authentication, it exposes web servers, SSH, databases, load balancers, and Kubernetes nodes broadly.** Anthropic reported a lab exploit that gains root with no credentials on servers running MPTCP listeners, and upstream fixed it by swapping `kfree()` for `kfree_rcu()`.

**If you manage servers or Kubernetes infrastructure with Claude Code, or automate security audits, check your running kernel version against your distro's security tracker and run `ss -Mlnp` to see whether any MPTCP listeners are exposed — patching should be the top priority.** [GeekNews](https://news.hada.io/topic?id=36352)

## Ecosystem & Plugins

### Opus 4.8 fast mode enters deprecation — removal on 11/30 (v2.1.316)

**Opus 4.8's fast mode entered deprecation as of October 30, 2026, and will be fully removed on November 30.** After removal, requests sent to Opus 4.8 with fast mode will not fall back to standard Opus 4.8 — they'll simply return an error. To keep the speed benefit, you'll need to move to Opus 5.5.

**If any of your pipelines or automation depend on Opus 4.8 fast mode, test your migration to Opus 5.5 before November 30 to avoid requests failing outright once the mode is gone.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### A Claude Code plugin recreates OpenAI's Navier-Stokes proof workflow (10/31)

**This unofficial Claude Code plugin ports over the workflow OpenAI described using for its Navier-Stokes proof work — splitting each hypothesis into separate proving and disproving teams that verify independently, cross-sharing each team's key findings every round, and reallocating budget toward the most promising hypotheses.** Verification criteria are defined before exploration begins, so only claims that survive independent verification make it into the conclusion, and the tool automatically judges whether the team-based approach actually beat a solo baseline. The creator notes it burns 8–10x more tokens, making it worthwhile only for expensive questions without one clean answer.

```bash
/plugin marketplace add mydal-lab/hypothesis-teams
```

**If you're handing Claude Code complex verification tasks where multiple hypotheses look equally plausible, it's worth trying this plugin's structure of splitting proving and disproving teams for cross-verification instead of letting Claude judge alone.** [GeekNews](https://news.hada.io/topic?id=36319)

## Minor Changes

All of the following are from **v2.1.316** (10/31).

- **Added `managed.policy_mode: layered`**: instead of applying only a single matching policy as before, all matching policies are now merged in order from the bottom up.
- **Added `guardrail.input_tagging` for the Bedrock upstream**: wraps prompts with the input tags required by Amazon Bedrock guardrail's prompt attack filter. Using `all_messages_and_system` also tags the system prompt.
- **Added `CLAUDE_CODE_DISABLE_LOOPED_CROSS_CERT_DROP`**: lets private CA environments with mutually-cross-signed certificates forming a loop keep those certificates instead of having them stripped.
- **[VSCode] You can now log into the Claude apps gateway directly from the chat panel**, without needing a terminal.
- **[Cloud sessions] Added form cards for responding to or declining input requests from MCP servers**; previously these requests went unseen and were simply canceled.
- **[Code Review] Added a card on the analytics page showing finding counts by severity over time.**
- **Fixed an issue on Vertex AI and Bedrock where sessions would error out mid-session if the latest sonnet, opus, or haiku model wasn't yet available in the account or region**; it now automatically falls back to an older model instead.
