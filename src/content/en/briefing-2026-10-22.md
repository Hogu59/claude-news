# Claude Code Daily Briefing - 2026-10-22

## Release Summary

| Version | Date | Key Changes |
|------|------|----------|
| **v2.1.307** | 10/21 | Added `/claude-api api-version`, added the `claude_code.safety_event` OTel event, added `@claude review stop` to Code Review, and 40+ other changes |
| v2.1.306 | 10/21 | Fixed a `claude -p` cloud session login error, fixed a "prompt too long" error in sessions with many MCP tools — 2 changes total |
| v2.1.305 | 10/20 | Added `sandbox.allowNestedUserNamespaces` and 40+ other changes (covered in the 10/21 briefing) |

**A day after v2.1.305 landed on 10/20, v2.1.306 and v2.1.307 both shipped on 10/21.** v2.1.306 was a small patch fixing a cloud-session login error and a compaction bug in MCP sessions. The following v2.1.307 added the Claude API version-migration command and safety-event observability, while also fixing a batch of bugs including duplicate MCP tool-call sends, fork subagent collisions, and WebFetch error handling in Cowork.

[Full release notes](https://github.com/anthropics/claude-code/releases)

## New Features & Practical Usage

### Claude Duet — Anthropic's always-on personal AI agent that reaches out first when work needs a decision (announced 10/21)

**Anthropic unveiled Claude Duet as a research preview: a personal AI agent that handles tasks you hand it by message on Anthropic's own cloud computer, then reaches out first whenever a decision is needed or the work is finished.** Tasks keep running even after you close your laptop or power off your phone, and it rounds up what matters from your email, calendar, and connected apps into a daily morning digest. Irreversible actions — sending a message, making a payment, signing something, deleting something — are designed to require your approval before Duet executes them. It's currently rolling out via a waitlist to US Pro and Max subscribers; Team and Enterprise plans aren't included yet. It lands in the same competitive space as other always-on agents like OpenAI's Dots and Meta's Muse.

**If you're weighing whether to hand off ongoing email or calendar management to Claude, it's worth checking how the approval gate for sensitive actions like payments and signatures is designed before joining the waitlist.** [Claude Duet](https://claude.com/product/claude-duet)

### `/claude-api api-version` — migrate your Claude API code to the latest API version in one shot (v2.1.307)

**The new `/claude-api api-version` command moves a project's Claude API calling code to the latest API version, 2026-10-21.** Previously, every time the API version bumped, you had to track down the changed request/response formats yourself and update the code by hand.

```bash
# Move Claude API code to the latest API version (2026-10-21)
/claude-api api-version
```

**If you maintain code that calls the Claude API directly, it's more efficient to run this command first and review whatever differences remain, rather than manually tracking every change each time the API version advances.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### `claude_code.safety_event` — observe the exact moment permission rules, auto mode, hooks, or the sandbox block a tool call (v2.1.307)

**The new OpenTelemetry event `claude_code.safety_event` fires whenever permission rules, auto mode, safety checks, hooks, or the sandbox stop, re-prompt, or roll back a tool call.** Previously, figuring out which safeguard kicked in and when meant digging through session logs by hand.

**If you want to monitor, at an organizational level, how often — and for what reasons — Claude Code's permission and sandbox policies actually fire, feeding this event into your OpenTelemetry pipeline and building a dashboard around it is useful for tuning safety policy.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Developer Workflow Tips

### Running several fork subagents at once no longer steps on their own work as often (v2.1.307)

**When multiple fork subagents run concurrently, each one now knows which run it belongs to, which largely eliminates the problem where one fork mistook another's in-progress work for its own and tried to start it again.** Previously, forks launched in parallel would occasionally duplicate each other's work.

**If you rely on calling several fork subagents in a single message for parallel work, this fix makes the pattern noticeably more stable — worth pushing fork parallelism further now.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Self-hosted runner checkout hooks now fail by default past 30 minutes (v2.1.307)

**The default behavior changed so that if a checkout hook runs past 30 minutes, the session setup itself is now treated as failed; if your hook legitimately needs longer, you can raise `--checkout-hook-timeout-min` or set it to `0` to remove the limit entirely.** Previously, checkout hooks could run indefinitely while continuing to occupy a runner slot.

**If you run a self-hosted runner with a checkout hook that takes a while — repository initialization, large LFS downloads, and the like — check whether it typically runs past 30 minutes before upgrading to v2.1.307, and adjust `--checkout-hook-timeout-min` ahead of time if needed.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### `/permissions` > Recently denied now shows the actual denied command (v2.1.307)

**A bug where the Recently denied list in `/permissions` failed to show the denied shell command has been fixed; approving a row now displays the actual command name instead of a description of it.** Alongside this, a bug where auto mode's local classifier ignored approvals from this list when inspecting retried commands was also fixed.

**If you manage permissions by running auto mode and retroactively approving commands from the Recently denied list, it's now worth taking advantage of seeing the actual command for an accurate judgment call — and the approval takes effect immediately on retry.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Security & Limitations

### Claude service status — a 40-minute spike in Claude Fable 5 request errors was reported and resolved (10/21)

**Checking the official status.claude.com directly, an investigation notice went up at 19:49 UTC on 10/21 reporting increased errors on Claude Fable 5 requests, and it was marked resolved by 20:29 UTC.** The notice only states that an issue affecting other Claude models was resolved at the same time, so the exact scope of impact can't be confirmed from the page alone. As of 10/22, claude.ai, the Claude API, Claude Code, Claude Console, Claude Cowork, and Claude for Government are all showing Operational status.

**If you hit errors or failed responses from Claude Fable 5 on the evening of 10/21, it's more likely this 40-minute incident than a local configuration issue, so retrying is worth a shot.** [Claude Status](https://status.claude.com)

### LiteLLM 1.107.0 package and Docker images were compromised in a supply-chain attack, shipping credential-stealing malware and a RAT backdoor (10/21)

**Version 1.107.0 of LiteLLM, an LLM proxy package downloaded over 92 million times a month, was compromised in a supply-chain attack across PyPI, Docker Hub, and GHCR, installing credential-stealing malware that runs on every Python startup along with a secondary RAT backdoor.** It harvested SSH keys, cloud credentials, CI/CD secrets, and even LLM provider keys stored in the LiteLLM proxy, exfiltrating them to lookalike domains mimicking the official one; the compromised version was pulled roughly 2 hours after it went live.

**If you run Claude Code through a LiteLLM proxy via `ANTHROPIC_BASE_URL`, check whether you installed 1.107.0 during that window — if so, roll back to a known-safe earlier version and rotate every credential immediately, including your LLM provider keys.** [GeekNews](https://news.hada.io/topic?id=35767)

### GitLab patched a CVSS 10.0 vulnerability that could lead to unauthenticated remote code execution (10/22)

**GitLab CE/EE released a security patch for a critical CVSS 10.0 vulnerability caused by an integer overflow in the CI/CD regex compiler, which could let an unauthenticated attacker execute arbitrary code on the server; self-managed installations are strongly urged to upgrade immediately.** GitLab.com has already been patched.

**If you connect Claude Code's Code Review or self-hosted runners to a self-managed GitLab instance, this vulnerability specifically targets CI/CD pipelines, so checking your connected GitLab instance's patch version should be top priority.** [GeekNews](https://news.hada.io/topic?id=35777)

## Minor Changes

All of the following are from **v2.1.307** (10/21), with a couple carried over from **v2.1.306** (10/21).

- **`@claude review stop` (or `off`, `pause`) was added to Code Review**, letting you end a PR's "@claude review always" subscription without kicking off a new review.
- **WebFetch in Cowork cloud sessions now returns a site's 4xx response or robots.txt refusal as a normal result instead of a tool error**, matching local-session behavior.
- **The browser login success screen now appears as soon as login finishes**, instead of waiting to load the account profile first.
- **Fixed `claude -p` incorrectly reporting "Not logged in" when started inside a cloud session without session environment variables** (v2.1.306).
- **Fixed API errors in sessions with many MCP tools being mislabeled as "prompt is too long," which was triggering unnecessary compaction** (v2.1.306).
- **[VSCode] When voice dictation stops itself after 15 seconds of no detected speech or hitting the 2-minute cap, the mic button now shows why it stopped and keeps the text transcribed so far.**
