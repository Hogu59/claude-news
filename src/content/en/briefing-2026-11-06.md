## New Features & Practical Usage

### Cloud sessions can now start without picking a repository (v2.1.318)

**When starting a cloud session in Anthropic's hosted environment, there's now a "No repository" option that skips picking any repository at all.** Until now, every cloud session had to start by choosing which repository to connect to — an unnecessary hurdle for research, scratch work, or one-off questions unrelated to any particular codebase.

**If you've wanted to run research or quick script experiments in a cloud session without tying it to a git repository, as of v2.1.318 you can open a new session and skip the repository-picking step entirely.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### `assume_role` added to the Claude apps gateway's mantle upstream, enabling per-AWS-account cost attribution (v2.1.318)

**The Claude apps gateway's mantle upstream now supports an `assume_role` setting, letting it send requests under a role in a different AWS account — which also makes it possible to attribute AWS costs by developer.** For organizations that run across multiple AWS accounts while operating the Claude apps gateway centrally, figuring out which team's or developer's usage should land on which account's bill has been a hassle until now.

```yaml
# Example Claude apps gateway config (assume_role on the mantle upstream)
upstreams:
  - name: finance-team-mantle
    type: mantle
    assume_role:
      role_arn: arn:aws:iam::123456789012:role/claude-gateway-finance
```

**If your organization spans multiple AWS accounts and centralizes Claude usage through the Claude apps gateway, it's worth using `assume_role` to assign per-account roles — that gets you cost attribution and guardrail separation at the same time.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Developer Workflow Tips

### The grounded-expert skill makes agents search out and cite official docs instead of answering from memory (Show GN, 11/5)

**Persona prompts like "act as an HTTP expert" push the model to answer from memory, so wrong answers come out sounding just as confident as correct ones — grounded-expert is a Claude Code skill that, when a question comes in, forces a subagent to use WebSearch/WebFetch to pull up the actual spec, documentation, or paper and base its answer only on that.** Every claim gets tagged `EXTRACTED` (a verbatim quote with a source URL), `INFERRED` (reasoning stitched together from multiple sources), or `not confirmed` (unverifiable), and before concluding it runs one more search specifically looking for counter-evidence; you can pick a depth of quick, standard, or thorough.

```bash
# Install the grounded-expert skill in Claude Code
/plugin install grounded-expert --marketplace pko89403/grounded-expert
```

**If you've ever been burned by Claude giving a plausible but unverified answer to something like "did this API's behavior change in the latest version," this skill is worth trying — it requires every answer to come with EXTRACTED citations you can check against the original source.** [GeekNews](https://news.hada.io/topic?id=36651)

### Running multiple coding agents at once? Give each one its own git worktree for isolation

**A research engineer at Salesforce AI Research shared how they run five to six coding agents at once — Claude Code, OpenCode, Codex, Pi, and others — and the key is assigning each agent its own git worktree so their file changes never interfere with each other.** With that isolation in place, you can try a bold idea in a fresh worktree right away, and if it doesn't pan out, just discard that worktree with nothing lost. As an example, they describe prototyping a noise-reduction feature for a Mumble client with a single prompt in about 20 minutes.

```bash
# Give each agent its own workspace so they don't interfere with one another
git worktree add ../myproject-agent2 -b agent2-noise-reduction
```

**If you've run Claude Code across multiple sessions and had one agent's changes contaminate another agent's working directory, it's worth writing worktree-per-agent into your CLAUDE.md or team workflow docs as a hard rule.** [GeekNews](https://news.hada.io/topic?id=36586)

## Security & Limitations

### Claude service status — no incidents on 11/5, everything still normal as of 11/6

**Checking status.claude.com directly: 11/5 shows "no incidents reported today," and as of 11/6 claude.ai, the Claude API, Claude Code, Claude Console, Claude Cowork, and Claude for Government are all showing "all systems operational."** The most recent incident was a Google Calendar/Gmail connector error, resolved on 10/28.

**If you ran into service errors in the past few days, they've all since cleared up — if you hit a problem today, it's more likely worth checking your local setup or network first.** [Claude Status](https://status.claude.com)

### A bug report claims Claude Code sends your account email to third parties during web search (11/6, unverified)

**In a GitHub issue (anthropics/claude-code#107757), a user claims that Claude Code 2.1.318 includes the account email address in the request's `User-Agent` header when performing web searches, and that this is causing them to receive dozens of spam emails a day.** However, no actual request headers, reproduction steps, or destination sites have been shared, so there's no independent way to verify the claim yet; the issue remains open and no official response from Anthropic has been confirmed. Comments note that v2.1.317 and later include a check called `cc-plugin-privacy` that lets you review or disable this behavior from `/plugins`, and several other users separately reported seeing identifiable values — like company names or repository names — in request headers.

**If leaking account info over the network is a concern for a workflow that relies heavily on web search, it's worth checking the `cc-plugin-privacy` setting under `/plugins` directly — even with the report itself unverified.** [GeekNews](https://news.hada.io/topic?id=36676)

## Ecosystem & Plugins

### Show GN: Payple MCP — a payment processor's own MCP server for letting AI coding tools read its integration docs (11/5)

**Korean payment processor Payple has released an MCP server that lets AI coding tools directly search and read 22 payment integration docs from its developer center, with no API key required to connect.** It covers domestic card/account payments, recurring billing, payment links, international card payments, settlement/payout processing, reconciliation, and response codes — and it's designed to guide implementation off a single source of truth, warning against mixing up keys and response codes between domestic, international, and settlement/payout flows, and instructing the agent to ask the developer rather than invent any value not found in the docs. It doesn't initiate payments or look up transaction records itself.

```bash
# Connect the Payple MCP server to Claude Code
claude mcp add --transport http payple https://mcp.payple.kr/mcp
```

**If you've done payment integration work with Claude Code and watched it confidently invent a parameter or response code that isn't in the docs, this MCP server is worth trying — it pushes the AI to look up the official docs instead of guessing.** [GeekNews](https://news.hada.io/topic?id=36629)

## Minor Changes

All of the following are from **v2.1.318** (11/4).

- **Fixed `claude mcp add`/`remove` overwriting the config file without waiting for its lock** — they now wait for the lock, or exit with code 1 on failure (though another task saving in the meantime can still overwrite the server config).
- **Fixed stdio MCP servers that exit on a version-check request getting re-probed every startup** — a server that dies within 3 seconds for its own reasons now gets pinned to the legacy handshake for 7 days.
- **Fixed a deleted session transcript being regenerated from the last prompt when an idle non-interactive session was terminated.**
- **Fixed all connections failing when the `NODE_EXTRA_CA_CERTS` file starts up empty, not in PEM format, or with a corrupted certificate** — only readable certificates are now used, with a warning printed to stderr.
- **Fixed version-cleanup logic mistaking a running process owned by another user (e.g., via `sudo claude`) for a dead one and deleting its binary.**
- **Fixed Remote Control hosts, background daemons, and self-hosted runners failing to start new sessions (`spawn ENOENT`) after an update or version cleanup deleted the binary of a still-running process.**
- **Improved non-interactive runs (`claude -p`, the SDK) to skip rewriting `~/.claude.json` when nothing in it has changed.**
- **Fixed cloud sessions getting blocked by an inaccessible redirect when reading GitHub Actions logs via `gh run view --log`/`gh api`** — logs now fetch normally in most environments.
- **Added the `google-chrome` name and `CHROME_PATH` to cloud sessions**, so tools other than Playwright can also find the bundled Chromium.
