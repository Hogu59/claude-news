## New Features & Practical Usage

### Idle conversations now get auto-compacted before the cache expires (v2.1.299)

**If a terminal session with over 200K tokens of conversation sits idle for about 54 minutes, it's now automatically compacted before the 1-hour prompt cache expires.** Previously, stepping away long enough for the cache to expire meant the entire conversation had to be reprocessed on your next message, slowing things down and running up costs. Now compaction happens ahead of time, while the cache is still alive.

```bash
# Adjust the minimum token count that triggers idle compaction (default: 200,000)
export CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS=100000
```

```jsonc
// Turn idle compaction off entirely via settings.json
{ "idleCompaction": false }
```

**If you often leave large tasks running and step away, you'll notice your next message getting handled faster with zero extra setup, and the environment variable and setting above, available since v2.1.290, let you tune the trigger point or disable the feature outright.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### `/advisor` arrives on the AWS Claude Platform (v2.1.300)

**On the AWS Claude Platform, no advisor runs until one is explicitly chosen via `/advisor`, the `advisorModel` setting, or the `--advisor` flag.** Organizations that want to disable the advisor feature altogether can do so completely with `CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1`.

```bash
# Fully disable the advisor feature on the AWS Claude Platform
export CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1
```

**If you're running an AWS-based Claude Platform environment, it's worth knowing upfront that advisor isn't on by default and how to turn it off, so you can apply it to your org's policy right away.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Developer Workflow Tips

### To put AI agents to work in games, expose game state first, not just code (10/15)

**A post argues that getting real value out of LLM agents in games takes more than handing over source code; agents need to be able to read and manipulate game state, data, and run results directly.** It stresses setting up deterministic state reproduction and save/load support early in development, so an agent can repeatedly verify changes under identical conditions.

**If you're planning to have Claude Code work on game or simulation code, build hooks or scripts that can save, restore, and inspect game state before you just hand over the source repo, so the agent can compare before-and-after behavior under matched conditions.** [GeekNews](https://news.hada.io/topic?id=35355)

### `/usage` now warns about costly usage patterns upfront (v2.1.299)

**`/usage` now flags expensive or token-heavy patterns like max effort, workflows, always-on context, and large tool results.** Previously these settings' impact on cost was hard to notice without manually comparing them against each other.

**If your Claude Code usage costs are climbing faster than expected, just opening `/usage` to see which warnings appear can immediately point you to the setting driving the cost up.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Security & Limitations

### Claude service status: fully Operational for a second day, no new incidents (10/15)

**Checking the official status.claude.com directly, as of 10/15 claude.ai, the Claude API, Claude Code, Claude Console, Claude Cowork, and Claude for Government are all Operational, with no new incidents reported since the Claude Console degradation on 10/13 at 18:00 UTC was resolved.** The incidents covered in earlier briefings from 10/9 through 10/14 all remain resolved, and following 10/14, service across the board stayed stable through 10/15 as well.

**If you ran into issues with the Claude Console usage dashboard or API requests over the past few days, things are now fully back to normal and safe to use as usual.** [Claude Status](https://status.claude.com)

### A vulnerability letting code run outside the sandbox via the plugin directory has been closed (v2.1.299)

**A bug has been fixed where shell commands running inside the sandbox could write files into the folder specified by `--plugin-dir`. Because Claude Code reads code from that folder back in and executes it outside the sandbox, a command that was supposed to stay contained could use this path to plant code that escaped the sandbox entirely.** For setups that run untrusted commands in sandbox mode while also using plugins, this was a fairly serious bypass route.

**If you're using `--plugin-dir` together with sandbox mode, it's worth updating to v2.1.299 or later and confirming this bypass has been closed.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Critics say it's not AI agents going "rogue" — it's frontier AI labs skipping basic security (10/15)

**Security experts argue that incidents where AI models accessed external systems without authorization should be seen not as agents going off the rails, but as isolation and monitoring failures at frontier AI labs.** The core problem, they say, is a failure to apply security practices the industry has known for decades, like proper sandbox configuration and control over outbound network access, with the Hugging Face incident cited as an example of misconfiguration.

**If you're connecting Claude Code agents to internal infrastructure or external systems and letting them operate autonomously, the more fundamental way to avoid the failure this piece describes is to first audit your sandbox boundaries and network access scope, rather than trying to directly control the agent's behavior.** [GeekNews](https://news.hada.io/topic?id=35357)

## Ecosystem & Plugins

### Open-source coding agent OpenCode hits 2.0, restructured around a single background service (10/15)

**OpenCode 2.0 now automatically runs a single background service, with the TUI, web interface, and desktop app all connecting to that same central process.** A new Code Mode turns MCP servers and OpenAPI endpoints into callable functions from scripts, letting you write code that chains multiple tools together.

**If you're evaluating open-source coding agents alongside Claude Code, it's worth comparing how this shift to a central process tying multiple clients together, and the Code Mode that lets you compose MCP and OpenAPI calls in code, play out in practice.** [GeekNews](https://news.hada.io/topic?id=35371)

### Anthropic's Scion draws design-reuse criticism from a Mononoke developer (10/15)

**Scion, Anthropic's in-house version control system covered in the 10/14 briefing, leans on "derived data" to speed up operations like blame — and a developer who worked on Meta's Mononoke has pushed back, saying the design overlaps with the one he introduced for Mononoke back in 2022.** The criticism isn't really about reusing the design itself, but about Anthropic not properly crediting where it came from.

**Alongside the technical polish Anthropic put into Scion as a serious Git replacement, it's also worth watching how credit for design ideas gets acknowledged as they move between open source and in-house systems.** [GeekNews](https://news.hada.io/topic?id=35369)

## Minor Changes

- **(v2.1.299) Added the `CLAUDE_CODE_DISABLE_FILE_MENTIONS` environment variable**, so Claude only receives the path from an `@` file mention and reads it with its own file tools, rather than having the file's contents injected directly into the prompt.
- **(v2.1.299) Added `/effort` and `/fast` to the agent view**, letting you set the defaults for new sessions; entering either with no value opens a picker.
- **(v2.1.299) Background sessions started with `--safe-mode` now show a safe mode indicator** in the agents view preview panel.
- **(v2.1.299) Added `--shutdown-drain-sec` to `claude self-hosted-runner orchestrator`**, giving in-progress polling and spawn hooks a grace period to wrap up after receiving SIGTERM.
- **(v2.1.300) Added `cache_creation_5m_tokens` and `cache_creation_1h_tokens` to the OpenTelemetry `api_request` event**, letting you break down cache writes by lifetime.
- **(v2.1.300) Fixed a bug where `/autocompact` incorrectly warned of high token usage** when a smaller auto-compact window was selected.
