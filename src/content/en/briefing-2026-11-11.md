## New Features & Practical Usage

### Claude Fable 5.2 and Mythos 5.2 are now generally available, marking the debut of Mythos as a dedicated scientific research model (11/11)

**The 11/10 briefing only mentioned that v2.1.321 added Fable 5.2 as the default Fable model and that it scored 65 on the Artificial Analysis Intelligence Index — but Anthropic's own announcement goes well beyond that and introduces Mythos 5.2 for the first time.** Both models come from the same underlying model but differ in who can access them. Fable 5.2 ships with cybersecurity and biosecurity safeguards and is available to everyone, while Mythos 5.2 is restricted to vetted institutions doing security or life-sciences research. Anthropic recommends starting most coding and knowledge work with Opus 5.5, and reaching for Fable or Mythos only on the hardest tasks.

```bash
# Pricing: $8 per million input tokens, $40 per million output tokens (lower than 5.1)
# Fast mode: 2x the price ($16 in / $80 out) for up to 2.5x faster token generation
/model claude-fable-5-2
```

Anthropic says a Fable 5.2 agent formalized Fermat's Last Theorem in Lean in about 30 hours — a sharp drop from the 11 days a prior internal attempt took with a dedicated harness and human guidance. The announcement also describes coordinating more than 1,000 subagents over 8 days to build an operating system prototype, and three pieces of electronics built from single-paragraph requests that worked correctly without any circuit fixes. Mythos 5.2, meanwhile, developed a method for predicting adeno-associated virus (AAV) capsid structures, accurately modeling 28 of 34 cases.

**If you're already using Claude for work that demands deep reasoning — complex math proofs, scientific research, hardware design — it's worth following Anthropic's own recommendation rather than routing everything through Fable: start with Opus 5.5, and reserve Fable and Mythos for the genuinely hard cases.** [Anthropic's announcement](https://www.anthropic.com/claude-fable-and-mythos-5-2) · [GeekNews](https://news.hada.io/topic?id=36896)

### Claude Whiteboards and Sheets launch in beta, and Claude Data goes GA (11/11)

**Claude Whiteboards, a team collaboration board, and Claude Sheets, a spreadsheet tool, are now available in beta, while Claude Dashboards — which started in beta back in October — has graduated to general availability as Claude Data.** Whiteboards is a real-time board Claude and your teammates can edit together: turn a rough plan into a timeline with owners and dates, or pull action items out of meeting notes, then export the finished board as a doc or presentation, or send it to Lucid, Miro, or Vani by Zoho. Sheets lets you build spreadsheets from a prompt — tabs, formulas, formatting, and dropdowns included — highlights the cells Claude changes for easy change-tracking, and exports to .xlsx or CSV when you need full spreadsheet functionality. Data lets you query sources like Redshift, BigQuery, and ClickHouse, and adds certified queries (beta) so teams can approve a shared definition of a metric, plus live sharing (beta), which surfaces only pre-approved query results.

```text
Team plan         → all three features on by default
Enterprise plan   → Whiteboards and Sheets off by default; Data turns on by default starting 11/19
Where to change it → Organization settings > Artifacts
```

**If your organization has been bouncing between separate SaaS tools for whiteboarding, spreadsheets, and data analysis, this launch is a good excuse to handle the lightweight versions of that work directly inside Claude, and only hand off to specialized tools like Lucid, Miro, or Excel once you need serious editing power.** [Claude's announcement](https://claude.com/resources/articles/sheets-whiteboards-data) · [GeekNews](https://news.hada.io/topic?id=36958)

### Fast mode now works in Vertex AI's global, US, and EU regions (v2.1.322)

**Fast mode used to be limited to a handful of regions; as of this release it also works in Vertex AI's global, US, and EU regions, automatically falling back to standard speed if Vertex rejects the request.**

**If you're running Claude Code through Google Cloud Vertex AI, it's worth trying `/fast` right away in those regions — no extra configuration needed.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Developer Workflow Tips

### Google Chrome's modern-web-guidance skill lifted Claude Code's eval pass rate from 57% to 88% (11/11)

**This skill nudges coding agents away from the stale JavaScript patterns baked into their training data by searching a CLI-indexed guide of roughly 250 web platform features and 203 usage examples, then feeding the relevant results into context.** It searches offline using embeddings and BM25, with no network calls or API keys required, and uses Baseline data to suggest fallback implementations that match current browser support. In a Playwright-graded before/after comparison, Claude Code's pass rate rose from 57% to 88%, Codex CLI's from 54% to 82%, and Antigravity CLI's from 58% to 94%.

```bash
# Install the modern-web-guidance skill in your project
npx modern-web-guidance
```

**If Claude Code has been writing outdated polyfills or needlessly heavy JavaScript, it's worth installing this skill to steer it toward current CSS, DOM, and accessibility features, then checking whether your own pass rate actually improves.** [GeekNews](https://news.hada.io/topic?id=36964)

### When adopting a community skill into your project, use keep / bind / rewrite / drop / review to record your reasoning (11/10)

**Claude Code and Codex skills pulled from GitHub are written against the original author's project, so they often assume tools your project doesn't have or reference test commands that don't match yours — skilladopt addresses this by walking through the skill paragraph by paragraph and recording a keep (preserve as-is), bind (wire it in), rewrite, drop, or review (needs a closer look) decision along with the reasoning behind it.** When your project changes, it flags only the lines affected by that change; it never executes files from inside the skill, reading only a pinned commit instead; and the agent making the calls runs inside a read-only sandbox.

```bash
npx skilladopt setup
npx skilladopt anthropics/skills frontend-design
npx skilladopt impact   # see only the lines worth re-checking after a project change
```

**If you've ever hand-edited someone else's skill and then lost track of which lines needed another look every time a teammate changed a test command or rule, this tool is worth trying — it makes the reasoning behind each decision, and the lines it affects, traceable.** [GeekNews](https://news.hada.io/topic?id=36942)

## Ecosystem & Plugins

### Show GN: Herdr CKD — an open-source AI coding orchestrator bundling 13 MCP tools for Claude Code (11/11)

**This orchestrator tackles the problem of coding agents declaring a task "done" while build errors or missing requirements remain, not through prompt instructions but through physical permission separation and git worktree isolation.** A fixed coordinator (Core C) that can't edit files or run commands assigns work and issues the final PASS/FAIL verdict; implementation threads (A1 through An) work in their own worktrees; and audit threads (B1 through Bn) perform read-only reviews based solely on `git status` and `git diff --stat` output — never the implementer's own explanation. The key idea is that auditors never see the implementer's self-justification, which cuts down on tasks passing purely because the agent talked its way through. It also supports hybrid routing, mixing a cloud model like Claude for the coordinator with local models from LM Studio or Ollama for the implementation and audit threads.

```text
Core C (coordinator, no read/write) → A1-An (per-worktree implementation) → B1-Bn (read-only, git-diff-based audit) → PASS/FAIL
```

**If you've been running Claude Code with accept-edits or auto mode across multiple concurrent agents and found it hard to trust an agent's own "it's done" report, this structure is worth a look for physically separating implementation from audit.** [GeekNews](https://news.hada.io/topic?id=36946)

### Val Town is shutting down in phases after losing ground in the cloud computing market (11/11)

**Val Town stops billing on 11/10, switches to read-only mode on 12/10 (except for sqlite and blob storage), and shuts down completely on 1/10/2027.** Its source code is slated to go open source on February 1, 2027. The team also published migration guides to Cloudflare, Vercel, Netlify, and Render, saying they expect users to lean on current LLMs to help with the move, on the premise that today's models handle this kind of migration work well.

**If you're running an app on Val Town, you'll need to finish migrating before January 10, 2027 — and this is also a good opportunity to consider having Claude Code automate the move to another hosting environment.** [GeekNews](https://news.hada.io/topic?id=36961)

## Minor Changes

All of the following are **v2.1.321** (11/9) items not covered in the previous briefing.

- **Fixed a bug where the `PreToolUse` `mcp_tool` hook for stdio and HTTP MCP servers would be skipped if the response exceeded 16MiB** — now the tool call itself is rejected instead.
- **Fixed a bug where a read-only command written with a variable, like `grep -r foo "$PWD/src"`, triggered an unnecessary permission prompt that the same command with a literal path wouldn't.**
- **Fixed a bug where flags like `--permission-mode`, `--dangerously-skip-permissions`, `--model`, `--effort`, and `--agent` were ignored on the `claude agents` command whenever another flag such as `--verbose` was also present.**
- **Claude now refuses to send files whose names hide directional or control characters that make them display differently in the Claude app.**
- **Fixed high memory usage in long-running sessions that repeatedly read large files line by line.**
- **Fixed a bug where the git status passed to Claude at session start was misread as "clean" if git status itself failed** — it's now reported as "unknown" instead.
- **Notifications for background commands over 1,000 characters, and TaskStop results, now show Claude only the start and end instead of the full text**, saving context.

## Interesting Projects & Tools

- **Show GN: flickbook — replays AI-made changes step by step using Claude Code hooks (11/11)**: When an agent finishes a task, the diff usually shows up as one large blob that's hard to trace back to individual decisions. flickbook fixes this by marking a starting point with `flickbook start`, recording steps with `flickbook step` (done automatically if you use Claude Code hooks), and then letting you walk through each step's request, actual diff, and related concepts in a local web viewer via `flickbook replay`. It only reads files and never sends any data out, and unlike Claude Code's checkpoints, which exist for reverting changes, it's built purely for revisiting changes at any point.

```bash
npx flickbook --help
```
