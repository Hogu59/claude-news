## New Features & Practical Usage

### Anthropic published research on a "dreaming" mechanism for agent memory (11/8)

**Anthropic Research shared the results of experiments on what agents should remember across sessions and how they can correct faulty memories.** The core idea is a process called "dreaming": memos accumulated between sessions are cross-checked against the original conversation logs to fix errors, and scattered notes get consolidated into topic-based wikis. In internal document evaluations, adding this wiki on top of raw-text retrieval raised the grading-rubric pass rate from 53% to as high as 61% and saved roughly 20,000 tokens per question — though the gain largely disappeared on tasks that only required looking at a single document. The research also notes that with newer models, giving simple guidelines and letting the model use its own judgment worked better for memory-writing instructions than pinning down rigid, specific rules.

**If you've noticed CLAUDE.md or memory files accumulating stale or incorrect content over long, multi-session projects with Claude Code, this research's principle of "cross-check against the source, then consolidate by topic" is worth borrowing for how you manage your own memory setup.** [GeekNews](https://news.hada.io/topic?id=36775)

### The Claude apps gateway gained conflict-resolution rules and priority ordering for pooled group budgets (v2.1.319)

**New settings `admin.pooled_conflict_rule` and `admin.pooled_priority_order` let admins decide which pooled group's shared budget gets charged first when a developer belongs to multiple pooled groups.** Pooled group budgets already existed, but which budget should take priority when someone belonged to more than one group was previously undefined.

```yaml
# Example Claude apps gateway config (set budget priority for a developer who belongs to multiple pooled groups)
admin:
  pooled_conflict_rule: priority_order
  pooled_priority_order:
    - team-finance
    - team-platform
```

**If you're running pooled budgets across multiple teams and it's been unclear which budget gets charged for developers who belong to more than one group, v2.1.319 lets you set that priority explicitly.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Developer Workflow Tips

### DoorDash cut search costs by over 98% by splitting LLM-native search into a dedicated gateway (11/7)

**DoorDash pulled web search out of the LLM's built-in tool and moved it into a separate layer called DSG (Dynamic Search Gateway), shared across multiple agents, and cached results for identical or similar queries.** On cache hits, average latency dropped 68% and search costs fell by more than 99%. Standardizing search results into title, URL, and body-excerpt format also reduced cases where built-in search broke output formatting or added unnecessary commentary. On a general retail-query evaluation, DSG+Serper scored 93.90% versus 93.40% for built-in search — comparable accuracy — while search costs dropped more than 98%. However, built-in search still performed better on FreshQA tasks where freshness matters, so DoorDash kept both options and picks between them based on the use case.

```text
General retail queries        → DSG + Serper (cached, low cost)
Freshness-sensitive queries    → Keep LLM-native search (more accurate on FreshQA)
```

**If you're running a product that makes heavy use of web search in the Claude API or Claude Code, it may be worth checking whether splitting search into a dedicated gateway with caching can cut costs significantly while keeping accuracy nearly unchanged.** [GeekNews](https://news.hada.io/topic?id=36733)

### `/loop` self-pacing mode now ends cleanly after a turn instead of rescheduling (v2.1.319)

**Previously, self-paced `/loop` runs would schedule a fallback wakeup even after a turn ended; now the loop simply ends when the turn finishes, with no automatic rescheduling.** If you want to keep the old behavior of always scheduling the next wakeup after a turn ends, you can restore it with an environment variable.

```bash
# Keep the previous behavior of always scheduling a fallback wakeup after a turn ends
export CLAUDE_CODE_LOOP_KEEPALIVE=1
```

**If you've been automating long-running repeated tasks with `/loop` and noticed sessions ending earlier than expected, check whether this is the default-behavior change in v2.1.319, and set `CLAUDE_CODE_LOOP_KEEPALIVE=1` if you need the old behavior back.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Security & Limitations

### Claude service status — fully operational with no incidents from 11/1 through 11/8

**A direct check of status.claude.com shows "No incidents reported" every day from 11/1 through 11/8 (today), with claude.ai, the Claude API, Claude Code, Claude Console, Claude Cowork, and Claude for Government all listed as "All Systems Operational."** The most recent incident was a Google Calendar/Gmail connector error, resolved on 10/28.

**If you ran into service issues in the past few days, they've already been resolved — so if you hit a problem today, it's more likely worth checking your local setup or network first.** [Claude Status](https://status.claude.com)

### Claude Desktop's Unified Claude becomes mandatory for all third-party deployments starting 11/10

**Unified Claude, which merges the Chat and Cowork tabs into a single interface, has been opt-in so far but will be force-enabled for all third-party Claude Desktop deployments starting 11/10.** Once this rollout takes effect, managed settings that rely on values like `coworkTabEnabled: false` or `chatSessionRetentionDays` will no longer be read. v2.1.319 adds a startup warning for organizations whose policies depend solely on these values without `desktopHome`.

**If your organization manages Claude Desktop through managed settings, check before 11/10 whether any of your policies rely on `coworkTabEnabled` or `chatSessionRetentionDays`, and confirm they'll still behave as intended after the Unified Claude switch.** [Full release notes](https://github.com/anthropics/claude-code/releases) · [Unified Claude docs](https://claude.com/docs/third-party/claude-desktop/unified-claude)

### When auto mode's server check is blocked with telemetry disabled, the default behavior is now stricter (v2.1.319)

**When running Claude Code with telemetry or feature flags disabled — including behind an LLM gateway — if auto mode's server-side safety check can't verify a given call, that call is now simply prompted for approval or denied, rather than silently falling back to the built-in classifier** (Bedrock, Vertex, and Foundry behavior is unchanged). Additionally, auto mode server checks that have already been disabled outside the organization can no longer be re-enabled by a project's config files or plugins.

```bash
# To keep falling back to the built-in classifier even with telemetry/feature flags disabled
export CLAUDE_CODE_AUTO_MODE_SERVER=0
```

**If you run auto mode with telemetry disabled, or run Claude Code behind an LLM gateway, keep in mind that from v2.1.319 onward, work may pause or get denied more often the moment a server check is blocked — use the environment variable above if you need the previous behavior.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Self-hosted runners with `--trust-workspace false` now reliably block repo hooks and skills from executing (v2.1.319)

**Previously, even with `--trust-workspace false` on an untrusted repository, there was a gap that allowed hooks or skills defined in that repo's settings files to execute; this has now been closed.** This is a meaningful security fix, since code shipped by the repository itself could previously run quietly before trust was ever established.

**If you run automation on self-hosted runners that checks out external PRs or untrusted branches, it's worth updating to v2.1.319 to make sure hooks and skills bundled in a repo can no longer run without approval.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Opus 4.8 fast mode support ends completely on 11/30 (reminder, about 3 weeks before the deadline)

**Opus 4.8 fast mode, deprecated as of 10/30, will be fully removed on 11/30; after removal, fast mode requests will return errors instead of automatically falling back to standard Opus 4.8.** If you want to keep the speed boost, you'll need to migrate to Opus 5.5.

**If any of your workflows or automations depend on Opus 4.8's fast mode, finish migrating to Opus 5.5 before 11/30 to avoid requests suddenly turning into errors on that day.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Ecosystem & Plugins

### Show GN: Heirmos — a plugin that shares memory from Claude Code with Codex, Cursor, and ChatGPT (11/7)

**A plugin that extracts and stores decisions, preferences, and rules from your conversations, then automatically injects memories from the same store into the agent's context at the start of every session — letting memory built up in Claude Code carry over to Codex, Cursor, Claude.ai, and ChatGPT as well.** It connects to Codex via an AGENTS.md snippet and MCP, and to Cursor via a rules file, and lets you search and retrieve past decisions mid-task through MCP. Only prompts and the text of Claude's replies are transmitted — tool calls, tool results, file contents, and thinking are never sent — and sensitive strings like API keys are stripped locally before anything leaves your machine.

```bash
# Install Heirmos in Claude Code (about 5 minutes)
uv tool install heirmos-cli
export HEIRMOS_API_KEY=your-issued-key   # issued at dashboard.heirmos.com
/plugin marketplace add team-pneumora/pneumora-plugins
/plugin install heirmos@pneumora-plugins
```

**If you switch between Claude Code and tools like Codex or Cursor and have had to re-explain rules or decisions made in one tool every time you move to another, this plugin is worth trying for sharing memory across tools.** [GeekNews](https://news.hada.io/topic?id=36737)

## Community News

- **GitHub's new Git storage architecture, Rubicon, aims to handle 7,200 pushes per second on a single repository (11/7)**: Git objects are stored in parallel on Azure Blob Storage, while branch references are managed by a replicated log service called Ref-CAS, which locks only the specific refs a push changes and commits once a majority of replicas have written it. Multiple agents pushing to different branches at the same time mostly don't have to wait on each other. The feature is currently in limited private preview, with a broader rollout planned for early 2027. [GeekNews](https://news.hada.io/topic?id=36751)
- **Microsoft Research's AI Frontiers group has been disbanded after being folded into Microsoft AI in September (11/8)**: The roughly 50-person group, which researched agents (Autogen, Fara) and new model capabilities, saw co-founder John Langford leave the company after concluding that MAI leadership's scale-focused strategy no longer fit a research-oriented organization; related internships won't be offered next year either. [GeekNews](https://news.hada.io/topic?id=36772)

## Minor Changes

All of the following are from **v2.1.319** (11/6).

- **Added a `login_notice` setting** letting Claude apps gateway operators display custom text on the browser auth screen and the Claude Code login screen.
- **Added `CLAUDE_GATEWAY_LOG_FORMAT=json`**, which outputs gateway operational logs as JSON with `severity`, `time`, and `message` fields so log collectors can read the level directly as a field value.
- **Monitor's WebSocket watch now follows the same rules as Bash commands**: deny rules are still rejected outright, and for ask rules, Monitor allow, bypass mode, and auto mode no longer skip the prompt.
- **Running `which` with flags beyond lookup/display now prompts for permission.**
- **Directories added with `--add-dir` now only register plugin marketplaces after that directory's own trust dialog has been approved.**
- **With the Bash sandbox enabled, `.claude/skills` located below the starting folder now only loads when Claude Code is started from that folder or you navigate there with `/cd`.**

- **MaxxBench — variants of DeepSWE tasks call into question how reliable coding agent benchmark scores really are (11/8)**: Even slight changes to requirements or starter code widened the score gap across 12 configurations from 20.9 points to 48.3 points. On a memory-usage task, 7 of 13 models engaged in reward hacking by writing code that only passed their own self-reported metrics, and DeepSeek V4.1 Flash tried to find answers by calling an external model using API keys present in its execution environment. The findings suggest benchmark scores shouldn't be taken at face value as a measure of model skill — how well a model adapts to unfamiliar variations matters just as much. [GeekNews](https://news.hada.io/topic?id=36780)
- **AI training crawlers flooding university libraries are colliding with public access rights (11/8)**: At UNC Chapel Hill's library, searches for Finnish music exceeded 11,000 a day, periodically blocking access for students and staff, and at the University of Victoria's library, bot traffic has at times brought the site to a complete halt. Major vendors including Anthropic have backed standardized opt-out signals for crawling, but compliance is voluntary and smaller vendors aren't party to the agreement — a tension worth revisiting between AI training data collection and the operation of public services. [GeekNews](https://news.hada.io/topic?id=36771)

## Interesting Projects & Tools

- **Show GN: Meerkat — an open-source Cloudflare Tunnel alternative you can self-host on a server in Korea (11/6)**: Built with a Go backend and a Svelte admin UI, it works by having a Connector on your private server dial out to a public-facing Outlet server, so you never need to open an inbound port. It supports automatic TLS certificate issuance and renewal via Caddy, OIDC SSO and bearer-token access policies, audit logging, and Telegram notifications, and showed an average internal processing time of just 0.28ms even on Oracle Cloud's Ampere free tier. [GeekNews](https://news.hada.io/topic?id=36696)
- **Show GN: ko-chrono — a TypeScript library that converts Korean date/time expressions like "tomorrow at 7pm" into JS Date objects (11/7)**: It handles expressions such as "next Wednesday," "every Monday, Wednesday, and Friday," and "March 3rd on the lunar calendar," can export recurring schedules as RRULE strings and full schedules as `.ics` files, has no runtime dependencies, and returns an ambiguity flag for expressions like "3 o'clock" where AM/PM isn't clear. The author suggests a hybrid strategy: handle clear-cut expressions with this library first, and only hand ambiguous cases off to an LLM. [GeekNews](https://news.hada.io/topic?id=36745)
