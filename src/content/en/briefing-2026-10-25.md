## Developer Workflow Tips

### Rendering Images from mods inside tmux now requires allow-passthrough and focus-events (v2.1.310)

**Mods' `Image` rendering now supports full-screen output on kitty, Ghostty, and iTerm2 3.5+, but inside tmux the actual image only renders if `allow-passthrough` and `focus-events` are turned on — otherwise you just get the `alt` text.**

```tmux
# ~/.tmux.conf
set -g allow-passthrough on
set -g focus-events on
```

**If a mod that's supposed to show an image inside tmux is only showing text, turning on these two options and restarting tmux may be all it takes to fix it.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### When an MCP server's elicitation request times out in a non-interactive session, Claude Code no longer repeats the same call (v2.1.310)

**In non-interactive sessions — `-p` or the Agent SDK — if an MCP tool call times out because the server's elicitation (user-confirmation) request never gets answered, Claude Code now surfaces both the fact that no response came back and an explicit note not to retry the same call.** Previously, Claude would sometimes repeat the call and hit the same timeout all over again.

**If you're running an MCP server that requires elicitation in a non-interactive or Agent SDK session where there's no one around to respond, it's safer to disable or work around that server's elicitation settings ahead of time.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Claude Code now automatically retries when a custom gateway rejects a beta header (v2.1.310)

**A bug where requests would fail behind some gateways or compatibility servers that reject the `effort-2025-11-24` beta value or mid-conversation system messages has been fixed — Claude Code now automatically retries without those values.** Previously, requests behind these gateways could simply fail outright.

**If you're routing through your own gateway or a compatible server via `ANTHROPIC_BASE_URL` and have run into request failures caused by a rejected beta header, upgrading to v2.1.310 will likely fix it without any manual workaround.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Security & Limitations

### Claude service status — all three 10/24 incidents resolved, everything operational as of 10/25

**Checking status.claude.com directly: the Fable 5.1, Sonnet 5.5, Haiku 5.5, and Opus 5.5 fast-mode errors covered in yesterday's briefing were marked resolved at 09:11 KST on 10/24, followed by a separate Opus 5.5-only incident from 09:23–09:37 KST and a Fable 5/Fable 5.1 incident from 14:00–14:53 KST that same day — both of which have also been resolved.** As of 10/25, no new incidents have been reported, and claude.ai, the Claude API, Claude Code, Claude Cowork, and Claude for Government are all showing Operational status.

**If you ran into errors on Fable, Sonnet, Haiku, or Opus requests up through yesterday, all three incidents are now resolved and there are no new issues today, so it should be safe to retry.** [Claude Status](https://status.claude.com)

### HTTP2Shell — the Brotli remote-code-execution flaw that started as Node2Shell has now spread to Python, Bun, Envoy, and Istio (10/25)

**The Brotli decompression vulnerability (CVE-2026-111497), first identified in Node.js as Node2Shell, turns out to share the same underlying flaw across a range of other HTTP libraries and applications, including Python packages, Bun, Envoy, and Istio.** Processing maliciously crafted compressed data can lead to memory leaks, process crashes, and remote code execution — and the risk isn't limited to requests a server receives directly; it can also hit code paths that process responses fetched from external sources.

**If you're using Claude Code to work on Node.js or Python-based services, or running a service mesh like Envoy or Istio, this is another "2Shell"-style vulnerability following PHP2Shell — start by checking whether a Brotli decompression library shows up anywhere in your dependency tree.** [GeekNews](https://news.hada.io/topic?id=35927)

## Interesting Projects & Tools

- **Rakazo — a self-hosted, open-source alternative to Grok Bot (10/24)**: An open-source project for building and running your own role-based AI assistants locally — things like inbox cleanup, sales research, or expense processing. Each bot keeps its own conversation history, memory, and task record, so you don't have to re-explain context every time, and it can drive the browser, terminal, files, and even the desktop screen. [GeekNews](https://news.hada.io/topic?id=35894)
- **GPU-unlock — a Linux module that removes the AI compute throttling on RTX 30-series GPUs (10/25)**: A Linux kernel module that lifts the instruction-issue-rate limits Nvidia imposes on FP16/BF16 compute for the RTX 30 series, unlocking throughput closer to what the professional-grade cards deliver. It patches things before the Nvidia driver initializes the GPU, so there's no need to modify the driver itself or re-patch it after every update. [GeekNews](https://news.hada.io/topic?id=35938)
