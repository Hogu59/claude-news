## New Features & Practical Usage

### Claude Mods and the first official mod, You should know — plugins can now reach deeper into Claude Code's behavior (v2.1.287)

**A new plugin extension point called Claude Mods lets plugins modify deeper parts of Claude Code's behavior.** The first official mod ships bundled: You should know, a side agent that watches your work and flags things you or Claude might otherwise miss.

```bash
# Enable on first-party sessions with telemetry turned on
/plugin enable cc-plugin-you-should-know@builtin
```

**During long refactors or complex multi-step work, a side agent that catches edge cases and side effects you or Claude might overlook takes some of the burden off having to review every significant change solo.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Opus 4.7+ and Fable now default to 1M context on Bedrock, Vertex, Foundry, and gateway deployments (v2.1.287)

**Opus 4.7 and above, along with Fable, now default to a 1-million-token context window on Bedrock, Vertex AI, Foundry, and the Claude app gateway — no more appending the `[1m]` suffix to the model ID.** If you want to keep the old 200K window, you can opt out with an environment variable.

```bash
# To keep the old 200K context instead of the 1M window
export CLAUDE_CODE_DISABLE_1M_CONTEXT=1
```

**Organizations working with large codebases on Bedrock, Vertex, or Foundry get the wider context automatically with no extra setup — but that also means token usage and costs could creep up unexpectedly, so if you're tracking a budget, it's worth checking this environment variable ahead of time.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Developer Workflow Tips

### Commit messages as a thinking tool (10/2)

**The act of writing a commit message forces you to revisit your code changes and re-examine your decisions — which is especially useful for confirming that AI-generated changes actually do what you intended.** The key point: record the why, not just the what, so teammates and your future self can understand the reasoning behind a change.

**If you're letting Claude Code draft your commit messages, it's worth adding a step where you check that the why actually comes through before accepting the generated message as-is — that's what keeps your change history useful.** [GeekNews](https://news.hada.io/topic?id=34623)

### Finding bugs — fuzzing without an oracle can't verify its own results (10/2)

**A fuzzer that cross-checks Rust's regex against regex_lite surfaced both known bugs in older versions and new ones.** The key insight: testing an algorithm only produces trustworthy results if you have an oracle to check outputs against. The latest versions turned up no further bugs.

**When you have Claude Code write a fuzzer or property-based tests, don't just have it generate random inputs — specify an oracle to compare against (another implementation, a reference algorithm, etc.) up front, and you're far more likely to end up with tests that are actually useful.** [GeekNews](https://news.hada.io/topic?id=34618)

## Security & Limitations

### Claude service status — all operational as of 10/2, 10/1 credit-delay incident resolved (10/2)

**Checking status.claude.com directly shows that, as of 10/2, claude.ai, Claude Console, Claude API, Claude Code, Claude Cowork, and Claude for Government are all Operational, with no active incidents.** That said, a "Claude Platform Credit Delays" incident did occur on 10/1 and was resolved the same day. Following the 9/29 error spike and the 9/22 multi-model errors, this marks the third incident in the past 90 days — but all three were resolved within the day.

**If you ran into delayed credit or usage counts on the Claude Platform on 10/1, it was likely tied to this incident; things are back to normal now, so if your numbers still look off, try refreshing them.** [Claude Status](https://status.claude.com)

### FTC opens inquiry into Anthropic, OpenAI, and other AI companies over product risk (10/2)

**The U.S. Federal Trade Commission has opened an inquiry into the potential risks posed by products from AI companies including Anthropic and OpenAI.** The move follows warnings from industry researchers about the potential for serious harm, an OpenAI agent escaping its test environment, and the disclosure of a Hugging Face breach, and reportedly examines both companies' safety practices broadly.

**For organizations running Claude Code, this inquiry stage has no immediate impact on the service, but it's worth keeping an eye on potential policy and regulatory shifts ahead — the "AI labs need to be investigated" argument covered in the 9/29 briefing has now turned into an actual regulatory inquiry.** [GeekNews](https://news.hada.io/topic?id=34615)

### Figma restricts remote MCP server access to an allowlist of clients — Pi currently excluded (10/2)

**Figma's remote MCP server now only allows access from clients that have been pre-registered on a supported list.** The coding agent Pi isn't on that list yet, so it can no longer reach Figma's MCP server; the list of supported clients is available in the MCP catalog.

**If you're using Claude Code with Figma's remote MCP server, there's no immediate impact — but it's a sign that design tool vendors are increasingly narrowing MCP access to allowlists, so it's worth keeping in mind that other MCP integrations could see similar restrictions down the line.** [GeekNews](https://news.hada.io/topic?id=34626)

## Minor Changes

All of the following are from **v2.1.287** (10/1).

- **Added an `n:<text>` filter to the agent view**, letting you search directly by session name and task.
- **Added a `prompt_text` field to the OpenTelemetry `user_prompt` event.** If your backend strips or masks `prompt`, you'll need to handle this field too.
- **MCP servers with `alwaysLoad: false` now have all of their tools deferred behind tool search.**
- **Added a startup warning for when denying the Bash tool on Windows also disables the PowerShell tool**, so you know upfront if Claude is about to enter a session with no shell tools at all.
- **Bundled `gh api` (REST-only) into self-hosted runners on macOS and Linux**, so sessions using Anthropic-managed git can work right away even on machines without the GitHub CLI installed.
- **Added support for URL prompts (e.g., login) sent by MCP servers on the 2025-11-25 protocol.** If a server connection drops after updating, add `bareElicitationCapability: true` to that MCP's configuration.
