## Developer Workflow Tips

### The Claude Code team revealed how it designs its verification loops (11/16)

**The Claude Code team writes and reviews roughly 90% of its own code with Claude, and said on its official blog that instead of having a human check every change, it leans on verification loops where the agent itself runs the work to prove it's correct.** Having a way to verify lets one person oversee dozens or hundreds of agents at once instead of just one or two, and giving a model a way to check its own output produced the biggest gains in success rate, especially on hard tasks. Three kinds of tests stood out as most valuable in practice: E2E tests that check real user flows (from adding something to a cart through checkout), property-based tests that check invariants that must always hold (like round-trip encoding or idempotency), and diff tests that compare the output of old and new systems on the same input during large migrations. The team treats unit tests alone as insufficient, so it keeps a `verify` skill under `.claude/skills/` that actually launches the app to check it — the Claude Chrome extension for web, the iOS/Android MCP for mobile, and the computer-use tool for desktop.

```text
.claude/skills/verify/   ← a skill describing how to actually launch and check the app
3-stage commit gate: off → observe (log what would have been blocked) → enforce (actually block)
Hand off to a human after 3 consecutive verification failures (applying check rules the code owner sets)
```

The verification system itself is treated as something to protect. Review rules are read from the base branch rather than from the files a PR modifies, so that changes to the verification logic itself can't become untrustworthy. Patterns that repeat across human review comments or reverts become candidates for new rules, but a candidate must appear in at least 2 PRs, be detectable from the diff alone, and pass review by 3 adversarial agents plus human approval before it becomes an official rule. Flaky tests must be fixed at the root cause — skipping them or retrying them into a pass is banned, and if the cause can't be found, the test is deleted and the reason logged.

**If reviewing results from several parallel subagents one by one has gotten tedious, this post's combination of E2E, property-based, and diff tests, its rule of 3 retries before looping in a human, and its design of keeping verification logic separate from what a PR can modify are all worth borrowing directly.** [Official claude.dev blog](https://claude.dev/blog/how-the-claude-code-team-thinks-about-verification/) (Addy Osmani, 11/16) · [GeekNews](https://news.hada.io/topic?id=37359)

### A large-scale benchmark finds that switching models means re-validating your agent harness too (11/18)

**FrontierHarness Eval v1.1, published by runta.com, ran 22 harnesses (the execution environment wrapping an agent) × 5 models × 62 terminal tasks × 4 attempts — 27,280 runs and roughly 83 billion tokens in total — and found that cost per task for the same model can swing 1.8x to 5.0x depending on the harness.** Model choice explains 92.8% of the cost variance, but harness rankings shuffle by an average of 11 positions whenever the model changes, so there's no single "best harness" — it depends on the model. The most striking cost-related finding wasn't prompt size but step count per attempt, which correlated most strongly with cost (roughly +0.51): since every step resends the full context, a small starting prompt still gets expensive if the number of steps is high. Failed attempts accounted for 64.5% of total cost, and the most common failure mode was confidently delivering a final answer from an incomplete state.

**If you've kept the same harness setup after switching models on Claude Code or another agent harness, this result is a good reason to re-check harness fit whenever you switch models, and if you're trying to cut costs, it's worth focusing on reducing steps per task before trying to shrink prompts.** [GeekNews](https://news.hada.io/topic?id=37362)

## Security & Limitations

**A check of the official status.claude.com shows that from 11/17 4:19 PM PT (11/18 12:19 AM UTC) to 11/17 5:33 PM PT (1:33 AM UTC) — about 1 hour 14 minutes — claude.ai, Claude Code, and Claude Cowork saw an incident with increased document-editing errors in the Google Docs connector, which has since been resolved.** Document reading was not affected. **If you rely on Claude Meetings' auto-join feature, it may still be unstable given this incident has gone unresolved for more than three days, so manually confirming you've joined is the safer approach for now — the Claude Code CLI itself and the Google Docs connector are already back to normal.** [Claude Status](https://status.claude.com)

### Modern Web Guidance 1.0 — the Chrome team officially launches its web development skill collection for coding agents (11/13)

**First previewed at Google I/O in May, this project has now launched as 1.0 with Firefox and Edge engineers joining as contributors, making it a cross-browser collaboration that isn't tied to any particular model or agent harness.** It packs in hundreds of vetted guidelines covering things coding models frequently miss — accessibility (keyboard focus management, form validation), performance (main-thread task scheduling, preventing layout shift), and security (HTML sanitization, CSP) — and its `/modern-web-guidance` command statically analyzes a project's HTML, CSS, JS, and `package.json` to surface safe upgrades. Paisabazaar reports cutting new page development time from 4 days down to a few hours, and MetaMask says a review bot built from a three-line prompt reviewed roughly 480 PRs over five weeks and surfaced 43 fixes. It installs via `npx modern-web-guidance@latest install` and supports plugin marketplaces including Claude Code's.

**If you've been using Claude Code to write frontend code but keep missing accessibility or performance details, it's worth installing this vetted guidance collection from browser vendors themselves to raise the quality of generated code.** [Chrome official blog](https://developer.chrome.com/blog/modern-web-guidance-v1) · [GeekNews](https://news.hada.io/topic?id=37324)

## Community News

- **In an audit experiment deploying roughly 100 AI agents, KPMG found cases where agents asked deeper questions than the human audit team (11/19)**: In "Project Exponential," an experiment run on the financial statements of an FTSE 250 company, agents handled information gathering, data analysis, documentation, and even drafting conclusions, with some agents asking questions human auditors hadn't asked. However, one agent misapplied a regulatory requirement in its documentation and needed human intervention, and this experiment wasn't a statutory audit — it wasn't used to approve an actual opinion. KPMG plans to scale up to as many as 20 large audits but said the technology isn't yet ready for thousands of audits, and the UK's FRC warned that AI must not undermine auditors' independence and professional skepticism. [GeekNews](https://news.hada.io/topic?id=37429)
- **A next-amino-acid prediction experiment suggests the latest Claude models were trained on large-scale protein sequences (11/19)**: When asked to predict the next amino acid in protein sequences with unknown function, Claude Fable 5.2 scored 54% accuracy on real sequences, clearly above the 9% baseline from shuffled-order controls, while GPT, Gemini, and seven open-weight models showed almost no difference from baseline. Performance held up without reasoning tokens, and accuracy tended to improve with more proteins in the same family, which the author says is hard to explain by literature memorization alone. The experiment's code and data are published in the llm-bioseq-probe repository on GitHub. [GeekNews](https://news.hada.io/topic?id=37436)

## Recommended Reads

- **We need better open source, not more apps (11/18)**: Now that AI-assisted coding has made it easy for anyone to spin up a personal habit tracker or note-taking app, this piece argues some of that energy should go instead toward making already widely used open-source tools easier to install and run. The author argues nonprofits end up switching to commercial tools not because open-source tools lack features, but because installing and operating them is too hard, and lays out contribution guidelines: talk to the maintainer before writing code, and keep changes small. Hacker News commenters raised curl's decision to shut down its bug bounty in January 2026 after a surge of AI-generated bug reports, and debated the idea of "Stewarded Open Source" — distinguishing code that merely carries a license from projects that promise actual support. If you've gotten used to cranking out personal projects quickly with Claude Code, this is worth reading to think about where to redirect that productivity. [GeekNews](https://news.hada.io/topic?id=37356)
- **A book list for computer scientists who want the real thing (11/16)**: Instead of general coding-habit books like Code Complete or Clean Code, this is a personal recommendation list that goes deep — language design (Stepanov, Stroustrup), algorithms (CLRS, Knuth), operating systems (Kerrisk), type theory (Pierce), and computational complexity (Sipser). The author deliberately leaves out machine learning, quantum computing, and information security. Hacker News commenters pushed back by asking whether this kind of theory still matters now that LLMs can just hand you the algorithm, while others countered with stories of catching an LLM's half-right answers thanks to domain knowledge while vibe coding, and some argued that supervising and verifying AI agents actually makes studying formal methods more necessary, not less. At a time when Claude Code can churn out code fast, this is worth reading to revisit the value of the foundational theory you'd use to judge that output. ## Interesting Projects & Tools

- **Show GN: codeme — a macOS app that manages Claude Code and Codex in one screen using Git worktrees (11/18)**: Running several Claude Code and Codex sessions at once tends to pile up terminal windows and make it hard to track which agent changed which files; this app solves that by giving each agent its own Git worktree and showing progress and changes for all of them on a single screen. It's built to sit alongside your existing IDE rather than replace it, supports terminal, test, Docker, and DB integration plus GitHub and Jira integration, and runs locally without a separate account or server. Commenters also shared another user's workflow of keeping CLAUDE.md and AGENTS.md short and having both agents share the same rules file. [Project page](https://codeme.team) · [GeekNews](https://news.hada.io/topic?id=37400)
- **Show GN: docs-suit — a Korean-language tool that assembles AI writing guidelines tailored to document type and audience (11/17)**: Instead of fixing the same problems after the fact in AI-written Korean documents — overused bold text, an emoji on every line, clichéd opening lines — this tool has you pick a document type (25 options) and audience (11 options) before writing, then combines 13 values like tone, length, and emphasis into a guidance file. It installs as a skill in Claude Code, Codex, and Antigravity CLI, and also ships a `check` command that reviews a finished draft against the same rules. The author reports that in a 27-pair blind comparison, the docs-suit version was preferred 15 times, while acknowledging the p-value of 0.21 isn't statistically conclusive. [Web demo](https://dodokim-lab.github.io/docs-suit/) · [GitHub](https://github.com/dodokim-lab/docs-suit) · [GeekNews](https://news.hada.io/topic?id=37309)
