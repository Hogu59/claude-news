## New Features & Practical Usage

### `/code-review` results now print as a readable list in cloud, SDK, and IDE sessions (v2.1.296)

**Until now, running `/code-review` in cloud sessions, the Agent SDK, or IDE integrations could leave the output as a raw, unformatted JSON array; v2.1.296 fixes this so findings print as a numbered list.** Terminal sessions were never affected, but the change is an immediate readability win for teams reviewing results in CI pipelines or IDE panels.

**If you're running `/code-review` through automation in an IDE or SDK, this fix means you no longer need custom parsing or rendering logic to get a clean list of results.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Edit and NotebookEdit now refuse to touch non-UTF8 files instead of corrupting them (v2.1.296)

**Editing a file saved in a non-UTF8 encoding — Windows-1252, Shift-JIS, GBK, and the like — with Edit or NotebookEdit used to mangle every non-ASCII character in the file; now the edit is refused outright.** Turning silent corruption into an explicit rejection prevents unnoticed damage when working with files carrying legacy encodings.

**If you ever need Claude Code to edit non-UTF8 files inherited from legacy systems (including old Korean- or Japanese-locale Windows files), the safest move once you see the rejection is to convert the file to UTF-8 first and then hand editing back to Claude.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Developer Workflow Tips

### Validate your README with a paid real user, not yourself (10/12)

**To test ActivityBot's install experience, the team paid a real user 25 euros an hour to follow the README exactly as written and watched where they got stuck.** The point: even when developers test their own docs, they tend to miss gaps caused by assumptions they already hold — things like command permissions, how options are notated, or whether a reboot is needed.

**If you've written a README or a CLAUDE.md onboarding section for a Claude Code project, instead of re-reading it yourself, pay someone with zero context on the project a small amount to follow it from scratch — it surfaces exactly where your unstated assumptions break down, much faster than self-review ever would.** [GeekNews](https://news.hada.io/topic?id=35177)

### Quoting a tilde (~) in PATH stops it from expanding (10/12)

**Writing `export PATH="$PATH:~/.local/bin/"` puts `~` inside quotes, so the shell leaves it as a literal character instead of expanding it to the home directory — the entry ends up pointing at `./~/.local/bin/`, relative to the current working directory, not your home folder.** It's a trap that's easy to miss: it fails silently most of the time, and only "works" by accident when a folder with that literal name happens to exist in your current location, which makes it maddening to debug.

**When you have Claude Code touch shell config scripts or PATH-related environment variables, telling it to keep `~` outside quotes or swap it for `$HOME` heads off this kind of silently broken PATH entry.** [GeekNews](https://news.hada.io/topic?id=35184)

## Security & Limitations

### Claude service status — Claude Console degraded for a fifth straight day, everything else normal (10/12)

**Checking status.claude.com directly: as of 10/12, claude.ai, the Claude API, Claude Code, Claude Cowork, and Claude for Government are all Operational, but Claude Console (platform.claude.com) has been in Degraded Performance for five straight days because of a usage data loading delay that started on 10/7.** No new incidents have been reported since the 10/7 spend-limit processing error (resolved 21:23 UTC) and usage data loading error (resolved 02:33 UTC), and the guidance remains that core functionality itself is unaffected.

**If the numbers on your Claude Console usage dashboard still look stale, that's this five-day-old degradation at work — it doesn't affect your actual Claude Code work or API calls, so keep using them as normal.** [Claude Status](https://status.claude.com)

### v2.1.296 security fixes — BASH_ARGV0 abuse and a Windows rm -rf permission bypass are closed (v2.1.296)

**v2.1.296 includes two permission-bypass fixes not covered in earlier briefings.** One closes a hole where setting the BASH_ARGV0 shell variable could make a command appear under a different name, letting the command that actually used that variable get auto-approved without a permission prompt — it now asks for approval as expected. The other fixes a Windows Git Bash issue where, in bypass permissions mode, a command like `rm -rf /c/Users/<name>` that deletes a user's home folder could run without any additional confirmation.

**If you rely on name-matching guardrails to filter dangerous Bash commands, or you run bypass permissions mode on Windows, update to v2.1.296 to pick up both of these closed bypass paths.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### v2.1.296 also fixes secret masking that was being skipped in shared logs (v2.1.296)

**v2.1.296 fixes a case where secret redaction failed to mask certain values — specifically keys with no trailing value, especially inside JSON embedded in shell strings.** That meant values matching this pattern could end up exposed, unmasked, when sharing transcripts or debug logs with someone else.

**If you ever share debug logs or session transcripts with teammates or outside parties, it's worth checking logs exported from versions before v2.1.296 for unmasked values matching this pattern.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Minor Changes

All of the items below are from **v2.1.296** (10/9) and haven't been covered in this week's briefings yet.

- **`/plugin` now shows a notice** when a plugin's hooks were excluded because its name collides with another active plugin.
- **`CLAUDE_CODE_TRANSCRIPT_LOCAL_GC` no longer rewrites large transcript files** when cleanup would free less than 10% of total space.
- **`--debug` output now flags unrecognized frontmatter field names in custom agent files**, with hints when it looks like a typo.
- **[VSCode] Fixed `claudeCode.spinnerVerbs` missing from the extension's settings list**, which broke settings.json autocomplete and validation — an invalid value no longer breaks the chat panel.
- **[VSCode] Fixed full Windows path links in chat** (e.g. `C:\repo\file.ts` or `file:///C:/repo/file.ts`-style links) failing to open files on Windows.
- **[Cloud sessions] Fixed all cloud sessions waiting on a self-hosted runner showing the same queue position** — each session now shows an accurate count of how many are ahead of it.
