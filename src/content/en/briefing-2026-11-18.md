## Developer Workflow Tips

### `claude mcp add-json <name> -` lets you pipe MCP server config via stdin instead of the command line (v2.1.327)

**Until now, registering an MCP server with `claude mcp add-json` meant passing the JSON config directly as a command-line argument — so if it contained a token or API key, that value could end up exposed in your shell history or process list.** Now, appending a `-` after the JSON tells the command to read the same content from stdin instead, keeping sensitive values off the command line. Note that this input method isn't available from inside a Claude Code session itself (e.g., via the Bash tool).

```bash
# Register an MCP server without exposing its token on the command line
cat server-config.json | claude mcp add-json my-server -
```

**If a CI script or shell function has been auto-registering MCP servers by passing token-laden JSON straight through as a command-line argument, switching to this stdin input method in v2.1.327 is worth doing to keep tokens out of shell history.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### `/status` now rolls up broken agent, skill, command, and hook configs into one view (v2.1.327)

**A new list in `/status` now gathers broken agent, skill, command, and output style files, keybinding errors, unusable sandboxes, ignored permission settings, and hook matchers that never fire — all in one place.** Previously, these configuration errors either surfaced scattered across different places or failed silently, making the root cause hard to track down.

```text
Run /status → see broken agent/skill/command/output style files, keybinding errors,
unusable sandboxes, ignored permission settings, and unmatched hook matchers in one list
```

**If you've been running a number of skills, agents, and hooks and couldn't tell which configs were being silently ignored, it's worth running `/status` right after upgrading to v2.1.327 to check this new diagnostics list first.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### A session's first Bash command now starts faster — disable it with `CLAUDE_CODE_DISABLE_SHELL_HEAD_START` if needed (v2.1.327)

**Shell startup files (e.g., `.bashrc`, `.zshrc`) can now run before a command is approved, making a session's first Bash command start faster.** This happens even when the command itself ends up being rejected, so it's worth knowing that startup files may now run regardless of approval status. If you'd rather keep the old behavior — startup files running only after approval — you can turn this off with the environment variable below.

```bash
# Disable the speed improvement that runs shell startup files before approval
export CLAUDE_CODE_DISABLE_SHELL_HEAD_START=1
```

**If a heavy initialization script in your shell startup files has made Claude Code's first Bash command feel slow, v2.1.327 should make that noticeably faster with no configuration needed. That said, if your startup files contain sensitive logic that shouldn't run before approval, it's safer to set the environment variable above to restore the previous behavior.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Security & Limitations

### Claude service status — the 11/17 Sign in with Apple incident is resolved, but claude.ai still shows Degraded Performance

**According to the official status.claude.com, some users were unable to sign in to claude.ai and the Claude iOS app with "Sign in with Apple" between 16:40 and 21:51 UTC on 11/17 (roughly 5 hours 10 minutes) — the cause was identified and a fix has since been deployed, resolving the incident.** Google sign-in and email sign-up were unaffected during this window. No new incidents have been reported today (11/18), but claude.ai still shows Degraded Performance due to recent history, while Claude API, Claude Code, Claude Console, and Claude Cowork are all Operational.

**If you've had trouble signing into claude.ai or the Claude iOS app with your Apple account in the past few days, this 11/17 incident is the likely cause — it's since been resolved, so it's worth trying again. The Claude Code CLI itself was unaffected and can be used as normal.** [Claude Status](https://status.claude.com)

### v2.1.327 tightens permission checks around symlinks, PowerShell, and Bash variable expansion

**Path checks that previously allowed certain symlinks masking a writable path are now stricter and reject writes through those links.** Separately, `permissions.blockReadsOutsideWorkingDirectories` now prompts for confirmation or denies more Bash commands in bypass and auto modes, and Bash commands that point at paths covered by a `Read` or `Edit` deny rule — which previously only prompted — are now denied in more cases. Bash commands where a variable expands into very long text are now also denied, with guidance shown to use a shorter value or write to a file instead. The PowerShell tool now asks for confirmation one more time even when a rule already allows a given command, and in situations where no one is available to respond, it's denied unless an allow-all rule, auto mode, or bypass permissions mode applies.

**If you're running Claude Code in sandboxed, auto, or bypass mode as part of an automated pipeline, it's worth accounting for the fact that after upgrading to v2.1.327, some commands that previously passed through silently may now require confirmation or get denied.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Minor Changes

All of the following are from **v2.1.327** (11/17).

- **Added the name `/tui classic`**, which, alongside `/tui default`, can now refer to the non-fullscreen renderer.
- **Fixed `/export` silently overwriting existing files** — it now prompts for confirmation first, and `/export <name>` tells you to re-run `/export` to keep the file.
- **Fixed an issue in `/plugin`** where pressing Enter right after a click could unintentionally install or disable a plugin.
- **Fixed Grep duplicating or skipping results when paging with `head_limit` and `offset`** — results are now sorted by file path.
- **Fixed the Read tool misreporting the size of files over 10MB** (too large to read in full) as 512KB instead of their actual size.
- **Added "Claude Code: Add to Chat"** to the right-click menu in the VS Code explorer, letting you @-mention selected files or folders directly in chat.
- **Added a note to the fallback message shown when auto mode falls back to a paid classifier request**, warning that this fallback itself will be removed in the next release.

If you've been copying Claude Code's answers straight into commit messages or PR descriptions, this piece spells out concretely what still needs polishing. [GeekNews](https://news.hada.io/topic?id=37316)
- **The CI Market Has Split Into Three (11/17)**: This analysis divides the CI market into generic runner infrastructure (GitHub Actions alternatives like Blacksmith and Depot), orchestration platforms (where the vendor provides the control plane and the customer brings compute), and the code/build engineering layer — arguing that in an era where agents write the code, local reproducibility and debuggability matter more than raw execution speed. It highlights agents burning idle time on flaky tests and CI delays, and predicts that as agents get broader access, CI's own security posture will become a purchasing criterion (citing the Shai-Hulud and tj-actions/changed-files supply-chain attacks). If you're weighing handing CI pipeline execution over to an agent like Claude Code, this is a useful rundown of what to check before speed. [GeekNews](https://news.hada.io/topic?id=37320)
- **How Rust Changed Me as a Developer (11/17)**: After more than six years with Rust, the author lays out how sum types and exhaustive `match` checking, static dispatch via generics and traits, types as a design tool, and ownership's separation of data mutation from data use all reshaped how they think. One concrete thread: ownership forced them to handle cyclic structures (like XML trees with parent pointers) using an index-based arena instead of references, which fed directly into their own library, Xot. Hacker News commenters pointed out these ideas have existed in OCaml and Haskell for decades, sparking a clash between "this kind of origin story feels out of place now that AI writes the code" and "understanding the language still matters." Even though Claude Code has sped up the writing of code itself, this is worth a read on why the language understanding you use to judge that code still holds value. ## Interesting Projects & Tools

- **Show GN: memdex — an MCP server that lets Claude Code and Codex share work context on the same Git repo (11/17)**: This project aims to cut down on the hassle of re-explaining which files you've checked and which causes you've ruled out every time you switch agents mid-task — from Claude Code to Codex or vice versa. Claude Code writes its findings and next steps to memdex, and Codex picks up that record in the same repo to continue the work; if a file referenced in the record has since changed, it's flagged as needing a re-check. Data is stored in a local SQLite database, and memory is shared across multiple git worktrees of the same repo. Install with `pipx install memdex-mcp`. [GitHub](https://github.com/ChoYugyeong/memdex) · [GeekNews](https://news.hada.io/topic?id=37338)
- **Show GN: wowTerminal — an open-source AI terminal with Korean input support that tells you when Claude Code is waiting for input (11/17)**: A free, MIT-licensed app that combines a terminal, SSH, SFTP, a code editor, and an AI assistant in one window. Its AI assistant reads the current tab's OS, shell, and last 100 lines of output to answer questions, and it supports OpenAI-compatible APIs (including local Ollama and vLLM). Starting in v0.22.1, it shows a question-mark indicator and desktop notification on any tab where Claude Code, Codex, or Gemini CLI is waiting for input, with a left-side panel showing agent status across all tabs at a glance. It also fixes a Korean input bug where switching windows mid-input would erase the line being typed. Built on Rust, Tauri 2, and React 19, it supports macOS, Windows, Linux, Android, and iOS. [GitHub](https://github.com/cuter74-dev/wowTerminal) · [GeekNews](https://news.hada.io/topic?id=37315)
