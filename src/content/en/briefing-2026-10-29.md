## Developer Workflow Tips

### If `claude -p` ended with no output at all, one misnamed command could have been the cause (v2.1.312)

**A bug where a single misnamed command could block all command loading - causing `claude -p` to end with no output whatsoever - has been fixed.** Previously, a naming mistake in just one custom slash command could silently fail an entire non-interactive run.

**If you've run `claude -p` in CI or a script and gotten nothing but empty output with no explanation, it's worth upgrading to v2.1.312 and double-checking the naming in your custom command files too.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Organization policies now reload properly mid-session after logging in through the VS Code extension (v2.1.312)

**A bug where managed settings and organization policies failed to reload for the rest of a session after logging in through the VS Code extension has been fixed.** Previously, policies that changed on the organization's side after login sometimes weren't reflected within that same session.

**If your organization controls Claude Code settings through admin policy and you're using the VS Code extension, you can now trust that policy changes land more reliably even after login, starting with v2.1.312.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### When WebFetch is blocked in a cloud session, it now tells you exactly which host to allow (v2.1.312)

**When WebFetch in a cloud session hits a host it can't resolve, Claude now explains that the host may be outside the allowed network domains and points out exactly which host needs to be allowed.** Previously, this kind of error sometimes just showed up as a generic, hard-to-diagnose network error.

**If you're running Claude Code with restricted network access in a cloud environment, the message that appears when WebFetch is blocked now tells you right away which host to add to the allowlist, cutting down on back-and-forth configuration.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Security & Limitations

### Claude service status - Google Calendar and Gmail connector errors both resolved on 10/28, all services operating normally as of 10/29

**Checking status.claude.com directly: the Google Calendar connector error that had been ongoing since 11:07 UTC on 10/26 had its impact end at 18:52 UTC on 10/28 and was marked resolved at 20:05 UTC, while the Gmail connector error from 23:00 UTC on 10/27 had its impact end at 05:29 UTC on 10/28 and was resolved at 05:48 UTC.** Both errors affected claude.ai, Claude Code, and Claude Cowork; as of 10/29, no new incidents have been reported, and claude.ai, the Claude API, Claude Code, Claude Console, Claude Cowork, and Claude for Government are all showing Operational status.

**If you've been connecting Google Calendar or Gmail connectors in Claude Code and running into unresponsiveness or errors over the past few days, both connectors were resolved within 10/28, so normal operation should be back as of today.** [Claude Status](https://status.claude.com)

### A severity 9.5/10 code execution vulnerability was found in TianoCore EDK II UEFI firmware (10/28)

**A code execution vulnerability rated 9.5/10 in severity and tracked as CVE-2026-97631 has been found in TianoCore EDK II, the UEFI implementation widely used by major firmware vendors.** It's a buffer overflow in how ICMP error messages are handled during PXE network boot, letting code run before the operating system and higher-level defenses like Secure Boot even come into play - putting most servers worldwide within the blast radius.

**If you run servers or infrastructure through Claude Code, or automate security checks, it's worth checking not just application-layer patches but whether your servers' UEFI/BIOS firmware is built on TianoCore EDK II and whether a vendor patch is available.** [GeekNews](https://news.hada.io/topic?id=36168)

### Browser fingerprinting scripts were found using bioweapon-adjacent strings to try to block LLM analysis (10/29)

**While investigating canvas-based browser-fingerprinting scripts across 10,000 websites, researchers found anti-bot scripts embedding function names and strings evoking bioweapons and self-harm.** The technique appears designed to trigger an LLM's safety guardrails with dangerous-sounding names and strings, pushing it to refuse deobfuscation or analysis.

**If you're having Claude Code or Claude deobfuscate or analyze suspicious JavaScript, it's worth keeping in mind that these trigger strings could cause the analysis to be refused or halted.** [GeekNews](https://news.hada.io/topic?id=36185)

## Ecosystem & Plugins

### kern - a lightweight, rootless runtime that runs AI-generated code in a fresh container every time (10/29)

**A Linux runtime that runs AI-generated code, agent tool calls, CI jobs, and similar workloads in an isolated container instead of directly on the host.** It runs as a single static binary with no daemon or socket, and doesn't require root privileges on the host.

**If you want code generated by a Claude Code subagent or auto mode to run in a clean container each time instead of straight on the host, this is worth trying as a lightweight isolation layer.** [GeekNews](https://news.hada.io/topic?id=36200)

## Minor Changes

All of the items below are from **v2.1.312** (10/27).

- **Fixed an issue where the spinner, the OpenTelemetry `effort` value, and the transcript displayed a newly selected effort level before the model actually applied it; they now show the level actually in effect.**
- **Fixed the `/model`/`/effort` cache warning that said a re-read would wait until the next message, to reflect that changing mid-task can now take effect sooner.**
- **Fixed an issue where some sessions were incorrectly marked as waiting for a user response even when the last message only mentioned a pending item in the middle of a sentence.**
- **Fixed an issue in agent view where input text cleared with Ctrl+C would reappear on the next run.**
- **Fixed an issue in vim mode where `d`/`c`/`y` combined with `gj`/`gk` and a large count would delete or yank past the number of remaining lines; it now moves the cursor exactly as Vim does.**
- **Fixed an issue where `/verify`'s long Claude-facing description was showing up as-is in `/help` and the `/` command menu.**
- **[Cloud sessions] Added an effort-level option to the model picker when creating or editing a routine that runs in the cloud.**
- **[Claude Tag] Slack's retry messaging now specifies the model in use or whether a rate limit was hit, instead of a generic API error.**
