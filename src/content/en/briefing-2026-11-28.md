## Developer Workflow Tips

### The "Prompt is too long" ending caused by repeated auto-compaction failures has been fixed (v2.1.332)

**Until now, once auto-compaction failed several times, a turn would simply end with "Prompt is too long" even when one more compaction attempt at the context limit could have let it continue — starting with this release, Claude now makes one more compaction attempt in that situation.** In the same release, when a compaction summary keeps getting truncated for exceeding the output limit, after three truncations the final attempt now asks for a shorter summary instead.

```text
Auto-compaction keeps failing in a long conversation
  → (Before) The turn simply ends with "Prompt is too long"
  → (As of v2.1.332) One more compaction attempt is made at the limit to continue
```

**If you've had a session suddenly end from a compaction failure in a long, context-full session before, it's worth upgrading to v2.1.332 and continuing long sessions with the knowledge that compaction now gets one more attempt in that situation.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### @-mentioning a large file that exceeds the read limit now tells Claude its size and how to read it (v2.1.332)

**Until now, when you @-mentioned a text file with an extension and even its first 2,000 lines exceeded the read limit, the file would silently drop out entirely and Claude wouldn't even know it existed — starting with this release, Claude is now told the file's size and how to read the rest of it.**

```text
@large-log.txt (a large log file over 2,000 lines)
  → (Before) The file silently drops out; Claude has no idea it exists
  → (As of v2.1.332) Claude is told the file's size and how to read the rest
```

**If you've @-mentioned a large log or data file before and gotten no response at all, as of v2.1.332 Claude will now know that file exists and how big it is, so it's worth following up and asking it to read just the part you need with Grep or an offset.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### PreToolUse hook rejection reasons now also show up in the Read, Grep, Glob, Edit, and Write approval windows (v2.1.332)

**Until now, a reason a PreToolUse hook gave when requiring approval showed up in the Bash command approval window but not in the Read, Grep, Glob, Edit, or Write approval windows — starting with this release, the hook's stated reason now appears in all five of those tools' approval windows too.** (anthropics/claude-code#102892, anthropics/claude-code#105343)

```json
{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Read", "hooks": [{ "type": "command", "command": "check-sensitive-path.sh" }] }
    ]
  }
}
```

**If you've used a PreToolUse hook to block Read or Edit on sensitive paths and written out a reason, only to have it stay invisible on anything other than Bash, as of v2.1.332 it's worth checking that the hook's stated reason now shows up the same way across all five tools.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Security & Limitations

### Claude service status — Fable 5.2 performance degradation on 11/27 (resolved), M365 add-in now being monitored for recovery after a mitigation, claude.ai shows Degraded Performance for a fourth day

**Checking the official status.claude.com shows that Claude Fable 5.2 had a performance-degradation incident on 11/27, which was marked resolved the same day at 10:49 UTC.** The issue affecting the Claude for Microsoft 365 add-in not appearing in Mac Excel, Word, and PowerPoint for personal Microsoft account users, ongoing since 11/24, got a new update on 11/27 at 19:48 UTC — following the 11/25 "root cause identified, discussing with upstream provider" update — saying a mitigation from an upstream provider has now been applied and recovery is being monitored. The claude.ai component has shown Degraded Performance for a fourth straight day, from 11/25 through today (11/28), with no further explanation attached. All other components, including Claude Code, remain Operational.

**If you've been using the Claude for Microsoft 365 add-in with a personal account on Mac, it's moved into the recovery-monitoring stage now that a mitigation has been applied, so it's worth watching a little longer — and also worth noting that claude.ai's Degraded Performance status has now persisted for four days.** [Claude Status](https://status.claude.com)

### A Convex skill on Anthropic's official plugin marketplace reportedly sends user ideas externally without disclosure and runs remote scripts without review (11/28)

**A GitHub issue reports that three skills in the Convex plugin listed on Anthropic's claude-plugins-official marketplace have problems.** The quickstart skill sends the user's one-line idea and template values as-is to a `/generate` endpoint on a Convex-external host, while the code only labels this as "telemetry 1/3" and never discloses it to the user. The add skill runs a script received from the same host directly as `curl | bash` with no review, and the labs-quickstart skill instructs that the download and execution be deliberately split into separate Bash calls, guiding it around the harness's safety classifier. The reporter believes this looks more like an attempt to smooth onboarding than malice, but flags that it bypasses safeguards the user has set up and leaves no way to review the code being executed. Convex's CEO responded that the prompt is used only for project generation and discarded within 30 seconds, that the current behavior is intentional, but added that they would review the code and make it more transparent.

**If you install and use third-party plugins in Claude Code, this is worth keeping in mind as evidence that being listed on the official marketplace alone doesn't guarantee the inline shell commands inside a skill are safe — the `PreSkillShellCommand` hook covered in the 11/26 briefing is one way to screen inline commands like these beforehand.** [GitHub Issue](https://github.com/convex/convex-backend-skill/issues/64) · [GeekNews](https://news.hada.io/topic?id=37973)

## Community News

- **GPT-6.2 Astra identified the maker of an 1808 sketchbook before historians did (11/28)**: In an experiment by the history outlet Generative History, GPT-6.2 Astra, given only minimal instructions, named the Viscount Chabot as the maker of an anonymous 1808 sketchbook held at Yale and, in about 22 minutes, even tracked down the location of an unpublished 162-page diary that would support the hypothesis. Anthropic's Fable 5.2 also named the same person in about 35 minutes but never found the decisive diary evidence, and Astra showed a tendency to remain overly skeptical even after receiving strong evidence. The author notes that in historical research, the human role of interpreting the past through a present-day lens still matters as much as unearthing the material itself, and presents the comparison between the two models' investigative approaches as a case worth examining. If you're having Claude or other models handle research or hypothesis-testing for you, this comparison is worth a look for gauging how carefully — or how excessively skeptically — a model reaches a conclusion even after finding the evidence. [Source](https://generativehistory.substack.com/p/gpt-62-astra-solves-a-historical) · [GeekNews](https://news.hada.io/topic?id=37969)

## Minor Changes

All of the following are from **v2.1.332** (11/25), items not already covered in the 11/26 and 11/27 briefings or above.

- **The startup header now shows your Cyber Verification Program tier.** It appears next to the model name when you're logged in with a claude.ai account and that tier applies to the current model.
- **Added a footer line that tells you when the current session has switched to a different model because of a message from another session**, shown until you pick a model yourself.
- **Cloud suggestions from `/schedule`, permission prompts, and `/loop` now say "cloud scheduled task" instead of "routine" or "cloud schedule."** The `/routines` command itself still works the same way.
- **On macOS, `computer-use` becomes a reserved skill name while Computer Use is enabled.** Any skill or command with the same name no longer loads, and you'll see a prompt at startup to rename it.
- **`--model default` or selecting Default now falls back to the previous model instead of stopping with an error when that model isn't available** (in auto mode, it only falls back to a model auto mode allows).

## Interesting Projects & Tools

- **ARCUS-STACK — a skill pack that lets Claude Code and other AI coding agents share the same SKILL.md (11/27)**: Born out of the annoyance of having to rewrite the same task instructions for each agent because every agent uses a different skill/rule format, this project writes every skill to the SKILL.md standard so Antigravity, Claude Code, Codex, Cursor, and OpenCode can all read the exact same file. It runs purely on markdown instructions with no MCP server, offering a flow where `/arcus-plan` produces a plan document covering root cause, blast radius, and verification conditions, `/arcus-work-loop` implements the checklist item by item, and `/arcus-review` has a fresh subagent review the commit. It also bundles skills for comparing UI alternatives, breaking DB migrations into stepwise stages, and catching recurring mistakes with types, lint, and tests instead of rule sentences. Install it with `npx skills add sacru2red/arcus-stack -g -y`; it's MIT-licensed. If you've been running several AI coding agents side by side and managing separate skills for Claude Code and rules for Cursor, this is worth consolidating into a single SKILL.md. [GitHub](https://github.com/sacru2red/arcus-stack) · [GeekNews](https://news.hada.io/topic?id=37932)
- **CarryOn — an app that shows the context usage of Claude Code, Codex, and other AI coding sessions in one screen (11/27)**: Built from the problem that when you're working across several terminal tabs, it's easy to miss which session's context is about to run out — it gathers all the Claude Code, Codex, Gemini CLI, and Aside sessions running on your machine into one list, shows context usage as a percentage, and separately flags sessions waiting on an answer. Turn it on in settings and Claude Code and Codex will back up the session history and run `/compact` on their own once they hit a threshold (85% by default), and you can also check and manage sessions from a phone on the same Wi-Fi. It only reads existing local session logs and can be used without an account, but keep in mind the source is closed and that running `/compact` sends the conversation to the model provider for summarization. If you've been running several Claude Code sessions at once and checking how full the context is with `/context` every time, this is worth a single install to keep an eye on everything from one screen. [Project site](https://carryon-app.pages.dev/?s=gn) · [GeekNews](https://news.hada.io/topic?id=37936)
