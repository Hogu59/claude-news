# Claude Code Daily Briefing - 2026-11-07

**Two days after v2.1.318 landed on 11/4, v2.1.319 shipped on 11/6.** Alongside new features like background processing for MCP tasks, a setting that auto-denies instead of prompting for permission, and a command for analyzing API latency, this release also bundled some notable security fixes — including a sandbox escape triggered during worktree creation and a Bash permission-check bypass.

## New Features & Practical Usage

### MCP server tasks are now automatically backgrounded in the terminal (v2.1.319)

**When an MCP server runs a tool call as a task, Claude Code now moves it to the background in the terminal too, and notifies Claude once it's done.** Previously, a long-running MCP task could block the entire turn until it finished. If you'd rather have Claude wait on the result directly, an environment variable keeps the old behavior.

```bash
# Keep MCP tasks blocking inside the tool call instead of moving them to the background
export CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND=1
```

**If you frequently call long-running MCP tasks — large data lookups, batched external API calls, and the like — as of v2.1.319 your session no longer has to sit idle waiting for them; you can keep working on other things in the meantime.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### A new `permissions.denyInsteadOfPrompting` setting auto-denies instead of prompting for permission (v2.1.319)

**With this setting on, any tool call that would normally wait on a permission prompt is denied immediately instead — across terminal sessions, subagents, and teammates alike — and the turn keeps moving.** Previously, an unattended environment or subagent that hit a command requiring approval would simply stall there, halting the whole task if no one was around to respond.

```json
{
  "permissions": {
    "denyInsteadOfPrompting": true
  }
}
```

**If you run Claude Code in background jobs or CI pipelines with no one standing by to approve prompts, this setting lets calls that need permission get quietly denied while the rest of the work keeps going.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### `/claude-api latency-optimize` finds the slow spots in your Claude API code (v2.1.319)

**`/claude-api latency-optimize` locates the points in your Claude API code that make users wait, then tries faster configurations against an eval you supply.** Previously, if API responses felt slow, tracking down which call or setting was causing the delay often meant changing things one at a time and testing by hand.

```bash
/claude-api latency-optimize
```

**If you're building a feature on the Claude API where response time matters to users, it's more efficient to let this command surface the latency bottlenecks automatically first, then optimize from there.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Developer Workflow Tips

### How Hightouch cut costs to a quarter by routing only ambiguous cases to Opus (11/6)

**For deciding whether two customer records refer to the same person, Hightouch tried a hybrid approach: a cheaper model, Jev, judges every case first, and only cases in the ambiguous confidence band (roughly 30-90%) get a second pass from Opus.** On the easy test set, sending just 22% of cases to Opus held accuracy at 98.8% (versus 99.0% for Opus alone) while cutting cost per 1,000 cases from $3.86 to $0.88; on the hard test set, accuracy held at 95.3% (versus 95.1% for Opus alone) while cost dropped from $5.39 to $2.94.

```text
confidence < 30%        → keep the cheap model's verdict
30% ≤ confidence ≤ 90%  → send to Opus for a second pass
confidence > 90%        → keep the cheap model's verdict
```

**If you're automating classification or matching tasks with Claude models where you can extract a confidence score, it's worth trying this pattern — routing only the ambiguous band to Opus instead of running everything through it — to cut costs substantially while keeping accuracy nearly intact.** [GeekNews](https://news.hada.io/topic?id=36725)

### Claude apps gateway users can now see today's, this week's, and this month's spend right in `/usage` (v2.1.319)

**For developers working behind a Claude apps gateway with no personal spending cap, as long as the gateway runs this version or later, `/usage` now shows spend for today, this week, and this month together.** Previously, developers without a cap had no good way to check how much they'd actually spent.

```bash
/usage
```

**If you use Claude Code through your organization's Claude apps gateway and have wanted to gauge your own usage trends, as long as the gateway is on a recent enough version, `/usage` now shows it with no extra setup.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### The "Earlier in this session" entry in `/tasks` lets you reopen finished subagents and message them (v2.1.319)

**`/tasks` now has an "Earlier in this session" row that collects completed subagents, so you can reopen one and send it a message even after it's dropped off the list or you've restarted the session.** Previously, once a subagent finished and fell out of the list, there was no way back in if you had a follow-up question about its results.

**If you've ever run several subagents at once and later wanted to revisit or follow up on a finished one's results, as of v2.1.319 you can find it again in `/tasks` and pick the conversation back up.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Security & Limitations

### Claude service status — no incidents, all systems operational from 11/4 through 11/7

**Checking the official status.claude.com directly shows "No incidents reported" for every day from 11/4 through 11/7 (today), with claude.ai, the Claude API, Claude Code, Claude Console, Claude Cowork, and Claude for Government all listed as "All Systems Operational."** The most recent incident was a Google Calendar/Gmail connector error, resolved on 10/28.

**If you ran into service issues in the past few days, they've already been resolved, so if something breaks today, it's worth checking your local setup or network first.** [Claude Status](https://status.claude.com)

### A sandbox escape during worktree creation has been fixed (v2.1.319)

**A flaw that allowed escaping the sandbox while creating a new worktree has been fixed in this version.** The release notes don't disclose the exact reproduction path, but since the sandbox is the core safeguard that limits the blast radius of commands Claude Code runs without approval, the mere existence of a way around it makes this a significant security fix.

**If you run Claude Code in sandbox mode and create worktrees often, it's worth upgrading to v2.1.319 to confirm you're on a version where this is fixed.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### A Bash permission-check bypass using crafted environment-variable prefixes has been fixed (v2.1.319)

**A Bash permission bypass has been fixed where prefixing a command with a specifically crafted environment-variable prefix could hide part of that command from the permission check.** Previously, a command written this way could potentially slip past deny/ask rules undetected.

**If you rely on deny/ask rules on Bash commands to block dangerous operations, keep in mind that on versions before v2.1.319, a command using an environment-variable prefix may have bypassed that defense — reason enough to prioritize upgrading.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### `sed` commands skipping permission checks in accept-edits/auto mode have been fixed (v2.1.319)

**A bug where certain forms of `sed` commands could skip permission checks in accept-edits mode and auto mode has been fixed.** Since `sed` can modify files directly, having that check skipped meant unintended file changes could happen without approval.

**If you frequently run Claude Code in accept-edits or auto mode, it's worth upgrading to v2.1.319 to make sure permission checks on `sed` commands are working properly.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Minor Changes

All of the following are from **v2.1.319** (11/6).

- **Added a `CLAUDE_CODE_DISABLE_FEATURE_FLAGS` environment variable**, letting you skip fetching feature flags without disabling telemetry. All flags fall back to their built-in defaults when set.
- **Fixed `/context` sending Claude the entire visual grid every turn in the terminal** — Claude now only reads the table.
- **Fixed `claude -p` exiting with code 0 in auto mode even when a task was rejected because it couldn't be safety-checked** — both text and JSON output now exit with code 1.
- **Fixed `NotebookEdit` modifying the wrong cell when notebook contents changed while a permission prompt was open.**
- **Changed the `/model` picker so older models no longer trail in a long list after current models** — they now appear grouped separately under a "More models" row.
- **[VS Code] Improved the confirmation dialog shown when removing the plugin marketplace so it re-checks which plugins are actually installed at that moment.**
- **[Claude Tag] Added a Claude Tag row to the Models admin page for Enterprise organizations with Claude Tag connected**, linking directly to where model defaults are managed.
