# Claude Code Daily Briefing - 2026-11-04

## Release Summary

| Version | Date | Key Changes |
|------|------|----------|
| **v2.1.317** | 11/3 | Added a cost report admin API to the Claude apps gateway, a cloud session MCP link card, `CLAUDE_CODE_DISABLE_NESTED_SESSION_ID`, and about 90 other changes |
| v2.1.316 | 10/31 | Added `CLAUDE_CODE_SUBAGENT_EFFORT` and `CLAUDE_CODE_DISABLE_ULTRATHINK`, pooled group budgets for the Claude apps gateway, and about 60 other changes (covered in the 11/1–11/3 briefings) |

**v2.1.317 shipped on 11/3, just three days after v2.1.316 (10/31).** Beyond new features like an admin API for tracking organizational spend and improved MCP link handling in cloud sessions, this release packs in several stability fixes with real day-to-day impact — including a case where `claude -p` would silently exit with a success code even when the disk was full.

[Full release notes](https://github.com/anthropics/claude-code/releases)

## New Features & Practical Usage

### A cost report admin API for querying historical spend has been added to the Claude apps gateway (v2.1.317)

**The Claude apps gateway admin API now includes `GET /v1/organizations/analytics/cost`, which returns historical spend for a given date range as an overall total, broken down by developer, by day, or by IdP group.** Alongside this, gateways with `admin:` configured now record each developer's IdP group daily and retain it for `admin.identity_retention_days`, which the cost report uses to produce group-level aggregates. OTel metrics, events, and spans also gained `anthropic.plan`, `anthropic.seat_type`, `anthropic.provider`, and `anthropic.custom_base_url` attributes, so you can cross-reference them against spend data.

```bash
# Example: query spend for a date range, broken down by IdP group
curl -H "Authorization: Bearer $ADMIN_API_KEY" \
  "https://<gateway-host>/v1/organizations/analytics/cost?start_date=2026-10-01&end_date=2026-10-31&group_by=idp_group"
```

**If you're managing Claude usage across multiple teams through the Claude apps gateway, you can now pull team- and period-level spend directly from this API instead of estimating it by hand — handy for setting up pooled budgets or compiling budget reports.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Cloud sessions now show a card for opening or declining links requested by MCP servers (v2.1.317)

**When an MCP server asks a cloud session to visit a specific URL, a link card now appears on screen letting you open or decline the request.** Previously, unlike in the terminal, these requests could pass through cloud sessions unnoticed.

**If you're using an MCP server in cloud sessions that requires visiting an external link for OAuth or additional approval, v2.1.317 means you won't miss that request anymore — you can review and act on it right away.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Developer Workflow Tips

### A new environment variable lets `claude -p` on self-hosted runners keep using the outer session's ID and transcript (v2.1.317)

**Setting `CLAUDE_CODE_DISABLE_NESTED_SESSION_ID` to `1` restores the previous behavior on self-hosted runners, so a `claude -p` invocation nested inside a session keeps using that session's ID and transcript.** Recent versions changed this so that a nested `claude -p` call uses its own session ID and generates its own title before sending it to the outer session; if that change broke an existing pipeline, this environment variable lets you keep the old behavior.

```bash
# On a self-hosted runner, make a nested claude -p keep using the outer session's ID
export CLAUDE_CODE_DISABLE_NESTED_SESSION_ID=1
```

**If you run automation that nests `claude -p` inside a session on a self-hosted runner, and you've noticed session ID or transcript handling change in a recent version, this environment variable is worth trying to restore your pipeline's previous behavior.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### The resume prompt shown on exit now remembers the flags you launched with (v2.1.317)

**The "Resume this session with" message shown when exiting Claude Code now prepends any flags the session was started with — such as `--chrome --debug` — in front of `--resume`.** Previously, this message only showed `--resume`, so resuming a session that had been started with specific flags meant remembering and retyping them yourself.

**If you often start sessions with particular flags like `--chrome` or `--debug`, you can now just copy and paste the message shown on exit to reopen a session under the same conditions.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### `/design-sync` now warns before starting an upload if the design system has already moved to Claude (v2.1.317)

**If an organization's design system has already been migrated to Claude, `/design-sync` now flags this upfront before doing any work, rather than proceeding to build.** Previously, this situation could proceed all the way to the upload step before failing, making it hard to know in advance where things would stop.

**If multiple people on the same team use `/design-sync`, this cuts down on cases where someone repeats a migration someone else already did, only to hit a failure at the upload step.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Security & Limitations

### Claude service status — no incidents and full operational status from 10/31 through 11/3

**Checking status.claude.com directly shows "No incidents reported" for every day from 10/31 through 11/3, with claude.ai, the Claude API, Claude Code, Claude Console, Claude Cowork, and Claude for Government all showing "All Systems Operational."** The most recent incident was a Google Calendar/Gmail connector error that was resolved on 10/28.

**If you ran into service issues in the past few days, they've already been resolved — so if something goes wrong today, it's worth checking your local setup or network first.** [Claude Status](https://status.claude.com)

### `/schedule` now warns when a new cloud scheduled task comes with unexpected connectors attached (v2.1.317)

**When creating a new cloud scheduled task, if a connector you didn't request gets attached, `/schedule` now warns you and explains how to remove it.** Previously, it wasn't always clear which connectors were attached to a scheduled task, raising the risk of a task running with a broader scope than intended.

**If you run several cloud scheduled automations that touch connectors like email or calendar, this warning in v2.1.317 lets you catch unwanted connectors on new scheduled tasks right away.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Web and shell tool calls now require confirmation before sending your account email over the network (v2.1.317)

**When a web or shell tool call attempts to send your account email address over the network, a confirmation step now appears before it happens.** Previously, this kind of transmission could happen without being noticeable, making it hard to know when your account email was going out unintentionally.

**If your workflows use WebFetch or Bash to integrate with external services, you can now rely on an explicit confirmation whenever your account email is about to leave over the network.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Ecosystem & Plugins

### Artifact links pasted into Slack's Claude Tag now render as simpler cards (v2.1.317)

**Artifact links newly pasted into a Slack channel now appear as a simpler card with an Open button, and clicking it opens the artifact inside Claude instead of Slack's side panel.** Previously, the same link would open in Slack's own side panel, separate from the Claude interface.

**If you frequently share artifacts made in Claude with teammates over Slack, v2.1.317's shorter card and Open button let you open and review the artifact directly inside Claude.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Minor Changes

All of the following are from **v2.1.317** (11/3).

- **Fixed `claude -p` silently exiting with code 0 when writing the transcript or `~/.claude.json` failed due to a full disk or exceeded quota** — it now prints an error and exits with code 1 in both text and json output (some fully NFS-exported setups may still miss this).
- **Fixed PDF metadata causing the Read tool and @-mentions to undercount a document's page count.**
- **Fixed regional or network blocks (HTTP 403) appearing as login failures** — the error message now explains that the request was blocked.
- **Fixed `DISABLE_PROMPT_CACHING_OPUS` and `DISABLE_PROMPT_CACHING_SONNET` not applying to `[1m]`, other regions, or dateless default model names.**
- **Fixed pressing Ctrl+C to clear input text also stopping all running background agents.**
- **Fixed shared artifacts not appearing in `/artifacts` and the Artifact tool's shared list once you owned 200 or more artifacts yourself.**
- **[Windows] Fixed all tool calls being denied on certain volumes where native path lookups failed** — working directory checks now compare folder identifiers instead.
- **[Gateway] Fixed a developer's own spend limit incorrectly showing as 100% exhausted in the status bar and `/usage` after a group's pooled budget ran out.**
