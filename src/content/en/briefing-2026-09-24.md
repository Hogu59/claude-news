## New Features & Practical Usage

### `"attribution": false` — hide commit and PR attribution entirely (v2.1.281)

**Adding `"attribution": false` to `settings.json` suppresses attribution text on every commit and PR.** **Older CLI versions, however, skip the entire config file when this value is present, so if you're sharing a settings file across a mix of CLI versions, keep the legacy object format instead of the boolean.**

```json
{
  "attribution": false
}
```

**If your team has a policy against marking commits as AI-assisted, this single setting rolls out organization-wide without needing to configure it commit by commit.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Auto mode's server-side classifier now covers direct API connections and read-only commands (v2.1.281)

**`CLAUDE_CODE_AUTO_MODE_SERVER` now applies to direct Anthropic API connections too — set it to `0` to opt out of the server-side classifier (falling back to the local classifier, which counts against usage), or `1` to opt in.** **In sessions running the server-side classifier, even read-only and sandboxed shell commands are now subject to review, and execution is blocked if the classifier flags them.**

```bash
# Explicitly enable the server-side Auto mode classifier on a direct Anthropic API connection
export CLAUDE_CODE_AUTO_MODE_SERVER=1
```

**After the server-side classifier became the default for Bedrock, Vertex, Foundry, and gateway setups in v2.1.278 on 9/19, its scope has now widened to direct API connections and read-only commands as well. If you're running automation pipelines on Auto mode, keep in mind that even commands you'd normally consider safe read-only checks may now wait on a classifier verdict.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### 950 Claude agents discovered a new enzyme system with CRISPR-like repeat sequences (9/24)

**By linking repeat sequences and accessory proteins found near already-known enzymes across a massive DNA database, the agents identified a previously uncharacterized enzyme system called ART.** **About 950 Claude agents spent 21 hours and 210 million tokens surveying more than 200,000 reverse transcriptases to make the discovery.**

**Following biomolecular model acceleration on 9/19 and the RSA-896 factorization on 9/21, this is another case of Claude automating the exploratory stage of scientific research itself through large-scale parallel agent runs.** [GeekNews](https://news.hada.io/topic?id=34195)

## Developer Workflow Tips

### Unreal Agent — an agent harness that cuts costs via asynchronous tool execution (9/23)

**Instead of having the model repeatedly poll to check whether a tool call has finished, this harness lets the runtime itself manage background tasks and completion notifications, cutting down on unnecessary model calls and token usage.** **It can explore code and search the web in parallel while setting up the dev environment, and it can still take additional instructions from the user while tools are running.**

**Following HarnessTax on 9/18 and Motif-code on 9/21, this continues a trend where harness design matters as much as raw model performance for real-world cost and speed. Worth a look if you're designing how custom subagents or Workflow scripts for Claude Code wait on tool completion.** [GeekNews](https://news.hada.io/topic?id=34163)

### Gauge whether to switch to Auto mode using the new /insights recommendation (v2.1.281)

**`/insights` now includes a recommendation that estimates how many permission prompts from your recent sessions could have been handled by Auto mode.**

```bash
/insights
```

**If you've been on the fence about switching to Auto mode, this estimate lets you check how many prompts in your own actual sessions could have been auto-handled before deciding, rather than relying on a gut feeling.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Security & Limitations

### Claude service status — all services operational as of 9/24 (9/24)

**A direct check of the official status.claude.com shows claude.ai, Claude Console, Claude API, Claude Code, Claude Cowork, and Claude for Government all Operational as of 9/24, with no active incidents.** **This marks a second consecutive incident-free day since the elevated error-rate incident affecting multiple models on 9/22 was resolved.**

**Despite a string of new model launches and major releases over the past few days, service stability hasn't taken a noticeable hit — it's a fine time to stay the course without any special precautions.** [Claude Status](https://status.claude.com)

### Claude Code found to skip reading AGENTS.md when telemetry is disabled (9/23)

**Turning off usage data transmission was found to also silently stop Claude Code from reading the project's instruction file, AGENTS.md, with no warning given.** **The local file-reading feature is tied to the same toggle that controls fetching data from the server, so disabling telemetry or other non-essential communication ends up disabling an unrelated local feature along with it.**

**If you've been relying on the AGENTS.md support covered in the 9/19 briefing to manage project instructions in an environment with telemetry disabled, it's worth checking right now whether the file is actually being loaded.** [GeekNews](https://news.hada.io/topic?id=34179)

## Minor Changes

All of the following are from **v2.1.281** (9/23).

- **`assume_role` was added to the Bedrock upstream for the Claude app gateway**, letting the gateway assume a role via STS to call Bedrock in a different AWS account, and also making it possible to separate sessions per developer.
- **Specifying `guardrail: {id, version}` on a Bedrock upstream applies the corresponding Amazon Bedrock guardrail to every request routed through it.**
- **MCP URL-mode elicitation was added**, letting a server request that a browser-based auth flow be opened, and the waiting dialog no longer lingers on screen when the server has no way to confirm completion.
- **`claude plugin validate` now checks MCP servers too**, reporting `.mcp.json` entries that would silently be dropped at load time, undeclared `${user_config.*}` references, and unsafe URLs.
- **The prompt for dangerous `rm` commands now waits 2 minutes for a response before rejecting the command with a rewrite hint**, so unattended sessions can keep going instead of stalling (can be disabled with `CLAUDE_CODE_DISABLE_DANGEROUS_RM_TIMEOUT=1`).
- **Session artifact links are now consolidated into a single footer pill below the prompt**, and opening `/artifacts` from there shows the current session's artifacts at the top of the list.
- **On self-hosted runners, the system prompt is now passed via a private file instead of command-line text**, eliminating execution failures caused by overly large prompts. Wrappers or hooks that pass `--system-prompt` or `--append-system-prompt` need to switch to `--system-prompt-file` and `--append-system-prompt-file`.
