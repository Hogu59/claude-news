## New Features & Practical Usage

### Claude Sonnet 5.5 arrives — replaces the default Sonnet model, output speed up 30%+ (v2.1.284)

**Claude Sonnet 5.5 (`claude-sonnet-5-5`) is now the default Sonnet model on the Anthropic API.** It supports a 1 million token context window, and pricing stays the same as Sonnet 5: $2 per million input tokens, $10 per million output tokens, and $0.20 for cache reads. According to GeekNews, it performs better on coding as well as document, slide, and spreadsheet work, with output speeds more than 30% faster than Sonnet 5. It also needs fewer tokens to do the same work, which improved cost efficiency in Anthropic's own testing.

```bash
# Explicitly pin Sonnet 5.5 via the API
export ANTHROPIC_MODEL=claude-sonnet-5-5
```

**If you were already using the default Sonnet model in Claude Code, you'll be switched over to 5.5 automatically with no configuration needed — the cost structure stays the same while speed and token efficiency both improve, so there's less reason than ever to pin an older model.** [GeekNews](https://news.hada.io/topic?id=34444)

### Gateway usage limits now show dollar amounts (v2.1.284)

**For environments running the Claude app gateway, `/usage` and the status bar now display spending limits as actual dollar amounts, like "$271.40 / $500.00 spent this month."** The status bar's `rate_limits.spend_limit` field also gained `used_usd`, `limit_usd`, and `period` fields.

**If your organization manages spending limits through the gateway, you can now see exactly how much has been spent instead of just a percentage, making it much faster to tell whether you're approaching budget.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Developer Workflow Tips

### Writing prompts for Claude Opus 5.5 (9/28)

**Prompts written for Opus 5 mostly carry over as-is, and it's recommended to start reasoning effort at the medium default and adjust from there.** Carrying over effort settings tuned for the previous model can waste time and tokens unnecessarily. In chat, phrases like "think carefully before answering" still meaningfully affect how much reasoning the model actually does.

**If you've been reusing Opus 5 system prompts or CLAUDE.md instructions as-is with Opus 5.5, it's worth revisiting your effort defaults and stripping out unnecessarily high-effort settings to cut costs.** [GeekNews](https://news.hada.io/topic?id=34424)

### `/mcp reconnect all` — reconnect every dropped MCP server in one shot (v2.1.284)

**In interactive terminals, you can now retry every MCP server that failed to connect or needs authentication with a single command instead of one at a time.**

```bash
/mcp reconnect all
```

**When you're running several MCP servers, it's common for a few to drop mid-session — this command lets you clean them all up at once instead of reconnecting each one individually.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Auto mode now offers "allow once, ask again next time" (v2.1.284)

**The prompt auto mode shows before reading a file outside the working directory now has a new answer: allow it just this once, and get asked again the next time the same situation comes up.** Previously there were only two extremes — allow permanently, or deny every single time.

**For workflows that only occasionally need to read files outside the working directory, you can now decide case by case without committing to a blanket allow, while still not missing the next prompt.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Ecosystem & Plugins

### Claude app gateway now supports sending telemetry directly via Google Cloud OTLP (v2.1.284)

**Adding `auth: { google: {} }` to a `telemetry.forward_to` target in the gateway config lets the gateway export telemetry directly to Google Cloud's OTLP endpoint, using credentials the gateway already holds.**

**If your organization runs its observability stack on Google Cloud, you can now stream telemetry straight from the gateway to OTLP without standing up a separate relay service.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Claude app gateway now supports certificate-based client authentication (v2.1.284)

**Certificate-based client authentication (`private_key_jwt`) has been added for authentication between the gateway and identity providers, allowing integration with identity providers that issue certificate credentials instead of client secrets.**

**Organizations using identity providers that require certificate-based identity verification — common in financial services — can now connect them to the gateway, which wasn't previously possible.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Minor Changes

All of the following are from **v2.1.284** (9/28).

- **`/rate-limit-options` was added to `/help` and the command menu**, so claude.ai subscribers can easily find the command referenced in usage-limit messages.
- **New keybinding actions `increaseEffort`, `decreaseEffort`, and `toggleUltracode` were added for the effort slider**, letting you rebind the arrow-key and Tab behavior in `keybindings.json`.
- **Fixed a lingering "Prompt is too long" error that could occur even after compaction** — if a compacted request is still too long, Claude Code now trims recent conversation further and compacts again.
- **When loading auto-memory, invisible characters and tags mimicking Claude Code's own markup in `MEMORY.md` and recalled memory notes are now neutralized.**
- **In the `/plugin` settings screen, boolean options now use true/false choices instead of free text, and numeric options reject invalid input.**
- **[VS Code] Added an option to show timestamps above each prompt and response** (date lines also appear when the date changes; off by default).

## Interesting Projects & Tools

- **Jeff — a 0.8B local decision model trained at home (9/29)**: A small classification model that takes a situation and a set of options as natural language input and returns calibrated probabilities per option in a single forward pass, with no text generation or response parsing needed, so it can be dropped straight into local code. It's fine-tuned from Qwen3.5 and Gemma4, and a decision takes about 30ms. It joins the line of System-1-style judgment models — Jev, Ollaya, CLM, jgrep — that have been emerging since 9/19, this time with a small model you can actually train yourself. [GeekNews](https://news.hada.io/topic?id=34459)
- **Imp — a full port of DSPy to BEAM (9/29)**: A project that reimplements DSPy's signatures, modules, optimizers, agent loops, and retrieval features — which let you declare a language model step's inputs and outputs and improve the program using examples and evaluation metrics — on top of the reliability and concurrency of Elixir and OTP. Worth a look if you want to declaratively build agent pipelines that call LLMs like Claude within the Elixir/BEAM ecosystem. [GeekNews](https://news.hada.io/topic?id=34438)
