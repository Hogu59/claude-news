**A day after v2.1.259 (9/2), v2.1.260 (9/3) shipped.** It brought new features like a **full-screen diff panel and a text-based `/advisor` for headless sessions**, along with **70+ fixes and improvements — including two security bugs that had been letting permission rules get bypassed**.

## New Features & Practical Usage

### Full-screen mode gets a diff panel — `/diff` (v2.1.260)

**Full-screen mode now shows a diff panel alongside the conversation, letting you watch uncommitted changes update live as Claude edits.** **Toggle it anytime with `/diff`.**

```bash
/diff
# Opens a diff panel next to the conversation, updating live as Claude edits
```

**This lets you track the conversation and the actual code changes side by side, without switching back and forth to an IDE or running `git diff`.** The same release also adds **`/reload-plugins` to headless sessions**, and brings a **text-based form of `/advisor` (`/advisor`, `/advisor <model>`, `/advisor off`) to the desktop app, Remote Control, and headless sessions**. [Full release notes](https://github.com/anthropics/claude-code/releases)

### Anthropic releases commerce agent blueprints and a Claude Code plugin for retail, travel, telecom, and ticketing platforms (9/3)

**Anthropic has published blueprints and a Claude Code plugin that let retail, travel, telecom, and ticketing platforms stand up shopping and merchant agents in a matter of days.** **The shopping agent is designed to parse multi-item natural-language requests and handle catalog search and comparison, personalized recommendations, cart building, and checkout.**

**If you're building Claude-based agents for the commerce domain, this blueprint and plugin are a solid starting point rather than designing everything from scratch.** [GeekNews](https://news.hada.io/topic?id=33176)

## Developer Workflow Tips

### Moving to Claude Fable 5.1? Re-evaluate your Fable 5 prompts (9/3)

**Existing Claude Fable 5 prompts will mostly still work on Fable 5.1, but since effort handling, progress updates, tool calls, conversation history, and output formatting have all changed, guidance recommends re-evaluating your setup rather than porting it over as-is.** **The suggested approach is to start with effort set to high by default and adjust down to low/medium or up to xhigh as needed.**

**If you're considering the switch to Fable 5.1, it's safer to pair this guide with the session-scoped `/effort xhigh s` option covered in the 9/2 briefing and re-validate your existing prompts one by one.** [GeekNews](https://news.hada.io/topic?id=33175)

### zg (zvec-grep) — a local hybrid search tool for finding code even when you don't know the keyword (9/3)

**The Qwen team has open-sourced zg (zvec-grep), a local-first search tool built for both humans and agents.** **It combines ripgrep's exact text search with vector search, BM25, and hybrid search, letting you explore code and docs by natural-language intent even when you don't know the exact function name or error string.**

**When Claude Code can't pinpoint the right spot in a large codebase using Grep alone, wiring up this kind of hybrid search via an MCP server or the Bash tool could improve search accuracy.** [GeekNews](https://news.hada.io/topic?id=33183)

## Security & Limitations

### Parenthesized permission rules were being ignored, leaving read-only folders writable (v2.1.260)

**Fixed a bug where `Edit`/`Write`/`Read` permission rules containing parentheses in the path were treated as invalid by the Bash sandbox and silently ignored.** **As a result, folders users had marked read-only could actually still be written to.**

**If your project has parentheses in folder or file names and you were relying on `Edit()`/`Write()` deny rules to protect specific paths, that protection may have been silently disabled until now — you should update to the latest version.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Command substitution hidden in zsh shell variables was being auto-approved (v2.1.260)

**Fixed a bug where hiding command substitution inside assignments to zsh shell variables like `REPORTTIME`, `REPORTMEMORY`, and `DIRSTACKSIZE` caused the Bash permission check to auto-approve them.** **These commands now require approval just like any other.**

**If you're running Claude Code in auto mode or a low-permission mode, you should update — until now there was a path that let arbitrary commands run without approval by disguising them as these shell variable assignments.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Claude service status — simultaneous OpenAI/Claude/Grok outage on 9/3 from a Microsoft Azure disruption, all systems now operational

**Checking status.claude.com directly shows two resolved incidents on 9/3**: **an elevated Claude Sonnet 5 error rate from 12:37-12:56 UTC (about 19 minutes), and elevated error rates across multiple models — Claude Mythos 5.1, Fable 5.1, Opus 5, Opus 4.8, and Opus 4.6 — from 13:26-16:23 UTC (about 3 hours).** **The same day, ChatGPT/Codex and xAI's Grok also went down at the same time**; **news reports pointed to an outage at Microsoft Azure, which all three services rely on, as the cause**, and **all three were reported back to normal by 12:38 PM Pacific Time**.

**As of 9/4, no new incidents have been logged and all systems are operational.** **If you're building a workflow that runs multiple AI services concurrently, plan a fallback strategy that accounts for the fact that even services from different companies can go down together when they share the same cloud infrastructure.** [Claude Status](https://status.claude.com/history) · [Axios](https://www.axios.com/2026/09/03/chatgpt-claude-grok-outages)

## Minor Changes

All of the items below are from **v2.1.260** (9/3).

- **Reverted a v2.1.259 change that applied `Read()` deny rules to Bash arguments as well.** That change had the side effect of causing a `Read(./**/build/**)` rule to block even `npm run build` in every mode, and made `cd … && grep` require confirmation even in auto mode.
- **Fixed an issue where a line range selected in the IDE would disappear when running a skill or slash command** — the "N lines selected" context is now correctly passed to Claude.
- **Fixed repository recognition for GitLab projects in nested subgroups** (`gitlab.com/group/subgroup/project`).
- **Fixed issue references in the `owner/repo#123` format incorrectly linking to github.com even when working in a GitLab repository** — they now correctly link to the gitlab.com issue.
- **Fixed a bug where a single file permission rule with an uncompilable pattern, like an unclosed `[`, caused every file edit to fail with an "Invalid regular expression" error** — such deny rules now correctly block only that literal path.
- **`Ctrl+L`/`Cmd+K` in full-screen mode now clears the transcript view like `clear` does in a terminal.** Scroll up to see the previous conversation again.
- **Removed the 1-hour execution time limit on background commands started by subagents** — like the main session, they now keep running until they finish or are stopped.
- [VSCode] **The model pill in the input footer now shows the selected effort level**, and an **Open/Closed status filter has been added to the session list.**

## Recommended Reads

- **"Static Allocation and Constant Work"**: **Object pools don't prevent the underlying logic error of use-after-free, but forcing memory to be reused only within the same type can eliminate most physical type confusion and the arbitrary code execution it enables** — this is the core diagnosis. **The key idea is a type-aware pool design: build an allocator that takes type information, so memory previously used by U can never be reused by T.** Developers writing or reviewing systems-language code with Claude Code may find this approach — **achieving memory safety through allocator design rather than at the language level** — worth studying. [GeekNews](https://news.hada.io/topic?id=33198)
- **"Speeding Up OCR Decoding with Diffusion"**: **By converting an OCR model to work as both autoregressive (AR) and block diffusion, a self-speculative decoding technique — drafting quickly with diffusion, then verifying with AR — achieved a 3.85x decoding speedup with no quality loss.** If you're building document-recognition or OCR pipelines on top of Claude Code, **this is a practical technique worth referencing for boosting inference speed.** [GeekNews](https://news.hada.io/topic?id=33187)
- **"It's Not Remote Work, It's Poor Async Communication"**: **The analysis argues that preserving the benefits of remote work requires fixing asynchronous communication rather than forcing a return to the office, and a study of 7,700 people found remote workers had higher well-being and lower turnover — but the abrupt pandemic-era transition weakened communication and collaboration.** If you're designing workflows that support remote/async collaboration with Claude Code — background sessions, handoffs between teammates via SendMessage — **this perspective, that the root cause is communication style rather than remote work itself, is worth keeping in mind.** [GeekNews](https://news.hada.io/topic?id=33178)
