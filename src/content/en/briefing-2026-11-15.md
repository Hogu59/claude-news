## Developer Workflow Tips

### Anthropic published the safety design behind running a 1,000-agent team on Fable 5.2 (11/14)

**Before general release, Anthropic's research team ran a "toy experiment" with one lead agent and 999 helper agents on Fable 5.2 simultaneously, formalizing Fermat's Last Theorem in Lean in just 28.7 hours.** Compared to a September experiment — where a researcher directly directed dozens of agents and it took 11 days — output tokens dropped to a third and proof length to a seventh. There was no dedicated collaboration tooling: each agent worked on its own git branch, and the lead agent set up five shared tables in a common Postgres database — Announce, Assign, Notes, Subtasks, and Landed — in just 10 minutes to coordinate everyone.

The safeguards came in three layers. Each agent ran in a lightweight, network-isolated VM with sudo removed and no API keys anywhere in the sandbox. SQL statements were capped at a 5-second timeout, and every shell command and file edit was screened fail-closed by an LLM classifier before execution. Across more than a million tool calls, not a single one tripped the blocking criteria.

```text
Isolated VM (no network, no sudo, no API keys)
  → 5-second SQL timeout
  → Every shell command / file edit pre-screened fail-closed by an LLM classifier
  → Per-agent git branches + coordination via shared Postgres
```

**If you've been spinning up multiple subagents in Claude Code for complex tasks and wondering how to coordinate them, this design is worth borrowing directly: git branches plus a shared database can get you surprisingly far without any heavyweight orchestration tooling, and the fail-closed classifier that screens shell commands and file edits before an unsupervised agent runs them is a particularly useful idea.** [Anthropic's official blog](https://claude.dev/blog/safely-scaling-multi-agent-teams-with-fable-5-2/) · [GeekNews](https://news.hada.io/topic?id=37159)

### Check PyPI's new security provenance signals before installing a package (11/13)

**PyPI revamped its project pages with a new Security tab that shows which workflow published each file and, when build provenance exists, which source commit it was built from.** A project gets a Full Provenance badge if every file has it, No Provenance if none do, and a warning appears if only some files have provenance, or if the repository or workflow changed, or if provenance suddenly disappeared. No Provenance doesn't necessarily mean a package is malicious, but it's a signal you can catch before installing — one that can flag a compromised account or build pipeline that altered a package's contents.

**If you've been installing MCP servers or dependencies in Claude Code based purely on the pip package name, it's worth making a habit of checking the Security tab on the PyPI project page first for provenance status and warnings.** [PyPI's official blog](https://blog.pypi.org/posts/2026-11-06-ui-updates-complete/) · [GeekNews](https://news.hada.io/topic?id=37178)

## Security & Limitations

### Claude service status — the Claude iOS app's Sign in with Apple error is still ongoing, while the claude.ai billing error has been resolved

**Checking status.claude.com directly: starting at 07:11 UTC on 11/14, some users reported being unable to sign in to the Claude iOS app with Sign in with Apple, and as of the latest update (20:12 UTC) the issue is still under investigation.** It mainly affects new sign-ups; signing up via Google or email reportedly works without issue. The same day, claude.ai also saw a separate incident of increased errors in billing, plan changes, and cancellation from 02:34 to 04:03 UTC (about 1.5 hours), which has since been resolved, with any delayed payments and plan changes now reflected. Core functionality itself was unaffected by either incident.

**If you've recently been unable to sign up for the Claude iOS app with a new Apple account, it's likely this ongoing incident rather than a local issue — if you're in a hurry, signing up via Google or email is a workable fallback.** [Claude Status](https://status.claude.com)

## Ecosystem & Plugins

### kr-career-skill — an agent skill for Claude Code and Codex that searches 277 Korean job-listing sites (11/13)

**Built for anyone too drained after work to handle job hunting themselves, this skill has an agent find listings matching your role, location, and experience level, research the companies, and draft a cover letter and resume.** It covers 277 job sites in total: the 104 major portals and industry-specific sites are searched directly via Python standard-library scripts, while the rest are handled through the agent's browser. It won't submit applications on your behalf, won't invent experience or numbers you don't have, and marks any missing information as `[Fill in directly: …]` for a human to complete. The author says they mainly tested it in the Pickle app and only confirmed skill recognition and early-stage behavior in Claude Code, and notes it covers far more sites than similar existing skills like jobstack and ai-job-search-kr, which handle only 3-4 sites each.

```bash
# Install by pointing directly at SKILL.md on GitHub
# GitHub: Whosekey-Labs/kr-career-skill
```

**If you've wanted to build job-hunt automation with Claude Code, this skill is worth trying first, given its broad site coverage and its deliberate design to never submit applications on its own.** [GitHub](https://github.com/Whosekey-Labs/kr-career-skill) · [GeekNews](https://news.hada.io/topic?id=37079)

## Community News

- **OpenAI dissolved its dedicated robotics team, handing robot control to its general-purpose models (11/13)**: Research staff were absorbed into the main research organization led by Mark Chen, while applied and hardware staff moved into Greg Brockman's Applied organization. The decision followed confirmation that general-purpose models like GPT-6 Astra can control robots directly without robot-specific training — in Nvidia's simulation benchmarks, an Astra-based agent hit a 74.8% success rate, beating the best dedicated robotics model's 51.0%. Counterarguments note that low-latency, offline environments still need small on-device models, and some have questioned whether the cost savings are real given that staff were reassigned rather than laid off. [GeekNews](https://news.hada.io/topic?id=37180)
- **A two-day Microsoft 365 outage exposed the structural risks of vendor lock-in (11/14)**: Following up on the outage itself, which was covered in the 11/14 briefing, later reporting covers Microsoft's warning that end-of-support Exchange Server 2016 and 2019 should now be treated as permanently vulnerable, a Nextcloud co-founder's point that single-vendor dependence makes backup systems and air-gapped operations difficult, and a Civo CEO's diagnosis that the real problem is critical infrastructure being concentrated in the hands of so few companies. The UK Parliament's science committee chair said the outage exposed a lack of resilience in the UK's digital infrastructure, and commenters discussed whether Microsoft Ireland — designated a critical ICT provider under the EU's DORA regulation — could face fines over the incident. [GeekNews](https://news.hada.io/topic?id=37175)

## Recommended Reads

- **Anthropic replaced Git with its own version control system, Scion, in its internal monorepo (11/12)**: As agent usage grew, daily merges in Anthropic's monorepo rose roughly 12x in four months — from about 2,500 in May to over 30,000 in September — and with around 25 million checkouts a day, the existing shallow-clone and internal-mirror setup couldn't keep up. Scion assumes most workspaces are always online and handles commits, rebases, and merges on the server, trading away Git's offline, full-history model in exchange for each workspace carrying far less data. The same piece compares OpenAI's parallel-push-only backend Pando, the open-source server Aspen that it inspired (handling roughly 567 pushes per second over a 5-minute test), and GitHub's merge queue, noting that as pushes get faster, the next bottleneck shifts to validating merges into main. If you're running a workflow where multiple agents commit to Claude Code concurrently, this is worth reading to get ahead of where that bottleneck will move next. [GeekNews](https://news.hada.io/topic?id=37034)
- **Why some developers choose Zig over C for systems programming (11/14)**: The piece compares Zig against C side by side — `errdefer` placing cleanup code right under the allocation and running it only in reverse order on error, `std.testing.FailingAllocator` letting you force a specific allocation to fail so you can test each failure path, and out-of-bounds array access panicking in Debug and ReleaseSafe modes. The author acknowledges Zig still doesn't catch use-after-free, that these checks are disabled in fast and small build modes, and that C still has broader language stability, tooling, and ecosystem support. Commenters pushed back that modern C can close much of the gap with sanitizers and C23's `[[nodiscard]]`, and debate continued over whether human-centered language design still matters as much in the age of LLMs. [GeekNews](https://news.hada.io/topic?id=37123)
- **A genealogy of software job titles, from the 1940s to today (11/14)**: This piece introduces an interactive timeline diagram tracing 104 software job titles from the 1940s to now, showing how "webmaster" splintered into web developer, sysadmin, and content roles before merging back into "full-stack," and how titles like "prompt engineer" — hot in 2023 — faded quickly as models improved and the role got absorbed into AI engineering. A historical anecdote about Goldstine and von Neumann in 1947 treating design as the real work and coding as mere clerical labor echoes today's debates about the AI era. If you've been watching coding work itself get rapidly automated with Claude Code, this historical lens is a useful reminder that even as titles change, the work itself just keeps splitting and recombining. [GeekNews](https://news.hada.io/topic?id=37182)

## Interesting Projects & Tools

- **Show GN: specmaxx — a web app that predicts inference speed before you buy a local AI rig (11/13)**: The author built this with Claude while shopping for hardware to run DeepSeek-class models locally, tired of manually calculating which specs they'd need to hit every time. You enter your hardware specs and model, and it predicts prefill and decode tokens per second, now refined to account for per-layer compute characteristics, cluster interconnect latency, and host RAM/SSD offloading. Settings sync to URL query parameters, so you can share a simulation result with a single link. [specmaxx](https://cro.sh/specmaxx) · [GeekNews](https://news.hada.io/topic?id=37143)
- **Show GN: Shady — a 3D Wayland compositor that lets AI agents see and control the screen over MCP (11/13)**: An experimental compositor that treats windows as objects in 3D space you can move, fold, or throw, usable either as a regular 2D desktop or run headless to hand agents an independent desktop separate from the user's own. It solves the problem that Wayland lacks a common input-injection tool like X11's xdotool by exposing typing, clicking, dragging, and screenshot commands directly over an IPC socket, wrapped in `shady-mcp` so you can connect it to Claude with a single `claude mcp add shady -- shady-mcp`. [GitHub](https://github.com/gloaming-dusk/shady) · [GeekNews](https://news.hada.io/topic?id=37036)
