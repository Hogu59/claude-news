## Developer Workflow Tips

### Check your existing architecture and design intent before implementing a feature (GeekNews, 10/29)

**As the architecture-visualization tool Specify — featured on GeekNews Show — points out, agent-written code that "works but drifts from the existing structure" tends to happen when you only check whether it runs and move on.** Before handing off a new feature, it helps to diagram the data flow and processing of existing functionality first, and to note which domain the new feature belongs to and whether it can reuse existing services or data — that way, reviewing the finished implementation against the original design intent becomes much easier.

**If you've ever handed a feature to Claude Code and only noticed later that the structure had quietly drifted, it's worth adding a step to your CLAUDE.md or task instructions telling it to first explain the flow and domain of related functionality before implementing.** [GeekNews](https://news.hada.io/topic?id=36223)

### Custom skills and slash commands sent from the VS Code and JetBrains panels no longer drop open files and selections (v2.1.311)

**A bug has been fixed where sending a custom skill or custom slash command from the VS Code or JetBrains panel would drop the open-file and selected-line context that's normally included automatically with a regular message.** Previously, this context was silently lost only when using custom commands from the panel, sometimes forcing you to re-explain the same thing.

**If you often keep files open or code selected while using custom skills or slash commands from an IDE panel, as of v2.1.311 you can trust that context now comes through automatically, without needing to restate it.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Running `claude mcp add` or `/mcp` from a monorepo subdirectory now points to the correct project's local MCP config (v2.1.311)

**A bug has been fixed where running `claude mcp add`, `claude mcp remove`, or `/mcp` from a subdirectory beneath the repo root would register the local-scope server entry in `~/.claude.json` under the current folder's name instead of the repo root — it now correctly targets the repo root's project entry.** Previously, registering a local MCP server after moving into a package directory within a monorepo could leave the config scattered under an unintended path.

**If you manage local MCP servers with `claude mcp` commands while moving between packages in a monorepo, it's worth upgrading to v2.1.311 and checking `~/.claude.json` for any stray entries left over from before.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Security & Limitations

### Claude service status — fully operational with no incidents on either 10/29 or 10/30, following the 10/28 connector fix

**A direct check of the official status.claude.com shows that the Google Calendar and Gmail connector errors covered in the 10/29 briefing were all marked resolved on 10/28, and both 10/29 and 10/30 show "No incidents reported," with claude.ai, Claude Console, the Claude API, Claude Code, Claude Cowork, and Claude for Government all Operational.**

**If you ran into connector errors over the past few days, they should already be resolved — so if something breaks today, it's more likely worth checking your local setup or network first.** [Claude Status](https://status.claude.com)

### Encryption keys in major PDF readers like MuPDF and Foxit have been narrowed to 9 bits, making them brute-forceable (10/30)

**A disclosed flaw shows that MuPDF (before 1.28.5), Foxit PDF Reader, OpenPDF, and iText draw the randomness used for AES-256 PDF encryption from an extremely narrow range — such as the Unix timestamp in whole seconds — making it possible to brute-force the entire key without knowing the password.** MuPDF's full 512 possibilities could be checked in 11 milliseconds with an unoptimized Python script, while a Rust tool could scan every timestamp since 1970 for Foxit in 4.85 seconds. There's no way to protect PDF files that have already been distributed.

**If you have a workflow that encrypts PDFs with Claude Code or another tool before sharing them externally, check whether the PDF library you're using is one of the implementations named here (or built on the underlying PDFium family), and look for a vendor patch.** [GeekNews](https://news.hada.io/topic?id=36253)

## Recommended Reads

- **For student developers hoping to become developers in the AI era (10/28)**: A follow-up to a 2018 post arguing that while a developer's role is shifting toward directing AI and taking responsibility for its output, you still need solid technical fundamentals to judge whether that output is actually correct. It also argues that a portfolio shouldn't just list technologies — it should tell the story of how you solved a problem, what you doubted in the AI's output, and how you verified it, which is a useful reference point for thinking about how junior developers using Claude Code should grow. [GeekNews](https://news.hada.io/topic?id=36135)
- **The uncanny valley of LLM-style prose (10/30)**: Martin Fowler writes that the moment writing starts to feel like an LLM wrote it, readers lose interest or feel put off — and while it's hard to pin down exactly what causes this, it doesn't go away just because you run it through a detection tool. His advice to hand an LLM an outline rather than a full draft, and write the body yourself, is a useful reference for deciding how much to delegate when using Claude Code to write commit messages, PR descriptions, or docs. [GeekNews](https://news.hada.io/topic?id=36244)
- **Zombie statistics: where do the numbers AI cites actually come from? (10/30)**: trakkr.ai tracked 1,285 statistics cited by five AI services and found only 40% actually matched the original research; 82% of the cited pages contained numbers, but only 21% directly cited the original study. The point that multiple AIs citing the same number doesn't mean it's verified — they usually trace back to the same unsupported chain — is a good reason to track down the original research yourself whenever you ask Claude Code or Claude to cite a statistic. [GeekNews](https://news.hada.io/topic?id=36254)

## Interesting Projects & Tools

- **oh-my-ouroboros — a self-refining Claude Code configuration harness that promotes repeated corrections into rules (10/29)**: When the same correction request repeats three or more times, it asks whether to promote it into a rule, warns when the CLAUDE.md and rules that get loaded on every commit grow past a size threshold, and splits frequently used rules from detailed policies into two tiers so the latter only load when needed. It ships with 13 agents, 32 skills, and 50 on-demand rules, under the MIT license. [GeekNews](https://news.hada.io/topic?id=36227)
- **Yenpo — a macOS app for properly reviewing code written by Claude Code and Codex (10/29)**: Built on the premise that scrolling through and approving a long AI-generated diff isn't real review, it reads your git repo directly to show diffs between AI-made commits and branch comparisons, and supports jump-to-definition and find-references through a local language server. Its read-only AI Reader shows which files it read, what it searched for, and down to the supporting line, and it works with no account or telemetry required — just your own AI provider key. [GeekNews](https://news.hada.io/topic?id=36217)
