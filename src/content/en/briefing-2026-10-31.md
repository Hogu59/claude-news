## New Features & Practical Usage

### VS Code and Claude Desktop's Code tab now auto-compact idle conversations (v2.1.314)

**Leave a conversation over 200K tokens idle for a while, and the Code tab in VS Code or Claude Desktop will now summarize it automatically — so when the prompt cache has expired and you send your next message, that summary gets used right away.** Previously, returning to a long conversation that had sat idle meant reprocessing the entire cache-expired conversation from scratch, which made the first response slower and more expensive.

**If you're in the habit of juggling multiple tasks during the day while keeping a long conversation open in VS Code's or Claude Desktop's Code tab, you can expect a lighter first response when you come back to it starting with v2.1.314.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Developer Workflow Tips

### Background agent status-summary calls were consuming 15-20% of total tokens (GeekNews, 10/29)

**An analysis found that Claude Code resends a background agent's entire conversation history to the model roughly every 30 seconds, asking it to "describe the most recent action in 3-5 words" — and that these status-summary calls account for 15-20% of total token usage.** The result is used only for the status line in the agent panel, yet there's no setting to turn it off; the author shared a script that blocks the summary timer without patching the binary, but noted it relies on internal strings and needs to be re-verified after every update.

**If your workflow involves running multiple background or subagents simultaneously for long stretches, it's worth keeping in mind how much these status-summary calls might be contributing to your usage limit consumption, and checking the actual share with `/usage`.** [GeekNews](https://news.hada.io/topic?id=36213)

### `permissions.blockWritesOutsideWorkingDirectories` can now block writes outside the working directory in every permission mode (v2.1.314)

**A new setting has been added that, when enabled, makes Write, Edit, and NotebookEdit always refuse to write to paths outside the working directory, regardless of permission mode.** Previously, modes with looser approval flows — like bypass permissions mode — left room for files outside the working directory to get modified.

```json
// settings.json
{
  "permissions": {
    "blockWritesOutsideWorkingDirectories": true
  }
}
```

**If you're running auto mode or bypass permissions mode across multiple repositories or an entire home directory, this setting is worth turning on to categorically prevent accidental edits to files outside your intended working directory.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Fixed background diff refreshes holding a git index lock that caused concurrent git commands to fail (v2.1.314)

**When Claude Code refreshes a diff in the background to display changes, it briefly held the repository's index lock — so running a git command in a terminal at that same moment could fail with "Unable to create '.git/index.lock': File exists." This has now been fixed.** Previously, running `git status` or `git commit` in a separate terminal while Claude Code was working could trigger a confusing lock error.

**If you frequently run git commands in a separate terminal alongside an active Claude Code session, you no longer need to worry about this kind of lock conflict starting with v2.1.314.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Security & Limitations

### Claude service status — no incidents from 10/29 through 10/31, everything operational

**A direct check of the official status.claude.com shows "No incidents reported" for 10/29, 10/30, and 10/31, with claude.ai, Claude Console, Claude API, Claude Code, Claude Cowork, and Claude for Government all showing Operational.** The most recent incident was the Google Calendar and Gmail connector errors on 10/28, which have since been fully resolved.

**If you ran into errors in the past few days, they should already be resolved — so if something goes wrong today, it's reasonable to check your local configuration or network first.** [Claude Status](https://status.claude.com)

### Fixed sandbox protections not applying to worktrees entered via `claude -p --resume` and `--continue` (v2.1.314)

**A bug where sandbox protections weren't applied when entering a worktree non-interactively via `claude -p --resume` or `--continue` has been fixed.** Previously, sandbox constraints that held in interactive sessions could fail to apply when resuming the same worktree non-interactively.

**If you're resuming worktrees that handle untrusted code via `claude -p --resume` or `--continue` in CI or scripts, it's worth upgrading to v2.1.314 and double-checking that the sandbox is actually being enforced.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Ecosystem & Plugins

### korea-data-mcp — an MCP server that keeps AI agents from misreading Korean public APIs (10/30)

**This server bundles the DART, Korea's Public Data Portal, and National Law Information Center APIs into a single MCP server, handling server-side the pitfalls AI agents commonly fall into when querying corporate, real-estate, and legal data — like confusing semi-annual cumulative figures with quarterly ones, mixing cancelled contracts into real transaction prices, or dealing with changed administrative district codes.** It provides 15 tools covering corporate disclosures and financial statements, apartment sale transaction prices, and statute and case law search, and runs entirely on your own machine.

**If you're building a Claude Code workflow around analyzing Korean companies or handling real-estate and legal data, connecting this MCP server is more efficient than handling the public API's quirks yourself every time.** [GeekNews](https://news.hada.io/topic?id=36277)

**Blackstone put out an outlook suggesting Anthropic may not achieve an investment-grade credit rating even after going public, followed by opinions that AI research companies have structurally fragile and speculative financial structures.** A counterargument also surfaced, however, noting that high risk isn't necessarily the same as a bad investment.

## Minor Changes

All of the items below are from **v2.1.314** (10/30).

- **Microsoft Foundry sessions now automatically fall back to an older model in the same family** when a resource has no deployment for the default Sonnet, Opus, or Haiku model.
- **Fixed image-heavy conversations on Bedrock failing on every turn, with `/compact` also blocked by "Input is too long."** — old images are now dropped and the conversation compacted before continuing.
- **Fixed TLS connections failing with `UNABLE_TO_GET_ISSUER_CERT`** when the system certificate store held a renewed root certificate cross-signed with an older root.
- **Fixed "auto-continue on usage limit" continuing past three turns without prompting** when turns were restarted by a `/goal` check-in or a background/scheduled job.
- **Fixed WebFetch in Cowork cloud sessions silently truncating PDF text past 100,000 characters** — it now reports how much was missed and where to continue reading.
- **Fixed compaction failing or looping when a PreCompact hook's output was very long** — each hook's output is now truncated at 10,000 characters.
- **Added a `groups` list to Claude apps gateway upstreams**, so that even during failover, only developers in the specified IdP groups are routed to that upstream.
