## Developer Workflow Tips

### A model-selection strategy: default to Opus 5.5, escalate to Fable 5.2 (11/9)

**Developer Addy Osmani suggests that, among the four generally available models — Haiku 5.5, Sonnet 5.5, Opus 5.5, and Fable 5.2 — most work should start with Opus 5.5 at `medium` effort, then be dialed up or down based on difficulty and cost.** Before switching models, raise the effort level first; only move to a higher-tier model at lower effort if that's still not enough. Sonnet 5.5 fits well-scoped bug fixes and repetitive work, Haiku 5.5 suits high-volume tasks like classification and routing as well as subagents, and Fable 5.2 should be reserved for the hardest jobs — large-scale refactors, architecture design, and orchestrating many subagents — where even Opus 5.5 at `high` falls short.

```markdown
---
name: log-reader
description: Reads test output and logs, and reports each failing case. Use after a test run.
tools: Read, Grep, Glob, Bash
model: haiku
---
```

Osmani explains that for tasks where results can be verified automatically, running everything at `low` effort first and only re-running failures at `high` is more efficient than running everything at `high`. On the same SWE-bench Pro subset, running everything at `high` passed 95.3% of tasks at $0.29 per task, while this approach passed about 97% at roughly $0.17 per task.

**If you've been mixing models in Claude Code and judging by feel when to escalate, this escalation order — add verification, raise effort, then raise model — along with offloading subtasks like log reading to Haiku subagents, is worth adopting directly.** [claude.dev](https://claude.dev/blog/which-claude-model-should-you-build-with/)

### JPMorganChase as a case study in scaling Claude Code across a large organization (11/9)

**Anthropic's official blog introduced how JPMorganChase expanded Claude Code access beyond engineering into commercial and investment banking, infrastructure and operations, security, product, risk and controls, and asset and wealth management.** The core of it is control design. Claude Code runs only on the company's own infrastructure, inside isolated environments such as the container-based development platform Devspace, and the agent never gets direct access to employee credentials or internal systems. Access expands only in stages, each new Claude model has to clear its own approval process before use, and thousands of automated tests and approval gates issue a pass/halt verdict on every change — the pipeline is built so Claude can never approve its own work.

```text
Isolated environment (Devspace) → staged permission expansion → per-model approval → automated gates (pass/halt, no self-approval)
```

**This comes from Anthropic's own announcement, with no independent confirmation from the bank, and it runs in the opposite direction from Goldman Sachs, which — as covered in the 11/9 briefing — narrowed Claude Code access for bankers and traders down to engineers only.** For anyone looking to expand Claude Code across an entire organization, this suggests that putting isolated environments, staged permissions, and automated gates in place first is how you widen access while still keeping accountability intact. [Anthropic's official case study](https://claude.com/resources/articles/jpmorganchase-expands-claude-code)

## Ecosystem & Plugins

### Anthropic officially launches its Nasdaq IPO roadshow — $70-78 per share, 825 million shares (11/10)

**Anthropic, PBC announced it has officially launched the roadshow for its Class A common stock IPO.** The offering totals 825 million shares: roughly 801.35 million shares issued directly by Anthropic and about 23.64 million shares sold by existing shareholders, with Anthropic receiving no proceeds from the shareholder-sold portion. The proposed price range is $70-78 per share, and underwriters have been granted an over-allotment option to purchase up to an additional 123.75 million shares within 30 days. The company has applied to list on the Nasdaq Global Select Market under the ticker "ANT." Its registration statement has been filed with the SEC but has not yet become effective, so no offers to buy can be accepted at this stage. A preliminary prospectus is available from joint lead underwriters Goldman Sachs and Morgan Stanley.

**If your organization runs Anthropic products including Claude Code, this roadshow launch marks the point where the IPO has moved into concrete pricing and share-count territory — worth tracking as the next step after the valuation-markdown review and S-1 filing covered in the 11/6-11/9 briefings.** [Anthropic's official announcement](https://www.anthropic.com/news/roadshow-launch)

### Atuin Threads — search and resume Claude Code/Codex agent sessions scattered across multiple machines from one place (11/12)

**Atuin, known as a terminal history tool, added a Threads feature in version 18.24 that lets you search and resume coding agent sessions scattered across different devices and tools.** The supported list explicitly includes Claude Code, Codex, Pi, Omp, and OpenCode, and it can auto-install an MCP server for Claude so agents can reference past sessions directly through MCP. Session collection is opt-in, syncing uses end-to-end encryption, and team-level session sharing is in development.

**If you've ever started something in Claude Code on a dev server and then struggled to pick it up again on your laptop because you couldn't remember what you did where, this feature lets you search sessions across all your machines from a single search box.** [Original blog post](https://blog.atuin.sh/threads-agent-sessions/) · [GeekNews](https://news.hada.io/topic?id=37009)

## Minor Changes

Below are items from **v2.1.321** (11/9) that previous briefings haven't covered yet.

- **Fixed an issue where a folder containing project skills, commands, and agents would stay missing for the rest of the session if it briefly disappeared mid-session (e.g., via `git stash`) and then reappeared.** The same fix applies after entering a worktree.
- **Fixed an issue in `/config` where the default permission mode showed as Manual when a new session actually started in auto mode.** Pressing Space on "Auto (default)" now saves as Don't Ask instead of Plan.
- **Starting Claude Code from an IDE terminal no longer installs or updates the IDE extension.** To install or update the extension, use `/ide` from an external terminal or the editor's extensions view instead.
- **Headless sessions now detect file changes in the `.claude/skills` folder and reload mods accordingly.** Set `CLAUDE_CODE_PLUGIN_DIR_WATCH=0` to turn this off.
- **Fixed an issue where, if the conversation got compacted after a turn started in auto mode, the report from a background subagent that turn had been waiting on would get lost.**
- **Fixed an issue where, when the first model stalled before responding and fell back to a fallback model, the fallback model would either refuse the request or say "the response was interrupted."**
