## New Features & Practical Usage

### `/usage` now breaks down Loops (v2.1.243)

**`/usage` gained a Loops section showing run count, total tokens, tokens per run, and last-run time for each loop**, making it easy to **spot a `/loop` job that's running away or firing far more often than expected**.

```bash
/usage
# Check each loop's run count, cumulative tokens, average tokens per run, and last-run time in the Loops section
```

**If you're keeping several `/loop` jobs running continuously, this view lets you immediately flag whichever loop is burning through more tokens than expected.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### `promptCacheTtl` and `subagentPromptCacheTtl` — separate cache lifetimes for the main conversation and subagents (v2.1.243)

**Two new settings let API key and cloud-provider users keep a 1-hour prompt cache on the main conversation while subagents stay on a 5-minute cache.** Previously, cache lifetime was a single setting shared by the main conversation and subagents alike; now **you can tune cache hit rates for a long-running main session independently from a subagent's inherently short lifecycle**.

**If your workflow keeps a long-lived main session alive while spinning up subagents frequently, it's worth trying a combination that trims main-conversation caching costs while leaving subagents on their existing short cache.** For exact configuration syntax, checking the [full release notes](https://github.com/anthropics/claude-code/releases) and official docs is the safer route.

### Sign in with your Anthropic Console account — no API key required (v2.1.243)

```bash
/login
# Choosing "Sign in with your Console account" (recommended) lets you log in without generating a new API key
```

**`/login` now lets organizations that don't permit API key issuance at all sign in directly with an Anthropic Console account.** A companion **`modelPicker` setting lets an org curate exactly which models appear in the `/model` picker, along with their order and labels** (including Vertex and Bedrock IDs) — useful for **organizations that want their whole team restricted to approved models only**.

## Developer Workflow Tips

### How many AI code review passes is enough? ~400 measured calls (8/24)

**In a write-review-fix loop, this experiment measured across roughly 400 LLM calls whether running additional review passes actually helps.** The data shows a **diminishing-returns curve: the first review catches most issues, and each additional pass turns up new problems far more slowly**.

**Practical takeaway**: if you're building a pipeline that has Claude Code write code and then loops automated review passes over it, **knowing roughly which pass stops turning up new issues lets you cut unnecessary review calls and their cost.** [GeekNews](https://news.hada.io/topic?id=32842)

### Raising the quality of LLM-generated code with agent.md (8/24)

**By consolidating code review guidance that used to be repeated every session into a single `agent.md` file that gets auto-injected into the prompt, this developer saw a noticeable drop in spaghetti code and missing comments/structure.** The write-up notes that **generated code that couldn't even compile in 2025 can now handle complex implementations and bug analysis in 2026 — but structure and documentation gaps, not capability, were what actually kept it out of production**.

**Claude Code's `CLAUDE.md` works the same way.** If you have style or structure rules you keep retyping into prompts, **writing them into `CLAUDE.md` once is far more efficient than re-explaining them every session.** [GeekNews](https://news.hada.io/topic?id=32833)

### The sandboxed Bash tool no longer previews its allowed-host list (v2.1.243)

**Until now, the sandboxed Bash tool's prompt listed accessible network hosts up front. That's changed: instead of assuming a host not on the list is automatically blocked, Claude now attempts the request and asks for approval on new hosts as they come up.**

**If you've been running tasks that call external APIs from a sandboxed environment, note that requests which previously never got attempted because they weren't on the visible allow-list may now surface as approval prompts instead.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Security & Limitations

### Claude service status — three incidents on 8/24 (including one Major), report spike, stable again as of 8/25

**Querying the official Claude Status API (status.claude.com) directly** shows three new incidents were logged on 8/24 alone.

- **Elevated errors for multiple models** — **2026-08-24 05:06-08:30 UTC (about 3 hours 24 minutes)**, impact **Major**, Resolved
- **Errors logging into Claude.ai** — 2026-08-24 17:12-17:16 UTC (about 4 minutes), impact Minor, Resolved
- **Issues logging into Claude.ai** — 2026-08-24 20:11-20:26 UTC (about 15 minutes), impact Minor, Resolved

All three incidents **affected claude.ai, the Claude API, Claude Code, and Claude Cowork**, breaking a **stretch of two straight incident-free days (8/22-8/23) with a shaky 8/24**. **As of 8/25, no new incidents have been logged and all systems are operational.**

**StatusGator shows 236 reports in the last 24 hours** — a sharp jump from **the week's low of 4 reports that held through 8/22-8/23** — most likely driven by the roughly 3-hour-24-minute Major incident on the morning of 8/24. [Claude Status](https://status.claude.com/history) · [StatusGator](https://statusgator.com/services/claude)

### Sonnet 5 pricing switched from introductory to standard — the September hike scenario needs a second look (v2.1.243)

**In v2.1.243, the `/model` picker and the bundled `claude-api` skill now display Sonnet 5's $2 input / $10 output per million tokens as "standard pricing" rather than a "limited-time promotion."**

**What this briefing has repeatedly reported over the past several days** was that this pricing was an introductory rate expiring August 31, set to rise to $3 input / $15 output (+50%) starting September 1. **This changelog entry directly contradicts that premise** — with $2/$10 now labeled as official standard pricing, **the planned 50% increase appears to have been withdrawn, or at minimum the labeling has changed ahead of any pricing update**. That said, **no separate official blog post or pricing-page update has been confirmed yet, so it's too early to treat one changelog line as conclusive.**

**If you've been budgeting Sonnet 5 costs around a September price increase, it's worth rechecking the official pricing page and adjusting your plan.** **The 50% weekly usage boost is still scheduled to end August 31, putting it at D-6.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Minor Changes

All items below are from **v2.1.243**.

- **Native install and auto-update download sizes shrink thanks to zstd compression** — roughly 340MB down to about 75MB on Linux x64.
- **Per-session memory usage drops by roughly 40-70MB** — code now loads on demand instead of keeping the entire bundle resident.
- **Peak memory usage in long-running sessions also improves** — the runtime now garbage-collects earlier as the heap grows.
- **Startup time improves** — sandbox and MCP initialization no longer block the first screen render, subcommand registration is skipped on simple invocations, and workflow discovery, settings, and trust-store handling all got cheaper.
- **`/status` gains a "Skipped sources" line** — flags when a managed settings source (e.g. `managed-settings.json`) exists but was overridden by a higher-priority source and never applied.
- **`/mcp` and `/plugins` now show a `managed` badge** on claude.ai connectors whose authentication is controlled by the organization.
- **`/tasks` and the agent detail view now show the model and effort level a subagent ran with.**
- **On Bedrock, Vertex, Foundry, and in environments with telemetry disabled, `/model`, `/fast`, and `/effort` now apply immediately instead of waiting for the turn to finish.**
- **Consecutive no-op wakeups in `/loop` now collapse into a single line in the terminal instead of printing separately.**
- **macOS computer use now triggers the standard permission dialog for Finder access when clicking the desktop, Dock, or Finder windows, matching other apps.**
