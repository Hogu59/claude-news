## New Features & Practical Usage

### Claude Mods teammate API `agent.spawn` lands — along with a big batch of stability fixes just two days after launch (v2.1.289)

**Plugins can now spawn teammate agents directly with the new `agent.spawn` API, paired with agent IDs that stay consistent across plugin hook events and idle/waiting state lookups via `$.agent.list()`.** Since Claude Mods — which shipped on 10/1 — is an extension point that reaches deep into Claude Code's internals, this same release also bundles roughly 20 stability fixes: mod-drawn UI freezing or crashing the whole session, plugin hot-reload failures, and commands hiding behind environment-variable prefixes that slipped past permission-deny rules.

```bash
# Spawn a teammate agent from mod/plugin code
$.agent.spawn(...)
```

**If you're building a mod that leans on side agents or teammates, it's worth trying patterns that coordinate multiple agents through `agent.spawn`, and if you're already running Mods, this update should make a noticeable dent in flakiness.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Developer Workflow Tips

### How to get the most out of Opus 5.5 in Claude and Claude Code (10/4)

**Opus 5.5 responds better when you hand it the whole task up front — the goal, completion criteria, and the conditions under which it should pause and ask — rather than walking it through instructions step by step.** It holds onto long, multi-stage work without losing the thread better than previous Opus versions did, letting early testers hand off hours-long coding tasks with minimal supervision. It also runs through its own reasoning before every response by default, so adding instructions like "think carefully" doesn't noticeably change how deeply it reasons.

**If you're running Opus 5.5 on long autonomous tasks, it's worth dropping the habit of micromanaging each step and instead front-loading the goal, completion criteria, and escalation conditions in one go — that's where the model plays to its strengths.** [GeekNews](https://news.hada.io/topic?id=34734)

## Security & Limitations

### Claude service status — all operational as of 10/4, three days stable since the 10/1 credit-delay incident (10/4)

**Checking status.claude.com directly: as of 10/4, claude.ai, Claude Console, Claude API, Claude Code, Claude Cowork, and Claude for Government are all Operational, with no active incidents.** The most recent incident — a 10/1 delay in platform credits posting — was resolved the same day at 18:23 UTC, and it's been three incident-free days since.

**With all three incidents from the past 90 days (the 9/22 multi-model errors, the 9/29 error spike, and the 10/1 credit delay) resolved within the same day they occurred, there's no need for any special action right now — business as usual.** [Claude Status](https://status.claude.com)

### D.C. Circuit Court of Appeals upholds the Pentagon's exclusion of Anthropic's Claude (9/25)

**The U.S. Court of Appeals for the D.C. Circuit ruled 2-1 to uphold the Department of Defense's decision last March to exclude Anthropic's Claude models from its defense supply chain.** The court found that Anthropic's built-in training restrictions — refusing to support tasks like mass domestic surveillance or fully autonomous weapons — amounted to the kind of interference with model design and operation the relevant statute addresses, and that the DoD had reasonable grounds to treat this as a national security risk. Anthropic had sued after refusing the DoD's demand to lift these restrictions, but the court didn't side with them.

**If you're selling Claude to government or defense-adjacent organizations, or courting customers in that space, this appellate ruling reconfirms that keeping the safety restrictions in place means U.S. defense supply-chain access stays off the table for now.** [The Hill](https://thehill.com/policy/technology/6111414-dc-circuit-upholds-anthropic-blacklist/)

## Minor Changes

All of the following are from **v2.1.289** (10/3).

- **Fixed a bug where `Read` deny rules didn't apply to files that were @-mentioned, edited, or selected in the IDE via a symlink.**
- **Fixed two issues where Bash commands could dodge deny/ask rules: values expanded after an environment-variable prefix (e.g. `TZ="$HOME" rm -rf build`) hid the real command, and bare variable assignments placed before a command skipped rule checks under sandbox auto-allow.**
- **Fixed `plugin list`, `plugin eval`, and `plugin update` showing stale copies for plugins installed from a local folder marketplace, plus a hot-reload issue with symlinked `--plugin-dir` paths.**
- **Fixed the terminal hanging — and published artifact pages freezing the viewer's browser tab — when a short code block contained many unclosed `<script>` tags.**
- **Improved load speed for large files opened in the plugin code panel** (syntax highlighting is now computed once at final width instead of repeatedly).
- **Fixed a bug where a user-installed plugin could override the login tool description of an org-managed MCP server.**

Teams running environments that spin huge numbers of containers up and down should keep an eye on this approach of treating OS behavior like a library, with no kernel changes required.
