## New Features & Practical Usage

### `ultrathink` in the VS Code chat panel now bumps effort to xhigh, just like the terminal (v2.1.316)

**In the terminal, typing `ultrathink` has long bumped that turn's effort to xhigh immediately and displayed it in rainbow colors — now the VS Code extension's chat panel does the same.** Previously, typing the same keyword in VS Code gave no visual way to confirm whether effort had actually increased or the rainbow styling had kicked in, unlike in the terminal.

```
# Type into the VS Code chat panel
ultrathink get to the root cause of this race condition, no matter how deep it goes
```

**If you bounce between the terminal and VS Code while using Claude Code, you can now trust that `ultrathink` bumps effort and displays the same way regardless of which one you're typing into.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Developer Workflow Tips

### SSL certificate error messages now point out likely causes (v2.1.316)

**When an SSL certificate error occurs, Claude Code now calls out common causes — like a server omitting its intermediate certificate — along with how to fix each one.** Previously, you'd often see nothing more than an error code like `UNABLE_TO_VERIFY_LEAF_SIGNATURE` and have to guess at the cause yourself.

**If Claude Code's network requests have ever been blocked by SSL errors in an environment using a corporate proxy or self-issued certificates, as of v2.1.316 you can now tell where to start looking just by reading the error message.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Specifying an unrecognized model with `/model <id>` now triggers a warning (v2.1.316)

**If you specify a model ID via `/model` that this version doesn't recognize, Claude Code now also warns you that auto-compact will assume a 200K-token context window.** Previously, specifying a custom deployment name or a stale model ID would pass silently, and auto-compact could end up triggering based on an assumption that didn't match the actual context window.

**If you're specifying a custom model ID directly via `/model` in an LLM gateway or self-hosted setup, it's worth checking whether this warning appears, to catch cases where auto-compact might be operating on a context-window assumption that doesn't match reality.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Fixed a Windows bug where Grep and Glob hung forever after timing out (v2.1.316)

**On Windows, Grep and Glob would sometimes wait indefinitely for a response when a search process was killed by a timeout but didn't actually terminate right away — that's now fixed.** Previously, a search timing out on a large repository could make the tool call itself appear to freeze entirely, sometimes forcing you to abort the session.

**If you've worked with large monorepos on Windows and seen Grep or Glob occasionally hang without responding, it's worth upgrading to v2.1.316 to confirm the issue is resolved.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Security & Limitations

### Claude service status — all systems normal on both 10/31 and 11/1, no incidents

**Checking the official status.claude.com directly: 10/31 shows "No incidents reported," 11/1 shows "No incidents reported today," and as of 11/2, claude.ai, the Claude API, Claude Code, Claude Console, Claude Cowork, and Claude for Government are all listed as "All Systems Operational."**

**If you ran into errors over the past few days, they appear to be fully resolved by now — so if something goes wrong today, it's more reasonable to check your local configuration or network setup first.** [Claude Status](https://status.claude.com)

### Fixed a bug where PowerShell hooks let some blocked commands through despite returning exit code 2 (v2.1.316)

**Fixed an issue where, if a command started with a type cast, `param`, `using`, or an attribute, a PowerShell hook's exit code 2 failed to actually block that command.** Previously, even if you'd set up a PreToolUse hook to block specific command patterns, the block could be silently bypassed whenever the command happened to start with one of these constructs.

**If you're relying on a PowerShell hook as a safety net to block dangerous commands, keep in mind that versions before v2.1.316 may have let commands starting with these constructs slip past that block — which is reason enough to prioritize upgrading.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Fixed a flaw where `--restricted` sessions could upload files outside the working directory (v2.1.316)

**Fixed a bug where, even with a session restricted via the `--restricted` flag, files outside the working directory could still be uploaded if the Read allow rules included paths outside it.** Previously, you might have assumed `--restricted` confined uploads to the working directory, when in practice the boundary could be broken depending on how your Read rules were configured.

**If you're using `--restricted` to limit upload scope while working with a sensitive repository, after upgrading to v2.1.316 it's also worth checking that your Read allow rules don't include any paths outside the working directory.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### A former Meta researcher testified to torrenting pirated books and later deleting them over the lawsuit (11/2)

**In Meta's copyright lawsuit over the Books3 dataset, testimony from former researcher Stephen Roller that he torrented and distributed pirated copies of books has become a key point of contention.** Meta countered that the testimony doesn't support the plaintiffs' interpretation, noting the copies in question were deleted from his personal computer more than two years after he left the company; the court has already ruled that training Llama on the books themselves qualifies as fair use, but how the BitTorrent downloads happened remains an unresolved core issue.

**As with the ruling on Anthropic's training on pirated books covered in the 10/28 briefing, lawsuits over how AI companies source their training data continue to play out across the industry — worth keeping in mind when adopting LLMs in an enterprise setting.** [GeekNews](https://news.hada.io/topic?id=36409)

## Ecosystem & Plugins

### Show GN: repo-transplant — a Claude Code plugin and MCP server for porting features from other repos into your project (11/1)

**Porting a feature from another open-source project into your own involves the hassle of tracing dependencies, adapting the code to your structure, and verifying it actually works — this plugin and MCP server analyzes the source repo's feature and ports it to fit your project's current tech stack.** To avoid blindly trusting AI-generated code, it focuses on verifying that changes followed an approved plan and that test results actually exist.

**If you regularly port features from other open-source projects into your own, this plugin's built-in plan-approval and test-verification steps are worth trying to bring structure to that process.** [GeekNews](https://news.hada.io/topic?id=36375)

### Show GN: memsearch-ko — a Claude Code memory search plugin that understands Korean queries (11/1)

**Once a Claude Code project's memory notes grow into the hundreds, they get hard to find when you phrase a query differently — unlike claude-mem, which relies on English-only embeddings, this plugin pre-indexes the meaning of your notes with the multilingual bge-m3 embedding model, so it can surface relevant notes even for Korean queries.** It runs on local Ollama, so there's no cost and your notes never leave your machine, and it's available either as a Claude Code plugin or as a standalone Python script.

**If you've been building up memory with Claude Code in Korean and found that English-embedding-based search misses the context, this plugin — free and fully local — is worth trying as an alternative.** [GeekNews](https://news.hada.io/topic?id=36364)

## Minor Changes

All of the following are from **v2.1.316** (10/31).

- **Fixed the Claude apps gateway not always checking a request's model name against `availableModels`, `deniedModels`, and `models`** — requesting a blocked model name now returns a 400 error that specifies which field caused it.
- **Fixed `claude auth login` being rejected in environments where managed settings require the Claude apps gateway** — the gateway login screen now appears in the terminal as expected.
- **Fixed prompts containing invisible characters requiring two presses of Enter to send** — plain-text prompts are now cleaned up and sent in a single press.
- **Fixed subagents woken by a background task or message inheriting their parent subagent's model instead of switching to the main model.**
- **Fixed the SDK's `register_repo_root` control request failing to load CLAUDE.md files from directories outside the working directory** (`CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1`).
- **[VS Code] Fixed the effort slider, Ultracode switch, and model name disappearing when a model setting carried a `[1m]` tag** (e.g., `opus[1m]`).
- **[Cloud sessions] A "Catching up…" line now appears when switching back to a cloud or Remote Control session whose messages are still syncing.**
