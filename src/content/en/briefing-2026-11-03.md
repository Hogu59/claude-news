## New Features & Practical Usage

### Code Review now shows findings as cards in cloud and Remote Control sessions too (v2.1.316)

**When you kick off `/code-review` from the Code tab in Claude Desktop or on the web, both cloud sessions and `claude remote-control` sessions now display findings as structured cards instead of a plain text list.** Until now, the terminal showed findings in easy-to-scan cards, but opening the same review in a cloud or Remote Control session meant scrolling through a long text list instead.

**If your team runs code reviews from cloud sessions in Claude Desktop or on the web, as of v2.1.316 you get the same severity-sorted cards you'd see in the terminal, which also makes it easier to share review results with teammates.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Developer Workflow Tips

### Zombie shell processes left behind on macOS/Linux when Claude Code exits on its own are gone (v2.1.316)

**Fixed an issue where running shell commands would survive on macOS and Linux after Claude Code terminated its own process — say, when credentials were rejected or a cloud session got archived.** Previously, if a session ended unexpectedly, any background commands it had launched stuck around, and you'd have to hunt them down with `ps` and clean them up yourself.

**If you've ever launched a long-running build or server process through the Bash tool and had the session abruptly end from a credential error or archiving, v2.1.316 saves you the hassle of manually tracking down and killing those leftover processes.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Multi-line bash aliases and hyphen-prefixed function names no longer break (v2.1.316, Git Bash excluded)

**Fixed an issue where bash aliases spanning multiple lines, or functions whose names started with a hyphen, would break or disappear entirely in the Bash tool's shell.** That said, the fix doesn't extend to Git Bash, so if you're using Git Bash on Windows, the same problem still applies.

```bash
# Previously broke or disappeared in the Bash tool
alias deploy='
  npm run build &&
  npm run test &&
  npm run deploy
'
-my-helper() { echo "multi-line alias and hyphenated function name"; }
```

**If your shell config defines multi-line aliases or hyphen-prefixed function names and you rely on them through Claude Code's Bash tool, it's worth checking that they now work as expected on macOS, Linux, and regular terminals as of v2.1.316. In Git Bash, though, you'll still need a separate workaround alias.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Clearer guidance from `/ultrareview` and cloud sessions when there's no GitHub remote (v2.1.316)

**When `/ultrareview`, cloud sessions, or cloud agents can't find a GitHub remote, they now point you specifically to create a repository at `https://github.com/new`, and `/ultrareview` no longer suggests `gh` commands that `gh` itself would reject.** Previously, using these features in a local repo with no remote could trigger unclear errors or suggest `gh` commands that failed when you actually ran them.

**If you're trying out `/ultrareview` or cloud sessions on a fresh project or a repo you haven't pushed to GitHub yet, v2.1.316 now tells you exactly where to create the repository.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Security & Limitations

### Claude service status — no incidents, all systems operational from 10/31 through 11/3

**A direct check of the official status.claude.com shows "No incidents reported" for every day from 10/31 through 11/3 (today), with claude.ai, Claude API, Claude Code, Claude Console, Claude Cowork, and Claude for Government all showing "All Systems Operational."** The most recent incident was a Google Calendar/Gmail connector error, resolved on 10/28.

**If you ran into connector or service errors in the past few days, they've all since been resolved — so if something goes wrong today, it's more reasonable to check your local setup or network first.** [Claude Status](https://status.claude.com)

### Signature verification added to server-managed settings for Team/Enterprise logins (v2.1.316)

**When logged in with a Team or Enterprise account, server-managed settings pulled from the Anthropic API are now applied immediately without a separate approval step — but if the locally cached copy of those settings fails signature verification, that cached copy gets rejected.** Previously, a locally cached copy of managed settings could be applied as-is even if it had been tampered with or corrupted, with no way to tell the difference.

**If your organization distributes Claude Code policy through managed settings, you can factor in that, as of v2.1.316, there's less risk of a corrupted or tampered local settings copy getting applied silently.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Minor Changes

All of the following are from **v2.1.316** (10/31).

- **Fixed an issue where built-in exception rules would disappear if `$defaults` was missing from the `autoMode.allow` list**, so the built-in exceptions from the host app's `--settings`, the first rule added via `/permissions`, and the ones pulled in from `/auto-mode-setup` are applied together again.
- **Fixed an issue where cloud sessions and scheduled cloud tasks weren't marked as "failed"** when auto mode stopped a turn because it didn't receive a safety assessment back from the server.
- **Fixed a case where `claude -p`'s text output didn't explain why auto mode had stopped a turn** while a background agent was still working.
- **Fixed an issue where the plugin MCP `headersHelper` script received a corrupted `CLAUDE_PLUGIN_ROOT` and server URL** when an environment variable with a credential-like name held a switch value such as `1`.
- **Fixed a rare issue where resuming a conversation wouldn't restore its plan** if `/clear` or `/resume` was run while part of that conversation was still being saved.
- **Fixed an issue where first-run setup would drop some words from the security notice and terminal configuration description** in narrow terminals.
- **[Windows] Fixed an issue where the Bash tool lost aliases and functions in Git Bash** when the rc file set `errexit`/`pipefail` and either defined only a winpty alias or none at all.
- **[Cloud sessions] Enterprise members can now add and remove network secrets directly from their own cloud environment** — previously, they could only view them.
