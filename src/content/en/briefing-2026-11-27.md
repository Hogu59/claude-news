## Developer Workflow Tips

### Google Cloud and Microsoft Foundry's sonnet/opus aliases now point to 5.5, and Foundry's default model is now Sonnet 5.5 (v2.1.332)

**Until now, using the `sonnet`/`opus` aliases on Google Cloud's Agent Platform and Microsoft Foundry could silently resolve to different model generations depending on the platform — starting with this release, the `sonnet` alias on both platforms now points to Sonnet 5.5, and Foundry's `opus` alias points to Opus 5.5.** Note that Amazon Bedrock's `sonnet` alias still points to Sonnet 4.5, so behavior now diverges across platforms. Microsoft Foundry's default model has also switched to Sonnet 5.5 — if you want to keep using a model you deployed yourself, you now need to either deploy it as `claude-sonnet-5-5` or set `ANTHROPIC_DEFAULT_SONNET_MODEL` to the model you want. On Google Cloud's Agent Platform, `sonnet` and background requests now read the `VERTEX_REGION_CLAUDE_5_5_SONNET` environment variable, and if that's unset while only the `_4_5` variable is set, it falls back to `CLOUD_ML_REGION` or `us-east5`. Additionally, terminal and VS Code sessions that moved to Sonnet 5 or 5.5 on Bedrock Mantle, Agent Platform, or Foundry now start in auto mode by default unless another mode is specified.

```bash
# To default to a specific deployed model on Microsoft Foundry instead of Sonnet 5.5
export ANTHROPIC_DEFAULT_SONNET_MODEL="my-deployed-model-name"

# To turn off auto mode auto-start on Bedrock Mantle, Agent Platform, or Foundry,
# add this to settings.json
{ "disableAutoMode": "disable" }
```

**If you're running Claude Code on Google Cloud or Microsoft Foundry and relying on the `sonnet`/`opus` aliases or Foundry's default model, this change may have silently shifted which model generation actually gets called — it's worth checking your `VERTEX_REGION_CLAUDE_5_5_SONNET` and `ANTHROPIC_DEFAULT_SONNET_MODEL` settings, and preemptively turning off auto mode via `disableAutoMode` if you'd rather not be switched over automatically.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### VS Code and Desktop now warn when part of a session fails to save or earlier messages fail to load (v2.1.332)

**Until now, if part of a session failed to save in the Code tab on VS Code or Desktop, or if reopening a session loaded it without earlier messages that the terminal still showed, there was no indication anything was wrong — starting with this release, both cases now surface an on-screen warning.** The save-failure warning also explains how to save on the spot using `/compact`, while the missing-messages warning simply brings VS Code and Desktop up to parity with information the terminal was already showing.

**If you've ever been working on a long conversation in the Code tab on VS Code or Desktop and felt context drop out for no apparent reason, as of v2.1.332 you can now tell right away from the on-screen warning whether it was a save failure or a message-loading issue, and respond with `/compact` accordingly.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### Plan mode now asks for approval instead of rejecting commands it can't judge the safety of (v2.1.332)

**Until now, when auto mode's safety checker in plan mode on Desktop's Code tab or VS Code couldn't determine whether a command was safe, it simply rejected it — starting with this release, plans entered from Manual or Accept Edits mode now request approval instead of being rejected outright.** Rather than unconditionally blocking commands whose safety is ambiguous, the default behavior now hands the final call to the human.

**If you've worked in plan mode on Desktop or VS Code and had your flow interrupted by a command getting rejected outright because its safety was uncertain, as of v2.1.332 you can now decide on approval right there — worth checking whether those previously-rejected commands were actually dangerous.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Ecosystem & Plugins

### Starting February 2027, Google will require Workspace AI agents to use its own MCP servers — Gmail sending remains partner-only (announced 11/24)

**Until now, AI agents accessing Google Workspace data like Gmail, Drive, and Calendar could call the REST API directly without restriction — but with the general availability launch of eight Workspace MCP servers on 11/24, Google also added a "Workspace AI Tools Addendum" to its terms, restricting direct REST calls from AI agents or AI-model-driven tools starting February 1, 2027.** After that date, agents calling REST directly will be forced onto the free Standard tier's quota (5,000 MCP requests per project per day, with a single Gmail search counted as 10) even if they're on a paid tier — the calls will still work, but will violate the terms of service. Deterministic scripts that don't use AI, like nightly backups or CRM syncs, can avoid this by using a separate OAuth client. The most glaring gap is Gmail: the public MCP server only supports search, read, draft creation, and label management, while sending, replying, forwarding, and editing drafts remain partner-only, and attachment downloads and filter management are also missing. Drive doesn't support move, share, or rename, and Calendar/Chat don't support creating or managing calendars or spaces. The paid Scaled tier will start billing for Gmail, Calendar, and Drive from April 1, 2027, and MCP gets billed from the very first request while REST still has a large free quota left — making the pricing itself look designed to push adoption toward MCP. Hacker News commenters pointed out that since Gmail supports SMTP, agents could easily route around the sending restriction, and criticized restricting sending to partners only — even though MCP's elicitation feature could be used to get user confirmation before sending — as looking more like a business decision than a safety one; the discussion also turned to alternatives like Microsoft 365, Fastmail, and self-hosted IMAP.

**If you're running a Claude Code agent or your own automation that connects to Google Workspace (Gmail, Drive, Calendar, etc.) via MCP, direct REST calls will be forcibly downgraded to the free quota after February 1, 2027 — it's worth planning your migration to the official MCP servers now, and checking alternatives like SMTP for features such as sending mail that remain partner-only.** [Source](https://techstackups.com/articles/google-workspace-ai-agents-mcp/) · [GeekNews](https://news.hada.io/topic?id=37919)

- **Speculation that OpenAI's latest models, Astra 6.2 and Sol 6.2, may have entered a cost-control mode (11/27)**: Running head-to-head matches through the author's own agent-duel system, Astra 6 and Sol 6.1 used a normal level of reasoning, but starting with version 6.2, output and reasoning tokens dropped noticeably, with the author claiming statistically significant differences (output token p-values of 0.0055 and 0.022, reasoning token p-values of 0.00013 and 0.0064). [Source](https://micjm.com/blog/openai-is-in-cost-control-mode/) · [GeekNews](https://news.hada.io/topic?id=37922)
- **Google's Cogentic agent framework and Gemini formally verified in Lean an integer-factorization algorithm with no unproven assumptions (11/27)**: It's a Las Vegas algorithm that fully factors an arbitrary integer N in subexponential time (L_N[1/3, 105]), verifying each prime factor with an AKS primality test, with the entire proof formalized using only Lean 4 and Mathlib. Both the paper and the formalization were written by Cogentic, Google Research's agent framework for mathematical discovery, running on Gemini 4, with the only human involvement being a single initial prompt. It was emphasized that this is only an upper-bound proof, and doesn't mean factorization is in polynomial time (P) or has become cryptographically easier. Commenters noted that this L_N[1/3] bound is already roughly what the General Number Field Sieve (GNFS) achieves empirically, so it poses no real threat to RSA — factoring 1024-bit RSA still takes roughly 500,000 core-years — and calculated that the constant term (105) makes the algorithm about e^103 times slower, exponentially, than the best existing algorithm (1.923). The article's related-reading list also links to the 11/26 briefing's coverage of Anthropic's compressed Lean proof of the Generalized Riemann Hypothesis, highlighting that AI-assisted formal mathematics is advancing at both Anthropic and Google simultaneously. ## Minor Changes

All of the following are from **v2.1.332** (11/25), items not already covered in the 11/26 briefing or above.

- **Added an "Always deliver" option to the confirmation prompt for pending messages from other sessions**, so you can receive future messages right away instead of choosing every time.
- **Added an OpenTelemetry `assistant_response` event for text Claude sends via SendUserMessage or Cowork's message tool**, so observability pipelines can aggregate response logging directly once it's enabled.
- **Fixed an issue where, for an interrupted background agent with unread subagent reports, pressing Ctrl+C at the prompt would start a new turn or fail to exit even after pressing it twice.**
- **Fixed an issue where voice input text over 10,000 characters would disappear.**
- **Fixed an issue on macOS where Esc wouldn't stop computer use while a Claude Code window or an allow-listed app was in the foreground** — Esc aimed at that app's popup now stops computer use itself.
- **Fixed an issue where idle compaction was being skipped for subscribers with plenty of weekly usage limit remaining.**
- **Fixed an issue where ordinary responses starting with "You've used" or "You've hit your" were incorrectly displayed as red usage-limit errors.**
- **Fixed an issue where Grep's `-o` flag would miss an empty match at the end of a file that has no trailing newline.**

- **Bypassing iOS Safari's 60 FPS Limit With Nothing but Web Tech (11/25)**: Even on a 120Hz iPhone, Safari caps `requestAnimationFrame` and touch events at 60Hz unless you flip a developer flag — but scrolling, handled by the compositor thread, isn't subject to that cap, and this project builds on that gap. It uses native scroll inertia and bounce as an input controller, combines `MessageChannel` and `setTimeout` timed to vsync to read roughly 90 unique positions per second, nudges ProMotion into its 120Hz mode with a hidden scroller, and skips main-thread rendering with `OffscreenCanvas` — reaching an average of 118fps (versus pointer events pinned at 60fps) measured over a 3-second drag filmed at 240fps on an iPhone 18 Pro. The author cautions against rebuilding an entire app this way, acknowledging the technique depends on current WebKit behavior and that Apple could block it without even violating the HTML spec. Commenters praised the WebKit source-diving itself as valuable, while noting the canvas-based version is noticeably slower on Android. If you've ever hit the 60fps wall on mobile web, this is a concrete look at where that limit comes from and how far you can push around it. ## Interesting Projects & Tools

- **Dot Buddy — a Mac desktop dot-pet that tells you when a Claude Code session ends or has a question (11/26)**: Built out of the problem that when you have several Claude Code terminal tabs open at once, it's easy to lose track of which session just finished. A pixel character wanders around the top or bottom of your screen, pops up a speech bubble when a session ends, and clicking it jumps straight to that terminal tab; while an agent is working it taps away on a tiny laptop, and a question mark appears when it has a question for you. It only reads the session files Claude Code already writes, without touching hooks or settings, and other agents like Codex, Gemini CLI, opencode, and Aider can be supported with just a single hook command call. Six characters ship by default, with custom PNGs and community characters downloadable from an in-app menu, though jumping to the exact terminal tab only works with cmux, Terminal, and iTerm2. It's written in Swift with no external dependencies and is MIT-licensed. If you've been running several Claude Code terminals at once and manually checking which session just finished, this is worth installing once and letting a corner of your screen handle the alerts. [GitHub](https://github.com/doldoldol21/dot-buddy) · [GeekNews](https://news.hada.io/topic?id=37877)
- **cysUML — an MCP server that draws UML at AI-specified coordinates and checks for overlaps (11/26)**: Built to address the problem that PlantUML and Mermaid auto-layout everything, so adding a single class can rearrange an entire diagram — this MCP server instead draws exactly the coordinates the AI assistant specifies. For class, package, component, use case, state, and activity diagrams, the assistant specifies coordinates directly; for sequence diagrams, you just supply participants, message order, and frames (loop/opt/alt/ref) and cysUML computes the positions itself. If boxes overlap or a line crosses a box or text, validation fails and it reports exactly which element is the problem and how to fix it, forcing the assistant to redraw until it passes. Install it with `claude mcp add cysuml -- uvx cysuml`; it's also published on PyPI and the official MCP registry, though it currently only supports PNG output and is still missing some UML elements like fork/join and asynchronous messages. If you've used Claude Code to draw UML for design docs and had to keep fixing the layout every time it shifted, this MCP server's fixed coordinates could save you that trouble. [GitHub](https://github.com/yschoi9733/cysUML) · [GeekNews](https://news.hada.io/topic?id=37895)
