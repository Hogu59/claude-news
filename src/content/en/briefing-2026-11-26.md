# Claude Code Daily Briefing - 2026-11-26

## Release Summary

| Version | Date | Key Changes |
|------|------|----------|
| **v2.1.332** | 11/25 | Skills shipped by MCP servers now show as `server:skill` (beta), new `PreSkillShellCommand` hook added, Cyber Verification Program rating now shown in the startup header, plus hundreds of other feature and stability fixes |
| v2.1.331 | 11/23 | Added Code Mode support for Bedrock, GCP Agent Platform, Microsoft Foundry, and AWS Claude Platform terminal sessions, added an API connectivity check to `claude doctor`, and more (covered in the 11/24 briefing) |

**Just two days after v2.1.331 (11/23), v2.1.332 shipped on 11/25.** The standout additions are skills shipped by MCP servers now appearing directly in the `/` menu, and a new hook that can intercept and deny inline shell commands embedded in skills and commands. The release also bundles hundreds of stability fixes, including one where a failed login save was incorrectly reported as a success, a hang during compaction, and reconnection issues with SSE MCP servers.

## New Features & Practical Usage

### A beta feature for installing Claude artifacts as standalone Mac and Windows desktop apps has launched (11/24)

**Until now, artifacts you built with Claude could only be opened inside Claude, but Anthropic's official guide has introduced a beta feature that installs an artifact as a standalone Mac or Windows app with its own icon and window.** Installed apps can be shared with others, automatically update whenever the original artifact changes, and can send notifications or add entries to the menu bar or system tray. The feature is available on all plans, is on by default for Team (though full computer access is off by default), and must be enabled by the owner on Enterprise. Apps start with browser-level permissions, but you can grant "full computer access" to apps you created yourself (or, on Team and Enterprise, apps created by other members of your organization), which lets the app run programs or read, modify, and delete files without asking each time. Some artifacts, such as Claude Docs, Slides, and Sheets, can't be installed, the feature isn't available for HIPAA-ready organizations or hybrid deployments, and because Anthropic doesn't review apps before installation, the guide recommends granting full access only to apps you trust.

```text
1. Describe the app you want to Claude
2. Run it as an artifact to confirm it works
3. Open the Share menu and click "Install as app"
   → Creates a standalone app with its own window and icon, which auto-updates whenever the original is edited
```

**If you've been using artifacts as in-house tools or personal utilities, it's now worth installing them as standalone apps instead of keeping a Claude window open, so you can take advantage of menu bar integration and notifications — just keep full computer access limited to apps you built yourself or otherwise trust.** [Anthropic's official guide](https://claude.com/resources/articles/install-as-app)

## Developer Workflow Tips

### Skills shipped by MCP servers now appear directly in the `/` menu as `server:skill` (beta, v2.1.332)

**The Skills over MCP announcement covered in the 11/24 briefing — where a server bundles a multi-step task guide as a skill — made it into an actual client release just a day later in v2.1.332: skills shipped by an MCP server now show up in the `/` menu tagged as `server:skill`, while skills not tied to a server keep their original names.** The turnaround from announcement to shipping feature took just one day, and now you can tell which server a skill came from just by looking at its name.

**If you connect multiple MCP servers and have had trouble telling which server a given skill came from, once you're on v2.1.332 the `server:skill` prefix in the `/` menu should make that immediately clear.** [Full release notes](https://github.com/anthropics/claude-code/releases)

### A new `PreSkillShellCommand` hook can intercept and deny inline shell commands in skills and commands (v2.1.332)

**Previously, inline shell commands embedded inside a skill or custom command would simply run the moment it loaded; starting with this release, the new `PreSkillShellCommand` hook event lets you intercept and deny that execution.** Note that on versions prior to 2.1.331, a startup dialog appears if a settings file has this hook registered by name.

```json
// Register a PreSkillShellCommand hook in settings.json
// to inspect and deny inline shell commands when a skill or command loads
{
  "hooks": {
    "PreSkillShellCommand": [
      { "hooks": [{ "type": "command", "command": "/path/to/validator.sh" }] }
    ]
  }
}
```

**If your organization allows installing skills or plugins from unclear sources, it's worth adding a `PreSkillShellCommand` hook as a safeguard that inspects inline shell commands at load time.** [Full release notes](https://github.com/anthropics/claude-code/releases)

## Security & Limitations

### Claude service status — 11/25 saw a 24-minute multi-model error incident (resolved); M365 add-in issue still unresolved on day two; claude.ai Degraded Performance for a second day

**According to the official status.claude.com, there was a 24-minute incident between 04:52 and 05:16 UTC on 11/25 with elevated errors across several Claude models, including Claude Fable 5.2, Mythos 5.2, Opus 5.5, Sonnet 5.5, and Haiku 5.5; the incident has since been resolved.** The Claude for Microsoft 365 add-in missing issue for personal Microsoft account users on Mac Excel, Word, and PowerPoint, covered in the 11/24 briefing, was listed as "under investigation" at the time; as of today's update (11/25, 20:21 UTC), the cause has now been identified and is being worked through with the upstream provider, though it remains unresolved. The claude.ai component has shown Degraded Performance for a second day running since 11/25, with no additional explanation attached. All other components, including Claude Code, are listed as Operational.

**If you use the Claude for Microsoft 365 add-in on Mac with a personal account, the cause has been identified but a fix isn't out yet, so it's worth using the office.com web version as a stopgap in the meantime — and it's also worth keeping an eye on claude.ai's Degraded Performance status, which has now persisted for two days.** [Claude Status](https://status.claude.com)

## Ecosystem & Plugins

### A new report finds enterprise AI spend grew 5.4x in a year, reaching an annualized $176.8 billion (November)

**According to Menlo Ventures' "2026 The State of Enterprise AI" report, enterprise AI usage spend reached an annualized ~$176.8 billion as of September 2026, up 5.4x year over year, with Anthropic, OpenAI, and Google together accounting for 69% of total usage spend.** Coding and enterprise chatbots made up 76% of the $77.3 billion application market, and within coding specifically, AI-native vendors captured 96% of share — a sharp contrast with IT, data science, and HR, where incumbent software vendors still hold strong. Open-source models' share of tokens rose from 11% to 19%, but their share of spend actually fell from 6% to 4% due to falling prices, and the report notes that 55% of incremental spend is coming from new budgets rather than replacing existing software, meaning the market itself is expanding. On average, enterprises spent about 2.5x their original planned budget, agents now generate 80% of OpenRouter tokens, and spend is scaling with workload rather than headcount. GeekNews commenters were surprised that the combined share of the three leading vendors was "only" 69%, and wondered how continued improvements to Gemini might reshape that share going forward.

**If your organization is budgeting for coding agents like Claude Code, this report's figures — a 96% share for AI-native vendors in coding and enterprises overspending their plans by roughly 2.5x on average — are worth citing as grounds for not underestimating your own budget.** [Menlo Ventures](https://menlovc.com/perspective/2026-the-state-of-enterprise-ai/) · [GeekNews](https://news.hada.io/topic?id=37806)

## Community News

- **Anthropic researchers and Claude compressed a Lean proof of the Generalized Riemann Hypothesis (GRH) down to 76,000 lines (11/26)**: Building on Levent Alpöge and Claude's GRH proof covered in the 11/21 briefing, Anthropic researchers worked with Claude to produce a compressed version of roughly 76,000 lines, separate from the readability-focused version (about 300,000 lines) and released it publicly. Both versions prove the same five theorems on top of Lean 4 and Mathlib, using only the three basic axioms with no additional ones added. Commenters questioned why this compression ratio is so unusually large — community-led compression typically achieves only around a 33% reduction, whereas this amounts to roughly a 99.56% reduction from the original code. At the same time, it was noted that this has only passed machine verification; there's no full review by human mathematicians yet, nor an accompanying paper, and it remains a research output that isn't accepting maintenance or outside contributions. Pushback also surfaced against the existing criticism that this is "a huge proof without insight," arguing that compression alone doesn't guarantee insight. [GeekNews](https://news.hada.io/topic?id=37854)
- **Scott Aaronson described AI's recent string of solved math problems as "a change of enormous scale" (11/26)**: Theoretical computer scientist Scott Aaronson highlighted that OpenAI recently proved the matrix multiplication exponent ω is exactly 9/4 by establishing matching upper and lower bounds, and also produced a lower bound for Fourier transforms that matches a computation method improving on standard FFT. He interprets this not as isolated results but as a wave that's opening up whole new regions of mathematical truth at once. He says he's provisionally accepting the published Lean proof certificates absent counter-evidence, though he thinks it could take humans years to fully understand the solutions. Commenters pushed back in several directions: that the 9/4-exponent algorithm is a "galactic algorithm" with constants too large to be practical; that claims of cryptography being broken wholesale are exaggerated (one-time pads remain secure, and symmetric keys are still only exposed to Grover-level attacks); and an analysis of why AI company stock prices have actually fallen despite these math achievements, due to open-weight models. ## Minor Changes

The following are all **v2.1.332** (11/25) items not already covered above.

- **Fixed `claude auth login` incorrectly reporting "Login successful." when it actually failed to save a claude.ai login** — it now exits with code 1 and surfaces things to check, such as a locked lock file or insufficient disk space.
- **Fixed Read, @-mentions, and compaction hanging indefinitely on an unread named pipe** (such as a `.env` mounted by a locked secrets manager) — they now fail after 20 seconds instead.
- **Fixed SSE MCP servers that, after a dropped event stream came back on a new endpoint or never came back at all, would freeze or reject all tool calls until manually reconnected.**
- **Fixed `temp_*` folders piling up in `~/.claude/plugins/cache`** due to plugin downloads that failed to copy.
- **Extended how long tab-mode voice input keeps the microphone on** — from 15 seconds of silence / 2 minutes max to 60 seconds of silence / 10 minutes max — and any unsent text now persists so you can continue it in the next tab.
- **Fixed the `sonnet` alias on Bedrock Mantle incorrectly resolving to Haiku 4.5** — it now points to Sonnet 5, and accounts that can't use it will get an error telling them to activate it first.
- **Sonnet 5.5 now replaces Sonnet 4.5 in the Claude apps gateway's default built-in model list**, and Claude Desktop now starts with Sonnet 5.5 under policies that disallow Opus 4.6.

## Recommended Reads

- **Smart, genuinely accountable people use tools (11/19)**: This piece argues that LLMs only amplify a user's existing habits — responsible engineers use AI to widen their verification scope, validating designs, building API simulators, and testing edge cases, while irresponsible engineers simply ship code they don't understand faster. It argues today's system instability isn't purely an AI problem but stems from decades of accumulated engineering debt and operations that rely on undocumented tacit knowledge, and that management replacing skilled staff with subscriptions while rewarding deployment volume alone makes systems even more fragile. Commenters pushed back that handing modeling over entirely to an LLM is delegation, not abstraction, and that it's hard to reliably predict the outcome of a prompt tweak, while others shared experiences that developers who ship fast and leave cleanup for later have always been rated more highly by management. It's worth revisiting whether the time Claude Code has freed up through faster verification is actually being spent widening your verification scope, or not. - **Porting Rockbox to a $9 unbranded MP3 player using an LLM (11/14)**: A case study reverse-engineering an AliExpress YP3 device — 512 KiB of RAM, 2MB of flash — and getting the open-source music firmware Rockbox running on it, all without disassembly or soldering, using only existing flashing tools, Ghidra, a webcam, and audio input. The LLM wrote most of the code while the human handled direction, testing, and QA; getting to boot and playback took about a week, with optimization taking another month. The author notes that their first attempt, using a Codex-based approach, produced an overly complex result, so they switched to Claude and simplified it down to a handful of Python scripts — after which a follow-up device reached an alpha build in just 4 hours. Commenters noted that an LLM is unlikely to replace the 25 years of human refinement baked into Rockbox itself, but is well suited to porting work specifically, alongside concerns that vibe coding could eventually lead toward subscription fees or usage restrictions. Worth a look if you're considering LLM-assisted embedded reverse engineering and want to know what tool combinations actually work. [Original](https://jayd.ml/2026/11/14/rockbox-on-yp3.html) · [GeekNews](https://news.hada.io/topic?id=37853)
- **EmailEngine's long road to $20k in monthly revenue (11/25)**: A retrospective on EmailEngine, an open-source tool for managing email accounts via REST API, which spent a year and a half as free open source with only 3 paying customers and 750 euros in total revenue — until switching to a source-available model that requires an active subscription to function, after which it brought in $2,000 in its first month and has since grown to $20k in monthly recurring revenue (MRR). The author says the product and marketing didn't fundamentally change — the shift in monetization model was the key factor — and that raising the initial price from 250 euros/year to as much as $1,450/year didn't reduce new customer signups. The author, who develops, supports, sells, and documents the product alone with no employees or investors (using AI for some tasks), credits the experience, trust, and prospective customer base built up during the open-source phase as the foundation for the transition, but cautions that starting a software business isn't a reliable path for anyone who needs to replace a salary quickly. Worth a look if you're maintaining an open-source project and weighing how to build a sustainable revenue model — changing the monetization approach itself may be the option to consider. ## Interesting Projects & Tools

- **Agent Run Inspector — a local tool that visualizes Claude Code and Codex run history as a live graph (11/25)**: This tool reads the local run logs (JSONL) that Claude Code and the Codex CLI leave behind, and renders the relationships between orchestrators, subagents, and tool calls as a live graph and timeline, while also aggregating token usage and estimated cost per agent. It works without hooks or a proxy, reading only existing run logs, so there's no need to change your execution environment; it supports Claude Code subagents, Agent Teams (teammates), and the Codex CLI, with Orca bot and worker tracking added recently. The server only listens on `127.0.0.1`, restricts access via a token, and its only outbound communication is for version checks and user-initiated update installs. Worth trying if you've been running multiple subagents or agent teams at once and found it hard to tell from the terminal alone what each agent is doing or how many tokens it's burning. [GitHub](https://github.com/th-yong/agent-run-inspector) · [GeekNews](https://news.hada.io/topic?id=37817)
- **Claude Navigation — a template that organizes work into hypothesis, execution, and evaluation steps so Claude Code doesn't retry approaches it already abandoned (11/25)**: This folder template addresses the problem where, during long Claude Code sessions, context gets compacted or the session changes and Claude ends up retrying an approach that already failed. There's no server or sign-up required — you just copy the folder and start using it. Four slash commands — `/pdca-init`, `/pdca-start`, `/pdca-status`, and `/pdca-wrap` — record the hypothesis, execution, evaluation, and next direction, and a hook blocks responses that fail to log the work, enforcing the record-keeping. Abandoned approaches are kept on record along with the reason and the conditions under which they'd be worth retrying, so a new cycle can be checked against that list before starting. Worth trying if you want to carry context and a lightweight history of trial and error across session changes, without the complexity of a full orchestration tool's setup. [GitHub](https://github.com/ohohoh2018/claude-navigation-ko) · [GeekNews](https://news.hada.io/topic?id=37839)
