## New Features & Practical Usage

### Claude Ship — a beta feature that hands off PR review, fixes, and approval has launched (11/23)

**Until now, even after writing code with Claude Code, developers still had to open the PR themselves, wait for review, and handle CI failures and merge conflicts by hand — but Anthropic's official blog has introduced Claude Ship, a beta feature that takes over this entire workflow.** Code Review (generally available) examines a PR from multiple angles, verifies and categorizes what it finds, and leaves comments on the PR, with Quick, Standard, and Deep review intensities configurable per repository. PR Steward (beta) keeps a PR passing by responding to failed CI runs, merge conflicts, and review feedback, posting a comment on every push explaining what changed and how to revert it — but it does not approve or merge on its own. Claude Approvals (beta) follows an approval policy written as a file in the repository, auto-approving minor changes while requiring a human sign-off in specific cases; Anthropic recommends starting in observe-only mode before applying it to branch protection rules. It's available on Team and Enterprise plans for GitHub repositories, and is not yet available to organizations using Zero Data Retention, HIPAA configurations, or customer-managed encryption keys.

```bash
# After a developer makes a change
/ship
# → Claude pushes the change, opens a PR, reviews it itself,
#   and responds to feedback and failed checks (merging still depends on permissions and branch rules)
```

**If context-switching to handle CI failures or review feedback after opening a PR has been eating into your day, and you're on a Team or Enterprise plan using GitHub repositories, it's worth letting `/ship` take review and fixes off your plate — just validate the auto-approval scope in observe-only mode first.** [Anthropic official blog](https://claude.com/resources/articles/introducing-claude-ship)

### MCP servers now support skill distribution, background tasks, mid-call confirmation requests, and file uploads (11/24)

**Until now, MCP servers mostly just exposed tools for Claude to call, but Anthropic's official blog announced four new capabilities that let a server treat Claude more like "another agent."** Skills over MCP (public beta) lets a server ship multi-step task guides or org-specific playbooks as skills alongside its tools, which Claude loads only when needed and which stay current automatically as the server updates. Tasks (generally available) lets a server run long tasks or an entire agent loop in the background while Claude keeps working on other things, and Elicitation (generally available) lets a server pause mid-call to collect user confirmation — through a form or link — for things like cost approval or risky actions, then continue. File uploads (coming soon) will let PDFs, spreadsheets, and images go straight to the server without passing through the context window. Skills over MCP is on by default for Pro, Max, and Ultra, requires an admin to enable it on Team, and is coming soon to Enterprise.

**If you run your own MCP server, or connect several MCP servers to Claude Code, it's worth considering shipping skills alongside the server itself so guidance reaches users without a separate install, or adding an Elicitation confirmation step ahead of risky actions like cost approval.** [Anthropic official blog](https://claude.com/resources/articles/skills-over-mcp-tasks-and-more)

## Developer Workflow Tips

### An enterprise guide on safely scaling Claude Code across an organization has been published (11/23)

**Until now, security and engineering leaders scaling Claude Code organization-wide had to work out on their own which controls belonged where — but Anthropic's official guide lays out a three-layer control structure built not to eliminate risk, but to keep it "visible and bounded."** The judgment layer covers alignment training, prompt-injection detection, an auto-mode classifier that checks intent against action, and human approval for hard-to-reverse actions. The fixed-boundary layer covers priority deny rules, token-level analysis of Bash commands, a PreToolUse hook that blocks secrets from entering commits, OS-level local sandboxing, and cloud sessions that spin up a disposable VM for every task. The policy layer splits defaults into an extensible baseline and a centrally enforced locked mode, locked down with settings like `allowManagedDomainsOnly`, `allowManagedMcpServersOnly`, and `disableBypassPermissionsMode`. The guide names credential leakage, unverified MCP servers, plugins, skills, and `CLAUDE.md` files, data exfiltration, and prompt injection as the core risks, and recommends a two-week pilot on a low-sensitivity repository to review classifier blocks, sandbox blocks, and denied network access.

```text
Judgment layer (alignment training, injection detection, auto-mode classifier, human approval)
  → Fixed-boundary layer (permission rules, Bash analysis, hooks, local sandbox, cloud sessions)
  → Policy layer (baseline vs. locked settings, centrally enforced)
  → Auditability (session transcripts, OpenTelemetry, audit API)
```

**If you're expanding Claude Code adoption org-wide and weighing which controls to lock down first versus leave to developer discretion, it's worth following this guide's starting point directly: run a two-week pilot on a low-sensitivity repository and review the classifier, sandbox, and network-block logs first.** [Anthropic official guide](https://claude.com/resources/articles/enterprise-guide-to-securing-coding-agents)

### A piece on practical eval techniques argues evaluation is the most underrated skill in AI engineering (11/24)

**Until now, it's been tempting to judge whether a model or prompt change improved things by a single metric, but this piece argues you should start before any metric — by reading and categorizing 100+ real production failures yourself.** Its core argument: prompts get thrown away and models change every few months, but a library of accumulated failure cases keeps its value. It recommends filtering out anything checkable by code first — schema validation, regexes, running SQL against a test database — and reserving LLM judges only for what code can't verify; for RAG, it argues retrieval (recall@k, MRR, nDCG) and generation (groundedness) need to be measured separately so you can see which stage is actually failing. For agents, it recommends logging every tool call to check precision, recall, argument accuracy, and step count (citing a case where a three-step task took 14 calls), and makes the case for pass^k — where every run must succeed — over pass@k by pointing out that an 80%-per-run success rate only yields about a 33% chance of five consecutive successes. When using an LLM judge, it recommends hand-labeling 100+ examples split into train/dev/test sets, and warns that with a 95% confidence interval of roughly ±8 points on an 80%-accuracy, 100-sample test, a shift to 83% could just be noise.

**If you've been judging Claude Code's or your own agent's performance improvements by a single metric, it's worth applying this piece's approach directly: build up a failure-case library first, separate deterministic checks from LLM judgment, measure reliability with pass^k instead of pass@k, and avoid calling a small-sample accuracy difference an improvement without a confidence interval.** [GeekNews](https://news.hada.io/topic?id=37745)

## Security & Limitations

### Claude service status — an 18-minute Claude Haiku 5.5 error on 11/24 (resolved), the M365 add-in issue still open, claude.ai currently Degraded Performance

**Checking the official status.claude.com, following the multi-model error incident on 11/23 (covered in the 11/24 briefing), Claude Haiku 5.5 saw a rise in errors for 18 minutes between 17:09 and 17:27 UTC on 11/24, resolved at 17:50 UTC after a fix was deployed.** Starting the same day (11/24) at 00:10 UTC, some users signed in with personal Microsoft accounts reported that the Claude for Microsoft 365 add-in had disappeared from Excel, Word, and PowerPoint on Mac; work and school accounts were reported unaffected, but the issue remains under investigation as of today (11/25), so affected users are advised to use the web version at office.com in the meantime. No new incidents have been reported today (11/25), but the claude.ai component is currently showing Degraded Performance on the live status page, with no further explanation posted. Every other component, including Claude Code, is Operational.

**If you ran into Claude Haiku 5.5 errors yesterday (11/24) morning, that was a temporary issue resolved within 18 minutes — but if you use the Claude for Microsoft 365 add-in with a personal account on Mac, that issue is still under investigation, so it's safer to fall back on the office.com web version for now, and worth keeping an eye on claude.ai's Degraded Performance status too.** [Claude Status](https://status.claude.com)

### Enterprise Frontier Safeguards with Zero Data Retention has moved to public beta (11/23)

**Until now, enterprise customers who wanted both safeguards and Zero Data Retention (ZDR) together had to apply for a private beta, but Anthropic's official blog announced it's moving to public beta after running the private beta with more than 100 customers across healthcare, finance, and legal.** Where standard ZDR only caught risk within a single request, Enterprise Frontier Safeguards (EFS) also detects abuse patterns split across multiple requests, while storing monitoring data in cloud storage the customer manages directly — Amazon S3 or Google Cloud Storage — so that neither Anthropic nor the cloud provider retains the data. It's available on the Claude Platform, Claude Platform on AWS, Amazon Bedrock, and Google Cloud, with Microsoft Foundry support "coming soon." When risk is detected, a Safety Case is generated that the customer can read from their own cloud storage or API; Anthropic emphasizes that these cases don't include the actual input or output content, and there's no human review process on Anthropic's side.

**If you've had to give up ZDR's data-retention benefits because of safeguards while handling sensitive data in healthcare, finance, or legal, it's worth looking at EFS's move to public beta as a way to get both at once by paying for customer-managed storage instead — just note that Microsoft Foundry environments aren't supported yet.** [Anthropic official blog](https://claude.com/resources/articles/zero-data-retention-with-enterprise-frontier-safeguards)

## Interesting Projects & Tools

- **orca-orchestration-kit — a three-tier orchestration kit for running dozens of Claude Code sessions in parallel, solo (11/24)**: It splits work across a main session (talks to the user and makes decisions), a task manager (distributes and merges work without implementing anything itself), and task sessions (one session, branch, and worktree per requirement), progressing wave by wave from shared groundwork (W0) through parallel requirements (W1), module integration (W2), to system integration (W3). Merges flow in order from `req/*` to `int/<module>` to `int/common` to `main`, without rebasing or force-pushing, and it auto-assigns a subscription CLI plus model and effort level — choosing among Claude, Codex, Antigravity, and Grok — based on task difficulty. The author's main takeaway: the real bottleneck isn't the number of sessions but the heavy tasks themselves, and isolation has to be designed in from the start. Install with `/plugin install orca-orchestration-kit --marketplace newrise0410/orca-orchestration-kit`; it's still at v0.5.0, conventions are still shifting, and the docs are mainly in Korean. [GitHub](https://github.com/newrise0410/orca-orchestration-kit) · [GeekNews](https://news.hada.io/topic?id=37768)
- **VerifyLens — an open-source tool that checks AI-written code against requirements and labels each as verified, mismatched, or unverified (11/24)**: Born out of not being able to trust an AI's claim that "I've implemented all the requirements" without checking line by line, it links each requirement to the specific lines of code behind it and the JUnit tests actually run against it. For a requirement like "lock the account after 5 consecutive failures," if the AI's code locks it on the 6th attempt instead, it's flagged as mismatched regardless of whether the tests pass. It uses no LLM at all — judging purely from the TypeScript compiler, git change history, and test results — so the same input always produces the same output, and when the evidence is inconclusive it reports unverified rather than defaulting to no issues found. That said, the author is upfront that version 0.26 still misjudges things — half of its verified calls pointed to the wrong lines — that it only supports TypeScript and JavaScript, and that it hasn't yet been validated against real Claude Code agent sessions. You can try it without installing anything, by pasting in requirements and code, or a public GitHub PR URL, on its demo page. [GitHub](https://github.com/DamunKorea/verifylens) · [GeekNews](https://news.hada.io/topic?id=37720)
