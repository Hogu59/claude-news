## 主要な新機能と実践活用

### Anthropicがエージェントメモリの「ドリーミング(dreaming)」メカニズムを研究として公開しました (11/8)

**Anthropic Researchが、エージェントがセッション間で何を記憶し、誤った記憶をどう修正するかを実験した結果を公開しました。** 核心は「ドリーミング」と呼ばれるプロセスで、セッション間で積み上がったメモを元の対話ログと照合して誤りを修正し、散らばったノートをトピックごとのwikiにまとめる作業です。社内文書評価では、原文検索にこのwikiを加えることで採点基準の達成率が53%から最大61%まで上昇し、質問1件あたり約2万トークンが節約できましたが、単一文書だけ見れば済むタスクでは明確な効果は見られませんでした。さらに、新しいモデルほどメモリ作成の指示を細かいルールで固定するより、シンプルな指示とモデル自身の判断に委ねるほうがうまく機能したとしています。

**Claude Codeを複数セッションにわたる長期プロジェクトで使っていて、CLAUDE.mdやメモリファイルが時間とともに古くなったり誤った内容を溜め込んでいくと感じているなら、この研究が示す「原文と照合して修正し、トピックごとにまとめる」という原則を自分のメモリ運用に取り入れてみる価値があります。** [GeekNews](https://news.hada.io/topic?id=36775)

### Claude apps gatewayにプール型グループ予算の競合解決ルールと優先順位が追加されました (v2.1.319)

**`admin.pooled_conflict_rule`と`admin.pooled_priority_order`が追加され、ある開発者が複数のプール型グループに属している場合、どのグループの共同予算がその開発者の支出を先に負担するかを設定できるようになりました。** これまでプール型グループ予算の機能自体はありましたが、1人が複数グループにまたがる場合にどの予算を優先するかは定義されていませんでした。

```yaml
# Claude apps gatewayの設定例(複数のプール型グループに属する開発者の予算優先順位を指定)
admin:
  pooled_conflict_rule: priority_order
  pooled_priority_order:
    - team-finance
    - team-platform
```

**複数チームのプール予算を同時運用していて、複数グループに所属する開発者の支出がどの予算から引かれるのか不明確だった場合、v2.1.319からはこの設定で優先順位を明示的に指定できます。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

## 開発者ワークフローティップス

### DoorDashがLLM内蔵の検索を別のゲートウェイに分離し、検索コストを98%超削減しました (11/7)

**DoorDashはLLMに内蔵されたWeb検索をDSG(Search Gateway)という別レイヤーに分離して複数のエージェントで共有できるようにし、同じまたは似た質問の検索結果をキャッシュしました。** キャッシュが効いている実行では平均レイテンシが68%減少し、検索コストは99%超削減されました。さらに検索結果をタイトル・URL・本文抜粋の形式に統一して渡すことで、内蔵検索が出力形式を無視して余計な説明を付け加える問題も減りました。一般的な小売クエリの評価では、DSG+Serperが93.90%、内蔵検索が93.40%と精度はほぼ同等でしたが、検索コストは98%以上低くなりました。ただし最新情報が重要になるFreshQAタスクでは内蔵検索のほうが精度が高く、用途によって両方式を使い分ける構成を維持しています。

```text
一般的な小売クエリ     → DSG + Serper(キャッシュ適用、低コスト)
最新性が重要なクエリ   → LLM内蔵検索を維持(FreshQAで精度が高い)
```

**Claude APIやClaude CodeのWeb検索機能を大量に使うプロダクトを運用しているなら、検索を別ゲートウェイに分離してキャッシュを導入するだけで、精度をほぼ維持したままコストを大きく削減できる余地があるか検討してみる価値があります。** [GeekNews](https://news.hada.io/topic?id=36733)

### `/loop`の自動ペーシングモードが、ターン終了後に再スケジュールせずそのまま終了するよう変更されました (v2.1.319)

**これまで自動ペーシングで動かしていた`/loop`は、ターンが終わっても次に起動するタイミングをフォールバックとして予約していましたが、今後はターンが終わると追加の予約なしにそのまま終了します。** 以前のようにターン終了後も次のウェイクアップを自動で予約しておきたい場合は、環境変数で以前の動作を維持できます。

```bash
# ターン終了後もフォールバックのウェイクアップを予約し続ける従来の動作を維持
export CLAUDE_CODE_LOOP_KEEPALIVE=1
```

**`/loop`で長時間の繰り返し作業を自動化していて、セッションが想定より早く終わってしまうと感じているなら、v2.1.319からデフォルト動作が変わったことを確認し、必要であれば`CLAUDE_CODE_LOOP_KEEPALIVE=1`で元の動作に戻してみるとよいでしょう。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

**公式のstatus.claude.comを直接確認したところ、11/1から11/8(本日)まですべて「No incidents reported」と表示されており、claude.ai・Claude API・Claude Code・Claude Console・Claude Cowork・Claude for Governmentのすべてが「All Systems Operational」で正常稼働しています。** 直近のインシデントは10/28に解決されたGoogle Calendar・Gmailコネクタの障害です。

### Claude DesktopのUnified Claudeが11/10からすべてのサードパーティ配布に強制適用されます

**ChatタブとCoworkタブを1つのインターフェースに統合するUnified Claude機能は、これまで任意適用でしたが、11/10からすべてのClaude Desktopサードパーティ配布で強制的に有効化されます。** この切り替えが適用されると、`coworkTabEnabled: false`や`chatSessionRetentionDays`といった値に依存してきたmanaged settingsは読み込まれなくなります。v2.1.319では、`desktopHome`を使わずこれらの値だけに依存するポリシーを運用している組織向けに、まず起動時の警告を追加しています。

**組織としてClaude Desktopをmanaged settingsで運用しているなら、`coworkTabEnabled`や`chatSessionRetentionDays`に依存するポリシーがないか11/10より前に確認し、Unified Claudeへの切り替え後も意図した動作が維持されるか確かめておくとよいでしょう。** [全リリースノート](https://github.com/anthropics/claude-code/releases) · [Unified Claudeドキュメント](https://claude.com/docs/third-party/claude-desktop/unified-claude)

### テレメトリが無効な状態でauto modeのサーバーチェックがブロックされた場合のデフォルト動作がより厳格になりました (v2.1.319)

**テレメトリやfeature flagが無効な状態で、LLMゲートウェイの背後も含めてClaude Codeを運用している場合、auto modeのサーバー側安全性チェックがある呼び出しを確認できないと、今後はその呼び出しはそのまま承認を求められるか拒否され、内蔵classifierへの自動フォールバックは行われません**(Bedrock・Vertex・Foundryは動作に変更ありません)。また、組織側で既に無効化しているauto modeのサーバーチェックは、プロジェクトの設定ファイルやプラグインから再度有効化できないようになりました。

```bash
# テレメトリ/feature flagが無効でも以前のように内蔵classifierへフォールバックしたい場合
export CLAUDE_CODE_AUTO_MODE_SERVER=0
```

**テレメトリを無効にしてauto modeを使っていたり、LLMゲートウェイの背後でClaude Codeを運用しているなら、v2.1.319からはサーバーチェックがブロックされた瞬間に作業が以前より頻繁に停止・拒否される可能性がある点を念頭に置き、必要であれば上記の環境変数で以前の動作を選択できます。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

### self-hosted runnerの`--trust-workspace false`が、リポジトリのフック・スキル実行までしっかりブロックします (v2.1.319)

**これまで`--trust-workspace false`で信頼していないリポジトリをチェックアウトしても、そのリポジトリのsettingsファイルに定義されたフックやskillsが実行されてしまう余地がありましたが、今回これが塞がれました。** 信頼できるかどうかを判断する前に、リポジトリ自体が持ち込んだコードが密かに実行されてしまう可能性があったという点で、重みのあるセキュリティ修正です。

**self-hosted runnerで外部PRや信頼できないブランチをチェックアウトして処理する自動化を運用しているなら、v2.1.319にアップグレードし、リポジトリが持つフック・スキルが承認なしに実行されないバージョンを使っているか確認しておくとよいでしょう。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

### Opus 4.8のfast modeサポートが11/30に完全終了します (期限まで約3週間のリマインダー)

**10/30付けで提供終了(deprecated)が予告されたOpus 4.8のfast modeは、11/30に完全に削除されます。削除後はfast modeへのリクエストはエラーを返し、標準のOpus 4.8への自動フォールバックは行われません。** 速度向上を継続して使いたい場合はOpus 5.5への移行が必要です。

**Opus 4.8のfast modeに依存するワークフローや自動化があるなら、11/30より前にOpus 5.5への移行を済ませ、当日になって突然リクエストがエラーになる事態を避けておくとよいでしょう。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

### Show GN: Heirmos — Claude Codeで使ったメモリをCodex・Cursor・ChatGPTまで共有するプラグイン (11/7)

**対話から決定・好み・ルールを抽出して保存しておき、セッションを開始するたびに同じストアの記憶をエージェントのコンテキストへ自動的に注入するプラグインで、Claude Codeで積み上げた記憶をCodex・Cursor・Claude.ai・ChatGPTでもそのまま使えます。** CodexにはAGENTS.mdのスニペットとMCPで、Cursorにはrulesファイルとしてつながっており、作業中はMCP経由で過去の決定を検索・参照することもできます。送信される内容はプロンプトとClaudeの回答本文のみで、ツール呼び出し・ツール結果・ファイル内容・thinkingは送信されません。APIキーのような機密文字列はローカル側で事前に除去されます。

```bash
# Claude CodeにHeirmosをインストール(約5分)
uv tool install heirmos-cli
export HEIRMOS_API_KEY=発行されたキー   # dashboard.heirmos.comで発行
/plugin marketplace add team-pneumora/pneumora-plugins
/plugin install heirmos@pneumora-plugins
```

**Claude CodeとCodex・Cursorを混在させて使っていて、一方のツールで決めたルールや決定を別のツールではまたゼロから説明し直す必要があったなら、このプラグインでツールを横断したメモリ共有を試してみる価値があります。** [GeekNews](https://news.hada.io/topic?id=36737)

## 知っておくと便利な小さな変更点

以下はすべて**v2.1.319**(11/6)の項目です。

- **`login_notice`設定が追加**され、Claude apps gatewayの運用者がブラウザ認証画面とClaude Codeのログイン画面に、自分で定めた案内文を表示できるようになりました。
- **`CLAUDE_GATEWAY_LOG_FORMAT=json`が追加**され、ゲートウェイの運用ログが`severity`・`time`・`message`フィールドを持つJSONで出力されるようになり、ログ収集ツールがレベルをフィールド値としてそのまま読み取れます。
- **MonitorのWebSocket watchがBashコマンドと同じルールに従うよう変更され**、denyルールはそのまま拒否し、askルールではMonitor許可・bypass mode・auto modeがプロンプトをスキップしなくなりました。
- **`which`を照会・表示以外のフラグで実行する際に、権限確認を求めるよう変更されました。**
- **`--add-dir`で追加したディレクトリは、そのディレクトリ自体の信頼確認ダイアログが承認された後にのみプラグインマーケットプレイスを登録**するよう変更されました。
- **Bash sandboxが有効な状態では、起動フォルダより下位にある`.claude/skills`は、そのフォルダでClaude Codeを起動した場合、または`/cd`でそこに移動した場合にのみロード**されるよう変更されました。
