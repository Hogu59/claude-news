## 主要な新機能と実践活用

### `/doctor prompt-audit` — CLAUDE.md・スキル・エージェント・コマンドの古いプロンプティングパターンを検出 (v2.1.283)

**CLAUDE.md、スキル、エージェント、コマンドファイルに残る、旧世代モデル向けに書かれたプロンプティングパターンを見つけてくれるコマンドが追加されました。** `/checkup prompt-audit`でも同じ機能を実行できます。

```bash
/doctor prompt-audit
# または
/checkup prompt-audit
```

**古くからのチームでは、Claude Code導入初期に書いたCLAUDE.mdやカスタムスキルに、現行モデルにはもう不要、あるいは逆効果になっている指示が残っていることが少なくありません。定期的にこのコマンドを実行し、指示ファイルを最新モデルに合わせて整理する習慣をつけておく価値があります。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### `deniedModels`・`availableModelsMatch: exact` — モデルの許可・拒否をより細かく制御 (v2.1.283)

**`availableModelsMatch`を`"exact"`に設定すると、`availableModels`に列挙したバージョンのモデルのみが許可されるようになり、新モデルがリリースされてもリストに明示的に追加するまでは自動で使えるようにはなりません。** **`deniedModels`管理設定を使えば、`availableModels`で許可したモデルであっても特定のモデルだけを個別に拒否できます。**

```json
{
  "availableModels": ["claude-opus-5-5", "claude-sonnet-5"],
  "availableModelsMatch": "exact",
  "deniedModels": ["claude-3-5-sonnet-20240620"]
}
```

**組織として使用モデルを厳格に管理しているチームにとっては、新モデル登場時に管理者が確認してリストに載せるまで自動的にブロックしておけるこの組み合わせが役立ちます。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### `x-claude-code-prompt-id`ヘッダーでLLMゲートウェイのリクエストをプロンプト単位にまとめる (v2.1.283)

**ゲートウェイヒントヘッダーに`x-claude-code-prompt-id`が追加され、自社でLLMゲートウェイを運用しているチームが、1つのユーザープロンプトから発生した複数のリクエストをまとめて見られるようになりました。** 有効化するには`CLAUDE_CODE_GATEWAY_HINT_HEADERS=1`でオプトインする必要があります。

```bash
export CLAUDE_CODE_GATEWAY_HINT_HEADERS=1
```

**社内のLLMゲートウェイやプロキシ経由でClaude Codeのトラフィックをロギング・分析しているチームなら、このヘッダーによって並列ツール呼び出しやリトライが同じプロンプトから出たものかどうかをゲートウェイ側で直接判別できるようになります。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## 知っておくと便利な小さな変更点

以下はすべて**v2.1.283**(9/25)の項目です。

- **`OTEL_LOG_TOOL_CONTENT=1`のとき、MCPツール・WebFetch・WebSearchの出力が`tool.output`のOpenTelemetryイベントにも記録**されるようになりました。
- **フルスクリーンモードで、他セッションの省略されたメッセージをクリック一つで展開表示**できるようになりました。
- **`--plugin-dir`の読み込み失敗項目に、読み込めなかったディレクトリのパス(`path`)が併記**されるようになりました。
- **`load_test_mode`を有効にしたClaudeアプリゲートウェイは、リクエストを生成・署名しつつ実際にはアップストリームへ送らず、あらかじめ決めておいたレスポンスを返すようになり、デプロイ環境の負荷テストに使え**ます。
- **`/ultrareview`の実行ダイアログが、ローカルブランチをレビューする際にコミットされていない変更もアップロードされる可能性があると案内**します。
- **`/model`ピッカーのOpus行とデフォルトモデル名で、Opusが既に100万トークンコンテキストに対応している場合は「(1M context)」の表記が省略され**ます。
- **ターミナルのプロンプト提案は20回連続で使われないと表示頻度が下がり、一度でも使うと元の頻度に戻り**ます。
- **`--system-prompt`と`--append-system-prompt`がテキストと`-file`形式を同時に受け付けられるようになり**、ファイルの内容が先に適用されてからテキストが続きます。
