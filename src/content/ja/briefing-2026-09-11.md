## 主要な新機能と実践活用

### WebFetchに300秒のデッドラインが追加されました — `CLAUDE_CODE_WEBFETCH_DEADLINE_MS` (v2.1.268)

**レスポンスを終了させずに接続だけを開いたままにするサーバーに対して、WebFetchが無限に待ち続けてしまう問題が修正されました。** **今後は300秒を過ぎるとfetchが失敗として終了し、`CLAUDE_CODE_WEBFETCH_DEADLINE_MS`でこの上限を変更したり、0を指定して無効化したりできます。**

```bash
# デッドラインを60秒に短縮し、応答のないサイトから素早く抜けられるようにします
export CLAUDE_CODE_WEBFETCH_DEADLINE_MS=60000

# 0を指定するとデッドラインが無効になります（推奨しません）
export CLAUDE_CODE_WEBFETCH_DEADLINE_MS=0
```

**スケジュール実行のジョブやCIでClaude Codeを動かしている場合、デフォルトの300秒でも長すぎることがあるため、処理全体の時間予算に合わせて短めに設定しておくと安全です。** 同じリリースでは、**localhostのようなドットを含まないホスト名をWebFetchが拒否する際に、理由を説明しcurlを勧めるようメッセージも改善されました。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### `claude plugin`の全サブコマンドに`--json`が追加されました (v2.1.268)

**`claude plugin install`・`uninstall`・`update`・`enable`・`disable`に`--json`が追加され、`claude plugin list --json`の各行には`errorDetails`と`noteDetails`が含まれるようになりました。** **併せて`claude auth status --json`の出力に`configDirectory`が加わり、現在のセッションがどの設定ディレクトリを使っているかをスクリプトから直接確認できます。**

```bash
# インストール結果をJSONで受け取り、成否をスクリプトで判定します
claude plugin install my-plugin@my-marketplace --json | jq -e '.success'

# どのプラグインがなぜ失敗したのかを行単位で確認します
claude plugin list --json | jq '.[] | select(.errorDetails) | {name, errorDetails}'
```

**チームのオンボーディングスクリプトやCIでプラグインのインストールを自動化する際、人間向けの出力をパースする代わりに、終了コードとJSONフィールドで判定できるようになりました。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### ゲートウェイの料金伝達と`gatewayInternalNetworks` (v2.1.268)

**Claude appsゲートウェイの`gateway.yaml`に`pricing:`を設定すると、サインイン済みのClaude Codeクライアントが管理設定を通じて同じ料金情報を受け取り、`/cost`やテレメトリの値が実際の課金メーターと一致するようになります。** **さらに`gatewayInternalNetworks`という管理設定が追加され、組織が保有するパブリックIPv4ブロックからでもゲートウェイへ`/login`できるよう管理者が許可できます。**

```yaml
# gateway.yaml
pricing:
  # クライアントがこの料金表を受け取り、/costの計算に使用します
  enabled: true

access_control:
  # 空のままだと起動時に警告が出て、パブリックIPから最初のリクエストが届いた際にも一度警告が出ます
  allow_cidrs:
    - 10.0.0.0/8
```

**ゲートウェイを運用している場合は、`access_control.allow_cidrs`を空のままにしている構成に今回から起動警告が付く点を、まず確認しておくとよいでしょう。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## セキュリティ・制限事項

### Anthropicの脅威インテリジェンスレポート — 偽のClaude Codeインストーラーと盗まれたAPIキーの市場 (9/10)

**Anthropicが2025年12月から2026年8月までに遮断した悪用事例をまとめた4回目の脅威インテリジェンスレポートを9/10に公開しました。** **Claude Codeユーザーにとって最も直接的なのは、「安価なClaudeアクセス」を謳うサイトが、人気のAIハーネス、とりわけClaude Codeを偽装したクライアントを配布し、端末上のすべての認証情報とセッショントークンを収集していたという部分です。**

**レポートは、盗まれたAPIキーとセッショントークンそのものが犯罪グループの目的になっていると整理しています。** ある行為者は**AI企業の自動評価サンドボックスに悪意ある指示を注入して、サンドボックスが保持していた本番APIキーを引き出し、その後4日ほどで約30社のAI企業を同じ手口で攻撃しました。** **複数の行為者がLiteLLMベースのラッパーサービスにプロンプトインジェクションを仕掛け、クラウド上のコンテナ環境にあった本番キーを窃取した事例も含まれます。**

**実務的には3点を点検する価値があります。第一に、Claude Codeは公式の配布経路からのみインストールすること。第二に、エージェントが読めるファイル・環境変数・サンドボックスに本番キーを置かず、サーバー側で強制すること。第三に、リポジトリやビルド成果物に残ったキーを定期的に洗い出すことです** — レポートに登場するあるグループは、Androidアプリ180万本をダウンロードしてハードコードされたシークレットを探索していました。 [Anthropic](https://www.anthropic.com/threat-intelligence-report-september-2026)

### v2.1.268のセキュリティ修正 — シンボリックリンクのdenyルール回避、エラーメッセージのシークレット露出 (9/10)

**macOSの`/etc`・`/tmp`・`/var`、Linuxの`/bin`のようにシンボリックリンクで結ばれたディレクトリに設定したdeny・askの権限ルールが、パスを実体の場所で指定すると適用されなかった問題が修正されました。** **シンボリックリンク表記で書かれたdenyルールをBashコマンドが無視していた問題や、`env -C`や`eval`のように権限チェッカーが解析できないコマンドが同じ行にあるとRead・Editのdenyルールが適用されなかった事例も併せて修正されています。**

**シークレットの露出も2か所で修正されました。プラグイン・マーケットプレイスのエラーがgitソースURLに含まれるトークンやパスワードをそのまま表示していた問題と、`/mcp`・`/plugin`のサーバー詳細、`claude mcp list`・`get`、MCPログインエラーが、MCP設定の`${VAR}`プレースホルダーから解決されたシークレットを表示していた問題です。** さらに、**信頼していないフォルダに同名のエージェントファイルがある場合、再生成されたインプロセスのチームメイトがそのファイルのツールやシステムプロンプトを取り込んでしまう問題**も修正されました。

**権限ルールをパス文字列で管理しているチームは、今回の修正によってこれまで通っていたコマンドがブロックされる可能性があるため、アップグレード後によく使うパスから確認しておくとよいでしょう。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### サードパーティエンドポイントがv2.1.265以降HTTP 400で全滅していたリグレッション、v2.1.268で修正 (9/10)

**`ANTHROPIC_BASE_URL`でサードパーティのAnthropic互換エンドポイントを使う構成において、v2.1.265以降すべてのターンがHTTP 400で失敗していた問題が修正されました。** **原因はArtifactツールの入力スキーマに含まれていた正規表現で、これらのエンドポイントがそれを拒否したためにリクエスト自体が弾かれていました。**

**9/8のv2.1.265から9/9のv2.1.267まで3日間続いたリグレッションで、独自のゲートウェイやプロキシを経由するチームにとってはv2.1.268への更新が唯一の解決策です。** 昨日取り上げた`CLAUDE_CODE_USE_GATEWAY`のリグレッションに続き、ゲートウェイ・プロキシ構成が連続して影響を受けているため、**この構成を使っているならリリースごとに実際の呼び出しを1回行うスモークテストをCIに置いておくと安全です。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### Claudeサービスの状況 — CoworkのWindows障害が継続中、その他は全サービス正常

**公式のstatus.claude.comを直接確認したところ、9/10 15:54 UTCに登録された「Degraded functionality for Claude Cowork on Windows」インシデントが、9/11時点でidentifiedのまま継続中です。** **9月8日に配信されたWindowsアップデートにより、Coworkのワークスペースがユーザーのドライブにアクセスできなくなり、ローカルコマンドの実行が止まっています。多くのユーザーではチャットとファイルの読み取り・編集は引き続き動作します。** **アプリ内で使える回避策はまだなく、再起動や再インストールでも解決せず、Microsoftが修正を準備中です。**

**その他のサービスは正常です。** claude.ai・Claude Console・Claude API・Claude Code・Claude for Governmentはいずれも Operational で、**Claude Code自体は今回の障害の影響範囲に含まれていません。** WindowsでCoworkを使ってローカル作業を回していたチームは、修正が配信されるまでClaude Code CLI側へ作業を移しておくのが現実的です。 [Claude Status](https://status.claude.com)

## 知っておくと便利な小さな変更点

以下はすべて**v2.1.268**（9/10）の項目です。

- **長時間起動したままのアイドルセッションがbusy loopでCPUコアを占有し続ける問題**が修正されます。セッションのリキャップ中に端末のフォーカス通知が高速に繰り返されてCPUが高止まりする問題も併せて解消されています。
- **`/compact`と自動compactが生成する要約が、`$`シーケンスを含むテキストを壊してしまう問題**が修正されます。
- **`CLAUDE_CODE_SESSIONEND_HOOKS_TIMEOUT_MS`が、per-hookの`timeout`を持たないSessionEndフックには適用されず1.5秒でキャンセルされていた問題**が修正されます。
- **`PermissionRequest`フックが`--print`モードで発火しない問題**と、**ポリシーヘルパーの警告がヘッドレス（`-p`）実行で出力されない問題**が修正されます。
- **タスク管理ツール（TaskCreate/Get/Update/List、TodoWrite）が、Claude 3.x、Opus 4.0〜4.7、Sonnet 4.0〜4.6、Haiku 4.5でのみ提供**されるようになります。それ以外のモデルで使うには`CLAUDE_CODE_ENABLE_TODO_TOOLS=1`を設定します。
- **`/plugin`でのインストール・有効化・無効化が、メニューを閉じた時点で反映**されるようになり、その後の`/reload-plugins`は不要になります。
- **`claude self-hosted-runner --remove-session-state`（デフォルト無効）が追加**され、セッション終了時に`<base-dir>/_sessions/`配下のセッションごとのディレクトリを削除できます。
- **autoモードの拒否メッセージが改善**され、どのルールが動作を止めたのかをClaudeに伝え、より安全な方法を試し、関連のない作業を終えてから確認するよう促します。
- **`--continue`・`--resume`がSessionStartフックを待たずに会話をすぐ表示**するようになり、最初のメッセージでトランスクリプト全体を読み直さなくなります。
