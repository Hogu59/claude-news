## 主要な新機能と実践活用

### Linked billing — APIキーを共有せずに顧客が直接課金できるベータ機能がClaude Platformで公開 (11/17)

**これまで、自社SaaSにClaude APIを再販するプラットフォームは顧客にAPIキーを共有するか利用料を自前で再請求する必要がありましたが、Anthropicが公式ブログで、顧客が自身のClaude Platform組織から利用料を直接支払えるベータ機能Linked billingを公開しました。** 申請できるのはAnthropicに前払いクレジットや請求書で直接支払っているClaude Platform組織のみで、顧客は連携するプラットフォームを承認し、支出上限を設定し、いつでも連携を解除できます。リクエストの実行場所自体は変わりませんが、IP許可リストや暗号化キーといった組織単位の設定は、連携されたプラットフォーム経由のリクエストには適用されません。公開当日、ClickHouseが自社のAgents・AI FunctionsにおけるClaude APIの利用料を、顧客が既存の契約条件のまま直接請求できるようにこの機能を適用した事例を公開しました。

**自社製品でClaude APIを再販していて、APIキーの共有や手動での再請求が煩わしかったプラットフォームであれば、顧客が自身のClaude Platform組織へ直接課金できるこのベータ機能を検討する価値があります。ただしHIPAA・FERPA対応が必要な顧客にはまだ推奨されていない点には注意が必要です。** [Anthropic公式ブログ](https://claude.com/blog/linked-billing-on-claude-platform)

## 開発者ワークフローティップス

### ClaudeにChaos Engineeringを直接任せてClaude Docsのローンチを検証した事例が公開 (11/17)

**Anthropicのエンジニアリングチームは、9月にリリースした共同文書編集ツールClaude Docsを出す前に、ステージング環境でClaudeエージェントが自らシステムに障害を起こし、それを自分で修復する「chaos loop」を2週間回し続けたと公式ブログで明らかにしました。** テストハーネスが負荷シナリオ（1日1,000万ドキュメント生成、2万2,000接続の同時再接続など）を選ぶと、ClaudeはDatadog MCPでテレメトリを読み取り、原因と選択肢を提示します。元に戻しやすい修正はClaude自身が書いてステージングにデプロイし、再テストしました。スキーマ変更のような取り消しづらい判断だけは人間が承認する仕組みです。この過程で、あるドキュメントが使用するメモリを約3GBから180MBに削減し、必要なPod数を500超から約50まで減らすことができ、実際のローンチ後9月22日までに460万件超のドキュメント、約20億件のリクエストを処理しながらもサーバーエラーはわずか60件、ロールバックは0件に抑えられました。ステージングで事前に経験した10件の障害シナリオのうち7件は、本番でも実際に同じ形で発生しました。

```text
テストハーネスが負荷シナリオを選択 → ClaudeがDatadog MCPでテレメトリを確認
  → 選択肢・推奨案を提示 → 元に戻しやすい修正はClaudeが記述してステージングにデプロイ・再テスト
  → スキーマ変更など取り消しづらい判断は人間が承認
```

**新機能をリリースする前に、人間が障害シナリオをひとつひとつ設計して復旧させる作業に時間を費やしていたなら、Claudeにオブザーバビリティ系のMCPサーバーを接続し、実際のトラフィックの何倍もの負荷と障害をステージングで自律的に起こして直させるこの設計、特に取り消しづらい変更だけを人間が承認する線引きの部分は、そのまま参考になります。** [claude.dev公式ブログ](https://claude.dev/blog/chaos-loop-claude-docs-launch/)

### `/code-review`がバグ・CLAUDE.md違反のみを報告するようスコープ縮小 — 再利用性・簡素化は`/simplify`に分離 (v2.1.328)

**これまで`/code-review`はバグだけでなく再利用可能なコード、簡素化、効率改善までまとめて指摘していたため、どの指摘が本当に直すべき問題なのか見極めるのが面倒でしたが、今回のリリースからほとんどのモデルでバグとCLAUDE.md違反のみを報告するようスコープが絞られました。** 再利用性・簡素化・効率改善を見たい場合は、別途`/simplify`を実行する必要があります。各指摘はImportant・Pre-existing・Nitのいずれかに分類され、要約の末尾には推奨される修正方法が付き、問題がないレビューでは「Code review found no issues.」と表示されるようになりました。

```bash
# バグ・CLAUDE.md違反だけを報告したい場合
/code-review

# 再利用性・簡素化・効率改善を別途報告したい場合
/simplify
```

**`/code-review`を実行するたびに本当のバグ指摘とスタイル面の提案が混在して優先順位をつけにくかったなら、v2.1.328以降は用途に応じて2つのコマンドを使い分ける方が、レビュー結果を素早く消化するのに役立ちます。** [リリースノート全体](https://github.com/anthropics/claude-code/releases)

### Opus 4.6・Sonnet 4.6もBedrock・GCP・Foundry・Claude appsゲートウェイでデフォルトでautoモードで起動 (v2.1.328)

**これまでautoモード（権限判断をセッションが自動で処理するモード）は主に最新モデルでのみデフォルト適用されていましたが、今回のリリースからAmazon Bedrock・Google CloudのAgent Platform・Microsoft Foundry・Claude appsゲートウェイでOpus 4.6とSonnet 4.6を使うセッションも対象に加わりました。** permissionモードを個別に指定していない対話型セッションは、これら4つのプラットフォームでも自動的にautoモードで起動するようになります。

```json
// プロジェクトの.claude/settings.jsonなど、適用範囲に合った設定ファイルに追加すると
// autoモードでの自動起動を無効化できます
{
  "disableAutoMode": true
}
```

**BedrockやFoundryなどでOpus 4.6・Sonnet 4.6を使っていてpermissionモードを個別に指定していなかった場合、v2.1.328へのアップグレード後にセッションが静かにautoモードで起動する可能性があることを踏まえ、これまでどおり毎ステップ確認を取りたいなら`disableAutoMode`で無効化しておくとよいでしょう。** [リリースノート全体](https://github.com/anthropics/claude-code/releases)

- **Reticle — AIコーディングエージェントがWeb・デスクトップアプリを直接操作して検証するツール (11/19)**: コーディングエージェントが機能を修正した後、実際にボタンを押したり値を入力したりしてログインや決済が意図どおりに動くかを確認し、クリック後のAPIリクエスト・レスポンス・コンソールエラー・画面変化まで併せて観察することで、決済ボタンを1回押しただけで注文が2回発生するような問題も検知します。各検証項目はPass・Fail・Inconclusiveのいずれかの結果を残し、ソースの位置が紐づいていればファイルと行番号まで表示され、一度検証したフローはFlowとして保存しておけば、AIモデルを使わずにCIで再実行できます。`npx @reticlehq/server`でWebプロジェクトを設定なしにすぐ検証でき、Claude Code・Cursor・CodexにMCP経由で接続できます。上記で触れたClaude Docsのchaos loopのような検証設計を、実際のアプリ操作まで自動化したツールとして参考になります。[GitHub](https://github.com/reticlehq/reticle) · [GeekNews](https://news.hada.io/topic?id=37440)
