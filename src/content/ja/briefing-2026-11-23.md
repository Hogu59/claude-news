## 開発者ワークフローティップス

### Code Modeでスクリプトが数千回ツールを呼び出してもターミナルがほぼ固まらなくなりました (v2.1.330)

**これまでCode Mode内でスクリプトが数千回単位でツールを呼び出すと、ターミナルがしばらく固まってしまっていましたが、今回のリリースからその固まる時間が大幅に短縮されました。** あわせて、ClaudeがCode Mode内で画像やPDFをどう読み込むべきかのガイダンスを受け取れるよう改善され、Escで中断したコマンドは赤いエラー表示ではなく「Interrupted」と表示されるようになりました。

```text
Code Modeスクリプトが数百〜数千個のファイルを巡回してツールを繰り返し呼び出す大量処理
  (例: 一括リファクタリング、大量のAPIチェックなど)
  → v2.1.330からターミナルの固まりが大幅に減少
```

**Code Modeで大量のファイルを巡回するスクリプトを実行するたびにターミナルがしばらく固まっていたという方は、v2.1.330にアップグレードすれば同じ処理でもかなり快適になったと感じられるはずです。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### `/ultrareview`がTeam・Enterpriseプランで残りの月間支出上限を事前に表示するようになりました (v2.1.330)

**これまで`/ultrareview`のコスト確認画面には今回のレビュー1回分の予想コストしか表示されず、チーム全体の月間支出上限にどれだけ余裕があるかは別途確認する必要がありましたが、今回のリリースからTeam・Enterpriseプランでは、残りの月間支出上限がレビュー1回分のコストより少ない場合にその数値も一緒に表示されるようになりました。**

```bash
/ultrareview
# → 確認画面に「今回のレビューの予想コスト」だけでなく
#    残りの月間支出上限がそれより少ない場合はその上限も一緒に表示
```

**チーム単位で`/ultrareview`を頻繁に実行しながら月間支出上限を超えないか毎回別途確認していたという方は、v2.1.330からは確認画面一つでその場に判断できるようになります。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### `claude --teleport`が一部環境でブランチを自動切り替えせず、gitコマンドのみ表示するようになりました (v2.1.330)

**これまで一部の設定では`claude --teleport`が選択したセッションのブランチに自動で切り替わっていましたが、今回のリリースからはブランチを切り替えるgitコマンドを画面に表示するだけで、実際の切り替えはユーザー自身が行う形に変わりました。** `-p`モードでは、ブランチを切り替えるまで終了コード1を返します。

```bash
claude --teleport
# → ブランチ切り替えのgitコマンドを表示するだけ(自分で実行する必要あり)
claude -p --teleport ...
# → ブランチを切り替えるまでは終了コード1を返す
```

**`--teleport`を自動化スクリプトに組み込んでブランチ切り替えまで任せていたという方は、v2.1.330にアップグレードした後はgitコマンドを実行するステップをスクリプトに直接追加しないと同じ動作にならない点に注意しておくとよいでしょう。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

- **Agent Office — Claude Codeのサブエージェントをピクセルオフィスとして表示するビューア (11/22)**: 複数のサブエージェントを同時に走らせると、ターミナルだけではどのエージェントが何をしていて、どこで止まっているのかが分かりにくいという課題から生まれました。メインエージェントを社長、サブエージェントを社員として表現し、Edit・Writeはタイピングで、Bashはモニター内のターミナルで表示し、ツール呼び出しが失敗すると「OOPS」の吹き出しが出て、3回連続で失敗するとモニターから煙が出ます。gitコミットでは紙吹雪が舞い、テスト通過時にはオフィス全体で拍手が起こり、コンテキスト圧縮はロボット掃除機で、使用量制限に達するとオフィスの照明が消えるといった表現になっています。画面上からそのまま権限プロンプトに答えられ、5分以上かかるコマンドには吹き出しが表示される仕組みで、Claude Codeのフックがローカルサーバーにデータを送ってSSEで更新する構造のため、ファイルの内容やコマンドの出力は保存せず、ツール名・作業名・レポートの1行目だけが残ります。`npx pixel-agent-office`でインストールできます。[GitHub](https://github.com/donasman/pixel-agent-office) · [GeekNews](https://news.hada.io/topic?id=37633)
- **Fast-Anything — アプリ全体ではなく遅い5%だけを見つけてRustに移植するコーディングエージェント向けツール (11/23)**: 関数をプロファイリングして実行時間と移植難易度でランク付けし、決定的でありふれたデータだけを扱う関数を選んで実際の呼び出し500件を記録、独立したRust crateと`TASK.md`を作成してコーディングエージェントに渡します。移植されたRustコードは、記録済みの呼び出しに加えてNaN・無限大・空入力といった派生入力まで再生し、元のコードと出力が一致するか検証、通過した変更だけが有効化され、無効化すれば元のバイト列にそのまま復元されます。公開されている例では、Pythonの文字列重複除去が4.91秒から42msに、PHPが2.94秒から53msに短縮されたと報告されていますが、コメント欄では、どの言語であれ書き直すこと自体で速くなる場合が多く、実際にはDBトランザクションやネットワーク呼び出しがボトルネックであることの方が多いという反論も出ています。`claude`・`codex`のように標準入力でプロンプトを受け取るコマンドと組み合わせて使えるほか、Claude CodeプラグインおよびMCPサーバー(ツール8個)としても提供されています。[GitHub](https://github.com/EL4CTEO/fast-anything) · [GeekNews](https://news.hada.io/topic?id=37645)
