## 主要な新機能と実践活用

### MCPサーバーのタスクをターミナルでも自動的にバックグラウンド処理します (v2.1.319)

**MCPサーバーがツール呼び出しをタスクとして実行すると、Claude Codeはターミナル上でもそのタスクを即座にバックグラウンドへ移し、完了したら結果をClaudeに通知するようになりました。** これまでは、時間のかかるMCPタスクが終わるまでターン全体が止まってしまうことがありました。タスクが終わる前にClaude自身に結果を待たせたい場合は、環境変数で以前の動作を維持できます。

```bash
# MCPタスクをバックグラウンドに移さず、ツール呼び出し内でそのまま待機させる
export CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND=1
```

**時間のかかるMCPタスク（大量データの取得や外部APIのバッチ処理など）を頻繁に呼び出しているなら、v2.1.319以降はそのタスクの完了を待つ間もセッションが止まらず、他の作業を続けられます。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### 権限プロンプトの代わりに自動で拒否する `permissions.denyInsteadOfPrompting` 設定が追加されました (v2.1.319)

**この設定を有効にすると、権限プロンプトの承認待ちが必要なツール呼び出しは、ターミナルセッション・サブエージェント・チームメイト（teammate）のいずれでも承認を待たずに即座に拒否され、ターンはそのまま進行します。** これまでは、無人環境やサブエージェントが承認の必要なコマンドに遭遇するとその場で停止してしまい、人が対応しなければ作業全体が止まることがありました。

```json
{
  "permissions": {
    "denyInsteadOfPrompting": true
  }
}
```

**承認者が常時待機していないバックグラウンド作業やCIパイプラインでClaude Codeを動かしているなら、この設定で権限が必要な呼び出しを静かに拒否しつつ残りの作業を続けさせることができます。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### `/claude-api latency-optimize` で自分のClaude APIコードのレイテンシ発生箇所を特定できます (v2.1.319)

**`/claude-api latency-optimize` は、自分が書いたClaude APIコードの中でユーザーを待たせている箇所を見つけ出し、自作のevalを基準により高速な設定を試します。** これまでは、API応答が遅いと感じても、どの呼び出し・どの設定がレイテンシを生んでいるのかを一つひとつ変えながら自分で確認する必要がある場合が多くありました。

```bash
/claude-api latency-optimize
```

**Claude APIを使ってユーザーへの応答速度が重要な機能を作っているなら、このコマンドでまずレイテンシの発生箇所を自動的に特定し、そこから最適化を始める方が効率的です。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## 開発者ワークフローティップス

### 曖昧なケースだけをOpusで再検討し、コストを4分の1に抑えたHightouchの事例です (11/6)

**顧客レコードが同一人物かどうかを判定する作業で、Hightouchは安価なモデルJevがまず全ケースを判定し、信頼度が曖昧な区間（約30〜90%）に入ったケースだけをOpusに再検討させるハイブリッド方式を試しました。** 易しいテストでは全体の22%だけをOpusに回し、精度98.8%（Opus単独では99.0%）を維持しながら1,000件あたりのコストを3.86ドルから0.88ドルに削減し、難しいテストでも精度95.3%（Opus単独では95.1%）を維持しつつコストを5.39ドルから2.94ドルに削減しました。

```text
confidence < 30%   → 安価なモデルの判定をそのまま採用
30% ≤ confidence ≤ 90% → Opusで再検討
confidence > 90%   → 安価なモデルの判定をそのまま採用
```

**分類・判定のように信頼度スコアを出せる作業をClaudeモデルで自動化しているなら、すべてのケースをOpusに通すのではなく、曖昧な区間だけを選別して回すこの方式で、精度をほぼ保ちながらコストを大きく削減できる可能性があります。** [GeekNews](https://news.hada.io/topic?id=36725)

### Claude apps gatewayの利用者は `/usage` で今日・今週・今月の支出をすぐ確認できます (v2.1.319)

**Claude apps gatewayの背後で作業していて、個別の支出上限が設定されていない開発者向けに、ゲートウェイがこのバージョン以上で動作していれば `/usage` に今日・今週・今月の支出が併せて表示されます。** これまでは、上限のない開発者は自分がどれだけ使っているかを確認する手段があまりありませんでした。

```bash
/usage
```

**組織のClaude apps gatewayを通じてClaude Codeを使いながら自分の利用傾向を自分で把握したいと思っていたなら、ゲートウェイのバージョンが合っていれば特別な設定なしに `/usage` でそのまま確認できます。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### `/tasks` の「Earlier in this session」で終了済みのサブエージェントを再度開いてメッセージを送れます (v2.1.319)

**`/tasks` に完了済みのサブエージェントをまとめて表示する「Earlier in this session」の行が追加され、一覧から消えたりセッションを再起動した後でも、そのサブエージェントを再び開いてメッセージを送れるようになりました。** これまでは、サブエージェントが作業を終えて一覧から外れると、その結果について追加で質問したくても再度アクセスする方法がありませんでした。

**複数のサブエージェントを同時に動かしていて、終わった作業の結果を後から見直したり追加で質問したりしたいことがあったなら、v2.1.319以降は `/tasks` でそのサブエージェントを再び見つけて続けて対話できます。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## セキュリティ・制限事項

### Claudeサービス稼働状況 — 11/4〜11/7、すべてインシデントなく全体正常です

**公式のstatus.claude.comを直接確認した結果、11/4から11/7（本日）まですべて「No incidents reported」と表示されており、claude.ai・Claude API・Claude Code・Claude Console・Claude Cowork・Claude for Governmentのすべてが「All Systems Operational」で正常な状態です。** 直近のインシデントは10/28に解決されたGoogle Calendar・Gmailコネクタのエラーです。

**ここ数日サービスの不具合に遭遇していたとしても、すでにすべて解消された状態なので、今日問題が発生するならまずローカルの設定やネットワーク側を点検してみるのが合理的です。** [Claude Status](https://status.claude.com)

### worktree作成時に発生していたsandbox escapeが修正されました (v2.1.319)

**新しいworktreeを作成する過程でサンドボックスを脱出できる不備が、このバージョンで修正されました。** リリースノートには具体的な再現手順は公開されていませんが、サンドボックスはClaude Codeが承認なしに実行するコマンドの影響範囲を制限する重要な安全装置であるため、そこから逃れる経路が存在していたという事実自体が重みのあるセキュリティ修正です。

**サンドボックスモードでClaude Codeを運用していてworktreeを頻繁に作成しているなら、v2.1.319に上げてこの問題が解消されたバージョンを使っているか確認しておく価値があります。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### 偽装した環境変数プレフィックスでBashの権限チェックを回避できた不備が修正されました (v2.1.319)

**コマンドの前に特定の方法で偽装した環境変数プレフィックスを付けると、そのコマンドの一部が権限チェックから見えなくなってしまうBashの権限回避の不備が修正されました。** これまでは、このような形で書かれたコマンドがdeny・askルールの目をすり抜けて実行される可能性がありました。

**Bashコマンドにdeny・askルールを設定して危険な操作を防いでいるなら、v2.1.319より前のバージョンでは環境変数プレフィックスを使ったコマンドがこの防御を回避できていた可能性がある点を踏まえて、アップグレードを急いだ方がよいでしょう。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### accept-edits・auto modeで `sed` コマンドが権限チェックをすり抜けていた問題が修正されました (v2.1.319)

**accept-editsモードとauto modeで、特定の形式の `sed` コマンドが権限チェックをすり抜けられる問題が修正されました。** `sed` はファイルを直接変更できるコマンドであるため、このチェックがすり抜けられると、意図しないファイル変更が承認なしに発生する可能性がありました。

**accept-editsやauto modeでClaude Codeを頻繁に動かしているなら、v2.1.319に上げて `sed` コマンドに対する権限チェックが正しく機能するバージョンを使っているか確認してみる価値があります。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## 知っておくと便利な小さな変更点

以下はすべて**v2.1.319**（11/6）の項目です。

- **`CLAUDE_CODE_DISABLE_FEATURE_FLAGS` 環境変数が追加**され、テレメトリは無効化せずにfeature flagだけを取得しないようにできます。この場合、すべてのflagは組み込みのデフォルト値を使用します。
- **`/context` がターミナルでClaudeに毎ターン全体のビジュアルグリッドを送っていた問題が修正**され、Claudeはテーブルのみを読み取るようになりました。
- **安全性チェックを受けられず作業が拒否されたにもかかわらず、auto modeで `claude -p` がexit code 0で終了していた問題が修正**され、テキスト・JSON出力のいずれもexit 1で終了するようになりました。
- **権限プロンプトが開いている間にノートブックの内容が変わると、`NotebookEdit` が間違ったセルを変更してしまう問題が修正**されました。
- **`/model` のモデルピッカーで古いモデルが現行モデルの後に長々と並んでいた表示方式が変更**され、「More models」という行にまとめて表示されるようになりました。
- **[VSCode] プラグインマーケットプレイスを削除する際に表示される確認画面が、その時点で実際にインストールされているプラグインを再確認するよう改善**されました。
- **[Claude Tag] Claude Tagが連携されたEnterprise組織のModels adminページにClaude Tagの行が追加**され、モデルのデフォルトを管理する画面に直接つながるようになりました。
