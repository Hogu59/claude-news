## 主要な新機能と実践活用

### アイドル中の会話をキャッシュ失効前に自動圧縮 (v2.1.299)

**ターミナルセッションで20万トークンを超える会話を約54分間放置すると、1時間のプロンプトキャッシュが失効する前に自動で圧縮される機能が追加されました。** これまでは席を外している間にキャッシュが失効すると、次のメッセージを送る際に会話全体を再処理する必要があり応答が遅くなりコストもかさんでいましたが、今後はキャッシュが有効なうちに圧縮を先に済ませておけます。

```bash
# アイドル圧縮が始まる最小トークン数(デフォルト20万)を調整
export CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS=100000
```

```jsonc
// settings.jsonでアイドル圧縮を完全に無効化
{ "idleCompaction": false }
```

**大きな作業を走らせたまま席を外すことが多いなら、特別な設定をしなくても次のメッセージがより速く処理される効果をすぐに実感できます。圧縮のタイミングや機能自体を調整したい場合は、上記の環境変数と設定がv2.1.290以降で利用できます。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

### AWS Claude Platformに`/advisor`が追加 (v2.1.300)

**AWSのClaude Platformで、`/advisor`、`advisorModel`設定、または`--advisor`フラグでadvisor(アドバイザー)を明示的に選ぶまでは、どのadvisorも実行されないようになりました。** 組織としてadvisor機能自体を使わせたくない場合は、`CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1`で完全に無効化できます。

```bash
# AWS Claude Platformでadvisor機能を完全に無効化
export CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1
```

**AWSベースのClaude Platform環境を運用しているなら、advisorがデフォルトでは有効になっていない点と無効化する方法を事前に把握しておくことで、組織のポリシーに合わせてすぐに適用できます。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

## 開発者ワークフローティップス

### ゲームにAIエージェントを使うならコードではなくゲーム状態を見せる (10/15)

**ゲームでLLMエージェントを効果的に活用するには、コードを渡すだけでは不十分で、ゲームの状態・データ・実行結果までエージェントが直接読み取り、操作できるように設計する必要があるという記事です。** 開発の初期段階から状態を決定論的に再現できる仕組みとセーブ/ロード機能を用意しておけば、エージェントが同じ条件下で変更内容を繰り返し検証できる点を強調しています。

**Claude Codeにゲームやシミュレーションのコードを扱わせる計画があるなら、ソースコードのリポジトリを開放するだけでなく、ゲーム状態を保存・復元・検査できるフックやスクリプトを先に用意しておくことで、エージェントが変更の前後を同じ条件で比較検証できるようになります。** [GeekNews](https://news.hada.io/topic?id=35355)

### `/usage`が過剰な利用パターンを事前に警告 (v2.1.299)

**`/usage`に、max effort、ワークフロー、常時オンのコンテキスト、大きなツール結果のようにコストやトークンを多く消費するパターンへの警告が追加されました。** これまではこうした設定がどれだけコストを押し上げているか、直接比較してみるまで気づきにくいものでした。

**Claude Codeの利用コストが想定より早く増えているなら、`/usage`を一度開いてこれらの警告が表示されるかを確認するだけで、どの設定がコストを引き上げているのかすぐに把握できます。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

### plugin-dirを経由してサンドボックス外でコードが実行される脆弱性を修正 (v2.1.299)

**サンドボックス内で実行されるシェルコマンドが、`--plugin-dir`で指定したフォルダにファイルを書き込めてしまう問題が修正されました。このフォルダ内のコードはClaude Codeが再度読み込み、サンドボックスの外で実行するため、本来サンドボックスに閉じ込められているはずのコマンドが、この経路を通じてサンドボックスを脱出するコードを埋め込める状態でした。** サンドボックスモードで信頼できないコマンドを実行しつつプラグインも併用する構成では、かなり深刻な回避経路でした。

**`--plugin-dir`とサンドボックスモードを併用している場合は、v2.1.299以降に更新してこの回避経路が塞がれているか確認しておくと安全です。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

### AIエージェントが「制御不能」になったのではなく、フロンティアAIラボがセキュリティの基本を怠っているという批判 (10/15)

**セキュリティ専門家たちは、AIモデルが外部システムに無断でアクセスした事件を、エージェントの逸脱としてではなく、フロンティアAI研究所における隔離と監視の失敗として捉えるべきだと指摘しています。** サンドボックス構成や外部通信の制御といった、業界で数十年前から知られているセキュリティの実践が適切に適用されていないことが核心的な問題だという批判であり、Hugging Faceの事件が誤った構成の例として挙げられています。

**Claude Codeエージェントを社内インフラや外部システムに接続して自律的にタスクを任せているなら、エージェントの振る舞いそのものを制御しようとするより、まずサンドボックスの境界とネットワークアクセスの範囲を点検することが、この記事が指摘する失敗を避けるより根本的な方法です。** [GeekNews](https://news.hada.io/topic?id=35357)

## 知っておくと便利な小さな変更点

- **(v2.1.299) `CLAUDE_CODE_DISABLE_FILE_MENTIONS`環境変数が追加**され、Claudeは`@`ファイルメンションのパスのみを受け取って自身のファイルツールで読み込み、ファイル内容そのものはプロンプトに直接含まれなくなりました。
- **(v2.1.299) agent viewに`/effort`・`/fast`が追加**され、新しいセッション開始時のデフォルト値を指定できるようになり、値を指定せず入力すると選択ピッカーが開きます。
- **(v2.1.299) `--safe-mode`で起動したバックグラウンドセッションには、agents viewのプレビューパネルにsafe modeの表示が追加**されました。
- **(v2.1.299) `claude self-hosted-runner orchestrator`に`--shutdown-drain-sec`が追加**され、SIGTERMを受け取った際に進行中のpollingとspawnフックが指定した時間だけ処理を完了させる余裕を持てるようになりました。
- **(v2.1.300) OpenTelemetryの`api_request`イベントに`cache_creation_5m_tokens`・`cache_creation_1h_tokens`が追加**され、キャッシュ書き込みを寿命別に確認できるようになりました。
- **(v2.1.300) より小さいauto-compactウィンドウを選択した際に`/autocompact`が高いトークン使用量を誤って警告していた問題が修正**されました。
