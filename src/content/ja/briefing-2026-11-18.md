## 開発者ワークフローティップス

### MCPサーバー設定をコマンドラインに残さずstdinで渡す `claude mcp add-json <name> -` が追加されました(v2.1.327)

**これまで`claude mcp add-json`でMCPサーバーを登録するには、JSON設定をコマンドライン引数として直接渡す必要があり、そこにトークンやAPIキーが含まれているとシェル履歴やプロセス一覧にそのまま残ってしまう危険がありました。** 今回、JSONの後に`-`を付けることでstdinから同じ内容を読み込めるようになり、機密情報をコマンドラインに晒さずに済みます。ただし、Claude Codeセッション内部(Bashツールなど)からはこの入力方式を使えません。

```bash
# MCPサーバー設定をトークンを露出させずに登録したい場合
cat server-config.json | claude mcp add-json my-server -
```

**CIスクリプトやシェル関数でMCPサーバーを自動登録する際、トークン入りのJSONをコマンドライン引数としてそのまま渡していたなら、v2.1.327からはこのstdin入力方式に切り替えることでシェル履歴にトークンが残るのを防げます。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### `/status` が壊れたagent・skill・command・hook設定を一覧で表示するようになりました(v2.1.327)

**`/status`に、壊れたagent・skill・command・output styleファイル、キーバインディングエラー、利用できないサンドボックス、無視されているpermission設定、そして一度もマッチしていないhook matcherまでをまとめて表示するリストが追加されました。** これまではこうした設定ミスが個別に散らばった形でしか見えなかったり、静かに無視されて原因を特定しにくい状態でした。

```text
/status を実行 → 壊れたagent・skill・command・output styleファイル / キーバインディングエラー /
利用できないサンドボックス / 無視されたpermission設定 / マッチしていないhook matcherを一つのリストで確認
```

**複数のskill・agent・hookを設定して使っていて、どの設定が静かに無視されているのか分かりにくかったという人は、v2.1.327にアップグレードした後に一度`/status`を実行してこの診断リストを確認してみる価値があります。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### セッション最初のBashコマンドの実行が速くなりました — 無効化したい場合は `CLAUDE_CODE_DISABLE_SHELL_HEAD_START`(v2.1.327)

**シェルの起動ファイル(`.bashrc`、`.zshrc`など)が、コマンドの承認前に先行して実行されるように変更され、セッション最初のBashコマンドがより速く始まるようになりました。** これはコマンド自体が拒否された場合でも同様に適用されるため、シェルの起動ファイルが承認の有無に関わらず先に動く可能性がある点は把握しておく必要があります。これまでのように承認後にのみ起動ファイルを実行したい場合は、以下の環境変数で無効化できます。

```bash
# シェル起動ファイルが承認前に先行実行される高速化を無効にしたい場合
export CLAUDE_CODE_DISABLE_SHELL_HEAD_START=1
```

**シェルの起動ファイルに重い初期化スクリプトを置いていて、Claude Codeの最初のBashコマンドが遅く感じられていたなら、v2.1.327からは特別な設定なしにこの高速化をすぐ体感できます。ただし起動ファイルの中に承認前に実行されてはいけない機密性の高い処理がある場合は、上記の環境変数で以前の動作に戻しておく方が安全です。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## セキュリティ・制限事項

### Claudeサービスの稼働状況 — 11/17のApple ログインエラーは解決済み、claude.aiは引き続きDegraded Performance表示

**公式のstatus.claude.comを確認したところ、11/17の16:40〜21:51 UTC(約5時間10分)の間、一部ユーザーがclaude.aiおよびClaude iOSアプリで「Sign in with Apple」によるログインができないインシデントが発生していましたが、原因が特定され修正がデプロイされて解決済みです。** Googleログインとメール登録はこの期間も影響を受けていませんでした。本日(11/18)新たに報告されたインシデントはありませんが、claude.aiは直近数日の履歴により依然としてDegraded Performance表示のままで、Claude API・Claude Code・Claude Console・Claude Cowork はいずれもOperational(正常)です。

**ここ数日claude.aiやClaude iOSアプリでApple IDによるログインができなかったという人は、11/17のこのインシデントが原因である可能性が高く、すでに解決済みなので再度試してみてください。Claude Code CLI自体はこのインシデントとは無関係に、通常どおり利用できます。** [Claude Status](https://status.claude.com)

### v2.1.327にシンボリックリンク・PowerShell・Bash変数展開をめぐる権限チェック強化が含まれています

**書き込み可能なパスを隠すタイプの一部シンボリックリンクをそのまま許可していたパスチェックが厳格化され、こうしたリンクへの書き込みを拒否するようになりました。** また、`permissions.blockReadsOutsideWorkingDirectories`がbypass・autoモードにおいてより多くのBashコマンドに確認を求めたり一部を拒否したりするよう変更され、`Read`や`Edit`のdenyルールが指定されたパスを指すBashコマンドについても、これまでは確認を求めるだけでしたが今後はより多くのケースで拒否されるようになりました。変数が非常に長いテキストに展開されるBashコマンドも拒否対象となり、短い値を使うかファイルに書き出すよう案内が表示されます。PowerShellツールは、特定のコマンドを許可するルールがあってももう一度確認を求めるように変更され、誰も応答できない状況では、全許可ルール・autoモード・bypass permissionsモードのいずれかでない限り拒否されます。

**サンドボックスやauto・bypassモードでClaude Codeを自動化パイプラインに組み込んでいる場合、v2.1.327へのアップグレード後、これまで静かに通過していた一部のコマンドが新たに確認を求められたり拒否されたりする可能性があることを念頭に置いておくとよいでしょう。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## 知っておくと便利な小さな変更点

以下はすべて**v2.1.327**(11/17)の項目です。

- **`/tui classic`という名前が追加**され、`/tui default`と並んでフルスクリーンではないレンダラーを指定できるようになりました。
- **`/export`が既存ファイルを確認なしに上書きしていた問題が修正**され、今後は先に確認を求め、`/export <name>`はファイルを保持したまま`/export`を再実行するよう案内するようになりました。
- **`/plugin`でクリック直後にEnterを押すと意図せずプラグインがインストール・無効化されてしまう問題が修正**されました。
- **Grepが`head_limit`と`offset`でページングする際に結果を重複表示したりスキップしたりしていた問題が修正**され、ファイルパス順にソートされるようになりました。
- **Readツールが10MB以上あって全体を読み込めないファイルのサイズを、実際のサイズではなく512KBと誤って報告していた問題が修正**されました。
- **VS Codeのエクスプローラーの右クリックメニューに、選択したファイル・フォルダをチャットへ直接@メンションできる「Claude Code: Add to Chat」が追加**されました。
- **autoモードが有料のclassifierリクエストにフォールバックする際の案内に、次回リリースでこのフォールバック自体が削除される予定である旨の文言が追加**されました。
