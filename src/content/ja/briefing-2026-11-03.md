## 主要な新機能と実践活用

### Code Reviewがクラウド・Remote Controlセッションでも検出結果をカードで表示します (v2.1.316)

**Claude DesktopのCodeタブやウェブ版から`/code-review`を開始すると、クラウドセッションと`claude remote-control`セッションの両方で、検出結果が構造化されたカード形式で表示されるようになり、単純なテキストリストのままにはならなくなりました。** これまでターミナルでは検出結果が見やすいカードで表示されていましたが、同じレビューをクラウドやRemote Controlセッションで開くと、長いテキストリストをそのまま読まなければならないことがありました。

**Claude Desktopやウェブでクラウドセッションを開いてコードレビューを進めているチームなら、v2.1.316からはターミナルと同様に重要度別に整理されたカードをすぐに確認できるようになり、レビュー結果をチームメンバーと共有するのも容易になりました。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## 開発者ワークフローティップス

### Claude Codeが自ら終了する際にmacOS・Linuxに残っていたゴーストシェルプロセスが解消されます (v2.1.316)

**認証情報が拒否されたり、クラウドセッションがアーカイブ処理されたりするなど、Claude Code自身がプロセスを終了する際、実行中だったシェルコマンドがmacOS・Linuxでそのまま残り続ける問題が修正されました。** これまでセッションが予期せず終了しても、そのセッションが起動したバックグラウンドコマンドがそのまま残ってしまい、`ps`で自分で見つけて片付けなければならないことがありました。

**長時間かかるビルドやサーバープロセスをBashツールで起動したまま、セッションが認証エラーやアーカイブ処理で突然終了してしまった経験があるなら、v2.1.316からはそうしたゴーストプロセスを手動で見つけて終了させる手間が減ります。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### 改行を含むbash aliasとハイフンで始まる関数名が壊れなくなりました (v2.1.316、Git Bashは対象外)

**複数行にわたって定義されたbash aliasや、名前がハイフンで始まる関数が、Bashツールのシェルで壊れたり丸ごと消えてしまったりする問題が修正されました。** ただしこの修正はGit Bashには適用されず、WindowsでGit Bashを使っている場合は依然として同じ問題が残っています。

```bash
# これまでBashツールで壊れたり消えてしまっていた形式
alias deploy='
  npm run build &&
  npm run test &&
  npm run deploy
'
-my-helper() { echo "改行aliasとハイフン関数名"; }
```

**シェル設定ファイルに複数行のaliasやハイフンで始まる関数名を定義していて、Claude CodeのBashツールでそのまま使っているなら、macOS・Linux・通常のターミナルではv2.1.316から問題なく動作するはずなので確認してみる価値があります。ただしGit Bash環境では依然として別のaliasで回避する必要があります。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### GitHub remoteがない場合の`/ultrareview`・クラウドセッションの案内メッセージがより明確になりました (v2.1.316)

**`/ultrareview`やクラウドセッション、クラウドエージェントがGitHub remoteを見つけられない場合、`https://github.com/new`でリポジトリを作成するよう具体的に案内するようになり、`/ultrareview`は`gh`が拒否する`gh`コマンドをもう提案しません。** これまでremoteがないローカルリポジトリでこれらの機能を使うと、原因が分かりにくいエラーや、実行しても失敗する`gh`コマンドの提案を受けることがありました。

**新しく始めたプロジェクトや、まだGitHubに上げていないリポジトリで`/ultrareview`やクラウドセッションを試してみようとしているなら、v2.1.316からはどこでリポジトリを作成すればよいかすぐに案内を受けられます。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## セキュリティ・制限事項

### Claudeサービス状況 — 10/31〜11/3までインシデントなく全サービス正常稼働

**公式のstatus.claude.comを直接確認した結果、10/31から11/3(本日)まで一貫して「No incidents reported」と表示されており、claude.ai・Claude API・Claude Code・Claude Console・Claude Cowork・Claude for Government全体が「All Systems Operational」の正常状態です。** 直近のインシデントは10/28に解決したGoogle Calendar・Gmailコネクタのエラーでした。

**ここ数日の間にコネクタやサービスのエラーに遭遇していたとしても、すでにすべて解消されている状態なので、本日問題が発生する場合はまずローカル設定やネットワーク側を確認してみるのが合理的です。** [Claude Status](https://status.claude.com)

### Team・Enterpriseログインのサーバー管理設定に署名検証が追加されました (v2.1.316)

**Team・Enterpriseアカウントでログインした際、Anthropic APIから取得するサーバー管理設定は別途の承認手続きなしにそのまま適用される一方、ローカルに保存された設定のコピーが署名検証を通過できない場合、そのコピーは拒否されるようになりました。** これまではローカルに残っている管理設定のコピーが改ざんされたり破損していたりしても、区別せずそのまま適用されてしまうことがありました。

**組織単位でmanaged settingsを通じてClaude Codeのポリシーを配布しているなら、v2.1.316からは破損・改ざんされたローカル設定のコピーが静かに適用されてしまうリスクが減った点を安心して反映してよいでしょう。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## 知っておくと便利な小さな変更点

以下はすべて**v2.1.316**(10/31)の項目です。

- **`autoMode.allow`リストに`$defaults`がないと組み込みの例外ルールが消えてしまう問題が修正**され、ホストアプリの`--settings`、`/permissions`で追加した最初のルール、`/auto-mode-setup`から取り込んだ組み込み例外が再び一緒に適用されるようになりました。
- **auto modeがサーバーから安全性評価の結果を受け取れずターンを停止した際、クラウドセッションとクラウド予約タスクが「失敗」と表示されない問題が修正**されました。
- **バックグラウンドエージェントがまだ作業中のときにauto modeがターンを停止すると、`claude -p`のテキスト出力が理由を伝えてくれないことがありましたが、修正**されました。
- **認証情報のような名前の環境変数に`1`のようなスイッチ値が入っていると、プラグインMCPの`headersHelper`スクリプトが破損した`CLAUDE_PLUGIN_ROOT`とサーバーURLを受け取ってしまう問題が修正**されました。
- **会話の一部が保存中に`/clear`や`/resume`を実行すると、その会話を再開した際にplanが復元されないという稀な問題が修正**されました。
- **幅の狭いターミナルで初回起動時の設定が、セキュリティ案内やターミナル設定の説明の一部の単語を欠落させてしまう問題が修正**されました。
- **[Windows] rcファイルがerrexit・pipefailを設定していて、winpty aliasのみが定義されている場合や全く定義されていない場合に、Git BashでBashツールがalias・関数を失ってしまう問題が修正**されました。
- **[Cloud sessions] Enterpriseメンバーが自分のクラウド環境でネットワークsecretを直接追加・削除**できるようになりました。これまでは閲覧のみ可能でした。
