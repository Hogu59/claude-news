## 開発者ワークフローティップス

### 自動圧縮の繰り返し失敗で「Prompt is too long」が出ていた問題が修正されました（v2.1.332）

**これまでは自動圧縮が何度か失敗すると、コンテキスト上限でもう一度圧縮を試みれば続けられたはずのターンでも、そのまま「Prompt is too long」で終了してしまっていましたが、今回のリリースからはその状況でもう一度圧縮を試みるよう修正されました。** 同じリリースで、圧縮の要約が出力上限を超えて切り詰められ続ける場合も、3回切り詰められた後の最後の試行ではより短い要約を要求するように変更されています。

```text
長い会話で自動圧縮が繰り返し失敗する状況
  → （これまで）「Prompt is too long」でターンがそのまま終了
  → （v2.1.332以降）上限でもう一度圧縮を試みて継続
```

**コンテキストをいっぱいに使った長いセッションで、圧縮の失敗によって作業が突然終わってしまった経験があるなら、v2.1.332にアップグレードすればそうした状況でもう一度圧縮が試みられることを踏まえて、長いセッションを続けてみる価値があります。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### 読み取り上限を超える大きなファイルを@-mentionすると、Claudeがファイルサイズと読み取り方法を案内されるようになりました（v2.1.332）

**これまでは拡張子付きのテキストファイルを@-mentionした際、最初の2,000行だけで読み取り上限を超えると、そのファイルは黙って丸ごと除外され、Claudeはそのファイルが存在したことすら把握できませんでしたが、今回のリリースからはClaudeがファイルサイズと残りを読む方法を案内されるようになりました。**

```text
@large-log.txt（2,000行を超える大容量ログ）
  → （これまで）ファイルが黙って除外され、Claudeは存在自体を知らない
  → （v2.1.332以降）Claudeがファイルサイズと残りを読む方法を案内される
```

**大容量のログやデータファイルを@-mentionしても何も反応がなかった経験があるなら、v2.1.332以降はClaudeがそのファイルの存在とサイズを認識するようになったので、Grepやoffsetでピンポイントに必要な部分だけ読んでもらうよう続けて依頼してみる価値があります。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### PreToolUseフックが拒否した理由が、Read・Grep・Glob・Edit・Writeの承認画面にも表示されるようになりました（v2.1.332）

**これまでPreToolUseフックが承認を求める際に記載した理由（reason）は、Bashコマンドの承認画面では表示されていましたが、Read・Grep・Glob・Edit・Writeの承認画面には表示されませんでした。今回のリリースからはこの5つのツールの承認画面にも、フックが記載した理由が併せて表示されるようになりました。**（anthropics/claude-code#102892, anthropics/claude-code#105343）

```json
{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Read", "hooks": [{ "type": "command", "command": "check-sensitive-path.sh" }] }
    ]
  }
}
```

**PreToolUseフックで機密パスへのRead・Editを止めつつ理由を記載していても、Bash以外のツールではなぜ止められたのか見えず困っていたなら、v2.1.332からは5つのツールすべてでフックが記載した理由をそのまま確認できるようになったので、試してみる価値があります。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## 知っておくと便利な小さな変更点

以下はすべて**v2.1.332**（11/25）の項目のうち、11/26・11/27のブリーフィングおよび上記で取り上げていないものです。

- **起動時のヘッダーにCyber Verification Programの等級が表示**されます。claude.aiアカウントでログインしていて、その等級が現在のモデルに適用されている場合にモデル名の横に表示されます。
- **別のセッションから届いたメッセージによって今のセッションが別のモデルに切り替わっている場合、モデルを自分で選び直すまでその事実を知らせるフッター行が追加**されました。
- **`/schedule`・権限プロンプト・`/loop`のクラウド提案が「routine」や「cloud schedule」ではなく「cloud scheduled task」と表現**されるようになりました。`/routines`コマンド自体はそのまま動作します。
- **macOSでコンピュータ使用がオンのとき、`computer-use`が予約されたskill名**になりました。同じ名前のスキルやコマンドはこれ以降読み込まれなくなり、起動時に名前を変更するよう案内が表示されます。
- **`--model default`やDefault選択で該当モデルが利用できない場合、エラーで停止する代わりに以前のモデルへフォールバックするよう変更されました**（autoモードでは、autoモードが許可するモデルにのみフォールバックします）。

## 注目プロジェクト＆ツール

- **ARCUS-STACK — Claude Codeなど複数のAIコーディングエージェントが同じSKILL.mdを共有するスキルパック（11/27）**：エージェントごとにスキルやルールのフォーマットが違うせいで、同じ作業指示を何度も書き直さなければならなかった不便さから生まれ、すべてのスキルをSKILL.md標準で記述することで、Antigravity・Claude Code・Codex・Cursor・OpenCodeが同じファイルをそのまま読み込めるようにしています。MCPサーバーなしでマークダウンの指示だけで動作し、`/arcus-plan`で原因・影響範囲・検証条件を含む計画書を作成し、`/arcus-work-loop`でチェックリストを一つずつ実装した後、`/arcus-review`で新しいサブエージェントにコミットをレビューさせるという流れを提供します。UIの代替案比較、DBマイグレーションの段階的な分割、繰り返されるミスをルール文ではなく型・リンター・テストで防ぐスキルも収録されています。`npx skills add sacru2red/arcus-stack -g -y`でインストールでき、MITライセンスです。複数のAIコーディングエージェントを併用していて、Claude Code用のスキルとCursor用のルールを別々に管理していたなら、ひとつのSKILL.mdに統合してみる価値があります。 [GitHub](https://github.com/sacru2red/arcus-stack) · [GeekNews](https://news.hada.io/topic?id=37932)
- **CarryOn — Claude Code・Codexなど、AIコーディングセッションのコンテキスト使用量を一画面で確認できるアプリ（11/27）**：複数のターミナルタブを開いて作業していると、どのセッションのコンテキストが埋まりかけているのか見落としやすいという課題から生まれ、コンピュータ上で動いているClaude Code・Codex・Gemini CLI・Asideのセッションを一つのリストにまとめて、コンテキスト使用率をパーセントで表示し、応答待ちのセッションは別に表示します。設定でオンにしておくと、Claude CodeとCodexが基準値（デフォルト85%）に達した際にセッション履歴をバックアップしたうえで自動的に`/compact`を実行し、同じWi-Fi上のスマートフォンからもセッションを確認・整理できます。既存のセッション履歴をローカルで読み取るだけでアカウントなしでも使えますが、ソースは非公開で、`/compact`実行時には要約のために会話内容がモデルプロバイダーに送信される点は留意すべきです。複数のClaude Codeセッションを同時に動かしながら、コンテキストがどれだけ埋まっているかを毎回`/context`で確認していたなら、一度インストールするだけで一画面でまとめて確認できるようになります。 [プロジェクトサイト](https://carryon-app.pages.dev/?s=gn) · [GeekNews](https://news.hada.io/topic?id=37936)
