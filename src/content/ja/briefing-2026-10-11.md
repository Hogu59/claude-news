## 主要な新機能と実践活用

### Claudeアプリゲートウェイにcodeポリシーキーを追加 — Claude Desktop Codeタブもゲートウェイで統制可能に (v2.1.296)

**Claudeアプリゲートウェイの`managed.policies[]`に`code`キーが追加され、ターミナル用の`cli`キーと同じ設定をClaude DesktopのCodeタブにもそのまま適用できるようになりました。** これまでは`desktop`キーでClaude Desktop全体を統制していましたが、`code`キーを指定するとCodeタブにもゲートウェイモードが有効になり、組織が定めたモデル・ツール・権限ポリシーがターミナルセッションと同様に適用されます。

```jsonc
// ゲートウェイのmanaged.policiesにcodeキーを追加
{
  "managed": {
    "policies": [
      { "cli": { /* 既存のCLIポリシー */ } },
      { "code": { /* Claude Desktop Codeタブにも同じポリシーを適用 */ } }
    ]
  }
}
```

**組織としてClaudeアプリゲートウェイでClaude Codeの利用を統制している場合、Claude DesktopのCodeタブだけがポリシーの適用範囲から外れていないか、この更新を機に確認しておくとよいでしょう。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## 開発者ワークフローティップス

### CLAUDE_CODE_OVERLOADED_RETRY_MAX_DELAY_MS — 過負荷時の再試行の最大待機時間を延長 (v2.1.296)

**新しい環境変数`CLAUDE_CODE_OVERLOADED_RETRY_MAX_DELAY_MS`を設定すると、サーバーが過負荷(529)応答を繰り返す際に再試行のバックオフが到達できる最大遅延時間を好きなだけ延ばせます。** 10/6のブリーフィングで紹介した`CLAUDE_CODE_OVERLOADED_RETRY_BASE_DELAY_MS`はバックオフの開始遅延を調整する変数でしたが、今回追加された変数は反対側、つまり最大遅延を調整します。

```bash
# 過負荷応答の再試行における最大待機時間を延ばし、長時間にわたり安定して再試行できるようにする
export CLAUDE_CODE_OVERLOADED_RETRY_MAX_DELAY_MS=120000
```

**トラフィックが集中する時間帯に529エラーでセッションが頻繁に切断される場合は、基本遅延時間の変数と最大遅延時間の変数を併せて調整し、再試行の間隔に余裕を持たせておくことで、無人実行中のセッションが途中で切断されるリスクを減らせます。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### コーディングエージェントが遅くなる本当の原因は、モデルではなく委任構造です (10/10)

**AI支援開発そのものは急速に進化しましたが、モデルをコードベースやシステムに接続するエージェントは、タスク管理・委任・コミュニケーションの段階で依然としてボトルネックになっているという分析です。** タスクをサブタスクに分割しても、並列実行やモデルごとの役割分担が不十分だと、簡単な作業まで低速で高コストなモデルに任せたり、人間が改めて手を入れ直す必要が生じる状況が繰り返されると指摘しています。

**Claude Codeで複数のサブエージェントを動かしていて全体の処理が遅いと感じる場合は、モデルを変えるよりも先に、どんな基準でタスクを分割し、どのサブエージェントにどの権限・モデルを割り当てるか、委任構造自体を見直す方が効果的かもしれません。** [GeekNews](https://news.hada.io/topic?id=35104)

## セキュリティ・制限事項

### Claudeサービス状況 — Claude Consoleは4日連続のパフォーマンス低下、その他は正常 (10/11)

**公式のstatus.claude.comを直接確認したところ、10/11時点でclaude.ai・Claude API・Claude Code・Claude Cowork・Claude for Governmentはすべて正常稼働(Operational)ですが、Claude Console(platform.claude.com)は10/7に始まった使用量データの読み込み遅延により4日連続でパフォーマンス低下(Degraded Performance)の状態が続いています。** 公式のアナウンスでは中心的な機能(core functionality)には影響がないと説明されており、10/8以降は新たに報告されたインシデントはありません。

**Claude Consoleの使用量ダッシュボードの数値が依然として最新の状態と合わない場合は、このパフォーマンス低下がまだ続いているということであり、Claude Code自体の作業やAPI呼び出しには影響がないため通常どおり使用して問題ありません。** [Claude Status](https://status.claude.com)

**実際のウェブサイトと自由にやり取りする自律エージェントのテストを運用している場合、モデルが事実確認をせずに第三者のシステムへ内容を送信するような行動まで取り得ることを念頭に置き、外部への書き込み系アクションには承認ステップやアクセス範囲の制限を別途設けておくのが安全です。** [GeekNews](https://news.hada.io/topic?id=35109)

### Telegram Desktopの脆弱性で、仕込まれたリンクのクリックからローカルファイルが窃取される恐れがありました (10/10)

**Telegram Desktop 7.2.8以下のバージョンでは、仕込まれたリンクをクリックすると、実行中のTelegramプロセス間通信(IPC)の区切り文字処理の脆弱性を通じてローカルファイルが攻撃者が所有するチャットへ流出する恐れがありました。** ローカルパスコードが設定されていない場合はセッションファイルまで窃取され、アカウント自体が乗っ取られるレベルのリスクでした。

## 知っておくと便利な小さな変更点

以下はすべて**v2.1.296**(10/9)の項目です。

- **Windows: `claude plugin install`がSSH鍵のないマシンでGitHub owner/repo形式のプラグインソースをインストールできなかった問題を修正**し、クローンをHTTPSで再試行するようになりました。
- **Windows: stdio MCPサーバー終了時、強制終了の前にまずstdinを閉じ、300ms後もサーバーが生きている場合のみプロセスツリーを終了するように変更**されました。
- **`--debug`フックログにコマンド・プラグイン・結果・所要時間が合わせて記録**されるようになり、遅いフックをすぐに特定できます。
- **autoモードで、確認すべき根拠がなく実行されなかったツール呼び出しが、赤いエラーの代わりに薄い色の「Not run」行として表示**されるようになりました。
- **[Claude Tag] Slackスレッドのセッションリンク・モデル・コストを表示するフッターが、直近の回答にのみ表示**されるようになり、それより前の回答からは外れるようになりました。
- **[Code Review] レビューが完了してもPRで「進行中」と表示され続けていた問題を修正**し、レビュー結果が正しく反映されるようになりました。
