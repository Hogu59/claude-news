## 主要な新機能と実践活用

### CLAUDE_CODE_AUTO_MODE_MODEL — クライアント側auto modeクラシファイアが使うモデルを直接指定できます (v2.1.302)

**新しい環境変数`CLAUDE_CODE_AUTO_MODE_MODEL`で、auto modeのクライアント側クラシファイアが使うモデルを直接指定できるようになりました。** ただしこの変数はサーバー側(server-side)のauto modeが使うモデルには影響せず、クライアント側クラシファイアにのみ適用されます。

```bash
# クライアント側auto modeクラシファイアに、より速くて安価なモデルを指定
export CLAUDE_CODE_AUTO_MODE_MODEL=claude-haiku-5-5
```

**auto modeでClaude Codeを運用しながらクラシファイアの判定速度やコストを調整したいなら、この変数でクラシファイア専用のモデルだけを切り替えてみられます。サーバー側auto modeを使っている組織の場合は、この設定が適用されない点を先に確認しておく必要があります。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

### Fork subagentがclaude -p・Agent SDK・デスクトップアプリ・VS Codeでもデフォルトで有効になります (v2.1.302)

**ターミナルでは既にデフォルトだったfork subagent(`subagent_type: "fork"`)が、`claude -p`、Agent SDK、デスクトップアプリ、VS Codeでもデフォルトで有効になるよう変更されました。** `CLAUDE_CODE_FORK_SUBAGENT=0`で無効化でき、`claude mcp serve`はそもそもこのオプションを提供していません。合わせて、デスクトップアプリやVS Codeのメイン会話に属するサブエージェントはターミナルと同様に常にバックグラウンドで実行され、逆にサブエージェント自身が起動するAgent呼び出しは`claude -p`・SDK・デスクトップアプリ・VS Codeでデフォルトでフォアグラウンド実行されるようになりました。

```bash
# fork subagentのデフォルト動作をオフにしたい場合
export CLAUDE_CODE_FORK_SUBAGENT=0
```

**デスクトップアプリやVS Code、Agent SDKでサブエージェントを頻繁に起動しているなら、今回の変更でバックグラウンド/フォアグラウンド実行のデフォルトがターミナルと揃った点を踏まえて、既存の自動化スクリプトの前提を見直しておく価値があります。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

**自作の参照カウンタや共有メモリ構造体が古いCコードベースに残っているなら、今回のケースのように小さな整数オーバーフローが数十年経ってから見つかることもあるという点を踏まえて、カウンタのビット幅と競合状態の可能性を見直してみる価値があります。** [GeekNews](https://news.hada.io/topic?id=35491)

## 知っておくと便利な小さな変更点

以下はすべて**v2.1.302**(10/16)の項目です。

- **`/config`にIdle compaction行が追加**され、アイドル中の会話の自動圧縮をオフ・オンに切り替えられるようになり、圧縮後の案内文にオフにする方法も表示されます。
- **プロンプト・エージェントのフックが同じイベントにつき最大12個までしか同時実行されない**ように変更され、残りは順番待ちになります。
- **サーバー側クラシファイアを使うauto modeが改善**され、安全性チェックに使うには長すぎる会話の場合、確認済みのツール呼び出しをすべて拒否する代わりに会話を圧縮してから処理を進めるようになりました。
- **gitがreftable参照フォーマットをデフォルトで使う環境で、プラグインマーケットプレイスが更新のたびに再クローンされ、新規インストールしたgitプラグインのバージョンが「unknown」と表示される問題が修正**されました。
- **PowerShellツールがプラグインの`bin/`フォルダ内のコマンドを見つけられない問題、検索結果が空の場合に`Select-Object`などに渡すとエラーになる問題が修正**されました。
- **Windows: exFAT・FAT32ドライブ上のプロジェクトでファイル書き込みがすべて拒否されたり、毎回確認を求められたりする問題が修正**されました(`--plugin-dir`で開始したセッションを含む)。
