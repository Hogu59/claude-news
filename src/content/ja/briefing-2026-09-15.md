## 主要な新機能と実践活用

### Remoteセッションにもfast modeが適用されます(v2.1.271)

**クラウドセッションやセルフホストランナー上で動くRemoteセッションでも、fast modeがサポートされるようになりました。** **ホスト側のfast-mode設定やセッション内で入力した`/fast`が、組織が許可する範囲内でそのまま適用されます。**

```bash
# Remoteセッション内でfast modeをオンにする
/fast on

# 現在のfast mode状態を確認
/fast
```

**ターミナルを直接開かずクラウドや自前のランナーでセッションを動かしているチームなら、これまでローカルセッションでしか使えなかったfast modeをリモート実行にも同じように適用できます。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

### autoモードのサンドボックスにコマンド単位の`allowed_domains`が追加されます(v2.1.271)

**Bash、PowerShell、Monitorがautoモードでサンドボックス化される際、各コマンドが実際に必要とするホストだけがそのコマンドとともに検討され、そのコマンドに限って許可し、残りのホストは拒否するよう細かくなりました。** 従来はセッション全体にかかる許可リストをすべてのコマンドが共有していましたが、これからはコマンド単位でアクセス範囲を絞り込めます。

**パッケージインストールや外部API呼び出しのように特定のホストだけにアクセスすればよいBashコマンドをautoモードで頻繁に実行しているチームなら、セッション全体の許可リストを広げることなく、コマンドごとに必要なドメインだけを開放して攻撃対象領域を減らせます。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

### `omitClaudeMd` — CLAUDE.mdなしでサブエージェントを実行します(v2.1.271)

**カスタム・プラグインサブエージェントがユーザー・プロジェクト・ローカルのCLAUDE.mdファイルを一切読み込まずに実行されるようにする`omitClaudeMd`が、エージェントのfrontmatterと`--agents`のJSONに追加されました。管理ポリシーファイルはこの設定に関係なく引き続き読み込まれます。**

```yaml
---
name: reviewer
description: コードレビューだけを専任するサブエージェント
omitClaudeMd: true
---
```

```bash
# --agentsのJSONでも同じように指定できます
claude --agents '[{"name":"reviewer","omitClaudeMd":true}]'
```

**リポジトリルートのCLAUDE.mdが特定のサブエージェントの狭い役割と無関係だったり、むしろコンテキストを無駄にしていたりする場合、このオプションでそのサブエージェントだけをCLAUDE.mdなしですっきり起動できます。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

**Claude Codeに機能実装を任せる前に、取り消しにくい決定だけを絞り込んで短い設計文書にまとめさせ、そのレビューを通過してから実装を始めさせれば、誤った前提の上にコードが積み上がるのを事前に防げます。** [GeekNews](https://news.hada.io/topic?id=33696)

### 高速なTokioアプリケーションの原則 — ポーリングをなくすより、実際の指標から出発する(9/15)

**Tokioランタイムのパフォーマンスは、公平性とバッチ処理、競合と分離のバランスにかかっており、同じタスクでもランタイム上で一緒に実行される他のタスク次第で体感速度が変わるという分析です。** **最適化は長いポーリングそのものを無条件になくすところから始めるのではなく、実行準備から実際のポーリングまでにかかる時間のように、本当に改善すべき指標を先に定めてから取り組むべきというのが要点です。**

**Claude Codeのバックグラウンドエージェントやワークフローツールで非同期タスクを複数同時に動かしているなら、特定のエージェントが遅く感じるときにむやみに並行度を下げるのではなく、実際のボトルネックが何かをまず計測するアプローチが有効です。** [GeekNews](https://news.hada.io/topic?id=33708)

**AIエージェントがパッケージレジストリのインフラ脆弱性そのものを自ら発見し悪用しうるという事例であるだけに、Claude Codeでパッケージ配布やレジストリのスクレイピングパイプラインを自動化しているなら、エージェントがアクセスするサービスのキャッシュ・認証境界を人間側で別途点検しておくのが安全です。** [GeekNews](https://news.hada.io/topic?id=33701)

## 知っておくと便利な小さな変更点

以下はすべて**v2.1.271**(9/14)の項目です。v2.1.272(9/15)は詳細な変更点が公開されていません。

- **動的ワークフローのデフォルトサイズがProプランでsmallに引き下げられ、mediumサイズのガイドラインもエージェント15体から10体に減ります。**
- **Monitor watchに常に締め切りが設定されるようになります。** 最大30分(単発の`-p`実行は10分)経過するとClaudeに再度かけ直すよう通知する方式で、無制限に待機できた`persistent`オプションを置き換えます。
- **autoモードで、スキルやスラッシュコマンド内のインライン`!`シェルコマンドが、classifierではなくdefaultモードの権限ルールに従うよう変わります。** どのルールにも該当しないコマンドは、レビュー対象のツール呼び出しとして実行されます。
- **`claude plugin install`・`update`に`--accept-command <sha256>`が追加され**、直前の`--json`実行で表示されたコマンドを正確に指定して承認できるようになりました。包括的に承認する`-y`の代わりに使えます。
- **`modelPricing`の管理設定とClaudeアプリゲートウェイの`pricing`ブロックに1〜10倍の`multiplier`が追加され**、社内chargeback用のマークアップ率を設定できるようになりました。
- **アカウント・組織・APIキーを切り替えた後もキャッシュされた組織ポリシーがそのまま再利用されていた問題**が修正され、認証情報が変わると1時間ごとのチェックを待たずに即座に更新されるようになりました。
- **サンドボックス化されたコマンドが起動に失敗した後に残る古い`.git/config.lock`が、セッション中ずっと`git checkout -b`・`push -u`・`git config`を妨げていた問題**(Linux)が修正されます。
- **Markdownファイルをアーティファクトとして公開すると、見出しヘッダーやドキュメントのタイポグラフィ、シンタックスハイライトが適用されたドキュメントページとしてレンダリング**されるようになります。
