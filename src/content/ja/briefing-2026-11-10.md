## 主要な新機能と実践活用

### Claude Fable 5.2が既定のFableモデルとして追加され、Artificial Analysisで過去最高の65点を記録 (v2.1.321)

**`claude-fable-5-2`が新しい既定のFableモデルとして追加されました。** 100万トークンのコンテキストに対応し、価格は入力100万トークンあたり8ドル、出力100万トークンあたり40ドル、キャッシュ読み取りは100万トークンあたり0.20ドルです。同日GeekNewsに掲載されたArtificial Analysisのベンチマークによると、Max設定のFable 5.2はIntelligence Indexで65点を獲得し、同価格帯モデルの中央値(40点)を大きく上回りました。ただしその代償も明確で、タスクあたりの処理時間は44.1分(比較対象モデルの中央値12.9分)、最初の応答トークンが出るまでの時間は231.55秒(比較対象モデルの中央値13.07秒)、タスクあたりの平均コストは26.54ドルと、比較対象モデルよりかなり時間がかかり高額です。

```bash
# Fable 5.1を引き続き使いたい場合(保存済みの選択は自動的に5.2へ移行します)
/model claude-fable-5-1
```

**Fableモデルに深い推論が必要なタスクを任せているなら、v2.1.321から既定値がFable 5.2に変わり、インテリジェンススコアは大きく上がる一方で応答を待つ時間とコストも増えるため、タスクの性質に合わせてモデルを選ぶ必要があります。** [GeekNews](https://news.hada.io/topic?id=36910) · [全リリースノート](https://github.com/anthropics/claude-code/releases)

### `claude remote-control`に`--settings <file>`オプションが追加され、セッションごとに設定ファイルを適用できるようになりました (v2.1.321)

**このオプションで指定した設定ファイルは`claude remote-control`が起動するすべてのセッションに適用され、ファイルを変更しても`claude remote-control`を再起動するまで新しいセッションには反映されません。**

```bash
claude remote-control --settings ./remote-settings.json
```

**リモートで複数セッションを起動して運用する際、セッションごとに同じ設定を毎回指定し直す必要があったなら、このオプションで設定ファイル1つをすべてのセッションに一貫して適用できます。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

### 保存済みのFable 5.1選択がv2.1.321から自動的にFable 5.2へ切り替わります

**Pro・Maxプランは一括で、Team・Enterpriseプランは組織が許可するタイミングに合わせて、セッションに保存されたFable 5.1のモデル選択がFable 5.2へ移行されます。** これまでFable 5.1を既定として指定して使っていた場合、次のセッションからは案内なしに、より遅く高額な5.2が代わりに使われる可能性があります。

```bash

```

**短い応答が重要なタスクにFableモデルを固定して使っていたなら、v2.1.321へのアップグレード後に応答速度が目立って遅くなっていないか確認し、必要なら上記のコマンドで5.1に戻すとよいでしょう。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

### AIに会社のコンテキストを与えるには暗黙知を文書化し、検証担当者を別途割り当てましょう (11/9)

**AIが自社固有の基準に沿って答えるには、指標の計算方法、承認基準、社内用語のように推測できない情報を文書としてまとめ、実際の業務ツールと連携させる必要があるという提案です。** 頻繁に変わる情報はモデルを再学習させるよりも検索や最新データの参照で提供するほうが適切で、正解が分かっている質問で定期的に検証し担当者を割り当てることで、個人にしか残らない知識が組織の資産として残ります。

```text
指標の定義・承認基準・社内用語  → 文書化 + 業務ツールと連携
頻繁に変わる情報              → ファインチューニングではなく検索/最新データの参照
正解が分かっている質問        → 定期的な検証 + 担当者の割り当て
```

**CLAUDE.mdや社内スキルに自社固有のルールを書いておいても時間が経つと内容が古びていくと感じていたなら、この3段構成をそのままCLAUDE.mdの運用ルールに適用してみる価値があります。** [GeekNews](https://news.hada.io/topic?id=36856)

## セキュリティ・制限事項

### Claudeのサービス稼働状況 — 11/8にFable 5.1のパフォーマンス低下が14分間発生、11/9はインシデントなし、11/10時点で全サービス正常稼働中

**公式のstatus.claude.comを直接確認した結果、11/8にClaude Fable 5.1のリクエストでエラーが増加するインシデントが発生していました(08:18〜08:32 UTC、約14分間、解決済み)。** 11/9は「No incidents reported」と表示され、11/10時点ではclaude.ai・Claude API・Claude Code・Claude Console・Claude Cowork・Claude for Governmentを含む全サービスが「Operational」で正常状態です。

**ここ数日サービスのエラーに遭遇していたとしても、すでに解消済みのインシデントなので、今日問題が発生するならまずローカルの設定やネットワーク周りを確認するのが合理的です。** [Claude Status](https://status.claude.com)

### MCPサーバーがリダイレクトを利用してOAuth認証情報を別のホストに送信してしまう不具合が修正されました (v2.1.321)

**MCPサーバーがOAuthリクエストを別のホストにリダイレクトさせると、refresh tokenなどの認証情報がそのホストにも一緒に送信されてしまう不具合が修正されました。** これはサーバー側が意図的にリダイレクトを設計するだけで認証情報を抜き取れたということを意味し、信頼できないMCPサーバーを使う際のリスクが大きかった不具合です。

**組織外から入手したMCPサーバーやカスタムOAuthを使うサーバーを接続している場合、v2.1.321にアップグレードしてこの経路でトークンが漏洩しないバージョンを使っているか確認する価値があります。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

### 読み取り専用のBashコマンドがサンドボックス外で権限プロンプトなしに実行されてしまう不具合が修正されました (v2.1.321)

**特定の状況で読み取り専用に分類されたBashコマンドがサンドボックスを外れて実行されながら、権限を確認しない不具合が修正されました。** サンドボックスはClaude Codeが承認なしに実行するコマンドの影響範囲を制限する重要な安全装置であるため、読み取り専用という分類を信用してプロンプトを出さずに通過していた経路があったという点で、重要度の高い修正です。同バージョンでは、Bashの権限チェックが誤ったフォルダへのファイル書き込みを判定できずプロンプトを表示しない問題、`cp`・`mv`でディレクトリに書き込むファイルにdenyルールと保護ファイルプロンプトが適用されない問題も併せて修正されました。

**サンドボックスモードでClaude Codeを運用しているなら、v2.1.321にアップグレードして読み取り専用コマンド・`cp`・`mv`関連の権限チェックがすべて意図通りに動作するバージョンを使っているか確認する価値があります。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

## 知っておくと便利な小さな変更点

以下はすべて**v2.1.321**(11/9)の項目です。

- **Claudeがセッション中に作成したmodが、auto mode・bypass modeでは確認なしに自動で有効化されるようになりました。** 管理者設定の`allowUnsandboxedCommands: false`や`allowManagedDomainsOnly`が設定されていても同様に適用され、`dontAsk`モードではロードされません。
- **mod自体のツール呼び出し(`$.tool.call`、`$.mcp.call`)が権限プロンプトを表示しなくなりました。** ユーザーが自分で設定したaskルールや`dontAsk`・`-p`実行でも同様で、denyルールと組織ポリシーはそのまま適用されます。
- **コンテキスト使用量の推定値が、正確なトークン数が分からない場合にツール定義を過大に集計していた問題が修正**されました。
- **Remote Controlのウェブ・モバイル画面で`/compact`が二重に表示されていた問題が修正**されました。
- **プラグインの自動更新と`/plugin`マーケットプレイスの更新が、リポジトリのワークツリーやフォルダごとに同じプラグインを重複してダウンロードしていた問題が修正**されました。
- **WebFetchが、ページを読み取るモデルがテキストを返さない場合に「応答なし」をページの内容としてClaudeに渡していた問題が修正**され、今後は明確なエラーとして失敗します。
