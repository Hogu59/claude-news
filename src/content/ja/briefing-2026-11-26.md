## 主要な新機能と実践活用

### ClaudeのアーティファクトをMac・Windowsのデスクトップアプリとしてインストールできるベータ機能が公開されました (11/24)

**これまでClaudeで作ったアーティファクトはClaudeの中でしか開けませんでしたが、Anthropicが公式ガイドでアーティファクトを専用アイコンと独立したウィンドウを持つMac・Windows向けのスタンドアロンアプリとしてインストールできる機能をベータ公開しました。** インストールしたアプリは他の人と共有でき、元のアーティファクトを修正するとアプリも自動で更新され、通知を送ったりメニューバー・システムトレイに項目を追加することもできます。全プランで利用可能で、Teamではデフォルトで有効になっており(フルコンピュータアクセス権限はデフォルトで無効)、Enterpriseではオーナーが有効化する必要があります。アプリはブラウザ相当の権限で起動しますが、プログラムの実行やファイルの読み取り・変更・削除を毎回確認せずに行える「フルコンピュータアクセス」権限を、自分が作成したアプリ(Team・Enterpriseでは組織メンバーが作成したアプリにも)に付与できます。Claude Docs・Slides・Sheetsなど一部のアーティファクトはインストールできず、HIPAA-ready組織やハイブリッドデプロイ環境では利用できません。また、Anthropicはインストール前にアプリをレビューしていないため、フルアクセス権限は信頼できるアプリにのみ付与するよう案内しています。

```text
1. Claudeに作りたいアプリを説明する
2. アーティファクトとして実行して確認する
3. Shareメニュー→「Install as app」をクリック
   → 専用ウィンドウ・アイコンを持つ独立したアプリが作成され、元を修正すると自動更新される
```

**社内ツールや個人用ユーティリティをアーティファクトとして作って使っていたなら、Claudeのウィンドウを常に開いておく代わりに独立アプリとしてインストールしてメニューバーや通知まで活用してみる価値があります。ただし、フルコンピュータアクセス権限は自分で作った、または信頼できるアプリにだけ有効にしておくのが安全です。** [Anthropic公式ガイド](https://claude.com/resources/articles/install-as-app)

## 開発者ワークフローティップス

### MCPサーバーが配布したskillが`/`メニューに`server:skill`として直接表示されます (ベータ, v2.1.332)

**11/24のブリーフィングで紹介したSkills over MCPの発表(サーバーが複数ステップの作業ガイドをskillとして一緒に配布する仕組み)が、わずか1日後のv2.1.332で実際のクライアントに反映され、MCPサーバーが配布したskillは`/`メニューに`server:skill`の形で区別されて表示され、該当サーバー以外のskillは元の名前のままになります。** 発表の翌日にそのまま動作に反映された形で、どのサーバーのskillなのか名前だけで見分けられるようになりました。

**複数のMCPサーバーをつないで使っていて、サーバーごとに配布されたskillが混ざってどこから来たものか分かりにくかったなら、v2.1.332にアップデートした後は`/`メニューの`server:skill`という接頭辞を見るだけで区別できるようになります。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### スキル・コマンド内のinlineシェルコマンドを横取りして拒否できる`PreSkillShellCommand`フックが追加されました (v2.1.332)

**これまでスキルやカスタムコマンドに埋め込まれたinlineシェルコマンドはロードされた瞬間にそのまま実行されていましたが、今回のリリースから`PreSkillShellCommand`フックイベントでその実行を横取りして拒否できるようになりました。** なお、2.1.331より前のバージョンでは、このフックを名前で登録した設定ファイルがあると起動時にダイアログが表示されます。

```json
// settings.jsonにPreSkillShellCommandフックを登録して
// スキル・コマンドのロード時にinlineシェルコマンドを検査・拒否する
{
  "hooks": {
    "PreSkillShellCommand": [
      { "hooks": [{ "type": "command", "command": "/path/to/validator.sh" }] }
    ]
  }
}
```

**出どころが不明なスキルやプラグインを組織内でインストールできるようにしているなら、`PreSkillShellCommand`フックでロード時点のinlineシェルコマンドをまず検査する仕組みを入れておく価値があります。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## 知っておくと便利な小さな変更点

以下はすべて**v2.1.332**(11/25)の項目のうち、上記で取り上げていないものです。

- **`claude auth login`がclaude.aiへのログインを保存できなかった際に「Login successful.」と誤表示していた問題が修正**され、今後はexit 1で終了し、ロックされたロックファイルやディスク容量不足といった確認すべき点を知らせるようになりました。
- **誰も使っていないnamed pipe(ロックされたシークレットマネージャーがマウントした`.env`など)をRead・@メンション・圧縮処理が待ち続けてハングしていた問題が修正**され、20秒後に失敗するよう変更されました。
- **イベントストリームが切断された後、新しいエンドポイントに復帰した、あるいは最終的に復帰しなかったSSE接続のMCPサーバーが、手動で再接続するまですべてのツール呼び出しを停止または拒否していた問題が修正**されました。
- **コピーに失敗したダウンロード済みプラグインのせいで`~/.claude/plugins/cache`に`temp_*`フォルダが積み重なっていた問題が修正**されました。
- **タブモードの音声入力でマイクをオンにしておく時間が、無音15秒・最大2分から無音60秒・最大10分に延長され**、終了時に未送信のテキストが残っていた場合は次のタブでそのまま続けて書けるようになりました。
- **Bedrock Mantleで`sonnet`エイリアスがHaiku 4.5に誤って紐付いていた問題が修正**され、今後はSonnet 5を指すようになり、これを利用できないアカウントは先に有効化が必要というエラーを受け取ります。
- **Claude appsゲートウェイの標準搭載モデル一覧でSonnet 5.5がSonnet 4.5の代わりになり**、Opus 4.6を許可しないポリシーではClaude Desktopが今後Sonnet 5.5で起動するようになりました。

- **Agent Run Inspector — Claude Code・Codexの実行過程をリアルタイムグラフで可視化するローカルツール (11/25)**: Claude CodeとCodex CLIがローカルに残す実行ログ(JSONL)を読み込み、オーケストレーター・サブエージェント・ツール呼び出しの関係をリアルタイムのグラフとタイムラインで表示し、エージェントごとのトークン使用量と推定コストも集計します。フックやプロキシを使わず既存の実行ログだけを読み取るため実行環境を変える必要がなく、Claude Codeのサブエージェント・Agent Teams(teammate)・Codex CLIに対応し、最近ではOrcaボットとワーカーの追跡も追加されました。サーバーは`127.0.0.1`でのみ開き、トークンでアクセスを制限し、外部通信はバージョン確認とユーザーが選択したアップデートのインストールのみに限定されています。複数のサブエージェントやエージェントチームを同時に動かしていて、どのエージェントが何をしていて、トークンをどれだけ使っているかをターミナルだけでは把握しづらかったなら、すぐに試してみる価値があります。[GitHub](https://github.com/th-yong/agent-run-inspector) · [GeekNews](https://news.hada.io/topic?id=37817)
- **Claude Navigation — Claude Codeが一度捨てたアプローチを繰り返さないよう、仮説・実行・評価で作業を整理するテンプレート (11/25)**: 長時間のClaude Code作業でコンテキストが圧縮されたりセッションが切り替わったりすると、すでに失敗した方法を再び試してしまう問題を減らすためのフォルダテンプレートで、サーバーや会員登録なしにフォルダをコピーするだけで使えます。`/pdca-init`・`/pdca-start`・`/pdca-status`・`/pdca-wrap`の4つのスラッシュコマンドで仮説・実行・評価・次の方向性を記録し、作業内容を記録しないとフックが応答をブロックして記録を強制します。捨てた方向性は理由と再試行の条件とともに残しておき、新しいサイクルを始める前にそのリストと照らし合わせるよう設計されています。オーケストレーションツールのような複雑な設定なしに、セッションが切り替わっても文脈と試行錯誤の履歴を軽く引き継ぎたいなら試してみる価値があります。[GitHub](https://github.com/ohohoh2018/claude-navigation-ko) · [GeekNews](https://news.hada.io/topic?id=37839)
