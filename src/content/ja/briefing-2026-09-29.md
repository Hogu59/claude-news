## 主要な新機能と実践活用

### Claude Sonnet 5.5リリース — デフォルトSonnetモデルを刷新、出力速度30%以上向上(v2.1.284)

**Claude Sonnet 5.5(`claude-sonnet-5-5`)がAnthropic APIのデフォルトSonnetモデルに指定されました。** 100万トークンのコンテキストに対応し、価格は従来のSonnet 5と同じく100万トークンあたり入力2ドル・出力10ドル、キャッシュ読み込みは0.20ドルです。GeekNewsによると、コーディングやドキュメント・スライド・スプレッドシート作業の性能が向上し、Sonnet 5比で出力速度が30%以上速くなったうえ、同じタスクに必要なトークン数自体が減ったことでAnthropic自身のテストでもコスト対効果が改善したとしています。

```bash
# APIでSonnet 5.5を明示的に指定
export ANTHROPIC_MODEL=claude-sonnet-5-5
```

**Claude Codeでデフォルトのsonnetモデルを使っていた場合は特に設定を変えなくても自動的に5.5へ切り替わり、コスト構造はそのままに速度とトークン効率だけが向上する形になるため、あえて旧モデルに固定しておく理由は薄れています。** [GeekNews](https://news.hada.io/topic?id=34444)

### ゲートウェイの利用上限がドル金額で表示されるように(v2.1.284)

**Claudeアプリのゲートウェイを使っている環境では、`/usage`とステータスバーの支出上限が「$271.40 / $500.00 spent this month」のように実際のドル金額で表示されるようになりました。** ステータスバーの`rate_limits.spend_limit`にも`used_usd`・`limit_usd`・`period`フィールドが追加されています。

**組織単位でゲートウェイの支出上限を管理している場合、パーセンテージだけを見ていた状態から、実際の消化金額をそのまま確認できるようになるため、予算超過かどうかをずっと素早く判断できます。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## 開発者ワークフローティップス

### Claude Opus 5.5のプロンプトの書き方(9/28)

**既存のOpus 5用プロンプトはおおむねそのまま使えますが、推論量はeffortのデフォルト値であるmediumから始めて調整することが推奨されています。** 旧モデル向けに設定していたeffort設定をそのまま持ち込むと、時間とトークン消費が不必要に増える可能性があります。チャットでは「答える前によく考えて」といった文言が依然として実際の推論量に影響します。

**Opus 5向けに書いたシステムプロンプトやCLAUDE.mdの指示をOpus 5.5にそのまま流用している場合は、effortのデフォルト値から見直し、不要な高強度推論設定を外すとコスト削減につながります。** [GeekNews](https://news.hada.io/topic?id=34424)

### `/mcp reconnect all` — 切断されたMCPサーバーを一括再接続(v2.1.284)

**対話型ターミナルで接続に失敗した、または認証が必要なすべてのMCPサーバーを、1つのコマンドでまとめて再試行できるようになりました。**

```bash
/mcp reconnect all
```

**複数のMCPサーバーをつないでいると、セッションの途中で一部が切断されることはよくありますが、サーバーごとに個別に再接続を試みる代わりに、このコマンドで一括して整理できます。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### autoモードに「今回だけ許可、次回はまた確認」というオプションが追加(v2.1.284)

**作業ディレクトリ外のファイルを読む前にautoモードが表示する確認プロンプトに新しい選択肢が加わり、今回だけ許可して次回同じ状況になったら再度確認させることができるようになりました。** これまでは一度許可すると以降もずっと許可され続けるか、毎回拒否するかという二択しかありませんでした。

**作業ディレクトリ外のファイルをたまにしか読む必要がないワークフローでは、毎回「全許可にするか」を悩まずに都度判断しつつ、次のプロンプトも取りこぼさずに済みます。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## エコシステム＆プラグイン

### Claudeアプリのゲートウェイ、Google Cloud OTLPへのテレメトリ直接送信に対応(v2.1.284)

**ゲートウェイ設定の`telemetry.forward_to`の送信先に`auth: { google: {} }`を追加すると、ゲートウェイがすでに保有しているGoogle Cloudの認証情報を使って、テレメトリをGoogle CloudのOTLPエンドポイントへ直接送信できるようになります。**

**Google Cloud上で可観測性スタックを運用している組織であれば、別途中継サービスを用意しなくても、ゲートウェイから直接OTLPでテレメトリを流し込めます。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### Claudeアプリのゲートウェイ、証明書ベースのクライアント認証に対応(v2.1.284)

**ゲートウェイとidentity provider間の認証に証明書ベースのクライアント認証(`private_key_jwt`)が追加され、クライアントシークレットの代わりに証明書クレデンシャルを発行するidentity providerとも連携できるようになりました。**

**金融業界など証明書ベースの本人確認を要求するidentity providerを使っている組織であれば、これまで難しかったゲートウェイ連携が今回のアップデートで可能になります。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## 知っておくと便利な小さな変更点

以下はすべて**v2.1.284**(9/28)の項目です。

- **`/rate-limit-options`が`/help`とコマンドメニューに追加**され、利用上限の案内文が指しているコマンドをclaude.aiのサブスクライバーがすぐに見つけられるようになりました。
- **effortスライダーの`increaseEffort`・`decreaseEffort`・`toggleUltracode`キーバインディングアクションが追加**され、矢印キーやTabキーの動作を`keybindings.json`で再バインドできるようになりました。
- **コンパクション後も残っていた「Prompt is too long」エラーが修正**され、コンパクションしたリクエストがまだ長すぎる場合は直近の会話をさらに削って再度コンパクションするようになりました。
- **auto-memoryの読み込み時に、`MEMORY.md`や想起されたメモリノート内でClaude Code自体のマークアップを模倣する不可視文字・タグが無効化**されるようになりました。
- **`/plugin`設定画面でboolean(真偽値)オプションが自由テキストではなくtrue/falseの選択肢に変わり、数値オプションは不正な入力を拒否**するようになりました。
- **[VSCode] 各プロンプト・レスポンスの上に時刻を表示するオプションが追加**されました(日付が変わると日付の行も表示、デフォルトはオフ)。
