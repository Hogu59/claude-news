## 主要な新機能と実践活用

### 内蔵「Concise」出力スタイルが追加されます (v2.1.237)

**結論を先に述べ、前置きやナレーションを省きながらも、作業自体は従来通り丁寧にこなす内蔵の出力スタイル**が追加されました。`/config`のOutput style項目から選択できます。

```bash
# /config実行後、Output styleメニューで「Concise」を選択
/config
```

**Claude Codeの応答が冗長に感じられていた、あるいはCIログやスクリプト出力で結果だけを素早く確認したいワークフロー**なら、試してみる価値があります。[リリースノート全文](https://github.com/anthropics/claude-code/releases)

### `keybindingFlavor` — BashのようにCtrl+Wが動作するreadlineモード (v2.1.238)

**プロンプト入力でのCtrl+Wの動作方式を指定する`keybindingFlavor`設定**が追加されました。**`"readline"`に設定するとCtrl+WがBashと同様に直前の空白まで削除**し、デフォルト値の`"classic"`は従来通りの動作のままです。

```json
// settings.json
{
  "keybindingFlavor": "readline"
}
```

**ターミナルでBashのショートカットに慣れている開発者なら、この設定一つでClaude Codeのプロンプト入力でも同じ指の癖をそのまま使えます。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## 開発者ワークフローティップス

### 長時間セッションでメモリが際限なく増え続ける問題が解決 (v2.1.238)

**サブエージェントのツール結果が直近の表示ウィンドウ(recent display window)から外れると、メモリから解放**されるよう修正され、**長時間開きっぱなしのインタラクティブセッションでメモリが際限なく増え続けていた問題**が修正されました。

**一日中一つのセッションを立ち上げたまま複数のサブエージェントを繰り返し走らせるワークフロー**なら、今回の修正で**セッションを長時間維持してもメモリ使用量がより安定**します。[リリースノート全文](https://github.com/anthropics/claude-code/releases)

### self-hosted runnerの運用オプションが拡充 (v2.1.238)

```bash
# SIGTERMを受け取ると、接続中のセッションはそのままサービスを続けつつ、指定時間後に残りのセッションを片付けて終了
claude self-hosted-runner --defer-shutdown-max-min 15

# 接続ごとに新規発行されたProxy-Authorizationヘッダーが必要なegressプロキシ環境向け
claude self-hosted-runner --proxy-authorization-command "./mint-proxy-token.sh"
```

**`--defer-shutdown-max-min`は、ランナーを再デプロイする際に既に接続済みのセッションを強制終了せず猶予時間を与え、`--proxy-authorization-command`/`--proxy-authorization-file`は、接続のたびに新しいトークンを要求するegressプロキシの背後でランナーを運用**できるようにします。

**self-hosted runnerをデプロイ・ローリングアップデートしている、あるいは社内プロキシの背後で運用しているなら、どちらのオプションも運用面で役立ちます。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### zshシェルの条件文に対するBashツールの権限チェックが改善 (v2.1.238)

**zsh特有の構文を使うシェル条件文について、Bashツールの権限チェックの精度が改善**されました。**zshをデフォルトシェルとして使っていて、Claude Codeが条件文コマンドを誤判定し不要な承認プロンプトが出ていた経験**があれば、今回の改善でそうした誤検知が減ります。[リリースノート全文](https://github.com/anthropics/claude-code/releases)

### MCP `headersHelper`の信頼ゲートと認証情報の分離が強化 (v2.1.238)

**プロジェクトの`.mcp.json`の`headersHelper`、およびプロジェクト・プラグインのエージェントファイルに定義されたインラインMCPサーバーの`headersHelper`の実行に、該当フォルダのtrustダイアログの承諾が前提条件として追加**されました(`claude -p`でも同様に適用)。また、**プロジェクトの`.mcp.json`・プラグイン・エージェントファイル由来の`headersHelper`は、継承された認証情報の環境変数なしで実行**され、**user・managed・claude.aiスコープのヘルパーはClaude設定ディレクトリ内で実行**されます。

**信頼していないプロジェクトを開いた際、`.mcp.json`に仕込まれた`headersHelper`がセッションが既に保持している認証情報の環境変数にアクセスする経路を遮断**するハードニングです。MCPサーバー連携で`headersHelper`を使っているなら、**v2.1.238からはtrustダイアログを先に承諾しないと実行されない点**に注意してください。[リリースノート全文](https://github.com/anthropics/claude-code/releases)

## 知っておくと便利な小さな変更点

以下はすべて**v2.1.238**の項目です。

- **プラグインマーケットプレイスの`headersHelper`**が、カタログや同一オリジンのアーカイブfetch用のHTTPヘッダー(短命トークンなど)を発行します — **インストール・更新時にはコマンドが先に表示された上で`[y/N]`(または`-y`)による確認**を経ます。
- **`claude mcp list`・`claude mcp get`が、無効化されたサーバーをヘルスチェックで接続する代わりに、`⊘ Disabled`として即座に表示**するようになりました。
- **フルスクリーンでCtrl+L・Cmd+Kが常に画面の再描画のみを行うように変更**されました — ダブルプレスで`/clear`を実行するショートカットが削除され、1行だけのnvimターミナルで自動`/clear`ループに陥っていた問題も同時に解消されています。
- **クロスセッションメッセージングで受信を拒否しているセッション(`crossSessionInbound: "refuse"`など)にメッセージを送ると、静かに成功したように見える代わりに送信元に「拒否されました」と通知**されるようになりました。
- **受信箱がメッセージを処理できないセッション(レートリミット・キュー満杯)に送信しても、メッセージが静かに消える代わりに送信元セッションに通知**が届きます。
- **ネットワークエッジ・VPN・プロキシの一時的なHTTP 403拒否を、Remote Controlが最大3分まで許容**するようになり、拒否が続く場合はどの主体がブロックしているかを知らせます。
- **自動アップデート確認が起動直後にCPUを奪い合う代わりに、起動から約10秒後に実行**されるようになり、起動時のレスポンスが改善しました。
- **低速なSSH・mosh接続でキー入力がまとまって届く際、Backspaceを長押しすると無視されていた問題**が修正されました。
