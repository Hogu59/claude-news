# Claude Code デイリーブリーフィング - 2026-08-22

## 最新リリース概要

| バージョン | 日付 | 主な変更 |

**v2.1.238(8/20)に続きv2.1.239(8/21)がリリースされました。** Added項目はわずかですが、**Fixed項目が40件を超える今週最大規模のリリース**となり、**Bedrockプロキシの二重課金バグ、断片化していたOpenTelemetryトレース、`/resume`・Remote Control・クリップボード関連の細かなバグまで幅広く手が入り**ました。ただ、今日のブリーフィングでより重点的に扱うのはCLIリリースそのものではなく、この後で紹介する**Anthropic公式のプラットフォーム発表**です。

## 主要な新機能と実践活用

### Computer Use・Browser Use Tool・Skills API・Files APIが正式リリース (8/20)

**Anthropicがこれまでベータとして提供してきたComputer Useに加え、新たにBrowser Use Tool、Skills API、Files APIをまとめて正式版(GA)としてリリース**しました。**Computer Useは1ターンで複数のアクションを処理**できるようになり、**作業完了までの時間とコストが約30%削減**されるほか、**規制業界向けにBAAの下でHIPAA対応も可能**になりました。**Browser Use Toolはスクリーンショットベースの操作にページ構造の解析を組み合わせる**ことで、ピクセル座標だけに頼っていた従来の方式よりも安定してWeb要素を捉えられるようになっています。**Skills APIはバージョン管理された指示フォルダをアップロードしてClaudeのサンドボックス内で実行**する仕組みで、**Files APIは組織あたり1TBのストレージと自動有効期限、従来比5倍のレートリミット**を備えています。

**実務への落とし込み方**: Files APIでファイルを読み込み、Skillsで定義した手順を実行し、Browser・Computer UseツールでWeb作業を自動化してから結果を再びファイルとして保存する、という一連の流れを、**独自のセルフホスト型インフラを用意することなくClaude Platform単体で完結できる**のがポイントです。3機能とも**Microsoft Foundryでも利用可能で、Google Cloud Vertex AI対応は準備中**とのことです。Claude APIの上でファイルアップロードやブラウザ自動化のパイプラインを自前で構築してきたなら、今回のGAで**ベータヘッダーなしの安定版エンドポイントがそのまま使えるようになった点**は確認しておく価値があります。[出典](https://claude.com/blog/computer-use-skills-api-files-api)

### Claude Academyが開設 (8/20)

**Anthropicが社内研修で使ってきた手法をそのまま外部公開した無料学習ハブ、Claude Academyがオープン**しました。**Claude 101のような入門コースから、Claude APIやClaude Codeでエージェントを構築する技術的な上級コースまで**をカバーしており、**開発者・学生・教育者・非営利団体向けにトラックが分かれています。**

**チームにClaude Codeを新規導入する際のオンボーディング資料に困っていたなら、Claude Code 101のような公式カリキュラムをそのまま活用**できます。[Claude Academy](https://academy.claude.com/)

### `/claude-api upgrade` — PythonプロジェクトをAnthropic 1.xへ移行 (v2.1.239)

```bash
# claude-apiスキルでPythonプロジェクトのanthropic 0.x依存を1.xへ移行
/claude-api upgrade
```

**`claude-api`スキルに、Pythonプロジェクトの`anthropic`を0.xから1.xへ移行するコマンドが追加**されたほか、**スキルのPythonリファレンスドキュメントも1.x仕様に更新**されました(例: タイムアウト指定は`httpx.Timeout`ではなく`anthropic.Timeout`を使うようになっています)。

**`anthropic` SDK 1.xへのアップグレードを先延ばしにしてきたプロジェクトがあれば、このコマンドで変更が必要な箇所を自動的に洗い出し、最初の一歩を踏み出せます。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## 開発者ワークフローティップス

### リトライウォッチドッグが支出上限エラーで無限待機しなくなりました (v2.1.239)

**`CLAUDE_CODE_RETRY_WATCHDOG`で有効化する持続リトライモードが、組織の支出上限超過やクレジット枯渇エラーに遭遇した際、リセットをひたすら待つのではなく即座に失敗する**よう変更されました。

**実務への落とし込み方**: 夜間に走らせているCIやバックグラウンド自動化が支出上限に引っかかった場合、これまではリトライウォッチドッグがリセット時刻まで延々とリトライを繰り返し、処理を占有し続けていました。**この種のエラーでは即座に失敗するようになったことで、パイプラインがその時点で詰まっている状態をより早く検知し、通知や再キューイングといった次の対応に移れます。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### PreToolUseフックが遅延させたツール実行のトレースが分断されなくなりました (v2.1.239)

**`PreToolUse`フックがツール実行を遅延させた場合、その実行が新しいOpenTelemetryトレースを開始するのではなく、元のターンのトレースに続けて記録される**よう修正されました。

**Claude CodeのOpenTelemetry出力をDatadogやHoneycombといった監視ツールに流し、ターン単位でレイテンシを分析していたなら、これまではフックが介入したツール呼び出しだけが別トレースとして切り離され、ターン全体のレイテンシを正確に再構成するのが難しい状況でした。** 今回の修正により、**フックがかかったツール実行も同じターンのトレース内でそのまま確認**できるようになります。[リリースノート全文](https://github.com/anthropics/claude-code/releases)

### ソフトウェア工場になっても人間の判断は消えず、置き場所が変わるだけです (8/21)

**コード生成を自動化する「ソフトウェア工場」モデルが定着しても、プロダクトの意図・システム設計・品質基準・最終的なリリース判断には依然として人間の責任が残る**という指摘です。**Claude CodeやCodexだけで実装自体は十分こなせるとしても、実際の作業をイベント駆動キューで反復処理し、エージェント間で状態・コンテキスト・エビデンスを確実に受け渡すインフラを整えること自体が別の課題として残る**、というのが要点です。

8/16〜8/20のブリーフィングで繰り返し取り上げてきた**「完了条件と、人間が引き続き担う判断をあらかじめ定義しておくべき」というループエンジニアリングの原則**が、今回は**イベントキューとエージェント間のエビデンス受け渡しという具体的なアーキテクチャパターン**へとさらに一歩踏み込んだ形です。複数のエージェントをパイプラインとして連携させているなら、**次の段階に引き継ぐ状態・コンテキスト・エビデンスを何と定義するかがキュー設計の核心的な問いになる**という点は参考になります。[GeekNews](https://news.hada.io/topic?id=32737)

## セキュリティ・制限事項

### Bedrockプロキシのストリーミングバグ — 毎ターンのリクエストが静かに二重課金されていた問題 (v2.1.239)

**レスポンスのContent-Typeヘッダーを取り除くプロキシの背後でBedrockストリーミングを使っていた場合、毎ターンが気づかれないまま非ストリーミング方式で再実行され、実質的にAPI呼び出しが二重に課金されていたバグ**が修正されました。

**Bedrockを社内プロキシやゲートウェイの背後で運用していたなら、このバグによってこれまでの請求額が実際の使用量より水増しされていた可能性**があります。v2.1.239へのアップデート後、**直近の請求内容と実際のリクエスト回数を一度突き合わせておく**と安心です。[リリースノート全文](https://github.com/anthropics/claude-code/releases)

### データレジデンシーワークスペースのコストプレミアムが正しく表示されるようになりました (v2.1.239)

**`/cost`、ステータスバー、`--max-budget-usd`といったコスト見積もりが、データレジデンシーワークスペースに適用されるUS-only-inference(米国限定推論)の1.1倍プレミアムを含めて計算**されるようになりました。

**データレジデンシー要件のために特定リージョンにワークスペースを固定しているなら、これまで画面上のコスト見積もりが実際の請求額よりやや低く表示されていた可能性があります。** 今回の修正により、**予算アラート(`--max-budget-usd`)やステータスバーの見積もりコストが実際の請求額により近づきます。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### Claudeサービスの稼働状況 — 8/22時点で新規インシデントなし、報告件数は減少が継続

**公式のClaude Status API(status.claude.com)を直接確認した**ところ、8/21のブリーフィングで取り上げた**8/20 18:32〜19:42 UTCのGoogleコネクターエラー(Minor)・複数モデルへのリクエストエラー(Major)**以降、**8/22時点で新たに登録されたインシデントはなく、全サービスが正常稼働(operational)**です。

**StatusGatorの確認時点(2026-08-21 23:53 UTC)で直近24時間のユーザー報告は7件**となり、**8/19の18件→8/20の9件→8/21の7件と3日連続で減少**しており、**8/16夜の認証障害以降高止まりしていた報告件数は、完全に平常時の水準に落ち着き**ました。[Claude Status](https://status.claude.com/history) ・ [StatusGator](https://statusgator.com/services/claude)

**Claude Codeの週間使用量50%ブーストとSonnet 5の導入価格は、いずれも8月31日で終了**します — **D-9**です。9/1からSonnet 5は入力3ドル・出力15ドル(+50%)に値上げされます。詳細は7/13のブリーフィングを参照してください。

## エコシステム＆プラグイン

### claude.aiで同期されたプラグインが`name@synced`と表示されるようになりました (v2.1.239)

**クラウドセッションでclaude.aiから同期されたプラグインが、`name@synced`という形式で表示**されるようになり、**`claude plugin enable/disable <name>@synced`で個別に操作できます。** 何より、**同じ名前でローカルに直接インストール済みのプラグインがある場合、同期版がそれを上書きすることはありません。**

**claude.ai側で管理するプラグインとローカルに直接インストールしたプラグインを併用していたなら、名前の衝突でどちらが実行されているか分かりにくかった状況が、今回の変更で明確になります。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### 機能リクエスト — Claude CodeでのAGENTS.mdサポート (8/21)

**複数のコーディングエージェントが共通で参照するプロジェクト指示ファイルAGENTS.mdを、Claude CodeでもCLAUDE.mdとは別に複製せず、そのまま読み込んでほしいというコミュニティからの機能リクエスト**です。**提案されている方式は、CLAUDE.mdを優先して読み込み、それが存在しない場合のみAGENTS.mdにフォールバックするという二重ファイル対応**です。

**Claude Code、Codex、その他のエージェントを同じリポジトリで併用しているチームなら、指示ファイルをツールごとに別々に管理する手間を減らせるリクエスト**として注目に値します。まだ実装された機能ではない点には留意してください。[GeekNews](https://news.hada.io/topic?id=32716)

## 知っておくと便利な小さな変更点

以下はすべて**v2.1.239**の項目です。

- **Windowsでもクロスセッションメッセージングに対応**しました — macOS・Linuxと同様、複数マシン上のClaude Codeセッションが`SendMessage`で互いにメッセージを送り合い、`ListAgents`で互いを見つけられるようになります。
- **`ListAgents`がセッション自身の名前(他のセッションがメッセージを送る際に使う名前)を教えてくれる**ようになり、自分の名前宛てに`SendMessage`を送ると「no agent named …」の代わりにその旨を知らせてくれます。
- **`ListAgents`・`/list-agents`が、稼働中のチームメイトも表示する**ようになりました — これまではサブエージェントと他セッションしか表示されず、アクセス可能なチームメイトが一覧から漏れていました。
- **`keybindingFlavor: "readline"`が単語単位の移動・削除キーにも適用**されるようになりました — Alt+FとCtrl/Option+→が単語の末尾で止まり、Alt+Dが単語を削除し(Ctrl+Yで復元可能)、句読点が単語境界として扱われます。
- **Alpine/muslビルドでネイティブの画像貼り付け・クリップボード・音声キャプチャアドオンが正しく読み込まれる**ようになりました — glibc向けバイナリをmuslランタイムが拒否していた問題が、muslビルド版バイナリの採用で解決しました。
- **月間支出上限を使い切った状態で表示される使用量上限メッセージが、セッション・週間上限がいつリセットされるかも併せて知らせてくれます。**
- **Bedrock・Vertex・Foundryなど、これまで対象外だった環境にもフルスクリーンレンダラーの1回限りの案内が追加**されました — これらの環境での新規インストールは、今後フルスクリーンで開始されます。
- **Claude in Chromeで`/clear`を実行するとセッションのChromeタブグループが閉じられ**、空のタブグループは`/resume`実行時とClaude Code終了時にも整理されます。
- **モバイルからアップロードした画像に保存済みのファイルパスが含まれる**ようになり、Claudeが新規作成するファイルにそのままコピーできるようになりました。
- **[VSCode] 使用量上限バナーの「View usage」リンクが、バナー中央に浮いていた表示から、警告テキストと並ぶインライン表示に変更**されました。
