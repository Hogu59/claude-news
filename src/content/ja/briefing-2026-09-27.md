## 主要な新機能と実践活用

### `load_test_mode` — 実際のアップストリーム呼び出しなしでデプロイを負荷テスト（v2.1.283）

**セルフホスト型Claudeアプリゲートウェイの設定に、オプトインの`load_test_mode`ブロックが追加されました。** **このブロックを有効にすると、リクエストは通常どおり生成・署名されますが実際のアップストリームには送られず、クライアントには事前に用意したレスポンスが返されます。**

```json
{
  "load_test_mode": {
    "enabled": true
  }
}
```

**実際のAPIコストやアップストリームへの負荷をかけずにゲートウェイのデプロイ全体を負荷テストできるため、新しいデプロイの前に想定トラフィック規模を検証しておきたいチームに役立ちます。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### Claude Tagの「Claudeが検索できるチャンネル」設定 — Slack検索範囲を公開チャンネルに限定（v2.1.283）

**組織の管理者が、ClaudeによるSlack検索の範囲をClaudeが追加されている公開チャンネルのみに制限できる管理設定が追加されました。** **組織・ワークスペース・チャンネル単位で個別に設定できます。**

**SlackでClaude Tagを利用している組織で、Claudeが機微な非公開チャンネルの内容まで検索して回答に反映してしまうことを懸念していたなら、この設定で検索範囲を公開チャンネルに絞り込めます。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## 開発者ワークフローティップス

### プランモードはもう時代遅れ — モデルが賢くなるほど事前計画ドキュメントの重みは減る（9/26）

**モデルがリポジトリを探索し妥当な仮定を立てる能力が向上するにつれ、実装方法を人間が事前に細かく指示するプラン（Plan）モードの必要性は薄れつつある、という指摘です。** **実装前に考えを整理するプロセス自体は依然として有用ですが、その結果を分厚い計画ドキュメントとして残すことが理解の深さに直結するわけではない、というのが要点です。**

**Claude CodeのPlanモードを使うたびに詳細なドキュメント作成に時間をかけていたなら、計画書の分量よりも実行中の判断力を検証する方向にワークフローを見直す価値があります。** [GeekNews](https://news.hada.io/topic?id=34304)

### LLM時代でもプログラミングを楽しみ続ける方法（9/27）

**コーディングは自分の手で行い、LLMには計画整理・調査・レビューといった周辺作業だけを任せることで、プログラミングの楽しさと適度な生産性向上を両立できるという提案です。** **コードベースへの理解と主導権を保つには、実装のすべてをエージェントに委ねず自分でコードを書き続けることが重要だ、というのが要点です。**

**Claude Codeに実装をすべて任せるのではなく、調査・計画立案・レビューといった周辺作業だけを委任し、コアとなるコードは自分で書くという線引きを意図的に設けることで、楽しさと生産性を両方確保できます。** [GeekNews](https://news.hada.io/topic?id=34336)

## セキュリティ・制限事項

### Claudeサービス稼働状況 — 9/27現在すべて正常、5日連続の安定運用（9/27）

**公式のstatus.claude.comを直接確認したところ、9/27時点でclaude.ai・Claude Console・Claude API・Claude Code・Claude Cowork・Claude for Governmentはすべて正常稼働（Operational）で、進行中のインシデントはありません。** **直近のインシデントだった9/22の複数モデルにわたるエラー増加が解消して以降、5日間インシデントなく安定運用が続いています。**

**過去90日間すべてのシステムが正常状態を保っていることから、特別な対応をせず通常どおり利用を続けて差し支えない時期です。** [Claude Status](https://status.claude.com)

### Windows PowerShellツールのドライブルート削除脆弱性を修正（v2.1.283）

**PowerShellツールが`cmd /c rd`・`rmdir`・`del`・`erase`コマンドを経由することで、`Remove-Item`であれば拒否されるはずのドライブルートやホームフォルダといった場所まで削除できてしまう問題が修正されました。**

**Windows環境でClaude Codeに広い自動化権限を与えているチームは、今回の修正でcmdベースの削除コマンドの危険範囲が`Remove-Item`と同水準に狭められたことになるため、最新版へのアップデートをおすすめします。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## 知っておくと便利な小さな変更点

以下はすべて**v2.1.283**（9/25）の項目です。

- **テレメトリを無効にした状態でweekly Fableの上限が`/usage`やVS Codeの使用量メーターに表示されなかった問題を修正**。
- **`/model`が日付や`-v1:0`サフィックス付きのSonnet 4.6・Sonnet 5の`[1m]` idを拒否していた問題を修正**。
- **`ANTHROPIC_DEFAULT_HAIKU_MODEL`で別のモデルを指定していても、`/model`ピッカーがハードコードされたHaikuのバージョンと価格を表示していた問題を修正**。
- **`DISABLE_PROMPT_CACHING_HAIKU`が、Haikuがセッションのメインモデルである場合には適用されなかった問題を修正**。
- **`claude plugin validate`が、`outputStyles`・`themes`・`monitors`・`lspServers`のパスが存在しない、またはプラグインディレクトリ外を指しているプラグインも検出して失敗させるように**。
- **`claude plugin details`が、`plugin.json`でMCPサーバーを宣言しているプラグインのMCPサーバー数を0と表示していた問題を修正**。
