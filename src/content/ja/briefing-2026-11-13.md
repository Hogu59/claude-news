## 主要な新機能と実践活用

### Claudeがツールを1つずつ呼び出す代わりにJavaScriptでまとめて呼び出す実験機能Code Modeが追加されました (v2.1.323)

**これまでClaude Codeはツールを1つ呼び出すたびにモデルへ戻って次の行動を尋ね直す必要がありましたが、Code Modeを有効にするとClaudeが複数のツール呼び出しをまとめたJavaScriptコードを書いて一度に実行できるようになります。** まだ実験的なopt-in機能のためデフォルトではオフになっており、組織単位でオン・オフを切り替えられます。Dockerのagent runtimeやOpenCodeに既にある同名の機能が、複数ステップにわたる作業でモデルとの往復回数を減らす仕組みで動いていることを踏まえると、Claude CodeのCode Modeも同様の効果を狙ったものと見られます。

**複数のツールを連鎖的に呼び出す複雑な作業で、モデルへの往復ごとの遅延やトークンコストが気になっていたなら、[公式ドキュメント](https://code.claude.com/docs/en/code-mode)を見てこの実験機能を試してみる価値があります。ただしまだ実験段階なので、重要なワークフローにいきなり適用するより、影響の小さい作業でまず動作を確認するのが安全です。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## 開発者ワークフローティップス

### サブエージェントの進行状況サマリーが煩わしいなら、`CLAUDE_CODE_DISABLE_AGENT_PROGRESS_SUMMARIES`でオフにできます (v2.1.323)

**2.1.318から実際には動作していたものの、今回初めて文書化されたこの環境変数を`1`に設定すると、サブエージェントの進行状況を要約する動作と、その要約を生成するための追加リクエスト自体が無効になります。**

```bash
# サブエージェントの進行状況サマリーとそのリクエストを無効にしたいとき
export CLAUDE_CODE_DISABLE_AGENT_PROGRESS_SUMMARIES=1
```

**複数のサブエージェントを同時に立ち上げて作業していて、進行状況サマリーのための追加リクエストとトークンコストがもったいないと感じていたなら、この環境変数でサマリー機能自体をオフにしてコストを抑える価値があります。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### 見慣れないモデルIDのコンテキストウィンドウ推定値が200Kから1Mに変わり、サードパーティモデル利用時の落とし穴になり得ます (v2.1.323)

**Claude Codeが認識しないモデルIDでセッションを開くと、今後はコンテキストウィンドウを200Kではなく1Mトークンと仮定するようになります。** 実際にはもっと小さいコンテキストウィンドウを持つサードパーティモデルをLLMゲートウェイ経由で使っている場合、Claude Codeは実際より遥かに大きな余裕があると誤認してコンパクションのタイミングを逃し、セッションが満杯になった後は`/clear`するまで毎ターン失敗し続ける可能性があります。

```bash
# これまでと同じく200K固定で使いたいとき
export CLAUDE_CODE_DISABLE_1M_CONTEXT=1
```

**Claude以外のモデルをゲートウェイ経由でClaude Codeに接続していて、そのモデルの実際のコンテキストウィンドウが1Mより小さいなら、v2.1.323へのアップグレード後はセッションが満杯になる前に`/autocompact`で先にコンパクションするか、上記の環境変数で以前の挙動を選んでおくのが安全です。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### Claude Code内部のgit・ripgrep呼び出しがログイントークンなしで実行されるようになり、一部のgit hookが動作しなくなる可能性があります (v2.1.323)

**Claude Code自身が内部的に実行するripgrepとほとんどのgitコマンドが、今後はほとんどのログイントークン・APIキーなしで実行されます。** その結果、こうした内部的なgitコマンドの下で動くcredential helperやgit hookが今までClaude Codeのログイン情報を利用していた場合、今後はその情報を見つけられなくなります。

**git hookやcredential helperをカスタマイズしてClaude Codeのセッショントークンに依存する自動化を組んでいたなら、v2.1.323以降はそのトークンにアクセスできなくなる点を踏まえて動作を再確認しておく価値があります。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### v2.1.323にサンドボックス・権限チェックのセキュリティ修正が多数含まれました

**今回のリリースでは、承認なしで実行されるコマンドの影響範囲を制限するサンドボックス関連の欠陥が複数修正されました。** 書き込み可能なフォルダ内のシンボリックリンクが別の場所や存在しないパスを指している場合にその書き込み権限をそのまま認めてしまう問題、`cp`・`mv`でディレクトリに書き込むファイルにdenyルールと保護ファイルのプロンプトが適用されない問題、Write・Editツールが`Read`のdenyルールが適用されたパスに書き込めてしまう問題、サンドボックスで隔離されたコマンドがClaude Code自身のチェックポイントのコピーを読み取れてしまう問題、Bashの権限チェックがコマンドの一部を見落としていた問題、セッションの途中でサンドボックスが静かに無効化され得る問題が、今回すべて修正されました。

**サンドボックスモードでClaude Codeを運用していて、承認なしコマンド実行の影響範囲を信頼していたなら、v2.1.323にアップグレードしてこれらの欠陥がすべて修正されたバージョンを使っているか確認する価値があります。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

**11/12のブリーフィングで取り上げたロードショーの正式開始(1株70~78ドル、8億2,500万株)に続き、CNBCを引用した海外メディアは、価格決定が11/18、ナスダック取引開始は11/19に予定されていると報じました。** IPOカレンダーサイトのIPOXも初日取引を11/19と案内していますが、Anthropicが日付を公式に確定したわけではなく、さらに後ろ倒しになる可能性も残っています。公開価格帯70~78ドル、想定調達規模、共同主幹事のGoldman Sachs・Morgan Stanleyなど、既存の条件はそのままです。

### `plugin.json`の`engines["claude-code"]`フィールドでプラグインのバージョン互換性が強制されます (v2.1.323)

**プラグインが`plugin.json`で対応するClaude Codeのバージョン範囲を`engines["claude-code"]`として宣言すると、その範囲外のClaude Codeにはインストール・更新・ロードされなくなり、インストールと更新はその範囲に合う最新バージョンを選ぶようになります。** これまでは、プラグインが特定のClaude Codeバージョンでしか動作しないように設計されていても、それを強制する手段がなく、互換性のないバージョンにインストールされた後に原因不明のエラーにつながることがありました。同じリリースで`claude plugin validate`にもプラグインのTypeScript hooksモジュールへの型チェックが追加され、`--strict`オプション付きで実行するとこうした問題を事前に検出できます。

**Claude Code用のプラグインを作って配布しているなら、`plugin.json`に`engines["claude-code"]`で対応バージョン範囲を明示し、ユーザーが互換性のないバージョンにプラグインをインストールして遭遇するエラーを未然に防ぐ価値があります。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## 知っておくと便利な小さな変更点

以下はすべて**v2.1.323**(11/12)の項目です。

- **Artifactツールのassetアップロードに`.docx`対応が追加**されました。
- **機密情報を含んでいるように見える「don't ask again」の許可ルールは、gitで追跡される`settings.local.json`に保存されそうな場合、セッション内だけで保持されファイルには保存されないように変更されました。**
- **同じマシン上のセッション同士がユーザー確認なしに送り合えるメッセージ数が、約20件から100,000件へ大幅に増えました。**
- **`/security-review`を実行する前に、Claudeが先に確認を求めるようになりました。**
- **`which`を参照・表示以外のフラグ付きで実行すると、権限確認を求めるようになりました。**
- **外部から見える、またはアクセス権限を確認できないartifactを更新する際は、allowルールがあっても先に確認を求めるようになりました。**
- **ヘッドレス(`claude -p`)セッションがメモリ不足で設定ファイルの保存に失敗した場合でもログイン情報が消去されず、Claude Code自体の起動が失敗していた問題が修正**されました。
