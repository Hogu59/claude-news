## 主要な新機能と実践活用

### クラウドセッションをリポジトリを選ばずにすぐ開始できるようになりました (v2.1.318)

**Anthropicがホストする環境でクラウドセッションを開始する際、リポジトリを一つも選ばずにそのまま始められる「No repository」オプションが追加されました。** これまでクラウドセッションは必ず接続先リポジトリを決めるところから始まっていましたが、特定のコードベースに紐づかないリサーチやスクラッチ作業、一回限りの質問にとってはこの手順自体が不要な障壁でした。

**Gitリポジトリとは無関係に資料調査や短いスクリプトの実験をクラウドセッションで試したかった方は、v2.1.318からリポジトリ選択なしで新規セッションをすぐ開けるようになりました。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### Claude apps gatewayのmantleアップストリームに`assume_role`が追加され、AWSアカウント別のコスト配分が可能になりました (v2.1.318)

**Claude apps gatewayのmantleアップストリームに`assume_role`設定が追加され、別のAWSアカウントのロールを引き受けてリクエストを送れるようになり、これにより開発者単位でのAWSコスト配分も可能になりました。** 複数のAWSアカウントにまたがる組織でClaude apps gatewayを一元的に運用している場合、これまではどのチーム・開発者の利用量をどのアカウントのコストとして計上すべきか切り分けるのが煩雑でした。

```yaml
# Claude apps gateway設定例 (mantleアップストリームにassume_roleを指定)
upstreams:
  - name: finance-team-mantle
    type: mantle
    assume_role:
      role_arn: arn:aws:iam::123456789012:role/claude-gateway-finance
```

**複数のAWSアカウントに分かれた組織でClaude apps gatewayを使ってClaude利用を一元化しているなら、`assume_role`でアカウントごとのロールを指定し、コスト配分とガードレールの分離を同時に整えてみる価値があります。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## 開発者ワークフローティップス

### grounded-expertスキルで、エージェントに記憶ではなく公式ドキュメントを調べて引用させながら答えさせられます (Show GN, 11/5)

**「HTTPの専門家になりきってください」のようなペルソナ型プロンプトは、モデルを記憶に頼って答えさせてしまい、誤った内容も正しい内容と同じ確信度で語らせてしまいますが、grounded-expertは質問が来るとサブエージェントがWebSearch・WebFetchで公式仕様・ドキュメント・論文を実際に調べ、その内容だけに基づいて答えることを強制するClaude Codeのskillです。** すべての主張に出典URLと原文そのままの引用を伴う`EXTRACTED`、複数の出典をつなぎ合わせた推論である`INFERRED`、確認できなかった内容を示す`not confirmed`というタグを付け、結論を出す前にもう一度反証を探す検索を行い、quick・standard・thoroughから深さを選べます。

```bash
# Claude Codeにgrounded-expertスキルをインストール
/plugin install grounded-expert --marketplace pko89403/grounded-expert
```

**「最新バージョンでこのAPIの挙動は変わった?」のような質問に対してClaudeがそれらしいが未確認の答えを返してきて困った経験があるなら、このスキルで回答ごとにEXTRACTEDの引用と原文との照合ができる根拠を求めてみる価値があります。** [GeekNews](https://news.hada.io/topic?id=36651)

### コーディングエージェントを複数同時に動かすときは、エージェントごとにgit worktreeを割り当てて分離しましょう

**Salesforce AI Researchのあるリサーチエンジニアが、Claude Code・OpenCode・Codex・Piなど5〜6個のコーディングエージェントを同時に運用する方法を公開しましたが、ポイントはエージェントごとに別々のgit worktreeを割り当て、ファイルの変更が互いに干渉しないようにすることです。** こうして分離しておけば、思い切ったアイデアを新しいworktreeでそのまま試し、気に入らなければそのworktreeだけ捨てればよいので、損失なく実験できます。実際にMumbleクライアントにノイズ低減機能をプロンプト一つで追加し、約20分でプロトタイプを作ったと説明しています。

```bash
# エージェントごとに独立した作業領域を作り、互いに干渉しないようにする
git worktree add ../myproject-agent2 -b agent2-noise-reduction
```

**複数のセッションでClaude Codeを同時に立ち上げて作業していて、あるエージェントの変更が別のエージェントの作業ディレクトリを汚してしまった経験があるなら、worktree単位で作業を分割するこの方法をCLAUDE.mdやチームのワークフロー文書にルールとして明文化しておく価値があります。** [GeekNews](https://news.hada.io/topic?id=36586)

**ウェブ検索を多用するワークフローでアカウント情報がネットワークに漏れることが気になるなら、未検証の報告である点を踏まえてもなお、`/plugins`で`cc-plugin-privacy`の設定を自分の目で確認しておくのが安全です。** [GeekNews](https://news.hada.io/topic?id=36676)

## 知っておくと便利な小さな変更点

以下はすべて**v2.1.318**(11/4)の項目です。

- **`claude mcp add`・`remove`が設定ファイルのロックを待たずに上書きしてしまう問題が修正**され、ロックを待つか、失敗時には終了コード1を返すようになりました(ただし他の処理による保存がその後にサーバー設定を上書きしてしまう可能性は残ります)。
- **バージョン確認リクエストで終了するstdio MCPサーバーが、起動のたびに再度プローブされてしまう問題が修正**され、自身の理由で3秒以内に終了するサーバーは7日間レガシーhandshakeに固定されるようになりました。
- **アイドル状態の非対話型セッションが終了する際、削除されたセッションのtranscriptが最後のプロンプトから再生成されてしまう問題が修正**されました。
- **`NODE_EXTRA_CA_CERTS`ファイルが空、PEM形式でない、あるいは破損した証明書で起動した際にすべての接続が失敗してしまう問題が修正**され、読み込める証明書だけを使用しstderrに警告を表示するようになりました。
- **`sudo claude`のように別ユーザーが所有する実行中プロセスを、バージョンクリーンアップ処理が停止済みと誤認してバイナリを削除してしまう問題が修正**されました。
- **更新やバージョンクリーンアップが実行中プロセスのバイナリを削除した後、Remote Controlホスト・バックグラウンドデーモン・self-hosted runnerが新規セッションの開始に失敗する(`spawn ENOENT`)問題が修正**されました。
- **`claude -p`・SDKのように非対話型で実行する際、`~/.claude.json`に変更がなければ毎回書き直さないように改善**されました。
- **クラウドセッションで`gh run view --log`・`gh api`を使ってGitHub Actionsのログを読む際、アクセスできないリダイレクトでブロックされてしまう問題が修正**され、ほとんどの環境でログを正常に取得できるようになりました。
- **クラウドセッションに`google-chrome`という名前と`CHROME_PATH`が追加**され、Playwright以外のツールも内蔵Chromiumを見つけられるようになりました。
