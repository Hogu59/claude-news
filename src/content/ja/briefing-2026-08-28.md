## 主要な新機能と実践活用

### `--restricted` — コマンド・コード実行ツールを取り除いたセーフモード (v2.1.248)

**`--restricted`フラグ（または`CLAUDE_CODE_RESTRICTED=1`）を有効にすると、コマンドやコードを実行する組み込みツールと`WebFetch`が取り除かれます**（`--tools`で明示的に指定した場合を除く）。**ファイルツールは作業ディレクトリ内に制限され、`bypassPermissions`は拒否され、ユーザー・プロジェクト・ローカルの設定ファイルは無視されます**。

```bash
claude --restricted
# または環境変数で
export CLAUDE_CODE_RESTRICTED=1
claude
```

**信頼できない入力を扱う場面や、ファイルの読み書き以上の権限を与えたくない自動化パイプラインにClaude Codeを組み込む際、コマンド実行の経路そのものを遮断できる専用モードができたことになります。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

### クロスセッションメッセージングがBedrock・Vertex・Foundryに対応拡大 (v2.1.248)

**同一マシン上で動くセッション同士がメッセージをやり取りする`SendMessage`/`ListAgents`が、これまで未対応だったBedrock・Vertex・Foundry環境やテレメトリを無効化したセッションでも動作**するようになりました。

**エンタープライズ向けクラウドプロバイダー経由でClaude Codeを運用していてクロスセッションメッセージングを使えずにいたなら、同じワークフローをそのまま試せるようになりました。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

## 開発者ワークフローティップス

### `experimental.cacheTtl` — エージェントごとにプロンプトキャッシュの有効期限を指定 (v2.1.248)

**エージェントのfrontmatterに`experimental.cacheTtl`（"5m"または"1h"）を指定すると、サブエージェント専用のTTL設定がない場合にそのエージェントだけに適用されるプロンプトキャッシュの有効期限を設定できます。**

```yaml
---
name: my-review-agent
experimental:
  cacheTtl: "1h"
---
```

**頻繁に呼び出される重いエージェントはキャッシュを長めに、一度きりのエージェントは短めにというように、エージェントごとにキャッシュポリシーを細かく分けたいなら試す価値があります。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

### Workflowツールのプロンプト容量が5.7kトークンから1kトークンに削減 (v2.1.248)

**Workflowツールの説明文自体が占めていたプロンプト容量が約5.7kトークンから約1kトークンに削減され、スクリプトの書き方に関する詳細なリファレンスはバンドルされた`workflow-authoring`スキルに分離されました。**

**Workflowツールを頻繁に使うセッションなら、毎ターンのシステムプロンプトに乗っていた固定コストが減った分、同じコンテキスト予算でより長く作業を続けられます。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

### Agent Behavior — エージェントの反復的な振る舞いを評価基準として明文化する標準 (8/28)

**長時間動作しながら何百回もの判断を下すAIエージェントを、最終的な成果物だけで評価するのは難しいという問題意識から生まれたオープンなフォーマットです。** **エージェントがどんな情報を確認し、何を判断し、どう実行し、情報不足や失敗が起きたときにどう立て直すべきかを、作業の過程で繰り返し示すべき振る舞いとしてあらかじめ文書化しておきます。**

**Claude Codeで作ったエージェントやサブエージェントの品質を、成果物だけでなくプロセスでも評価したいなら、最終成果物の採点基準の代わりにこうした振る舞い基準を先に定義しておくアプローチが参考になります。** [GeekNews](https://news.hada.io/topic?id=32962)

## セキュリティ・制限事項

### `/ultrareview`が認証情報・設定ファイルを誤ってアップロードしていた問題を修正 (v2.1.248)

**`/ultrareview`とローカルからシードされたクラウドセッションが、`prod.env`形式のファイルや`*.tfvars`ファイル、さらにエディタが残すスワップ・一時・バックアップファイル（例: `key.pem.tmp`、`id_rsa.swo`）といった認証情報のコピーまで、コミットされていない変更分ごとアップロードしていた問題が修正されました。** **こうしたファイルは今後ローカルマシンにのみ残ります。**

**`/ultrareview`やクラウドセッションで本番設定ファイルを含むリポジトリを扱ってきたなら、これまでコミットしていないシークレットがクラウドに一緒に送られていた可能性を確認しておく価値のある修正です。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

## 知っておくと便利な小さな変更点

以下はすべて**v2.1.248**の項目です。

- **`/model`とfast-mode切り替え通知のモデル名がコードとしてレンダリング**されるようになり、`[1m]`のような接尾辞がリンクではなく文字どおり表示されます。
- **非ラテン文字（韓国語IMEで入力した場合を含む）で入力した名前が、別セッションの@メンションでマッチしなかった問題**が修正されます。
- **`CI`環境変数が設定されているときに`claude agents`がワークスペース信頼プロンプトをスキップしていた問題**が修正されます。
- **長いルールが絵文字の途中で切れると、信頼ダイアログの権限ルール一覧に文字化けが表示されていた問題**が修正されます。
- **ctrl+c直後にshift+tabを押すと、権限モード表示が「もう一度押すと終了」ヒントの後ろに隠れていた問題**が修正されます。
- **起動時の警告（例: "N MCP servers need authentication"）がトランスクリプトより1マス右にレンダリングされていた問題**が修正されます。
- **エージェントビューのディスパッチ入力で、shift+enterが改行、ctrl+enterが送信・添付を担当**するように変更されます。
- **Anthropicテレメトリの送信失敗ログが、`[3P telemetry] OTEL diag error`ではなく`[Anthropic telemetry]`としてデバッグレベルで記録**されるようになり、自前のOTelコレクターのエラーと誤認しにくくなりました。
- **`claude self-hosted-runner --client-label <label>`（または`SELF_HOSTED_RUNNER_CLIENT_LABEL`）が追加**され、ランナーが登録するラベルをホスト名の代わりに直接指定できるようになりました。
- **AWS Marketplace・セルフサーブEnterprise・Enterpriseトライアルで請求される組織向けに`/usage-credits`が追加**され、メンバーが管理者に利用上限の引き上げをリクエストできるようになりました。
