## 主要な新機能と実践活用

### 会話の途中でツールを切り替える — mid-conversation tool changesベータ (Claude API、7/24発表)

Claude APIが**会話ターンの合間にツール(tool)リストを追加・削除してもプロンプトキャッシュをそのまま維持**する、mid-conversation tool changesをベータ公開しました — **Claude Fable 5・Claude Mythos 5・Claude Opus 4.8・Claude Opus 5**で利用できます。

- **なぜ必要か**: これまでは会話の途中でツールセットを変更するとプロンプトキャッシュが壊れ、以降のターンではキャッシュヒットなしに全体を再計算する必要がありました。このベータでは**ツールが変わってもキャッシュ済みのプレフィックスを再利用**できるため、段階ごとに使えるツールが変わるエージェントアーキテクチャ(例: 序盤は検索ツールのみ、中盤からコード実行ツールを追加)でコスト・レイテンシを大幅に削減できます。
- **使い方**: リクエストに`mid-conversation-tool-changes-2026-07-01`ベータヘッダーを含めるだけです。

```python
response = client.messages.create(
    model="claude-opus-5",
    tools=[...],  # ターンごとに異なるツールセットを渡してもキャッシュは維持されます
    extra_headers={"anthropic-beta": "mid-conversation-tool-changes-2026-07-01"},
    messages=[...],
)
```

ポイントは**「マルチステップのエージェントが段階ごとに異なるツールセットを使うことが、キャッシュコストなしで可能になった」**という点です — パイプラインの各段階でツールを絞り込むオーケストレーションを組んでいるチームなら、昨日のOpus 5発表の陰に隠れていたこのベータを今日チェックしておく価値があります。[Claude Platform release notes](https://platform.claude.com/docs/en/release-notes/api)

### 失敗したリクエストを自動で代替モデルに回す — fallbacks: defaultベータ (Claude API、7/24発表)

`fallbacks`パラメータが**`default`モード**に対応しました — リクエストが拒否(refusal)された場合、**拒否カテゴリごとにAnthropicが推奨する代替モデルへサーバーサイドで自動的に再リクエスト**します。

- **何が変わるか**: これまで`fallbacks`は代替モデルを自分で指定する必要がありましたが、今後は`"default"`の一行だけでAnthropicがカテゴリごとに選定した推奨モデルへ自動的にリトライしてくれます — 推奨代替モデルがないカテゴリでは拒否のままとなります。
- **使い方**: `server-side-fallback-2026-07-01`ベータヘッダーが必要です。

```python
response = client.messages.create(
    model="claude-fable-5",
    fallbacks="default",
    extra_headers={"anthropic-beta": "server-side-fallback-2026-07-01"},
    messages=[...],
)
```

ポイントは**「拒否対応のための代替モデル選定ロジックを自前で書く必要がなくなった」**という点です — 本番エージェントで拒否率を下げるために独自フォールバックロジックを保守していたチームなら、`default`モードに切り替えることでその負担をAnthropic側に任せられます。[Claude Platform release notes](https://platform.claude.com/docs/en/release-notes/api)

## 開発者ワークフローティップス

### シェルのコロン(:)は何もしない — それでも必須引数チェックに使える

シェルの`:`は何も実行せず引数だけを評価して終わるヌルコマンド(null command)です。それ自体は無意味に見えますが、**パラメータ展開と組み合わせると必須引数チェックとデフォルト値設定を1行で処理**できます。

```bash
: "${1:?missing argument, aborting!}"    # $1が未設定または空ならエラーメッセージと共に即終了
: "${CONFIG_PATH:=./default.json}"       # 空ならデフォルト値を代入するだけで先に進む
```

- **何が便利か**: hook・CLAUDE.mdに載せるシェルスクリプトやワークフロースクリプトで、引数検証コードを関数呼び出しなしに**1行に圧縮**できます — スクリプトの冒頭に`set -u`と共に入れておけば、不正な入力を早期に検出できます。

Claude Codeのhook・スクリプトをシェルで書いているチームにとって、引数検証のボイラープレートを減らす手軽な習慣です。[GeekNews](https://news.hada.io/topic?id=31814)

### Postgres LISTEN/NOTIFY、バッファリングで秒間6万件まで拡張できる

PostgresのLISTEN/NOTIFYはグローバル排他ロックのため単純な実装では処理量が低いとされていますが、**通知をバッファリングして一括送信すれば単一サーバーで秒間最大6万件のストリーム書き込み**を処理できるという実測結果が出ました。

- **鍵となるトレードオフ**: NOTIFYを呼び出したトランザクションは通知のコミット順序を保証するため、コミットとfsyncを待つ必要があります — ロスなしの順序保証とスループットの間のトレードオフを理解し、バッチサイズを調整して初めて実測上限に近づけます。
- **どこで使うか**: 別途メッセージブローカーを立てずPostgres単体でリアルタイム通知・イベントストリームを処理したいチームにとって、スケーラビリティの限界に関する通念を覆す実践的なデータです。

エージェントがバックエンドのスキーマ・クエリにまで手を入れるワークフローが増えている今、*Postgresにはできないこと*だと決めつける前に、こうした実測ベンチマークを確認する習慣に価値があります。[GeekNews](https://news.hada.io/topic?id=31808)

## おすすめコラム＆読み物

- **「メモリ安全性絶対主義者たち」**: unsafeの存在だけを理由にRustを排除し、Fil-Cだけが安全だとする基準は、実際のソフトウェアにおける適用範囲や技術的トレードオフを見落としているという反論コラムです。Fil-CはC/C++の不正なメモリアクセスをパニックに変換しますが、ABI非互換性・一部状況での数倍の性能低下・GC導入という代償を伴います — メモリ安全性を二分法(安全/危険)ではなく**コスト・互換性まで含めた多次元的なトレードオフ**として捉えるべきだという論旨は、エージェントが生成するコードの言語・ランタイムを選ぶ際にもそのまま当てはまります。[GeekNews](https://news.hada.io/topic?id=31822)
- **「インターフェースが画面から抜け出している - チャット、音声、エージェント型AIが変えるUX」**: ソフトウェアの中心が画面・メニューから離れ、対話・委任・バックグラウンド実行へと移る中で、UXデザインの対象も固定された画面ではなく**ユーザーの意図を解釈し行動するシステム**へと変わりつつあるという診断です。チャットがあらゆる作業を代替するインターフェースではなく、ユーザーが望むものを明確に把握している場合に限り有効な入口だという、バランスの取れた視点も示されています。今週のClaude音声モード拡張(7/23)や上記のChromeの無断ショートカット問題と併せて読むと、エージェント型インターフェースが増えるほどユーザーの同意・期待値管理がなぜより難しくなるのかを理解する助けになります。[GeekNews](https://news.hada.io/topic?id=31818)
- **「ハードドライブが常にいっぱいになる理由」**: ストレージ容量を何度増やしても使用量が共に増加し、81人が参加したMastodonアンケートでも約半数がディスクを75%以上使用していたという観察から出発したコラムです。空の状態よりも満杯の状態に至る方法の方がはるかに多いというエントロピーの論理で一部説明はつくものの、それだけではユーザー行動を完全には説明できないというバランスの取れた結論を出しています — エージェントがログ・アーティファクト・中間生成物を際限なく作り出す今、**ストレージは増やすほど再び埋まる**という原則を思い出させる一本です。[GeekNews](https://news.hada.io/topic?id=31819)

## 注目プロジェクト＆ツール

- **Show GN: エージェントのトークン浪費を検出するCLI — clew-custos (公開トレース6,780件)**: トークンの浪費が目立たないのは、失敗ではなく**重複**が原因だという問題意識から生まれたツールです。同じファイルを二度読む、同じ引数で再試行する、同じツールを繰り返し呼び出すといったパターンを、完了済みのトレースを読み込んで**どのステップがすでに終わったことを再び行っているかを指摘する方式**で検出します。`pip install "clew-custos[detect]"`ですぐに試せます — Claude Code・サブエージェントを幅広く運用しているチームにとって、今週続けて取り上げてきた同時実行数・予算上限の調整(v2.1.217〜219)と同じ文脈で、*上限を締める前にそもそもどこで漏れているのか*をまず確認させてくれるツールです。[GeekNews](https://news.hada.io/topic?id=31802)
- **Show GN: stinkpot — SQLiteベースのBashシェルヒストリー検索ツール**: Bashのコマンド履歴をSQLiteに保存してセッションをまたいで管理し、検索TUIで素早く見つけられるようにするツールです。Atuinから同期サーバー・AI・dotfilesマネージャー・KVストアを取り除き、必要な機能だけを**約400行のGo**で実装しました。エージェントが代わりに実行したコマンドまで混ざってシェルヒストリーが膨れ上がる今、軽量に検索さえきちんとできる代替を求める開発者にとって実用的な選択肢です。[GeekNews](https://news.hada.io/topic?id=31815)
