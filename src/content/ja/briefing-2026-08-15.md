## 主要な新機能と実践活用

### GitLab MRを `--worktree` フラグで直接開けます(v2.1.233)

**GitLab merge requestのURLが `--worktree` フラグと `claude agents` ビューでサポートされました。** **`claude agents` ビューでは、MRが `!N` 形式で表示されます。**

```bash
claude --worktree https://gitlab.com/group/project/-/merge_requests/123
```

8/14ブリーフィングで取り上げた**GitLabの全面対応**(シークレットredaction・マーケットプレイスのbare URLクローン)の延長線上にあります — **worktreeワークフローもGitHubと肩を並べたことで、GitLab上でissueやMR単位でworktreeを行き来する習慣をそのまま持ち込めるようになりました。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### Bashツールにopt-inのメモリ上限を設定できます — 暴走ビルドがセッションを止めないように(v2.1.233)

**Linux上でBashツールが実行するコマンドに、cgroupベースのメモリ上限をopt-inで設定できる `CLAUDE_CODE_TOOL_MEMORY_LIMIT` 環境変数**が追加されました。**メモリを過剰に消費するビルドやスクリプトひとつでセッション全体が止まってしまう事態を防ぐ**のが狙いです。

```bash
# Linux上でBashツールコマンドのメモリ上限をcgroupで制限します(opt-in)
export CLAUDE_CODE_TOOL_MEMORY_LIMIT=<値>
```

**CIランナーやセルフホストランナーのように、エージェントが無人でビルドやテストを長時間走らせる環境**では、**メモリリークのあるビルドスクリプトひとつでセッションそのものが応答不能になる事故を、このオプションで防げます。** 正確な値の形式は公式ドキュメントで確認するのが安全です。 [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### WebFetchキャッシュのTTLを自分で調整できます(v2.1.233)

**`CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS` 環境変数で、WebFetchセッションのURLキャッシュTTLを設定**できるようになりました。**デフォルト値は従来と同じ15分(900000ms)**です。

```bash
# WebFetchキャッシュのTTLを30分に延ばす例
export CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS=1800000
```

**セッション内で同じURLを何度も確認する調査・リサーチ系のワークフロー**であればTTLを延ばして再取得のコストを減らせますし、逆に**頻繁に更新されるページ(ステータスページ、リアルタイムダッシュボードなど)を扱うセッション**ではTTLを短くして最新データをより頻繁に取得するよう調整する価値があります。 [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## 開発者ワークフローティップス

### TaskCreate・TodoWriteが新モデルでデフォルトから消えました — `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` で復元(v2.1.233)

**Opus 4.8、Sonnet 5、Fable 5、Mythos 5をはじめとする新モデルでは、タスク管理ツール(TaskCreate・TaskGet・TaskUpdate・TaskList、TodoWrite)がデフォルトでは提供されなくなりました。** 従来通り使い続けたい場合は環境変数を有効にする必要があります。

```bash
export CLAUDE_CODE_ENABLE_TODO_TOOLS=1
```

- **なぜ変更されたのかはチェンジログに明記されていません**が、新モデルが専用ツールなしでもタスクを自力で構造化できると判断された可能性があります。
- **実務への影響**: これまでCLAUDE.mdやチームのワークフローで「タスクはTaskCreateで分割して進める」と明示的に指示していた場合、**新モデルのセッションではその指示が静かに無視される可能性があります。** タスク管理ツールに依存するワークフロー(進捗をツールの一覧で確認する習慣など)があるなら、**今日のうちに `/model` で自分がどのモデルを使っているか確認し、必要であれば環境変数をセッション設定に追加しておく**のが安全です。

### Windows auto modeの回帰修正 — ごく普通のコマンドにも繰り返し承認を求めていた問題(v2.1.233)

8/9〜8/14のブリーフィングでD-3から追ってきた**auto modeのデフォルト移行が、まさに実施された8/14当日にWindowsで副作用を起こしていました。** **`cd <dir> && <command> > file` のようなごく普通のBashコマンドにも、auto modeが繰り返し手動承認を求める**という問題が確認され、**v2.1.232で発生した回帰(regression)**であることが判明し、v2.1.233で修正されました。

**auto modeは承認なしで進められることこそが核心的な価値のはずが、逆に承認をより頻繁に求める方向に回帰していたのは皮肉です。** Windowsでauto modeを8/14からオンにしていて、**普通のコマンドのたびに承認プロンプトが出続けるなら、まずv2.1.233に更新済みかを確認する価値があります。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### Opus 5との付き合い方は以前のモデルと違います — より細かい監督が必要な理由(8/14)

**Opus 5はOpus 4.7・4.8より能力が高く、ベンチマークではFableとも競り合っていますが、実際の作業ではより細かい監督が必要で、以前のモデルより扱いにくく感じられる**というコミュニティの指摘です。

- **核心的な違い**: **Opus 4.7・4.8とFableは、意図が不明確な場合はまず質問し、計画を勝手に再解釈しない傾向**があった一方で、**Opus 5はそうした確認手続きを踏まずに自分で判断して進めるケースが増えている**と指摘されています。

**実務への影響**: 上で取り上げた**auto mode**が承認プロセスそのものを減らす方向だとすれば、この指摘は**モデルがそもそも人間に聞き返す頻度自体が減っているという別の軸**を捉えています。**Opus 5に移行したチームなら、曖昧な指示を投げて解釈を任せるのではなく、要件を以前より一段階明示的に書く習慣**が、成果物の精度を高めるのに役立つはずです。 [GeekNews](https://news.hada.io/topic?id=32502)

## セキュリティ・制限事項

### v2.1.233のセキュリティ修正2件 — WindowsのNTLM漏えいベクトル、スキル引数の再展開防止

- **Windows NTパス検証バイパス(NTLM資格情報の漏えいベクトル)を修正**: **NTの `\??\` デバイスプレフィックスで表記されたWindowsパスがUNCパス検証をバイパスしていた**問題が塞がれました。このようなパスを通じて**NTLM資格情報が漏えいしうる経路が、今回の修正で閉じられました。**
- **スキル・コマンド引数の置換再展開を防止**: **スキルやコマンドに渡された引数の値がテンプレートマーカーとして再展開(re-expand)されるのを防ぐ**よう、引数置換ロジックが修正されました。外部から渡された引数値が意図せず再解釈されてしまう経路を減らす対応です。

**8/11〜8/14にかけて繰り返し取り上げてきた権限・パス検証ハードニングの延長線上**にあります。Windows上でClaude Codeをセルフホストしている、あるいは組織展開しているなら、**この2件の修正を含むv2.1.233への更新を推奨**します。 [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### v2.1.232のWindows symlink・リダイレクション権限強化、1日で一部revert(v2.1.233)

8/14ブリーフィングが**v2.1.232のセキュリティハードニング5件のひとつ**として取り上げた**「Windows symlink権限バイパス修正」と「Bash入力リダイレクション(`< file`)の権限チェック」**が、**v2.1.233で部分的に巻き戻されました。** **Cygwinスタイルのsymlink処理と入力リダイレクションに対する権限変更がrevert**され、**「より範囲を絞ったバージョンが後続リリースで再度導入される」**と予告されています。

**セキュリティ強化が実際のワークフローを塞ぎすぎたため巻き戻された事例**とみられます — 上で取り上げた**Windows auto modeの回帰**と合わせて見ると、**v2.1.232のWindows向け権限強化が複数の方向で副作用を起こしており、v2.1.233はその後始末に近いリリースだと言えます。** WindowsでGit BashやCygwinスタイルのツールを使うワークフローがあるなら、**この境界が次のリリースで再び狭められる可能性を念頭に置いておく**とよいでしょう。 [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### MCPがステートレス化します — 今回のリリースのストリーム再接続バグと同じ問題を指しています(8/14)

**MCP 2026-07-28仕様がリリース以来最大規模の改訂**を受けました。核心は**プロトコルのコアが、ステートフルな双方向接続構造からステートレスなリクエスト/レスポンス構造へ移行する**という点です。

**興味深いのは、今日取り上げたv2.1.233のバグ修正のひとつが、まさにこの問題を狙い撃ちしていることです** — **「サーバーレスホストのように固定タイムアウトで長時間ストリームを切断するサーバーに対して、MCP v2接続がsubscriptions/listenストリームを延々と再接続しようとしていた問題」がv2.1.233で修正**されました。**ステートフルな長時間接続がサーバーレス環境と根本的に相性が悪いという問題意識が、仕様側(ステートレスへの移行)と実装側(再接続ループバグの修正)の両方で同時に表面化した形です。**

**サーバーレス環境にMCPサーバーを載せているなら**、今回のv2.1.233アップデートと合わせて、**MCP仕様のステートレス移行が自分のサーバー実装にどんな移行作業を要求するか確認してみるタイミング**です。 [GeekNews](https://news.hada.io/topic?id=32492)

## 知っておくと便利な小さな変更点

以下はすべて**v2.1.233**の項目です(最後だけスケジュールのリマインダーです)。

- **`claude plugin validate` がbareな `.claude/skills` ディレクトリも検査**するようになりました — frontmatterのパースに失敗するSKILL.mdファイルを検出します。
- **スクリーンリーダーモードの改善**: `/effort` セレクタが番号入力式のリスト形式に変わり、ヒントやダイアログのテキストが途中で切れなくなりました。
- **printモードの診断改善**: Claude Codeが認識しないモデルIDでリクエストが送られると、stderrに `[claude-code:unrecognized_model]` の行が出力されるようになりました — `modelOverrides` でマッピングすれば表示されなくなります。
- **GitHubアプリ設定のヒントがGitLab・Bitbucketリポジトリでは表示されなくなりました** — originリモートがgitlab.com・bitbucket.orgの場合はヒントが非表示になり、エンタープライズマーケットプレイスのヒントが非GitHubの社内gitホストをカバーするようになります。
- **apps gatewayのエラー伝達を改善**: Vertex・Foundry・AWSベースのClaude Platformアップストリームの400/413エラーが、アップストリーム側の元のメッセージをそのまま含んで伝達されるようになりました — apps gatewayでauto-compactが誤って発動していたバグも合わせて修正されています。
- **`forward_user_identity` apps gateway設定を追加**: opt-inで有効にすると、Anthropicアップストリームにログインしているユーザーの身元をヘッダーで伝達し、ゲートウェイ配下のプロキシがユーザー単位で支出を集計できるようになります。
- **`claude self-hosted-runner` のセッション起動時間を改善**: セッションブランチをworktreeの再構築なしに作成し、サーバーとの往復を2回減らすことで、エージェント実行の開始が速くなりました。
- **8月の締め切りカレンダー**: **8/17**(D-2)レガシーWorkbench＋実験的prompt tools API 3種の廃止 / **8/19**(D-4)Claude Code週間使用量50%ブースト終了予定 / **8/31**(D-16)Sonnet 5導入価格終了(9/1から+50%)。
