**組織でClaudeを使う中で、ホワイトボードやスプレッドシート、データ分析をそれぞれ別のSaaSに行き来して処理していたなら、今回の公開を機に軽い作業はClaude内で完結させ、本格的な編集が必要なときだけLucid・Miro・Excelのような専門ツールに渡す流れを作ってみる価値があります。** [Claude公式紹介](https://claude.com/resources/articles/sheets-whiteboards-data) · [GeekNews](https://news.hada.io/topic?id=36958)


## エコシステム＆プラグイン

### Show GN: Herdr CKD — Claude Code用MCPツール13種を含むオープンソースAIコーディングオーケストレーター（11/11）

**コーディングエージェントがビルドエラーや未対応の要件が残っているにもかかわらず作業完了を宣言してしまう問題を、プロンプトの指示ではなく物理的な権限分離とgit worktreeによる隔離で防ぐオーケストレーターです。** ファイルを直接編集したりコマンドを実行したりできない固定のコーディネーター（Core C）がタスクを割り当て最終的なPASS・FAILを判定し、実装スレッド（A1〜An）は各自のworktreeで作業し、監査スレッド（B1〜Bn）は実装者の説明ではなく`git status`・`git diff --stat`の結果だけを見て読み取り専用のレビューを行います。監査者が実装者自身の説明を見ない構造になっているため自己正当化で通過してしまうケースを減らせる点が核心で、コーディネーターにはClaudeのようなクラウドモデルを、実装・監査スレッドにはLM Studio・Ollamaのローカルモデルを組み合わせて使うハイブリッドルーティングもサポートします。

```text
Core C（コーディネーター、読み書き不可） → A1〜An（worktreeごとの実装） → B1〜Bn（git diffベースの読み取り専用監査） → PASS/FAIL
```

**Claude Codeにaccept-editsやauto modeを設定して複数のエージェントを同時に走らせる中で、エージェントの「完了しました」という報告をそのまま信じにくいと感じていたなら、この構造で実装と監査を物理的に分離してみる価値があります。** [GeekNews](https://news.hada.io/topic?id=36946)

### Val Townがクラウドコンピューティング市場の競争に押され、サービスを段階的に終了します（11/11）

**Val Townは11/10から課金を停止し、12/10には読み取り専用に切り替わり（sqlite・blob storageを除く）、2027/1/10にすべてのサービスが完全に終了します。** 2027年2月1日にはソースコードがオープンソースとして公開される予定です。運営元はCloudflare・Vercel・Netlify・Renderへの移行ガイドも同時に公開しており、現在のLLMがこうした移行作業をうまく処理できることを前提に、ユーザーがAIの助けを借りてアプリを移行することを期待しているとしています。

**Val Townで作ったアプリを運用している場合は2027年1月10日までに移行を完了させる必要があり、この機会にClaude Codeで別のホスティング環境への移行作業そのものを自動化してみることも検討する価値があります。** [GeekNews](https://news.hada.io/topic?id=36961)

## 知っておくと便利な小さな変更点

以下はすべて**v2.1.321**（11/9）の項目のうち、前回のブリーフィングで取り上げていなかったものです。

- **stdio・HTTP MCPサーバーの`PreToolUse` `mcp_tool`フックが、レスポンスが16MiBを超えるとスキップされていた問題を修正**し、今後はそのツール呼び出し自体が拒否されます。
- **`grep -r foo "$PWD/src"`のように変数で指定した読み取り専用コマンドが、パスを直接書いた同じコマンドと異なり不要な権限プロンプトを表示していた問題を修正**しました。
- **`claude agents`コマンドの後に`--verbose`など他のフラグが一緒に指定されていると、`--permission-mode`・`--dangerously-skip-permissions`・`--model`・`--effort`・`--agent`フラグが無視されていた問題を修正**しました。
- **ファイル名に文字の方向や制御文字が隠されていてClaudeアプリ上で別の名前に見えていたファイルを、Claudeが送信拒否するように変更**しました。
- **大きなファイルを1行ずつ繰り返し読み込む長時間セッションでメモリ使用量が増加していた問題を修正**しました。
- **セッション開始時にClaudeへ渡されるgit statusが、git status自体が失敗した場合に「クリーン」と誤って解釈されていた問題を修正**し、今後は「確認不可」として渡されます。
- **1,000文字を超えるバックグラウンドコマンドの通知とTaskStopの結果が、全体ではなく先頭と末尾の部分だけClaudeに表示されるように変更**され、コンテキストを節約します。

## 注目プロジェクト＆ツール

- **Show GN: flickbook — Claude Code hooksでAIが行った変更を段階的に再生して見せるツール（11/11）**: エージェントの作業が終わるとdiffが一つの大きな塊として表示され、各変更がなぜ起きたのか追いにくい問題を、`flickbook start`で開始点を記録し`flickbook step`で（Claude Code hooksを使えば自動で）各ステップを記録した後、`flickbook replay`で各ステップのリクエスト・実際のdiff・関連する概念をローカルのWeb画面で見返せるようにして解決します。ファイルを読むだけで外部にデータを送信することはなく、巻き戻し用のClaude Code checkpointとは異なり、任意の時点での変更を後から読み返す用途として作られています。

```bash
npx flickbook --help
```
