## 開発者ワークフローティップス

### Google Cloud・Microsoft Foundryのsonnet・opusエイリアスが5.5に切り替わり、Foundryの既定モデルもSonnet 5.5になりました（v2.1.332）

**これまでGoogle CloudのAgent PlatformとMicrosoft Foundryで`sonnet`・`opus`エイリアスを使うと世代が混在し、実際に呼び出されるモデルがプラットフォームごとに異なっていましたが、今回のリリースから両プラットフォームの`sonnet`エイリアスはSonnet 5.5に、Foundryの`opus`エイリアスはOpus 5.5にそれぞれ統一されました。** ただしAmazon Bedrockの`sonnet`エイリアスは引き続きSonnet 4.5を指すため、プラットフォーム間で動作が異なる点に注意が必要です。Microsoft Foundryの既定モデルもSonnet 5.5に変わったため、独自にデプロイしたモデルを使うには`claude-sonnet-5-5`をデプロイするか、`ANTHROPIC_DEFAULT_SONNET_MODEL`を使いたいモデルに設定する必要があります。Google CloudのAgent Platformでは、`sonnet`とバックグラウンドリクエストが今後`VERTEX_REGION_CLAUDE_5_5_SONNET`環境変数を読み込むようになり、この値がなく`_4_5`の変数だけが設定されている場合は`CLOUD_ML_REGION`または`us-east5`にフォールバックします。さらに、Bedrock Mantle・Agent Platform・FoundryでSonnet 5または5.5に切り替わったターミナル・VS Codeのセッションは、モードが明示的に指定されていない限り今後autoモードで開始されるようになります。

```bash
# Microsoft FoundryでSonnet 5.5ではなく特定のデプロイ済みモデルを既定値にするには
export ANTHROPIC_DEFAULT_SONNET_MODEL="my-deployed-model-name"

# Bedrock Mantle・Agent Platform・Foundryでautoモードの自動起動を無効にするには
# settings.jsonに以下の設定を追加
{ "disableAutoMode": "disable" }
```

**Google CloudやMicrosoft Foundryで`sonnet`・`opus`エイリアスやFoundryの既定モデルに依存してClaude Codeを運用している場合、今回の変更で実際に呼び出されるモデルの世代が変わっている可能性があるため、`VERTEX_REGION_CLAUDE_5_5_SONNET`・`ANTHROPIC_DEFAULT_SONNET_MODEL`の設定を確認し、autoモードへの自動切り替えを避けたいなら`disableAutoMode`を事前にオフにしておく価値があります。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

### VS Code・Desktopにセッションの一部保存失敗・過去メッセージ未読込の警告が追加されました（v2.1.332）

**これまでVS CodeやDesktopのCodeタブでセッションの一部が保存されなかったり、再度開いた際にターミナルでは表示されていた過去のメッセージが欠けたまま読み込まれても、特に案内が表示されませんでしたが、今回のリリースからどちらのケースでも画面上に警告が表示されるようになりました。** 保存失敗の警告には`/compact`でその時点の内容を保存する方法も併せて案内され、メッセージ未読込の警告はターミナルがすでに表示していた情報をVS Code・Desktopにも同じく表示するものです。

**VS CodeやDesktopのCodeタブで長い会話を続けていて、理由もわからずコンテキストが途切れたように感じたことがあるなら、v2.1.332からはその原因が保存失敗なのかメッセージ未読込なのかを画面上の警告で区別でき、`/compact`で対応できます。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

### プランモードが安全性を判断できないコマンドに対して拒否ではなく承認を求めるように変わりました（v2.1.332）

**これまでDesktopのCodeタブとVS Codeでは、プランモード中のautoモードの安全性チェッカーがあるコマンドの安全性を判断できない場合、そのコマンドをそのまま拒否していましたが、今回のリリースからManualまたはAccept editsで入ったプランについては拒否ではなく承認を求めるように変わりました。** 安全性の判断が難しいコマンドを一律でブロックするのではなく、最終判断を人間に委ねる方向にデフォルトの動作が変わったということです。

**DesktopやVS Codeでプランモードで作業中、安全性の判断が不確かなコマンドがそのまま拒否されて作業の流れが止まった経験があるなら、v2.1.332からはその場で承認するかどうかを自分で選べるようになったので、拒否されたコマンドが実際に危険かどうかをまず確認してみる価値があります。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

### Googleが2027年2月からWorkspace AIエージェントに自社MCPサーバーの利用を義務化します — Gmail送信は依然パートナー限定（11/24発表）

**これまでAIエージェントがGmail・Drive・CalendarなどGoogle Workspaceのデータにアクセスする際は、REST APIを直接呼び出しても特に制約はありませんでしたが、Googleは11/24にWorkspace MCPサーバー8種を正式リリースするとともに「Workspace AI Tools Addendum」という規約を追加し、2027年2月1日からAIエージェントやAIモデルが駆動するツールによるREST直接呼び出しに制約を課すことにしました。** その日以降、RESTを直接呼び出すエージェントは有料プランを使っていても無料のStandardプランの割り当て（プロジェクトごとに1日5,000 MCPリクエスト、Gmail検索1回は10回分として計算）が強制適用され、呼び出し自体は動作するものの規約違反の状態になります。AIを使わない夜間バックアップやCRM同期のような決定論的なスクリプトは、別のOAuthクライアントを使えばこの制約を回避できます。最も目立つ抜け穴はGmailで、公開MCPサーバーは検索・読み取り・下書き作成・ラベル管理のみをサポートし、送信・返信・転送・下書きの編集は依然パートナー限定のままで、添付ファイルのダウンロードやフィルター管理も対象外です。Driveは移動・共有・名前変更をサポートせず、Calendar・Chatはカレンダーやスペースの作成・管理をサポートしません。有料のScaledプランは2027年4月1日からGmail・Calendar・Driveに課金されますが、MCPは最初のリクエストから課金される一方でRESTには大規模な無料枠が残っており、価格設定そのものがMCPへの移行を促す形になっています。Hacker Newsのコメントでは、GmailがSMTPをサポートしているため送信制限をエージェントが簡単に回避できるという指摘や、MCPのelicitationで送信前にユーザー確認を取れるにもかかわらず送信をパートナー限定にしたのは安全性よりビジネス上の判断に近いという批判が多く見られ、Microsoft 365・Fastmail・自前ホストのIMAPといった代替手段を探す議論も続きました。

**MCPでGmail・Drive・CalendarなどGoogle Workspaceに接続して使うClaude Codeエージェントや自前の自動化を運用している場合、2027年2月1日以降REST直接呼び出しは無料枠へ強制的に切り替わるため、今のうちに公式MCPサーバーへの移行計画を立て、メール送信のようにまだパートナー限定で塞がれている機能についてはSMTPのような代替手段を事前に確認しておく価値があります。** [原文](https://techstackups.com/articles/google-workspace-ai-agents-mcp/) · [GeekNews](https://news.hada.io/topic?id=37919)

## 知っておくと便利な小さな変更点

以下はいずれも**v2.1.332**（11/25）の項目のうち、11/26のブリーフィングと上記で取り上げていないものです。

- 他のセッションから届いた保留中メッセージの確認ダイアログに「常に配信」（Always deliver）オプションが追加され、毎回選び直さなくても以降のメッセージをそのまま受け取れるようになりました。
- SendUserMessageやCoworkのメッセージツールでClaudeが送信したテキストに対するOpenTelemetryの`assistant_response`イベントが追加され、応答ロギングが有効な場合は観測パイプラインでそのまま集計できるようになりました。
- 中断したバックグラウンドエージェントに未読のサブエージェントレポートがある際、プロンプトでCtrl+Cを押すと新しいターンが始まってしまい、2回押しても終了しない問題が修正されました。
- 10,000文字を超える音声入力テキストが消えてしまう問題が修正されました。
- macOSでClaude CodeのウィンドウまたはAllowしたアプリが前面にあるとき、コンピュータ操作中にEscが動作を止められない問題が修正され、以降はそのアプリのポップアップに対するEscがコンピュータ操作自体を停止するようになりました。
- 週間使用量上限に大きな余裕がある契約者に対してアイドル圧縮（idle compaction）がスキップされてしまう問題が修正されました。
- "You've used"や"You've hit your"で始まる通常の応答が、赤い使用量上限エラーとして誤表示される問題が修正されました。
- Grepの`-o`が、末尾に改行のないファイルの最後の空マッチを取り落としていた問題が修正されました。
