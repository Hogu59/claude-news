## 主要な新機能と実践活用

### maxProseWidth設定を追加 — 広いターミナルでも応答の行幅を自分で指定できます (v2.1.282)

**超大型モニターや幅広のtmux paneでClaude Codeを使うと、説明文(prose)が画面いっぱいに広がってかえって読みにくいことがありましたが、この幅を個別に指定できるようになりました。** **テーブルとコードブロックはこの設定と無関係に、これまで通り画面幅いっぱいに表示されます。**

```json
{
  "maxProseWidth": 100
}
```

**広い画面にClaude Codeを常時開いている開発者なら、この設定で説明文だけ適度な幅に抑えつつ、テーブルやコードは従来通り広く表示させることで、手軽に読みやすさを上げられます。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### Claudeアプリゲートウェイにreadiness_grace_secondsを追加 — 短時間のDB障害でもready状態を維持 (v2.1.282)

**セルフホストのClaudeアプリゲートウェイ設定で `store.readiness_grace_seconds` を指定すると、Postgresのフェイルオーバーのような短時間のデータベース障害が発生しても `/readyz` ヘルスチェックが即座にnot ready状態に切り替わらず、設定した猶予時間だけready状態を維持します。**

```json
{
  "store": {
    "readiness_grace_seconds": 30
  }
}
```

**Kubernetesなどで `/readyz` を基準にトラフィックをルーティングしているセルフホストゲートウェイの運用チームなら、DBフェイルオーバーの数秒でPod全体がunready扱いになりトラフィックが途切れる事態を、このオプションで防げます。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## 開発者ワークフローティップス

### プラグインhookのCLAUDE_PLUGIN_ROOTは必ずクォートで囲みましょう (v2.1.282)

**`claude plugin validate` が、shell形式のhookで `${CLAUDE_PLUGIN_ROOT}` をクォートなしで使っている場合に警告を表示するようになりました。** **スペースを含むパスにプラグインがインストールされると、クォートなしの参照が静かに壊れてしまうためです。**

```json
{
  "hooks": {
    "PreToolUse": [
      { "hooks": [{ "type": "command", "command": "\"${CLAUDE_PLUGIN_ROOT}/scripts/check.sh\"" }] }
    ]
  }
}
```

**社内プラグインを配布する前に `claude plugin validate` を実行する習慣をつけておけば、macOSやWindowsのユーザー名にスペースが混じっていてもhookが壊れないか事前に確認できます。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### sandbox.network.allowLocalBinding — macOSサンドボックスでローカル開発サーバーが止まるときは (v2.1.282)

**macOSサンドボックス環境でローカル開発サーバーがポートをバインドできずに止まってしまう場合、Claudeが原因となりうる設定として `sandbox.network.allowLocalBinding` を直接案内するようになりました。**

```json
{
  "sandbox": {
    "network": {
      "allowLocalBinding": true
    }
  }
}
```

**サンドボックスを有効にしたまま `npm run dev` やローカルAPIサーバーを頻繁に起動するチームなら、毎回原因を探し回る代わりに、この設定をCLAUDE.mdやプロジェクトのsettings.jsonに事前にドキュメント化しておくとよいでしょう。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## セキュリティ・制限事項

### Claudeサービス稼働状況 — 9/25時点で全サービス正常 (9/25)

**新しいリリースとモデル発表が立て続けに出た1週間だったにもかかわらず、サービスの安定性には大きな影響がなかったことから、特別な対応をせず通常運用を続けて問題ない時期といえます。** [Claude Status](https://status.claude.com)

### macOSのシンボリックリンク経由でネットワークマウントまで読み込まれる問題など、権限まわりのセキュリティ修正が多数 (v2.1.282)

**起動時にCLAUDE.mdやrulesファイルを読み込む過程で、リポジトリ内のシンボリックリンクが `..` や `/.vol` 形式のカーネルパスを経由してmacOSの `/Network`(ネットワークマウント)に到達したり、macOSの `/home` を指すrulesリンクがそのまま列挙されてしまう問題が修正されました。** **権限ルールにNULバイトが混入しているとワイルドカードのようにあらゆるものにマッチしてしまう問題も修正され、今後はそうしたルールは何にもマッチしなくなります。**

**管理設定でも `disableClaudeAiConnectors` や `allowManagedPermissionRulesOnly` のようなboolean型のロックキーにタイプミスの値が入っているとロック自体が無視されてしまう問題、そして `permissions`・`autoMode`・`worktree`・`attribution` 設定のうち1つでも誤っているとブロック全体が無視されてしまう問題も併せて修正され、今後はタイプミスが起動時に名前つきで警告され、残りの有効な設定はそのまま適用されます。また、プロジェクト・ローカル設定ファイルでは `CLAUDE_CODE_ENABLE_TELEMETRY` や `OTEL_LOG_*` のようなテレメトリの有効化・エンドポイント・コンテンツキャプチャ用の変数を指定できなくなり、どの変数が無視されたかは起動時の通知や `/status`、`claude doctor` で確認できます。**

**リポジトリを複数人で共有していたり外部リポジトリをクローンして使っている組織なら、シンボリックリンクや壊れた権限ルールを介した迂回経路の多くが今回のリリースで塞がれているため、最新版へのアップデートが必要です。組織の管理設定でテレメトリや権限を厳格に統制していた場合は、タイプミスのせいでロックが静かに外れていなかったかも、この機会に点検する価値があります。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)
