## 主要な新機能と実践活用

### `CLAUDE_CODE_SUBAGENT_EFFORT`でサブエージェントの既定effortをメインセッションと別に指定できます (v2.1.316)

**これまでサブエージェントはeffortを個別指定しない限りメインセッションのeffortをそのまま引き継いでいましたが、この環境変数によってサブエージェント専用の既定値を別途設定できるようになりました。** 他で明示的にeffortを指定していないサブエージェントにのみ適用され、effortを明示したサブエージェントやメインセッションには影響しません。

```bash
# メインセッションはultrathinkまで上げつつ、サブエージェントは既定effortに固定
export CLAUDE_CODE_SUBAGENT_EFFORT=medium
```

**メインセッションのeffortをxhighやultrathinkまで上げて複雑な作業を任せる一方で、その下で何十個も立ち上がるサブエージェントまで同じeffortでトークンを消費するのはもったいないと感じていたなら、この環境変数でサブエージェントだけ低コストなeffortに固定しておくのがコスト管理に効果的です。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### Claude apps gatewayにグループで共有する月次予算プールが追加されました (v2.1.316)

**各メンバー個別の上限に加えて、グループ全体で共有する月次予算を1つ追加で設定できるようになりました。** spend limits admin APIの`pooled_budget`フィールドで設定し、個人の上限が残っていてもグループ全体の予算を使い切ると追加の支出をブロックする仕組みです。

```json
// spend limits admin APIの設定例
{
  "group_id": "eng-team",
  "pooled_budget": 5000
}
```

**チーム全体のClaude利用料を個人ごとの上限だけでは管理しきれなかった組織であれば、今回追加されたグループ予算プールでチーム単位の上限をもう1段設けられる点をadmin設定で確認しておく価値があります。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## 開発者ワークフローティップス

### `CLAUDE_CODE_DISABLE_ULTRATHINK`で`ultrathink`キーワード自体を無効化できます (v2.1.316)

**`ultrathink`がターン中に入力しても即座に残りのターンのeffortを引き上げるよう適用範囲が広がってから数日で、このキーワードを組織単位で丸ごと無効化できるスイッチが追加されました。** 複数人が同じ環境を共有していたり、ドキュメントやコミットメッセージに偶然この単語が含まれてeffortが意図せず急上昇する事態を防ぎたいときに使えます。

```bash
export CLAUDE_CODE_DISABLE_ULTRATHINK=1
```

**コストを厳しく管理する必要がある共有環境やCIでClaude Codeを動かしているなら、誰かが習慣的に`ultrathink`と入力してeffortが跳ね上がる事態を、この環境変数で根元から防いでおく価値があります。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### `SHELLOPTS`がexportされているとBashツールで実行したスクリプトが最初のコマンドの後で止まってしまう問題が修正されました (v2.1.316)

**シェル設定やCI環境では`set -o`で有効化したオプションを`SHELLOPTS`として子プロセスに引き継ぐことがありますが、この環境変数がexportされた状態だとBashツールで実行したスクリプトが最初の1コマンドだけ実行して停止してしまう問題がありました。** 原因が分からないとスクリプト自体に問題があると誤解しやすい不具合でした。

**スクリプトが途中で理由もなく止まる現象に遭遇し原因が分からなかったなら、まず`SHELLOPTS`をexportするシェル設定がなかったか疑ってみて、v2.1.316へのアップデートを検討する価値があります。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### 大規模リポジトリで`/diff`が更新されるたびに走っていたリポジトリ全体へのgitコマンドが1つ減りました (v2.1.316)

**`/diff`が画面を再描画するたびにリポジトリ全体をスキャンするgitコマンドを通常1つ少なく実行するようになり、gitの応答が遅いときは更新間隔を自動的に延長します。** これまでは大規模なモノレポで`/diff`を開いたままにしておくと、更新ごとにgitコマンドが積み重なり体感速度が低下することがありました。

**数万ファイル規模のモノレポで`/diff`を開きっぱなしにして作業しているなら、v2.1.316から更新が明らかに軽くなったか確認してみる価値があります。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### LinuxカーネルのTCP処理の欠陥によりCVSS 9.8のuse-after-free脆弱性が公開されました (10/29)

**CVE-2026-98432はIPv4のTCPハンドシェイク処理中に発生するuse-after-freeで、4.4以降パッチが適用されていないすべてのLinuxカーネルに影響し、アプリケーション認証より前の段階で発生するためWeb・SSH・DB・ロードバランサー・Kubernetesノード全般が晒されます。** AnthropicはMPTCPリスナーを持つサーバーで認証情報なしにroot権限を取得できる実験室攻撃を報告しており、アップストリームは`kfree()`を`kfree_rcu()`に置き換えて修正しました。

**Claude Codeでサーバーやkubernetesインフラを管理している、あるいはセキュリティチェックを自動化しているなら、稼働中のカーネルバージョンをディストリビューションのセキュリティトラッカーと照合し、`ss -Mlnp`でMPTCPリスナーがないか確認した上でパッチ適用を最優先にすべきです。** [GeekNews](https://news.hada.io/topic?id=36352)

## エコシステム＆プラグイン

### Opus 4.8のfast modeが非推奨予告に入りました — 11/30に削除 (v2.1.316)

**Opus 4.8のfast modeは2026年10月30日から非推奨予告の状態に入り、11月30日に完全に削除されます。** 削除後はOpus 4.8にfast modeで送ったリクエストが標準のOpus 4.8へ自動的に切り替わることはなく、そのままエラーを返します。速度向上を引き続き享受したい場合はOpus 5.5への移行が必要です。

**Opus 4.8のfast modeに依存するパイプラインや自動化があるなら、11月30日より前にOpus 5.5への移行をテストしておかないと、それ以降のリクエストがそのままエラーになる事故を招きます。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### OpenAIのNavier-Stokes証明作業の手法をそのまま取り入れたClaude Codeプラグインが公開されました (10/31)

**OpenAIがNavier-Stokesの証明作業で使ったと説明したワークフロー — 仮説ごとに証明チームと反証チームを分けて独立に検証し、ラウンドごとに各チームの主要な発見を相互共有した上でbudgetを有望な仮説に再配分する方式 — をそのまま移植した非公式のClaude Codeプラグインです。** 検証基準を探索前にあらかじめ定義し、独立検証を通過した主張のみを結論に反映するほか、チーム方式が単独実行のベースラインより実際に優れていたかどうかも自動で判定します。作者はトークン消費量が8〜10倍になると明かしており、答えが一つに定まらない高コストな問いにのみ適していると付け加えています。

```bash
/plugin marketplace add mydal-lab/hypothesis-teams
```

**複数の仮説が同時にそれらしく見える複雑な検証作業をClaude Codeに任せているなら、単独で判断させる代わりにこのプラグインで証明チームと反証チームに分けて相互検証する構成を試してみる価値があります。** [GeekNews](https://news.hada.io/topic?id=36319)

## 知っておくと便利な小さな変更点

以下はすべて**v2.1.316**(10/31)の項目です。

- **`managed.policy_mode: layered`が追加**され、従来は開発者にマッチするポリシーが1つだけ適用される方式でしたが、マッチするすべてのポリシーが下から順にマージ適用されるようになりました。
- **Bedrockアップストリームに`guardrail.input_tagging`が追加**され、Amazon Bedrock guardrailのprompt attackフィルターが要求する入力タグでプロンプトを包むようになりました。`all_messages_and_system`を使うとシステムプロンプトにもタグが付きます。
- **`CLAUDE_CODE_DISABLE_LOOPED_CROSS_CERT_DROP`が追加**され、相互に認証し合うクロス証明書がループ構造になっている独自CA環境で、それらの証明書を削除せず保持できるようになりました。
- **[VSCode] ターミナルを使わずチャットパネルから直接Claude apps gatewayにログイン**できるようになりました。
- **[Cloud sessions] MCPサーバーが要求する入力フォームに回答または拒否できるフォームカードが追加**され、これまでは表示されないままリクエストがキャンセルされてしまうことがありました。
- **[Code Review] 分析ページに期間別・深刻度別の検出件数を示すカードが追加**されました。
- **Vertex AI・Bedrockでsonnet・opus・haikuの最新モデルがアカウントやリージョンにまだ存在しない場合にセッション中にエラーを出していた問題が修正**され、古いモデルへ自動的にフォールバックするようになりました。
