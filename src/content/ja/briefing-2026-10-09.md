## 主要な新機能と実践活用

### フックに `onFailure: "block"` を追加 — 起動失敗・タイムアウトでもアクションを止められるように (v2.1.295)

**command・HTTPフックに `onFailure: "block"` オプションが追加され、フックが起動に失敗したりタイムアウトしたり想定外の終了コードを返した場合でも、そのまま通過させるのではなくアクションをブロックできるようになりました。** これまではフック自体が失敗すると、その検査が静かにスキップされてアクションが進んでしまうのが通常の動作でしたが、機密情報の検出のようなシビアなガードレールではこの挙動がむしろ危険になり得ました。

```json
{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Bash",
      "hooks": [{ "type": "command", "command": "./check.sh", "onFailure": "block" }]
    }]
  }
}
```

**機密情報の漏えい防止や危険なコマンドの検証など、失敗してはならないフックを運用しているなら、`onFailure: "block"` を指定して、フック自体がクラッシュしたり応答しなかったりしてもアクションがそのまま通過しないようにしておくのが安全です。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### OSC 7501 — ターミナルがClaude Codeの作業状態を直接受け取れるように (v2.1.295)

**Claude CodeがProgram Status Protocol(OSC 7501)のサポートを開始し、これに対応したターミナルは画面表示やウィンドウタイトルから推測するのではなく、Claude Codeが作業中なのか、ユーザーの介入を待っているのか、完了したのかを直接受け取って表示できるようになりました。** 同日GeekNewsにもこのプロトコル自体を取り上げた記事が掲載され、既存のptyをそのまま使いながら、専用のソケットAPIなしでSSH経由でも状態を伝達できる点が特徴として挙げられています。

**タブタイトルやステータスバーのカスタマイズプラグインを使っているターミナル(iTerm2、Ghostty系など)を使っているなら、OSC 7501対応バージョンに更新しておくと、複数のウィンドウでどのClaude Codeセッションが待機中かを一目で区別できるようになります。** [GeekNews](https://news.hada.io/topic?id=34994) · [リリースノート全文](https://github.com/anthropics/claude-code/releases)

**Claude Opus 5.5とGPT-6 Astraの両方に、「Italo Calvinoの『見えない都市』に登場するすべての都市をthree.jsとpnpmを使ってインタラクティブに可視化せよ」というプロンプトだけを与え、追加の質問なしに傑作ができあがるまで最大6時間自律的に作業させた実験です。** 10/4のブリーフィングで紹介した「Opus 5.5は細かい指示を分割するより、目標と完了条件を一度に伝える方が向いている」というティップスを、実際に数時間単位まで引き延ばして試した事例と言えます。

**長時間の自律実行が必要な創作・プロトタイピング作業をOpus 5.5に任せる際は、途中で様子を見ながら指示を追加したくなる誘惑を抑え、最初に目標・完了基準・出力形式だけを明確に伝えたうえで本当に数時間そのまま任せてみると、モデルが自ら反復改善する力をより長く引き出せます。** [GeekNews](https://news.hada.io/topic?id=35013)

### 「ifは呼び出し側、forは関数内」パターンをCLAUDE.mdの規約として明文化する (10/8)

**条件分岐は呼び出し側に置き、繰り返し処理はバッチ処理関数の内部に置くことで制御フローが一箇所に集約され、中核のロジックがシンプルになるというイディオムを整理した記事です。** 呼び出し側がNone処理を担い、関数側はOption(あるいは単なる値)を受け取るように役割を分けることで、入力の型判定と分岐の責務がコード全体に散らばらずに済みます。

**Claude Codeが生成する関数の構造がチームごとにばらついているなら、このパターン(「条件は呼び出し側、繰り返しはバッチ関数の内部」)をCLAUDE.mdのコーディング規約に明記しておくと、レビューのたびに同じ構造上のフィードバックを繰り返さずに済みます。** [GeekNews](https://news.hada.io/topic?id=35001)

## セキュリティ・制限事項

### Claudeサービスの稼働状況 — Claude Consoleの性能低下が2日目、他は正常 (10/9)

**公式のstatus.claude.comを確認したところ、10/9時点でclaude.ai・Claude API・Claude Code・Claude Cowork・Claude for Governmentはすべて正常稼働(Operational)ですが、Claude Console(platform.claude.com)は10/8に続き2日連続で使用量データの読み込み遅延による性能低下(Degraded Performance)が続いています。** 10/7には支出上限の処理エラーで一部組織のリクエストが誤って拒否されるインシデント(21:23 UTCに解決)と、UsageページおよびAdmin APIの使用状況レポートのエラー(02:33 UTCに解決)が発生していました。10/6のOpus 5.5エラー増加(12:43 UTCに解決)、10/5のMythos 5.1・Fable 5.1のエラー(13:21 UTCに解決)も、いずれも当日中に解消されています。

**Claude Consoleの使用量ダッシュボードの数値がまだ最新状態と合っていない場合は、この性能低下がまだ続いているということですが、Claude Code自体の動作やAPI呼び出しには影響がないので通常どおり利用して問題ありません。** [Claude Status](https://status.claude.com)

### 指示文形式のprompt・agentフックが本来止めるべき対象を素通りさせてしまう問題を修正 (v2.1.294)

**「次のようなコマンドをブロックせよ」といった自然言語の指示文で書かれたprompt・agentフックが、実際には止めるべき対象を素通りさせてしまうことがあった問題が修正されました。** 同リリースでは、Stop・SubagentStopにかけた「ビルドが壊れていても続行せよ」のような指示文フックの判定方法も改善され、Claudeが作業を早すぎるタイミングで止めてしまう傾向が減りました。

**決定的なコードの代わりに自然言語の指示文でブロックルールを書いたガードレールフックを運用しているなら、v2.1.294に更新して今回塞がれた回避経路を適用し、本当に失敗してはならないフックであれば先述のv2.1.295の`onFailure: "block"`と併用して二重に防御しておくのが安全です。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### 許可関数リストだけでは不十分 — 名前を使わずに関数を呼び出す (10/8)

**学校のCコード自動採点環境で、許可された関数リストのチェックを回避し、execveシンボルを直接使わずにシェルを起動する概念実証が公開されました。** ASLRがメモリ配置アドレス全体を変えても、同じセグメント内にある関数同士の相対的な位置関係は保たれるため、許可された関数のアドレスと目的関数までの相対オフセットさえ分かれば、名前を使わずに呼び出せるという仕組みです。

**コマンドや関数名を許可リストでフィルタリングして安全性を確保しようとするサンドボックスを設計しているなら、名前のマッチングだけでは同一バイナリ内の相対アドレス計算のような回避を防げないことを示す事例であり、実際の動作やシステムコールのレベルまで検証する防御を併せて設ける必要があります。** [GeekNews](https://news.hada.io/topic?id=35003)

## 知っておくと便利な小さな変更点

以下はすべて**v2.1.295**(10/8)での変更です。

- **`CLAUDE_CODE_RETRY_WATCHDOG_MAX_WAIT_MS` 環境変数が追加**され、無人リトライモード(`CLAUDE_CODE_RETRY_WATCHDOG`)が429・529エラーを待つ最大時間を直接制限できるようになりました。
- **ToolSearchで読み込むMCPツール説明の文字数上限が2,048文字から16,384文字に拡大されました。**
- **サブエージェントが`skills`フィールドで事前に読み込めるスキルが最大32個までに変更されました。** Skillツールを持つサブエージェントは、残りのスキルも直接呼び出せます。
- **Grep呼び出しに`-l`・`-c`・`-r`などgrep独自のフラグが混在していても失敗せずそのまま実行されるよう改善されました。**
- **応答が数万行に達した際にターミナルが固まり、Ctrl+Cも効かなくなる問題が修正されました。**
- **Claudeアプリゲートウェイの成功した推論レスポンスに`request-id`ヘッダーが追加**され、Claude Codeテレメトリの`request_id`とゲートウェイの監査ログを突き合わせられるようになりました。
