## 主要な新機能と実践活用

### VS Code・Claude Desktop Codeタブにアイドル中の会話の自動圧縮が追加されました（v2.1.314）

**200Kトークンを超える会話をしばらく放置すると、VS CodeとClaude DesktopのCodeタブが自動で要約し、prompt cacheが期限切れの状態で次のメッセージを送るとその要約がそのまま使われます。** これまでは、長時間放置した長い会話に戻ると、キャッシュが切れた全履歴をそのまま再処理する必要があり、最初の応答が遅く、コストも余計にかかっていました。

**日中に複数のタスクを切り替えながらVS CodeやClaude DesktopのCodeタブで長い会話を開いたままにする習慣があるなら、v2.1.314以降は再開時の最初の応答が軽くなることが期待できます。** [リリースノート全体](https://github.com/anthropics/claude-code/releases)

## 開発者ワークフローティップス

### バックグラウンドエージェントの状態要約呼び出しが全トークンの15〜20%を消費していました（GeekNews、10/29）

**Claude Codeがバックグラウンドエージェントの会話履歴全体を約30秒ごとにモデルへ再送し、「直前の行動を3〜5語で説明せよ」と要求していること、そしてこの状態要約呼び出しが全トークン使用量の15〜20%を占めているという分析が投稿されました。** 結果はエージェントパネルのステータス行にしか使われないにもかかわらず、これをオフにする設定は用意されておらず、投稿者はバイナリを改変せずに要約タイマーだけを止めるスクリプトを公開しましたが、内部文字列に依存しているためアップデートごとに再検証が必要だと述べています。

**バックグラウンドやサブエージェントを複数同時に長時間立ち上げるワークフローを使っているなら、この状態要約呼び出しが使用量上限の消費にどの程度影響しているか、`/usage`で実際の比率を確認してみる価値があります。** [GeekNews](https://news.hada.io/topic?id=36213)

### `permissions.blockWritesOutsideWorkingDirectories`で、どの権限モードでも作業ディレクトリ外への書き込みをブロックできます（v2.1.314）

**新しい設定が追加され、有効にするとWrite・Edit・NotebookEditが権限モードに関わらず、作業ディレクトリ外のパスへの書き込みを常に拒否するようになります。** これまでは、bypass permissionsモードのように承認プロセスが緩いモードでは、作業ディレクトリ外のファイルも変更されてしまう余地がありました。

```json
// settings.json
{
  "permissions": {
    "blockWritesOutsideWorkingDirectories": true
  }
}
```

**複数のリポジトリやホームディレクトリ全体を対象にauto modeやbypass permissionsモードを使っているなら、この設定で意図しない作業ディレクトリ外のファイルが誤って変更される事故を根本から防いでおく価値があります。** [リリースノート全体](https://github.com/anthropics/claude-code/releases)

### バックグラウンドのdiff更新がgitインデックスロックを握り、同時実行したgitコマンドが失敗する問題が修正されました（v2.1.314）

**Claude Codeが変更内容を表示するためにバックグラウンドでdiffを更新する際、リポジトリのインデックスロックを一時的に保持していたため、同じタイミングでターミナルからgitコマンドを実行すると「Unable to create '.git/index.lock': File exists」エラーで失敗することがありましたが、今回修正されました。** これまでは、Claude Codeが作業中に別のターミナルでgit statusやgit commitを実行すると、原因が分かりにくいロックエラーに遭遇することがありました。

**Claude Codeを起動したまま別のターミナルでgitコマンドを頻繁に併用しているなら、v2.1.314以降はこのロック競合をもう気にしなくて済みます。** [リリースノート全体](https://github.com/anthropics/claude-code/releases)

## セキュリティ・制限事項

### Claudeサービスの状況 — 10/29〜10/31はすべてインシデントなし、全サービス正常稼働中

**公式のstatus.claude.comを直接確認したところ、10/29・10/30・10/31のいずれも「No incidents reported」と表示されており、claude.ai・Claude Console・Claude API・Claude Code・Claude Cowork・Claude for Governmentのすべてが正常（Operational）稼働中です。** 直近のインシデントは10/28のGoogle Calendar・Gmailコネクタのエラーで、すでにすべて解決済みです。

**直近数日で発生していたエラーはすでに解消済みなので、今日問題が起きた場合はローカル設定やネットワーク周りをまず確認するのが合理的です。** [Claude Status](https://status.claude.com)

### `claude -p --resume`・`--continue`で入ったワークツリーにサンドボックス保護が適用されない不具合が修正されました（v2.1.314）

**非対話モードで`claude -p --resume`や`--continue`を実行してワークツリーに入る際、サンドボックス保護が適用されない問題が修正されました。** これまでは、対話型セッションでは適用されていたサンドボックスの制約が、同じワークツリーを非対話的に再開した際には適用されないケースがありました。

**CIやスクリプトから`claude -p --resume`・`--continue`で信頼できないコードを扱うワークツリーを再開しているなら、v2.1.314にアップデートしてサンドボックスが実際に機能しているか再確認する価値があります。** [リリースノート全体](https://github.com/anthropics/claude-code/releases)

### korea-data-mcp — AIエージェントが韓国の公共APIを誤読しないようにするMCPサーバー（10/30）

**DART（韓国の企業公示システム）、公共データポータル、国家法令情報APIを1つのMCPサーバーにまとめ、AIエージェントが企業・不動産・法令データを照会する際によく落ちる罠（半期累計と四半期数値の混同、解除済み契約が混在した実売買価格、変更された行政区域コードなど）をサーバー側で事前に処理します。** 企業の開示・財務諸表、マンション売買の実勢価格、法令・判例検索など15個のツールを提供し、ローカルマシン上でのみ実行されます。

**Claude Codeで韓国企業の分析や不動産・法律データを扱うワークフローを組んでいるなら、公共APIレスポンスの罠を毎回自前で処理する代わりに、このMCPサーバーを接続してみるのが効率的です。** [GeekNews](https://news.hada.io/topic?id=36277)

### Blackstone、AnthropicはIPO後も投資適格の信用格付けを得られない可能性があると評価（10/31）

**Blackstoneは、Anthropicが上場後も投資適格（investment grade）の信用格付けを得られない可能性があるとの見通しを示し、AI研究企業の財務構造は構造的に脆弱で投機的だとの意見が続きました。** ただし、リスクが高いことと悪い投資であることは必ずしも同義ではないという反論も出ています。

**Claude CodeやClaude APIを企業環境へ長期的に導入する意思決定をしているなら、Anthropicの財務健全性に関する外部評価が分かれている点を、一つのリスク要因として参考にする価値があります。** [GeekNews](https://news.hada.io/topic?id=36306)

## 知っておくと便利な小さな変更点

以下はすべて**v2.1.314**（10/30）の項目です。

- **Microsoft Foundryセッションで、デフォルトのSonnet・Opus・Haikuモデルのデプロイが存在しないリソースを使う場合、同モデル群のより古いモデルへ自動フォールバック**されます。
- **Bedrockで画像を多く含む会話が毎ターン失敗し、`/compact`も「Input is too long.」で止まっていた問題が修正**され、古い画像を削除・圧縮してから続行できるようになりました。
- **システムの証明書ストアに、以前のルートとクロス署名された更新済みルート証明書が入っている場合にTLS接続が`UNABLE_TO_GET_ISSUER_CERT`で失敗していた問題が修正**されました。
- **「使用量上限到達時の自動継続」が、/goalチェックインやバックグラウンド・予約タスクでターンが再開された際に確認を取らず3回を超えて継続していた問題が修正**されました。
- **CoworkクラウドセッションのWebFetchが、PDFテキストの100,000文字を超える部分を静かに切り捨てていた問題が修正**され、読み取れなかった範囲と続きの読み込み位置が表示されるようになりました。
- **PreCompactフックの出力が非常に長いと圧縮が失敗・繰り返されていた問題が修正**され、各フックの出力は10,000文字で切り詰められます。
- **Claude apps gatewayのアップストリームに`groups`リストが追加**され、フェイルオーバー時でも指定したIdPグループの開発者のみを該当アップストリームへ振り分けられます。
