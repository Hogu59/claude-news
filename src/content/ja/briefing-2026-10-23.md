## 主要な新機能と実践活用

### dataviz スキルがAPCAによるテキストコントラスト測定に対応しました (v2.1.309)

**バンドルされているdataviz スキルが、WCAG 2の明度コントラスト比の代わりに(あるいは併用して)APCAをテキストコントラストの測定基準として受け付けるようになり、パレット検証スクリプトに`apca(text, background)`関数が追加されたことで、色で塗りつぶされたチャート内のラベルが白にすべきか黒に近い色にすべきかをすぐに判定できるようになりました。** AA準拠が必要な場面では、従来のWCAG 2比率もそのまま使えます。

```js
// dataviz スキルのパレット検証スクリプト
apca(textColor, backgroundColor)
// → 色が塗られたチャート上のラベルを白にすべきか黒にすべきかを返す
```

**Claude Codeでダッシュボードやデータ可視化チャートを作る際にdataviz スキルを使っているなら、色で塗られた領域の上のラベル色を毎回目視で判断する代わりに、この関数で直接検証してみると便利です。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

### `/claude-api`スキルのManaged Agentsの既定値が動的ワークフロー(multiagent_20261001)に切り替わりました (v2.1.309)

**Claude PlatformでManaged Agentsのサブエージェントチームを構成する際、`/claude-api`スキルが従来の`coordinator`方式の代わりに、`multiagent_20261001`をベースにした動的ワークフローを既定で有効にしたチームを作るようになりました。** これまではサブエージェントチームの構造が固定のcoordinatorパターンでしか組めませんでした。

```
# /claude-api スキルが構成するManaged Agentsの既定値
workflow: multiagent_20261001 (dynamic workflows on)
# 従来の既定値: coordinator
```

**Claude PlatformでManaged Agentsベースのサブエージェントチームを運用しているなら、新しく構成するチームから動的ワークフローが既定で適用される点を確認し、既存のcoordinatorベースのチームとの挙動差を事前にチェックしておくとよいでしょう。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

## 開発者ワークフローティップス

### `--add-dir`で読み込んだスキル名が重複する場合、`folder:name`形式で呼び分けられます (v2.1.309)

**`--add-dir`で追加したフォルダのスキルが、同じ名前を使う別のスキルに隠れて呼び出せなかった問題が修正され、名前が重複するスキルは`<folder>:<name>`形式で提供されるようになりました。** これまでは名前が重複すると、後から読み込まれたスキルをそのまま使うことができませんでした。

```bash
# 例: apps/web フォルダのdeployスキルが別のdeployスキルと名前が重複する場合
/apps/web:deploy
```

**複数のリポジトリやプラグインから読み込んだスキルを`--add-dir`で同じセッション内に併用しているなら、名前が重複するスキル一覧から`<folder>:<name>`表記を見つけてそのまま呼び出す習慣をつけておくと、混乱を減らせます。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

### `/verify`と`/code-review`が、シェルで変更したネストしたパッケージ内の固有スキルを認識するようになりました (v2.1.309)

**モノレポでサブパッケージのファイルをシェルコマンドで変更した際、`/verify`と`/code-review`がそのパッケージ自身のスキルを見つけられなかった問題が修正されました。** これまではEdit・Writeツールではなくシェルでファイルを変更すると、サブパッケージのスキルが適用されないケースがありました。

**モノレポの各パッケージごとに個別のスキルを置いていて、シェルスクリプトやサブエージェントでファイルを頻繁に変更しているなら、今回の修正で`/verify`・`/code-review`が該当パッケージのスキルをより確実に見つけてくれるようになった点を活用する価値があります。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

### Windowsで Claude Codeが実行するgitコマンドが高速化し、エラーは常に英語で表示されるようになりました (v2.1.309)

**Claude Codeが内部で実行する各種gitコマンドの速度がWindowsで改善され、全プラットフォームにおいてgitが別言語に設定されていても、そのgitコマンドのエラーメッセージは英語で表示されるようになりました。** これまではロケール設定によってエラーメッセージが別言語で出力され、原因特定が面倒になることがありました。

**Windowsで Claude Codeを使い大規模リポジトリやワークツリーを頻繁に扱っていて、git関連の遅延や読みづらいエラーメッセージに悩まされていたなら、v2.1.309へのアップグレードで体感速度とエラーの可読性がともに改善されているか確認する価値があります。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

## セキュリティ・制限事項

### v2.1.309、サンドボックス・ワークツリー分離回避の不具合をまとめて修正 (10/22)

**今回のリリースでは、シンボリックリンク経由でアクセスした際にmacOSサンドボックスの`denyWrite`グロブパターンが適用されない問題、サンドボックスコマンドが実行のたびにシェル起動ファイルをサンドボックス外で実行していた問題、サンドボックスコマンドと自動承認された編集が`--mcp-config`で渡したMCP設定ファイルを変更できた問題、サブシェルを含む一部のコマンドで`Edit(path)`の拒否ルールがBashのリダイレクトを阻止できなかった問題、ワークツリー分離ガードがlocale接頭辞付きコマンドやzshの算術演算コマンドを検知できなかった問題、シンボリックリンク経由でアクセスした設定フォルダでプロファイルストアの書き込み保護が効かなかった問題を含め、分離・権限境界を回避できていた不具合を多数修正しました。** 個々には小さく見えても、いずれもサンドボックスやワークツリー分離が実質的に突破可能だった経路を塞ぐ修正です。

**サンドボックスモードやワークツリー分離機能を信頼境界として、信頼できないコードやエージェントを動かしているなら、v2.1.309へできるだけ早くアップグレードして、今回塞がれた回避経路を反映しておくのが安全です。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

### `claude ultrareview`がワークスペースの信頼確認を要求するようになりました (v2.1.309)

**`claude ultrareview`を実行すると、ターミナルでは信頼するかどうかを確認し、確認できない環境では実行を拒否するようになりました。** スクリプトでは値を取らない`--trust-workspace`フラグをPR番号やベースブランチの後に追加するか、環境変数`CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1`を設定することで、この確認をスキップできます。

**CIパイプラインや無人スクリプトから`claude ultrareview`を呼び出しているなら、v2.1.309へのアップグレード後に信頼確認で実行が止まらないよう、`--trust-workspace`か`CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK`の設定をあらかじめ追加しておく必要があります。** [全リリースノート](https://github.com/anthropics/claude-code/releases)

### Claudeサービス状況 — Connectorsの障害が4時間近く続いた後に解決 (10/22)

**公式のstatus.claude.comを確認したところ、10/22 03:50(UTC)にclaude.aiとClaude Coworkに影響したConnectorsの障害調査が始まり、07:28(UTC)に修正がデプロイされ、08:07(UTC)に解決済みと表示されました。** 10/23時点ではclaude.ai・Claude API・Claude Code・Claude Console・Claude Cowork・Claude for Governmentのすべてが正常稼働(Operational)状態です。

**10/22未明にClaude Coworkで外部Connector連携が切断されたり応答しなくなったりする症状に遭遇していたなら、ローカル設定の問題ではなく、この4時間のインシデントが原因だった可能性があります。** [Claude Status](https://status.claude.com)

### PHP2Shell — PHPの`session.upload_progress`のヒープUAF脆弱性、エンバーゴ前からすでに攻撃を受けていた (10/22〜10/23)

**PHPのアップロード進捗処理中にメモリが不足すると、残ったシリアライズ状態が同一プロセスの次のリクエストで再利用され、ヒープのuse-after-free(UAF)が発生するCVE-2026-109618・CVE-2026-109619(PHP2Shell)が公開され、AmazonはMadPotハニーポットの記録から、公開の4日前となる10月17日にすでに攻撃の試みがあったことを確認しました。** 公開直後に数千件のPoCが出回りましたが、デフォルトのPHPインスタンスでそのまま動く攻撃コードはまだ確認されておらず、Log4Shell・Heartbleedほど簡単に悪用できる水準ではないという分析も出ています。

**Claude CodeでPHPベースのサービスのCIやセルフホストrunnerを運用しているなら、デフォルトのPHPインスタンスであっても公開前から攻撃が試みられた前例がある以上、パッチ適用状況の確認を最優先にすべきです。** [GeekNews](https://news.hada.io/topic?id=35826)

## 知っておくと便利な小さな変更点

以下はすべて**v2.1.309**(10/22)の項目です。

- **`sed -i`が標準的なBashプロンプトを受け取り、記述どおりにそのまま実行**されるようになり、シミュレートされたファイル編集プレビューではなくなったため、他のBash編集と同様に`/rewind`では復元されません。
- **bypass permissionsモードで危険な`rm`・`rmdir`コマンドの確認ダイアログが、即座にコマンドを拒否して書き換えのヒントを表示する方式に変更**され、無人セッションが停止せずに進行を続けられるようになりました。
- **ワークツリーの作成・再利用時にgitがオンデマンドでオブジェクトをfetchしなくなるよう変更**され、Bashサンドボックスが設定されたパーシャルクローンでは必要なオブジェクトを事前にすべて取得します。
- **Linux: バックグラウンドコマンドがセッションより長く生き続けた場合に、サンドボックスの書き込み拒否が解除されてしまう問題を修正**しました。
- **Windows: カレントディレクトリを対象としつつ追加の引数が付いた一部のPowerShell `Set-Location`・`cd`コマンドが自動承認されていた問題を修正**し、現在は承認を求めるようになりました。
- **macOS: XcodeやCommand Line Toolsが入っていないMacでClaude Codeを起動するたびにインストール案内ダイアログが表示されていた問題を修正**しました。
- **[VSCode] Ctrl+Jがチャット入力欄で常に改行を挿入していた問題を修正**し、`~/.claude/keybindings.json`のChatコンテキストで`ctrl+j`を`null`に設定すれば、VS CodeとOSに動作を任せられます。
- **[VSCode] `/goal`のような長いスラッシュコマンドのメッセージがチャットパネルを埋め尽くしていた問題を修正**し、他のプロンプトと同様にShow moreの後ろに折りたたまれるようになりました。
