## 主要な新機能と実践活用

### `claude --desktop` — CLIからデスクトップアプリへワンステップで切り替え（v2.1.285）

**ターミナルで作業していたカレントディレクトリ、あるいは`--continue`や`--resume <id>`で指定したセッションを、Claudeデスクトップアプリでそのまま開けるようになりました。**

```bash
claude --desktop
claude --desktop --resume <id>
```

**ターミナルで短く始めたセッションを、より広い画面やアーティファクトビューで続けたいとき、セッションを最初から探し直す必要なく、コマンド一つでデスクトップアプリに切り替えられます。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

### `claude plugin configure` — プラグインのオプションをCLIから直接管理（v2.1.285）

**プラグインのオプション一覧と未設定の値を表示し、標準入力で読み込んだ新しい値を`--values-stdin`で保存できるコマンドが追加されました。** バンドルされた`.mcpb`のMCPサーバー自体の設定値も、`claude plugin install --config`に`<server>.<key>=<value>`形式で渡せば、インストール時点で値を指定でき、`/plugin` → Configure画面を経由せずにそのまま動作を開始します。

```bash
claude plugin configure <plugin>
claude plugin install <plugin> --config server.apiKey=xxx
```

**CIパイプラインやデプロイスクリプトでプラグインを自動インストールしているチームなら、対話形式のConfigureステップを挟まずに、必要な値をインストールコマンド一行に詰め込んで完全自動化できます。** [リリースノート全文](https://github.com/anthropics/claude-code/releases)

## 開発者ワークフローティップス

### LLM Wikiの不良ページをJevで選別しようとして失敗した実験から得た教訓（9/29）

**TypeSafeが判定モデルJevを知識業務向けリンターとして紹介したところ、実際に非公開・公開の2つのLLM Wikiに適用し、欠陥のあるページを絞り込めるかをブラインドラベリングで検証した実験です。** 結果は失敗でした。非公開Wikiは欠陥率が44%にも達し「結局全部読むしかない」状態になり、公開Wikiは深刻な欠陥がわずか6.5%しかなく、絞り込むだけの信号自体が不足していました。欠陥が中程度に混在しているときだけスコアベースの選別ツールが価値を発揮し、極端に多くても少なくても役に立たないというのが要点です。

**Claude Codeで生成したドキュメントやCLAUDE.md、自前のWikiをJevのような判定モデルで自動レビューしようと考えているなら、ツールをいきなり導入する前に、まず欠陥が実際どれくらい混ざっているか基準率を測ってみる方が得策です。** [GeekNews](https://news.hada.io/topic?id=34483)

### RAGインデックスとエージェントメモリをGitのようにバージョン管理する（LambdaDB、9/29）

**RAGナレッジベースやエージェントメモリは上書きされ続ける形で運用されることが多く、ある回答がどのデータ状態から生まれたのか後から追いにくいという問題意識から生まれたアプローチです。** LambdaDBは検索コレクション自体にGit式の参照を持たせ、branchで本番データに触れずに文書の履歴を管理し、tagで特定のスナップショットを固定し、aliasで複製なしにポインタだけを切り替えてバージョンを切り替えます。変更されていないファイルはS3上でバージョン間で共有され、`asOf`で過去時点のデータ状態からクエリをそのまま再現できます。

**Claude Code用のMCPサーバーで社内RAGインデックスやエージェントメモリを運用しているなら、文書を変更するたびに本番インデックスを直接上書きするのではなく、こうしたGit式のブランチ・タグモデルを参考に、まず再現性を確保しておく価値があります。** [GeekNews](https://news.hada.io/topic?id=34472)

## 知っておくと便利な小さな変更点

以下はすべて**v2.1.285**（9/29）の項目です。

- **`CLAUDE_CODE_DISABLE_WEB_FETCH`環境変数が追加**され、WebFetchツール自体をオフにできるようになりました。
- **`CLAUDE_CODE_NONSTREAMING_TIMEOUT_RETRIES`環境変数が追加**され、タイムアウトした非ストリーミングフォールバックリクエストの再送回数を制限できます。
- **カスタム`ANTHROPIC_BASE_URL`経由のセッションでも、1Mコンテキストに対応するモデル（Opus 4.7以降、Sonnet 5以降、Fable）の100万トークンコンテキストがそのまま使われる**ように変更されました。ゲートウェイが200Kで頭打ちになる場合は`/autocompact 200k`を実行してください。
- **バックグラウンドで実行したBash・PowerShellコマンドが時間制限（デフォルト30分、最大2時間）後に自動的に停止**するようになり、停止時にはClaudeに通知が届きます。
- **サンドボックスのauto-allowが、`=`を含むインラインスクリプト（`python3 -c`、`node -e`）のたびに毎回承認を求めていた問題が修正**されました。
- **SSH経由でプラグイン・マーケットプレイスをインストール・更新する際、`GIT_SSH`やgit configの`core.sshCommand`で指定したsshプログラムが無視されていた問題が修正**されました。
