## 주요 신규 기능 & 실전 활용

### 훅에 `onFailure: "block"` 추가 — 시작 실패·타임아웃도 이제는 액션을 막습니다 (v2.1.295)

**command·HTTP 훅에 `onFailure: "block"` 옵션이 추가되어, 훅이 시작되지 못하거나 타임아웃되거나 예기치 않은 종료 코드를 내도 그대로 통과시키는 대신 해당 액션을 막을 수 있게 됐습니다.** 지금까지는 훅 자체가 실패하면 보통 그 검사를 조용히 건너뛰고 액션이 진행됐는데, 민감한 가드레일이라면 이 동작이 오히려 위험할 수 있었습니다.

```json
{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Bash",
      "hooks": [{ "type": "command", "command": "./check.sh", "onFailure": "block" }]
    }]
  }
}
```

**비밀정보 노출 차단이나 위험 명령 검증처럼 실패해서는 안 되는 훅을 운영하고 있다면, `onFailure: "block"`을 지정해 훅 자체가 죽거나 응답하지 않을 때도 액션이 그냥 통과되지 않도록 바꿔두는 것이 안전합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### OSC 7501 — 터미널이 Claude Code의 작업 상태를 직접 전달받습니다 (v2.1.295)

**Claude Code가 Program Status Protocol(OSC 7501)을 지원하기 시작해, 이를 구현한 터미널은 화면 내용이나 창 제목을 추측하는 대신 Claude Code가 작업 중인지, 사용자 개입을 기다리는지, 완료됐는지를 직접 전달받아 표시할 수 있습니다.** 같은 날 GeekNews에도 이 프로토콜 자체를 다룬 글이 올라왔는데, 기존 pty를 그대로 쓰면서 별도 소켓 API 없이 SSH를 통해서도 상태를 전달할 수 있다는 점이 특징으로 꼽힙니다.

**탭 제목이나 상태표시줄 커스터마이징 플러그인을 쓰는 터미널(iTerm2, Ghostty 계열 등)을 쓰고 있다면, OSC 7501을 지원하는 버전으로 업데이트해두면 여러 창에서 Claude Code 세션이 대기 중인지 바로 구분할 수 있게 됩니다.** [GeekNews](https://news.hada.io/topic?id=34994) · [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### 지시문 형태의 prompt·agent 훅이 자신이 막아야 할 대상을 통과시키던 문제 수정 (v2.1.294)

**"다음과 같은 명령을 차단하라"처럼 자연어 지시문으로 작성된 prompt·agent 훅이, 실제로는 막아야 할 대상을 통과시키는 경우가 있던 문제가 수정됐습니다.** 같은 릴리스에서 Stop·SubagentStop에 걸린 "빌드가 깨져도 계속 진행하라" 같은 지시문 훅의 판정 방식도 개선되어, Claude가 작업을 너무 일찍 멈추는 경향이 줄었습니다.

**결정적인 코드 대신 자연어 지시문으로 차단 규칙을 작성한 가드레일 훅을 운영하고 있다면, v2.1.294로 업데이트해 이번에 막힌 우회 경로를 적용하고, 정말 실패해서는 안 되는 훅이라면 앞서 소개한 v2.1.295의 `onFailure: "block"`과 함께 써서 이중으로 방어해두는 것이 안전합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### 허용 함수 목록만으로는 충분하지 않습니다 — 이름 없이 함수 호출하기 (10/8)

**학교의 C 코드 자동 채점 환경에서 허용된 함수 목록 검사를 우회해, execve 심볼을 직접 쓰지 않고도 셸을 실행하는 개념 증명이 공개됐습니다.** ASLR이 메모리 배치 주소 전체를 바꾸더라도 같은 세그먼트 안에서 함수들 사이의 상대적 위치는 그대로 유지되기 때문에, 허용된 함수의 주소와 목표 함수까지의 상대 오프셋만 알면 이름을 쓰지 않고도 호출이 가능하다는 원리입니다.

**명령이나 함수 이름을 허용 목록으로 걸러 안전을 확보하려는 샌드박스를 설계하고 있다면, 이름 매칭만으로는 같은 바이너리 안의 상대 주소 계산 같은 우회를 막지 못한다는 점을 보여주는 사례이니, 실제 동작이나 시스템 호출 수준까지 검증하는 방어가 함께 필요합니다.** [GeekNews](https://news.hada.io/topic?id=35003)
