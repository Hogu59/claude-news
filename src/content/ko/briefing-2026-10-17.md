## 주요 신규 기능 & 실전 활용

### CLAUDE_CODE_AUTO_MODE_MODEL — 클라이언트 측 auto mode classifier가 쓸 모델을 직접 고릅니다 (v2.1.302)

**새 환경변수 `CLAUDE_CODE_AUTO_MODE_MODEL`로 auto mode의 클라이언트 측 classifier가 어떤 모델을 쓸지 직접 지정할 수 있게 됐습니다.** 다만 이 변수는 서버 측(server-side) auto mode가 쓰는 모델에는 영향을 주지 않으며, 클라이언트 측 classifier에만 적용됩니다.

```bash
# 클라이언트 측 auto mode classifier에 더 빠르고 저렴한 모델 지정
export CLAUDE_CODE_AUTO_MODE_MODEL=claude-haiku-5-5
```

**auto mode로 Claude Code를 운영하면서 classifier 판단 속도나 비용을 조정하고 싶다면, 이 변수로 classifier 전용 모델만 따로 바꿔볼 수 있습니다. 서버 측 auto mode를 쓰는 조직이라면 이 설정이 적용되지 않는다는 점을 먼저 확인해야 합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### Fork subagent가 claude -p·Agent SDK·데스크톱 앱·VS Code에서도 기본으로 켜집니다 (v2.1.302)

**터미널에서는 이미 기본이었던 fork subagent(`subagent_type: "fork"`)가 `claude -p`, Agent SDK, 데스크톱 앱, VS Code에서도 기본으로 켜지도록 바뀌었습니다.** `CLAUDE_CODE_FORK_SUBAGENT=0`으로 끌 수 있고, `claude mcp serve`는 애초에 이 옵션을 제공하지 않습니다. 함께 바뀐 부분으로, 데스크톱 앱과 VS Code의 메인 대화에 속한 서브에이전트는 터미널처럼 항상 백그라운드로 실행되며, 서브에이전트 자신이 띄우는 Agent 호출은 반대로 `claude -p`·SDK·데스크톱 앱·VS Code에서 기본적으로 포그라운드로 실행됩니다.

```bash
# fork subagent 기본 동작을 끄고 싶다면
export CLAUDE_CODE_FORK_SUBAGENT=0
```

**데스크톱 앱이나 VS Code, Agent SDK로 서브에이전트를 자주 띄운다면, 이번 변경으로 백그라운드/포그라운드 실행 기본값이 터미널과 동일하게 맞춰졌다는 점을 염두에 두고 기존 자동화 스크립트의 가정을 다시 점검해볼 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)
