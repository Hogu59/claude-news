## 개발자 워크플로우 팁

### `claude -p`가 아무 출력 없이 끝났다면, 이름이 잘못된 명령 하나가 원인일 수 있었습니다 (v2.1.312)

**이름이 잘못된 명령 하나가 전체 명령 로딩을 막아버려, 그 영향으로 `claude -p`가 아무 출력도 내지 않고 끝나던 문제가 수정됐습니다.** 지금까지는 커스텀 슬래시 명령 중 하나의 이름 설정이 잘못됐을 뿐인데도 비대화형 실행 전체가 조용히 실패하는 경우가 있었습니다.

**CI나 스크립트에서 `claude -p`를 돌리다 설명 없이 빈 출력만 받은 적이 있다면, v2.1.312로 업그레이드한 뒤 커스텀 명령 파일의 이름 설정도 함께 점검해볼 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### VS Code 확장에서 로그인한 뒤에도 조직 정책이 세션 내내 다시 불러와지지 않던 문제가 수정됐습니다 (v2.1.312)

**VS Code 확장에서 로그인하면 managed settings와 조직 정책이 그 세션이 끝날 때까지 다시 불러와지지 않던 문제가 수정됐습니다.** 지금까지는 로그인 시점에 적용된 정책이 그 이후 조직 쪽에서 바뀌어도 같은 세션 안에서는 반영되지 않는 경우가 있었습니다.

**조직에서 관리자 정책으로 Claude Code 설정을 통제하면서 VS Code 확장을 쓰고 있다면, v2.1.312부터는 로그인 이후에도 정책 변경이 더 안정적으로 반영된다는 점을 믿고 써도 됩니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### 클라우드 세션의 WebFetch가 막히면, 어떤 호스트를 허용 목록에 추가해야 하는지 바로 알려줍니다 (v2.1.312)

**클라우드 세션에서 WebFetch가 이름을 해석할 수 없는 호스트를 만나면, 이제 그 호스트가 허용된 네트워크 도메인 밖에 있을 수 있다고 설명하면서 Claude가 어떤 호스트를 허용해달라고 요청해야 하는지까지 짚어줍니다.** 지금까지는 이런 오류가 원인을 알기 어려운 일반적인 네트워크 오류로만 표시되는 경우가 있었습니다.

**클라우드 환경에서 네트워크 접근을 제한해둔 채 Claude Code를 운영하고 있다면, WebFetch가 막혔을 때 뜨는 안내만 보고도 허용 목록에 추가할 호스트를 바로 알 수 있어 설정 왕복이 줄어듭니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)
