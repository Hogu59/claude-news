## 개발자 워크플로우 팁

### Fork subagent를 한꺼번에 여러 개 띄워도 서로의 작업을 가로채는 일이 줄었습니다 (v2.1.307)

**여러 fork subagent를 동시에 실행하면 각 subagent가 자신의 실행이 어느 것인지 알게 되어, 서로 다른 fork가 상대방의 작업을 자기 것으로 오인해 시작하려는 문제가 크게 줄었습니다.** 지금까지는 병렬로 띄운 fork들이 가끔 서로의 작업을 중복 시도하는 경우가 있었습니다.

**병렬 작업을 위해 여러 fork subagent를 한 메시지에 동시 호출하는 패턴을 쓰고 있다면, 이번 수정으로 안정성이 올라간 만큼 더 과감하게 fork 병렬화를 늘려볼 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### Self-hosted runner의 체크아웃 훅이 30분 넘으면 기본적으로 실패 처리됩니다 (v2.1.307)

**체크아웃 훅(checkout hook)이 30분을 넘기면 세션 설정 자체가 실패로 처리되도록 기본값이 바뀌었으며, 더 오래 걸리는 훅을 쓴다면 `--checkout-hook-timeout-min` 값을 올리거나 `0`으로 설정해 제한을 없앨 수 있습니다.** 지금까지는 체크아웃 훅이 무한정 실행되며 러너 슬롯을 계속 점유하는 경우가 있었습니다.

**self-hosted runner에서 저장소 초기화나 대용량 LFS 다운로드처럼 오래 걸리는 체크아웃 훅을 쓰고 있다면, v2.1.307로 올리기 전에 평소 소요 시간이 30분을 넘는지 확인하고 필요하면 `--checkout-hook-timeout-min`을 미리 조정해두는 것이 안전합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### `/permissions` > Recently denied에서 거부된 명령어 자체를 바로 볼 수 있습니다 (v2.1.307)

**`/permissions`의 Recently denied 목록이 거부된 셸 명령어를 보여주지 않던 문제가 수정돼, 이제 행을 승인하면 명령어 설명이 아니라 실제 명령어 이름으로 표시됩니다.** 덧붙여 auto mode의 로컬 분류기가 재시도된 명령을 검사할 때 이 목록에서의 승인을 무시하던 문제도 함께 고쳐졌습니다.

**auto mode를 켜고 Recently denied 목록으로 명령을 사후 승인하는 방식으로 권한을 관리하고 있다면, 이제는 실제 명령어를 보고 정확히 판단할 수 있고 승인 즉시 재시도에도 반영된다는 점을 활용해볼 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

## 알아두면 좋은 소소한 변경사항

아래는 모두 **v2.1.307**(10/21) 항목이며, 일부는 **v2.1.306**(10/21)에서 가져왔습니다.

- **`@claude review stop`(또는 `off`, `pause`)이 Code Review에 추가**돼, PR의 "@claude review always" 구독을 새 리뷰를 시작하지 않고 끝낼 수 있습니다.
- **Cowork 클라우드 세션의 WebFetch가 사이트의 4xx 응답이나 robots.txt 거부를 도구 오류 대신 정상 결과로 반환**하도록 바뀌어, 로컬 세션과 동작이 같아졌습니다.
