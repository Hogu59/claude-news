## 주요 신규 기능 & 실전 활용

### Anthropic이 에이전트 메모리의 "드리밍(dreaming)" 메커니즘을 연구로 공개했습니다 (11/8)

**Anthropic Research가 에이전트가 세션 사이에 무엇을 기억하고 잘못된 기억을 어떻게 고칠지 실험한 결과를 공개했습니다.** 핵심은 "드리밍"이라는 과정으로, 세션 사이에 쌓인 메모를 원본 대화 로그와 대조해 오류를 고치고, 흩어진 노트를 주제별 위키로 묶는 작업입니다. 내부 문서 평가에서 원문 검색에 이 위키를 더하자 채점 기준 충족률이 53%에서 최대 61%로 올랐고 질문당 약 2만 토큰이 절약됐지만, 단일 문서만 보면 되는 과제에서는 뚜렷한 이득이 없었습니다. 또한 최신 모델일수록 메모리 작성 지침을 구체적인 규칙으로 못박기보다 단순한 지침과 모델의 자체 판단에 맡기는 편이 더 잘 작동했다고 설명합니다.

**Claude Code를 여러 세션에 걸친 긴 프로젝트에 쓰면서 CLAUDE.md나 메모리 파일이 시간이 지날수록 낡거나 틀린 내용을 쌓아간다고 느꼈다면, 이 연구에서 제시한 "원본과 대조해 고치고 주제별로 묶는다"는 원칙을 자신의 메모리 운영 방식에 참고해볼 만합니다.** [GeekNews](https://news.hada.io/topic?id=36775)

### Claude apps gateway에 풀드 그룹 예산의 충돌 해결 규칙과 우선순위가 추가됐습니다 (v2.1.319)

**`admin.pooled_conflict_rule`과 `admin.pooled_priority_order`가 추가돼, 한 개발자가 여러 풀드 그룹에 속해 있을 때 어느 그룹의 공동 예산이 먼저 그 개발자의 지출을 지불할지 정할 수 있습니다.** 지금까지는 풀드 그룹 예산 자체는 있었지만, 한 사람이 여러 그룹에 걸쳐 있는 경우 어떤 예산이 우선할지는 가려져 있었습니다.

```yaml
# Claude apps gateway 설정 예시 (여러 풀드 그룹에 속한 개발자의 예산 우선순위 지정)
admin:
  pooled_conflict_rule: priority_order
  pooled_priority_order:
    - team-finance
    - team-platform
```

**여러 팀의 풀드 예산을 동시에 운영하면서 교차 소속 개발자의 지출이 어느 예산에서 빠져나갈지 불명확했다면, v2.1.319부터는 이 설정으로 우선순위를 명시적으로 정해둘 수 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

## 개발자 워크플로우 팁

### DoorDash가 LLM 내장 검색을 별도 게이트웨이로 분리해 검색 비용을 98% 넘게 줄였습니다 (11/7)

**DoorDash는 LLM에 내장된 웹 검색을 DSG(검색 게이트웨이)라는 별도 레이어로 분리해 여러 에이전트가 공유하게 하고, 같거나 비슷한 질문의 검색 결과를 캐시했습니다.** 캐시가 채워진 실행에서는 평균 지연 시간이 68% 줄고 검색 비용이 99% 넘게 줄었으며, 검색 결과를 제목·URL·본문 발췌로 통일해 전달해 내장 검색이 출력 형식을 어기고 불필요한 설명을 붙이는 문제도 줄였습니다. 일반 소매 질의 평가에서 DSG+Serper는 93.90%, 내장 검색은 93.40%로 정확도는 비슷했지만 검색 비용은 98% 이상 낮아졌습니다. 다만 최신 정보가 중요한 FreshQA 과제에서는 내장 검색이 더 정확해, 업무 특성에 따라 두 방식을 선택하는 구조를 유지합니다.

```text
일반 소매 질의        → DSG + Serper (캐시 적용, 저비용)
최신성이 중요한 질의   → LLM 내장 검색 유지 (FreshQA에서 더 정확)
```

**Claude API나 Claude Code의 웹 검색 기능을 대량으로 쓰는 제품을 운영한다면, 검색을 별도 게이트웨이로 분리하고 캐싱을 넣는 것만으로도 정확도를 거의 그대로 유지하면서 비용을 크게 줄일 여지가 있는지 검토해볼 만합니다.** [GeekNews](https://news.hada.io/topic?id=36733)

### `/loop` 자가 페이싱 모드가 턴이 끝나면 재스케줄 없이 바로 종료되도록 바뀌었습니다 (v2.1.319)

**지금까지 자가 페이싱으로 돌리던 `/loop`는 턴이 끝나도 다음 깨어날 시점을 폴백으로 예약해뒀는데, 이제는 턴이 끝나면 별도 예약 없이 그대로 종료됩니다.** 이전처럼 턴이 끝난 뒤에도 다음 웨이크업을 자동으로 예약해두고 싶다면 환경변수로 이전 동작을 유지할 수 있습니다.

```bash
# 턴 종료 후에도 폴백 웨이크업을 계속 예약해두던 이전 동작을 유지
export CLAUDE_CODE_LOOP_KEEPALIVE=1
```

**`/loop`로 장시간 반복 작업을 자동화하고 있는데 세션이 예상보다 일찍 끝나버린다고 느꼈다면, v2.1.319부터 기본 동작이 바뀌었다는 점을 확인하고 필요하면 `CLAUDE_CODE_LOOP_KEEPALIVE=1`로 되돌려볼 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

**Chat 탭과 Cowork 탭을 하나의 인터페이스로 합치는 Unified Claude 기능이 지금까지는 선택 적용이었지만, 11/10부터 모든 Claude Desktop 서드파티 배포에 강제로 켜집니다.** 이 전환이 적용되면 `coworkTabEnabled: false`나 `chatSessionRetentionDays` 같은 값에 의존해온 관리형 설정이 더 이상 읽히지 않습니다. v2.1.319는 `desktopHome` 없이 이 값들에만 의존하는 정책을 쓰는 조직을 위해 시작 시 경고를 먼저 추가했습니다.

**조직 차원에서 Claude Desktop을 managed settings로 운영하고 있다면, `coworkTabEnabled`나 `chatSessionRetentionDays`에 의존하는 정책이 있는지 11/10 전에 점검해 Unified Claude 전환 뒤에도 의도한 동작이 유지되는지 확인해둘 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases) · [Unified Claude 문서](https://claude.com/docs/third-party/claude-desktop/unified-claude)

### 텔레메트리가 꺼진 상태에서 auto mode의 서버 체크가 막히면 기본 동작이 더 엄격해졌습니다 (v2.1.319)

**텔레메트리나 feature flag가 꺼진 상태로, LLM 게이트웨이 뒤를 포함해 Claude Code를 운영할 때 auto mode의 서버 쪽 안전성 체크가 어떤 호출을 확인할 수 없으면, 이제 그 호출은 그냥 승인을 묻거나 거부되며 내장 classifier로 자동 대체되지 않습니다** (Bedrock·Vertex·Foundry는 동작이 그대로입니다). 또한 조직 밖에서 이미 꺼둔 auto mode 서버 체크는 프로젝트의 설정 파일이나 플러그인이 다시 켤 수 없도록 바뀌었습니다.

```bash
# 텔레메트리/feature flag가 꺼진 상태에서도 이전처럼 내장 classifier로 대체하려면
export CLAUDE_CODE_AUTO_MODE_SERVER=0
```

**텔레메트리를 끄고 auto mode를 쓰거나 LLM 게이트웨이 뒤에서 Claude Code를 운영하고 있다면, v2.1.319부터는 서버 체크가 막히는 순간 작업이 예전보다 더 자주 멈추거나 거부될 수 있다는 점을 염두에 두고, 필요하면 위 환경변수로 이전 동작을 선택할 수 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### self-hosted runner의 `--trust-workspace false`가 저장소의 훅·스킬 실행까지 확실히 막습니다 (v2.1.319)

**지금까지 `--trust-workspace false`로 신뢰하지 않는 저장소를 받아도, 그 저장소의 settings 파일에 정의된 훅이나 skills가 실행될 수 있는 틈이 있었는데 이번에 이를 막았습니다.** 신뢰 여부를 판단하기 전에 저장소 자체가 실어온 코드가 몰래 실행될 수 있었다는 점에서 비중 있는 보안 수정입니다.

**self-hosted runner로 외부 PR이나 신뢰할 수 없는 브랜치를 체크아웃해 처리하는 자동화를 운영하고 있다면, v2.1.319로 올려 저장소가 가진 훅·스킬이 승인 없이 실행되지 않는 버전을 쓰고 있는지 확인할 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### Opus 4.8 fast mode 지원이 11/30에 완전히 종료됩니다 (마감 약 3주 전 리마인더)

**10/30일부로 지원 종료(deprecated)가 예고된 Opus 4.8의 fast mode는 11/30에 완전히 제거되며, 제거 이후 fast mode 요청은 오류를 반환하고 표준 Opus 4.8로 자동 대체되지 않습니다.** 속도 향상을 계속 쓰고 싶다면 Opus 5.5로 옮겨야 합니다.

**Opus 4.8의 fast mode에 의존하는 워크플로나 자동화가 있다면, 11/30 전에 Opus 5.5로 마이그레이션을 마쳐 당일 요청이 갑자기 오류로 바뀌는 상황을 피할 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

**대화에서 결정·선호·규칙을 추출해 저장해두고, 세션을 시작할 때마다 같은 저장소의 기억을 에이전트 컨텍스트에 자동으로 넣어주는 플러그인으로, Claude Code에서 쌓은 기억을 Codex·Cursor·Claude.ai·ChatGPT에서도 그대로 쓸 수 있습니다.** Codex에는 AGENTS.md 스니펫과 MCP로, Cursor에는 rules 파일로 연결되며, 작업 중에는 MCP를 통해 과거 결정을 검색·조회할 수도 있습니다. 전송되는 내용은 프롬프트와 Claude 답변 본문뿐이고 도구 호출·도구 결과·파일 내용·thinking은 보내지 않으며, API 키 같은 민감한 문자열은 로컬에서 먼저 지웁니다.

**Claude Code와 Codex·Cursor를 섞어 쓰면서 한 도구에서 정한 규칙이나 결정을 다른 도구에서는 처음부터 다시 설명해야 했다면, 이 플러그인으로 도구를 넘나드는 메모리 공유를 시도해볼 만합니다.** [GeekNews](https://news.hada.io/topic?id=36737)
