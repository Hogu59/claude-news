### dataviz 스킬이 APCA 텍스트 대비 측정을 지원합니다 (v2.1.309)

**번들로 제공되는 dataviz 스킬이 WCAG 2 명도 대비 비율 대신(혹은 함께) APCA를 텍스트 대비 측정 기준으로 받아들이도록 바뀌었고, 팔레트 검증 스크립트에 `apca(text, background)` 함수가 추가돼 색이 채워진 차트 안의 레이블이 흰색이어야 하는지 검은색에 가까운 색이어야 하는지 바로 알려줍니다.** AA 준수가 필요한 곳에서는 기존 WCAG 2 비율도 그대로 유지됩니다.

```js
// dataviz 스킬의 팔레트 검증 스크립트
apca(textColor, backgroundColor)
// → 차트 색상 위에 올릴 레이블이 흰색/검은색 중 어느 쪽이어야 하는지 반환
```

**Claude Code로 대시보드나 데이터 시각화 차트를 만들 때 dataviz 스킬을 쓰고 있다면, 색이 채워진 영역 위 레이블 색을 매번 눈으로 가늠하는 대신 이 함수로 바로 검증해보는 것이 유용합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### `/claude-api` 스킬의 Managed Agents 기본값이 동적 워크플로(multiagent_20261001)로 바뀌었습니다 (v2.1.309)

**Claude Platform에서 Managed Agents 서브에이전트 팀을 구성할 때 `/claude-api` 스킬이 기존 `coordinator` 방식 대신 `multiagent_20261001`을 기반으로 동적 워크플로가 기본으로 켜진 팀을 만들도록 바뀌었습니다.** 지금까지는 서브에이전트 팀 구조를 고정된 coordinator 패턴으로만 구성했습니다.

```
# /claude-api 스킬이 구성하는 Managed Agents 기본값
workflow: multiagent_20261001 (dynamic workflows on)
# 기존 기본값: coordinator
```

**Claude Platform에서 Managed Agents 기반 서브에이전트 팀을 운영하고 있다면, 새로 구성하는 팀부터 동적 워크플로가 기본 적용된다는 점을 확인하고 기존 coordinator 기반 팀과의 동작 차이를 미리 점검해두는 것이 좋습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

## 개발자 워크플로우 팁

### `--add-dir`로 불러온 스킬 이름이 겹치면 `folder:name` 형식으로 구분해 호출합니다 (v2.1.309)

**`--add-dir`로 추가한 폴더의 스킬이 이미 같은 이름을 쓰는 다른 스킬에 가려 호출할 수 없던 문제가 수정돼, 이제는 이름이 겹친 스킬이 `<folder>:<name>` 형식으로 제공됩니다.** 지금까지는 이름이 겹치면 나중에 로드된 스킬을 그냥 쓸 수 없었습니다.

```bash
# 예: apps/web 폴더의 deploy 스킬이 다른 deploy 스킬과 이름이 겹칠 때
/apps/web:deploy
```

**여러 저장소나 플러그인에서 가져온 스킬을 `--add-dir`로 한 세션에 같이 쓰고 있다면, 이름이 겹치는 스킬 목록에서 `<folder>:<name>` 표기를 찾아 바로 호출하는 습관을 들여두면 혼동을 줄일 수 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### `/verify`와 `/code-review`가 셸에서 변경한 중첩 패키지의 자체 스킬을 이제 찾아냅니다 (v2.1.309)

**모노레포에서 하위 패키지 파일을 셸 명령으로 변경했을 때, `/verify`와 `/code-review`가 그 패키지 자신의 스킬을 찾지 못하던 문제가 수정됐습니다.** 지금까지는 Edit·Write 도구가 아니라 셸로 파일을 바꾸면 하위 패키지의 스킬이 적용되지 않는 경우가 있었습니다.

**모노레포의 각 패키지마다 별도 스킬을 두고 있고 셸 스크립트나 서브에이전트로 파일을 자주 수정한다면, 이번 수정으로 `/verify`·`/code-review`가 해당 패키지의 스킬을 더 안정적으로 찾아낸다는 점을 기대하고 활용해볼 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### Windows에서 Claude Code가 실행하는 git 명령 속도가 빨라지고, 오류가 항상 영어로 표시됩니다 (v2.1.309)

**Claude Code가 내부적으로 실행하는 다양한 git 명령의 속도가 Windows에서 개선됐고, 모든 플랫폼에서 git이 다른 언어로 설정돼 있어도 그 git 명령의 오류 메시지는 이제 영어로 표시됩니다.** 지금까지는 로캘 설정에 따라 오류 메시지가 다른 언어로 나와 원인 파악이 번거로운 경우가 있었습니다.

**Windows에서 Claude Code로 대용량 저장소나 워크트리를 자주 다루며 git 관련 지연이나 알아보기 힘든 오류 메시지를 겪었다면, v2.1.309 업그레이드로 체감 속도와 오류 가독성이 함께 나아졌는지 확인해볼 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

## 보안/제한 이슈

### v2.1.309, 샌드박스·워크트리 격리 우회 결함을 한꺼번에 수정했습니다 (10/22)

**이번 릴리스는 심링크를 거쳐 접근했을 때 macOS 샌드박스의 `denyWrite` 글롭 패턴이 적용되지 않던 문제, 샌드박스 명령이 매 실행 전 셸 시작 파일을 샌드박스 밖에서 실행하던 문제, 샌드박스 명령과 자동 승인된 편집이 `--mcp-config`로 넘긴 MCP 설정 파일을 수정할 수 있던 문제, 서브셸을 포함한 일부 명령에서 `Edit(path)` 거부 규칙이 Bash 리다이렉트를 막지 못하던 문제, 워크트리 격리 가드가 locale 접두사가 붙은 명령이나 zsh 산술 연산 명령을 걸러내지 못하던 문제, 심링크로 접근한 설정 폴더에서 프로필 저장소 쓰기 보호가 적용되지 않던 문제를 포함해 격리·권한 경계를 우회할 수 있던 결함을 다수 고쳤습니다.** 개별로는 작아 보이지만 모두 샌드박스나 워크트리 격리가 실제로는 뚫려 있던 경로를 막는 수정입니다.

**샌드박스 모드나 워크트리 격리 기능을 신뢰 경계로 삼아 신뢰할 수 없는 코드나 에이전트를 돌리고 있다면, v2.1.309로 최대한 빨리 업그레이드해 이번에 닫힌 우회 경로들을 반영하는 것이 안전합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### `claude ultrareview`가 이제 워크스페이스 신뢰를 요구합니다 (v2.1.309)

**`claude ultrareview`를 실행하면 터미널에서는 신뢰 여부를 묻고, 묻을 수 없는 환경에서는 실행을 거부하도록 바뀌었습니다.** 스크립트에서는 값을 받지 않는 `--trust-workspace` 플래그를 PR 번호나 base 브랜치 뒤에 추가하거나, 환경변수 `CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1`을 설정해 이 확인을 건너뛸 수 있습니다.

**CI 파이프라인이나 무인 스크립트에서 `claude ultrareview`를 호출하고 있다면, v2.1.309 업그레이드 후 신뢰 확인에 걸려 실행이 막히지 않도록 `--trust-workspace`나 `CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK` 설정을 미리 추가해둬야 합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### Claude 서비스 현황 — Connectors 오류가 4시간 가까이 지속됐다 해결됐습니다 (10/22)

**공식 status.claude.com을 직접 확인한 결과, 10/22 03:50(UTC) claude.ai와 Claude Cowork에 영향을 준 Connectors 오류 조사가 시작돼 07:28(UTC) 수정이 배포되고 08:07(UTC) 해결로 표시됐습니다.** 10/23 현재 claude.ai·Claude API·Claude Code·Claude Console·Claude Cowork·Claude for Government 전체는 정상(Operational) 상태입니다.

**10/22 새벽 Claude Cowork에서 외부 Connector 연동이 끊기거나 응답하지 않는 증상을 겪었다면, 로컬 설정 문제가 아니라 이번 4시간짜리 인시던트 때문일 가능성이 있습니다.** [Claude Status](https://status.claude.com)

### PHP2Shell — PHP `session.upload_progress`의 힙 UAF 취약점이 엠바고 전에 이미 공격받고 있었습니다 (10/22~10/23)

**PHP 업로드 진행률 처리 중 메모리가 부족해지면 남은 직렬화 상태가 같은 프로세스의 다음 요청에서 재사용되며 힙 해제 후 사용(UAF)이 발생하는 CVE-2026-109618·CVE-2026-109619(PHP2Shell)가 공개됐고, Amazon은 MadPot 허니팟 기록에서 공개 나흘 전인 10월 17일에 이미 공격 시도가 있었음을 확인했습니다.** 공개 직후 수천 개의 PoC가 유통됐지만, 기본 PHP 인스턴스에서 바로 작동하는 익스플로잇은 아직 확인되지 않아 Log4Shell·Heartbleed만큼 쉽게 악용되는 수준은 아니라는 분석도 함께 나왔습니다.

**Claude Code로 PHP 기반 서비스의 CI나 self-hosted runner를 운영하고 있다면, 기본 PHP 인스턴스라도 공개 전부터 공격이 시도된 전례가 있는 만큼 패치 적용 여부를 최우선으로 확인해야 합니다.** [GeekNews](https://news.hada.io/topic?id=35826)
