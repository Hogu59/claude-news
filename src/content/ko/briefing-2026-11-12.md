## 개발자 워크플로우 팁

### Opus 5.5를 기본값으로 쓰고 Fable 5.2로 에스컬레이션하는 모델 선택 전략입니다 (11/9)

**개발자 Addy Osmani는 현재 일반 공개된 Haiku 5.5·Sonnet 5.5·Opus 5.5·Fable 5.2 네 모델 중, 대부분의 작업을 Opus 5.5·effort `medium`으로 시작하고 난이도와 비용에 따라 위아래로 조정하라고 제안합니다.** 모델을 바꾸기 전에 먼저 effort 단계를 올려보고, 그래도 부족하면 더 낮은 effort의 상위 모델로 넘어가는 순서를 권장합니다. Sonnet 5.5는 범위가 명확한 버그 수정이나 반복 작업에, Haiku 5.5는 분류·라우팅 같은 대량 작업과 서브에이전트에, Fable 5.2는 대규모 리팩터링·아키텍처 설계·다수 서브에이전트 지휘처럼 Opus 5.5 `high`에서도 부족한 가장 어려운 작업에만 투입합니다.

```markdown
---
name: log-reader
description: Reads test output and logs, and reports each failing case. Use after a test run.
tools: Read, Grep, Glob, Bash
model: haiku
---
```

자동으로 결과를 검증할 수 있는 작업이라면, 모든 작업을 `low` effort로 먼저 돌리고 실패한 것만 `high`로 재실행하는 편이 전부 `high`로 돌리는 것보다 효율적이라고 설명합니다. 같은 SWE-bench Pro 부분집합에서 전부 `high`로 돌리면 95.3%를 작업당 0.29달러에 통과했지만, 이 방식은 약 97%를 작업당 약 0.17달러에 통과했습니다.

**Claude Code로 여러 모델을 섞어 쓰면서 언제 상위 모델로 올려야 할지 감으로 판단하고 있었다면, 이 에스컬레이션 순서(검증 추가 → effort 상향 → 모델 상향)와 로그 읽기 같은 하위 작업을 Haiku 서브에이전트로 넘기는 패턴을 그대로 적용해볼 만합니다.** [claude.dev](https://claude.dev/blog/which-claude-model-should-you-build-with/)

### JPMorganChase 사례로 보는 대규모 조직의 Claude Code 확대 설계입니다 (11/9)

**JPMorganChase가 Claude Code 접근을 엔지니어를 넘어 상업·투자은행, 인프라·운영, 보안, 제품, 리스크·통제, 자산관리 부문까지 넓혔다고 Anthropic이 공식 블로그로 소개했습니다.** 핵심은 통제 설계입니다. Claude Code는 컨테이너 기반 개발 플랫폼 Devspace 등 격리된 환경에서 회사 자체 인프라 위에서만 실행되고, 에이전트는 직원의 자격 증명이나 내부 시스템에 직접 접근하지 못합니다. 접근 권한은 단계적으로만 넓어지고, 새 Claude 모델은 자체 승인 절차를 거쳐야 쓸 수 있으며, 수천 개의 자동화 테스트와 승인 게이트가 모든 변경을 pass·halt로 판정해 Claude가 자기 작업을 스스로 승인할 수 없도록 파이프라인이 강제합니다.

```text
격리 환경(Devspace) → 단계적 권한 확대 → 모델별 자체 승인 → 자동 게이트(pass/halt, 자기 승인 불가)
```

**이 소식은 Anthropic 자체 발표로 은행 측의 독립적인 확인은 없지만, 지난 11/9 브리핑에서 다룬 골드만삭스가 뱅커·트레이더의 Claude Code 접근을 엔지니어로 좁힌 사례와 정반대 방향입니다.** 조직 전체에 Claude Code를 넓히려는 입장이라면, 격리 환경·단계적 권한·자동 게이트를 먼저 갖추는 것이 접근을 넓히면서도 책임 소재를 지키는 방법이라는 점을 참고할 만합니다. [Anthropic 공식 사례](https://claude.com/resources/articles/jpmorganchase-expands-claude-code)

## 알아두면 좋은 소소한 변경사항

아래는 모두 **v2.1.321**(11/9) 항목 중 지난 브리핑들에서 다루지 않은 것들입니다.

- **프로젝트 skills·commands·agents가 들어있는 폴더가 세션 중간에 사라졌다가(예: `git stash`) 다시 돌아와도 계속 사라진 상태로 남아있던 문제가 수정**됐습니다. worktree에 들어간 뒤에도 동일하게 적용됩니다.
- **`/config`에서 새 세션이 auto mode로 시작될 때 기본 권한 모드가 Manual로 잘못 표시되던 문제가 수정**됐습니다. "Auto (default)"에서 Space를 누르면 이제 Plan이 아니라 Don't Ask로 저장됩니다.
- **IDE 터미널에서 Claude Code를 시작하면 더 이상 IDE 확장을 설치·업데이트하지 않도록 바뀌었습니다.** 확장을 설치·갱신하려면 외부 터미널에서 `/ide`를 쓰거나 에디터의 확장 뷰를 이용해야 합니다.
- **헤드리스 세션이 `.claude/skills` 폴더의 파일 변경을 감지해 mod를 다시 로드하도록 바뀌었습니다.** 이 동작을 끄려면 `CLAUDE_CODE_PLUGIN_DIR_WATCH=0`을 설정하면 됩니다.
- **auto mode에서 턴이 시작된 뒤 대화가 압축되면, 그 턴에서 기다리던 백그라운드 서브에이전트의 보고가 사라지던 문제가 수정**됐습니다.
- **첫 번째 모델이 응답 전에 막혀 폴백 모델로 넘어갈 때, 폴백 모델이 요청을 거부하거나 "응답이 중단됐다"고 말하던 문제가 수정**됐습니다.
