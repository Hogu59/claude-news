## 주요 신규 기능 & 실전 활용

### 클라우드 세션을 저장소 선택 없이 바로 시작할 수 있습니다 (v2.1.318)

**Anthropic이 호스팅하는 환경에서 클라우드 세션을 시작할 때, 이제 저장소를 하나도 고르지 않고 바로 시작하는 "No repository" 옵션이 추가됐습니다.** 지금까지 클라우드 세션은 항상 어떤 저장소에 연결할지부터 정해야 했는데, 특정 코드베이스와 무관한 리서치·스크래치 작업·일회성 질문에는 이 단계 자체가 불필요한 장벽이었습니다.

**깃 저장소와 무관하게 자료 조사나 짧은 스크립트 실험을 클라우드 세션에서 돌려보고 싶었다면, v2.1.318부터는 저장소를 고르는 과정 없이 바로 새 세션을 열어 쓸 수 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### Claude apps gateway의 mantle 업스트림에 `assume_role`이 추가돼 AWS 계정별 비용 귀속이 가능해졌습니다 (v2.1.318)

**Claude apps gateway의 mantle 업스트림에 `assume_role` 설정이 추가돼, 다른 AWS 계정의 역할을 맡아 요청을 보낼 수 있고 이를 통해 개발자별 AWS 비용 귀속도 가능해졌습니다.** 여러 AWS 계정에 걸쳐 조직을 운영하면서 Claude apps gateway를 중앙에서 운영하는 경우, 지금까지는 어느 팀·개발자의 사용량이 어느 계정 비용으로 잡혀야 하는지 가르는 것이 번거로웠습니다.

```yaml
# Claude apps gateway 설정 예시 (mantle 업스트림에 assume_role 지정)
upstreams:
  - name: finance-team-mantle
    type: mantle
    assume_role:
      role_arn: arn:aws:iam::123456789012:role/claude-gateway-finance
```

**여러 AWS 계정으로 나뉜 조직에서 Claude apps gateway로 Claude 사용을 중앙화하고 있다면, `assume_role`로 계정별 역할을 지정해 비용 귀속과 가드레일 분리를 동시에 챙겨볼 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### grounded-expert 스킬로 에이전트가 기억 대신 공식 문서를 찾아 인용하며 답하게 할 수 있습니다 (Show GN, 11/5)

**"HTTP 전문가 역할을 맡아라" 같은 persona 프롬프트는 모델이 기억에 기대어 답하게 만들어 틀린 내용도 맞는 내용과 같은 확신으로 말하게 하는데, grounded-expert는 질문이 들어오면 서브에이전트가 WebSearch·WebFetch로 공식 스펙·문서·논문을 직접 찾아 그 내용에만 근거해 답하도록 강제하는 Claude Code skill입니다.** 모든 주장에 출처 URL과 함께 원문 그대로 인용한 `EXTRACTED`, 여러 출처를 엮은 추론인 `INFERRED`, 확인하지 못한 내용인 `not confirmed` 태그를 붙이고, 결론 전에 반대 근거를 찾는 검색을 한 번 더 돈 뒤 quick·standard·thorough 중 깊이를 골라 쓸 수 있습니다.

```bash
# Claude Code에 grounded-expert 스킬 설치
/plugin install grounded-expert --marketplace pko89403/grounded-expert
```

**"최신 버전에서 이 API 동작이 바뀌었나?" 같은 질문에 Claude가 그럴듯하지만 확인되지 않은 답을 내놓아 낭패를 본 적이 있다면, 이 스킬로 답변마다 EXTRACTED 인용과 원문 대조가 가능한 근거를 요구해볼 만합니다.** [GeekNews](https://news.hada.io/topic?id=36651)

### 코딩 에이전트를 여러 개 동시에 돌릴 때는 에이전트마다 git worktree를 배정해 격리하세요

**Salesforce AI Research의 한 연구 엔지니어가 Claude Code·OpenCode·Codex·Pi 등 5~6개 코딩 에이전트를 동시에 운용하는 방식을 공개했는데, 핵심은 에이전트마다 별도의 git worktree를 배정해 파일 변경이 서로 간섭하지 않게 하는 것입니다.** 이렇게 격리해두면 과감한 아이디어를 새 worktree에서 바로 시도해보고, 마음에 들지 않으면 그 worktree만 버리면 되므로 손실 없이 실험할 수 있습니다. 실제로 Mumble 클라이언트에 노이즈 감소 기능을 프롬프트 한 번으로 추가해 약 20분 만에 시제품을 만들었다고 설명합니다.

```bash
# 에이전트별로 독립된 작업 공간을 만들어 서로 간섭하지 않게 함
git worktree add ../myproject-agent2 -b agent2-noise-reduction
```

**여러 세션에서 Claude Code를 동시에 띄워 작업하다 한 에이전트의 변경이 다른 에이전트의 작업 디렉터리를 오염시킨 경험이 있다면, worktree 단위로 작업을 쪼개는 이 방식을 CLAUDE.md나 팀 워크플로 문서에 규칙으로 박아둘 만합니다.** [GeekNews](https://news.hada.io/topic?id=36586)

## 알아두면 좋은 소소한 변경사항

아래는 모두 **v2.1.318**(11/4) 항목입니다.

- **`claude mcp add`·`remove`가 설정 파일 락을 기다리지 않고 덮어쓰던 문제가 수정**돼, 이제 락을 기다리거나 실패 시 종료 코드 1을 반환합니다(다만 다른 작업의 저장이 뒤이어 서버 설정을 덮어쓸 수는 있습니다).
- **버전 확인 요청에서 종료되는 stdio MCP 서버가 시작할 때마다 다시 프로브되던 문제가 수정**돼, 자체 이유로 3초 안에 죽는 서버는 7일간 레거시 handshake로 고정됩니다.
- **유휴 상태인 비대화형 세션이 종료될 때 삭제된 세션 transcript가 마지막 프롬프트로 재생성되던 문제가 수정**됐습니다.
- **`NODE_EXTRA_CA_CERTS` 파일이 비어있거나 PEM 형식이 아니거나 손상된 인증서로 시작할 때 모든 연결이 실패하던 문제가 수정**돼, 읽을 수 있는 인증서만 사용하고 stderr에 경고를 표시합니다.
- **`sudo claude`처럼 다른 사용자가 소유한 실행 중 프로세스를 버전 정리 작업이 죽은 것으로 오인해 바이너리를 지우던 문제가 수정**됐습니다.
- **업데이트나 버전 정리가 실행 중 프로세스의 바이너리를 지운 뒤, Remote Control 호스트·백그라운드 데몬·self-hosted runner가 새 세션 시작에 실패(`spawn ENOENT`)하던 문제가 수정**됐습니다.
- **`claude -p`·SDK처럼 비대화형으로 실행할 때 `~/.claude.json`에 바뀐 내용이 없으면 매번 다시 쓰지 않도록 개선**됐습니다.
- **클라우드 세션에서 `gh run view --log`·`gh api`로 GitHub Actions 로그를 읽을 때 접근할 수 없는 리다이렉트로 막히던 문제가 수정**돼, 대부분 환경에서 로그를 정상적으로 가져옵니다.
- **클라우드 세션에 `google-chrome` 이름과 `CHROME_PATH`가 추가**돼, Playwright 외의 도구도 내장 Chromium을 찾을 수 있습니다.
