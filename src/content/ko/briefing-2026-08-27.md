## 주요 신규 기능 & 실전 활용

### SendFeedback 도구 — 세션 중 문제가 생기면 Claude가 피드백 초안을 씁니다 (v2.1.247)

**세션 도중 뭔가 잘못됐을 때, Claude가 직접 피드백 보고서 초안을 작성**하고 사용자는 `/feedback`에서 이를 검토한 뒤 보낼지 결정하는 도구가 추가됐습니다.

```bash
# 세션 중 이상 동작을 감지하면 Claude가 피드백 초안을 자동으로 준비합니다
/feedback
# 초안 작성 자체를 원하지 않는다면 feedbackDrafts 설정으로 끌 수 있습니다
```

**지금까지는 세션에서 이상한 동작을 겪어도 그 순간의 맥락(무엇을 하다 무엇이 잘못됐는지)을 기억해 뒀다가 나중에 따로 피드백을 작성해야 했습니다.** 이제는 **문제가 발생한 바로 그 시점의 맥락을 담은 초안이 자동으로 준비돼, 검토·전송만 하면 됩니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### `/claude-api cost-optimize` — API 지출을 항목별로 뜯어보고 줄입니다 (v2.1.247)

```bash
# 기존 프로젝트의 Claude API 지출 구조를 프로파일링하고
# 캐싱·토큰 절약·배치·effort·모델 선택 순으로 비용 절감 방안을 하나씩 짚어줍니다
/claude-api cost-optimize
```

**기존 프로젝트의 Claude API 사용 패턴을 프로파일링한 뒤, 캐싱·토큰 절약·배치 처리·effort 조정·모델 선택이라는 각 비용 레버를 한 번에 하나씩, 측정 가능한 단위로 점검**해 주는 명령입니다. `claude-api` 스킬에는 **Admin API(조직 멤버, 초대, 워크스페이스, API 키, 레이트 리밋 리포트, 워크로드 아이덴티티 페더레이션, CMEK) 커버리지도 함께 추가**됐습니다.

**API 비용이 예상보다 늘고 있는데 어디서부터 손대야 할지 감이 안 잡힌다면, 이 명령으로 우선순위가 매겨진 체크리스트부터 받아볼 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### Sonnet 5의 자동 압축 임계값이 전체 1M 컨텍스트로 넓어집니다 (v2.1.247)

**1M 컨텍스트 창을 쓰는 Sonnet 5 세션의 기본 auto-compact 임계값이, 이전보다 늘어난 전체 1M 기준으로 재계산**됩니다. 그 결과 **자동 압축이 걸리는 시점이 약 934K 토큰에서 약 967K 토큰으로 늦춰집니다.**

**장문 컨텍스트를 자주 채우는 세션이라면, 압축 없이 버틸 수 있는 여유 토큰이 약 3만 토큰 정도 더 늘어난 셈**입니다. [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

## 개발자 워크플로우 팁

### Bash 권한 프롬프트에서 한 키로 auto mode로 전환합니다 (v2.1.247)

**Bash 권한 프롬프트에 auto mode를 안내하는 팁이 추가**되며, **"Yes, and switch to auto mode"를 한 번의 키 입력으로 바로 선택**할 수 있습니다.

**반복되는 Bash 명령마다 매번 승인 프롬프트를 눌러 왔다면, 이 팁을 계기로 auto mode 전환을 바로 시도해 볼 만합니다.** 어떤 규칙이 자동 승인을 유발하는지는 v2.1.246에서 추가된 `/permissions`의 Auto Mode 탭에서 확인·조정할 수 있습니다. [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### RAG는 생각보다 단순합니다 — 벡터 DB보다 BM25부터 (8/27)

**많은 RAG 시스템이 처음부터 임베딩·벡터 DB·재순위화 파이프라인을 도입하지만, 실제로는 상당수 검색 문제를 BM25와 질의 재작성만으로 해결할 수 있다**는 진단입니다. **데이터 신선도, 문서 변경률, 질의 유형, 검색량, 팀 역량에 따라 6가지 검색 구조를 단계적으로 선택**하고, 더 복잡한 구조가 필요할 때만 단계를 올리라는 것이 핵심입니다.

**Claude Code나 Claude API 위에 사내 문서·코드베이스 검색을 얹는 RAG 파이프라인을 설계하고 있다면, 벡터 DB부터 도입하기 전에 이 글의 단계별 체크리스트로 현재 요구사항이 실제로 어느 단계에 해당하는지 먼저 가늠해 볼 만합니다.** [GeekNews](https://news.hada.io/topic?id=32916)

### Bedrock·Vertex·Foundry에서 MCP 연결 실패를 Claude가 명확히 알게 됩니다 (v2.1.247)

**Bedrock, Vertex, Foundry 세션(그리고 텔레메트리가 꺼진 모든 세션)에서, 설정된 MCP 서버 연결에 실패하면 Claude가 "도구가 아예 존재하지 않는다"고 오판하는 대신 연결 실패 자체를 전달받도록** 바뀌었습니다.

**엔터프라이즈 배포 환경에서 MCP 서버를 운영하고 있다면, 지금까지 Claude가 도구 부재로 오인해 엉뚱하게 작업을 우회하던 상황을 이 수정으로 줄일 수 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

[GeekNews](https://news.hada.io/topic?id=32922)
