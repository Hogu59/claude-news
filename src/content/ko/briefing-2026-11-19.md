## 개발자 워크플로우 팁

### Claude Code 팀이 검증 루프를 어떻게 설계하는지 공개했습니다 (11/16)

**Claude Code 팀은 자신들 코드의 약 90%를 Claude로 작성·리뷰하는데, 모든 변경을 사람이 직접 확인하는 대신 에이전트가 스스로 실행해 작업을 증명하는 검증 루프를 핵심 기반으로 삼고 있다고 공식 블로그에서 밝혔습니다.** 검증 수단이 있어야 사람이 한두 개가 아니라 수십~수백 개의 에이전트를 동시에 감독할 수 있고, 모델에게 자기 출력을 검증할 방법을 주면 특히 어려운 작업에서 성공률이 가장 크게 올랐다고 합니다. 실전에서 가치가 높다고 꼽은 테스트는 세 종류입니다. 실제 사용자 흐름(장바구니 담기부터 결제까지)을 확인하는 E2E 테스트, 라운드트립 인코딩이나 멱등성처럼 항상 지켜져야 할 불변 조건을 확인하는 속성 기반 테스트, 대규모 마이그레이션에서 신·구 시스템의 출력을 같은 입력으로 비교하는 차이 테스트입니다. 단위 테스트만으로는 부족하다고 보고, 웹은 Claude Chrome 확장, 모바일은 iOS·Android MCP, 데스크톱은 컴퓨터 사용 도구로 앱을 실제로 띄워 확인하도록 `.claude/skills/`에 `verify` 스킬을 둡니다.

```text
.claude/skills/verify/   ← 앱을 실제로 띄우고 확인하는 방법을 적어둔 스킬
커밋 게이트 3단계: off(끄기) → observe(차단했을 항목만 기록) → enforce(실제 차단)
3회 연속 검증 실패 시 사람에게 넘김 (code owner가 정한 체크 규칙 적용)
```

검증 체계 자체도 보호 대상으로 다룹니다. 리뷰 규칙은 PR이 수정한 파일이 아니라 base 브랜치에서 읽어, 검증 로직 자체가 바뀌어도 믿을 수 없게 되는 일을 막습니다. 사람의 리뷰 코멘트나 되돌림(revert)에서 반복되는 패턴은 규칙 후보가 되는데, 최소 2개 PR에서 나타나고 diff만으로 판별 가능해야 하며 적대적 에이전트 3개의 검토와 사람의 승인을 거쳐야 정식 규칙이 됩니다. 불안정한(flaky) 테스트는 근본 원인을 고쳐야 하고, 건너뛰거나 재시도로 통과시키는 것은 금지되며 원인을 못 찾으면 테스트를 지우고 이유를 기록합니다.

**여러 서브에이전트를 병렬로 돌리면서 결과를 일일이 리뷰하기 번거로웠다면, 이 글에서 소개한 E2E·속성·차이 테스트의 조합과 사람 개입 전 3회 재시도 규칙, 그리고 검증 로직 자체를 PR의 수정 대상에서 분리하는 설계를 그대로 참고할 만합니다.** [claude.dev 공식 블로그](https://claude.dev/blog/how-the-claude-code-team-thinks-about-verification/) (Addy Osmani, 11/16) · [GeekNews](https://news.hada.io/topic?id=37359)

## 알아두면 좋은 소소한 변경사항

아래는 모두 **v2.1.327**(11/17) 항목 중 11/18 브리핑에서 다루지 않은 것들입니다.

- **`claude mcp add --scope project`가 `.mcp.json`이 `mcpServers` 키 없이 서버 목록을 최상위에 둔 경우, 파일을 덮어쓰는 대신 멈추도록 변경**됐습니다.
- **원격 MCP 서버가 VPN 끊김 같은 장기 장애 뒤에도 연결이 끊긴 채로 남던 문제가 수정**돼, 호스트명으로 https에 접속하는 대부분의 원격 서버가 이제 약 하루 동안 백그라운드에서 재접속을 재시도합니다.
- **커밋 시 Claude가 비밀 정보가 담겼을 법한 파일은 커밋하지 않도록 안내하는 지침이 최신 모델과 PowerShell에서 개선**됐습니다.
- **세션의 billing group 이름을 지정하는 `attributionProject` 설정이 추가**돼, `admin.billing_group_tag`를 설정하는 Claude apps 게이트웨이에서 쓸 수 있습니다.
- **Windows에서 Git Bash와 `pwsh`가 PATH에 없을 때의 시작 속도가 개선**돼, PowerShell 표준 설치 위치를 한 번에 확인합니다.
- **VS Code에서 PreToolUse hook이 제공하는 확인 이유가 권한 프롬프트에 표시되지 않던 문제가 수정**됐습니다.
