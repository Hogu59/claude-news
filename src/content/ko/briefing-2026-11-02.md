## 주요 신규 기능 & 실전 활용

### VS Code 채팅 패널에서도 `ultrathink`가 터미널처럼 xhigh effort로 올라갑니다 (v2.1.316)

**터미널에서는 이미 `ultrathink`를 입력하면 그 턴의 effort가 xhigh로 즉시 올라가고 레인보우 색으로 표시됐는데, 이제 VS Code 확장의 채팅 패널에서도 똑같이 동작합니다.** 지금까지는 VS Code에서 같은 키워드를 입력해도 터미널과 달리 effort가 오르는지, 레인보우가 표시되는지 눈으로 구분하기 어려웠습니다.

```
# VS Code 채팅 패널에 입력
ultrathink 이 레이스 컨디션의 근본 원인을 끝까지 파헤쳐줘
```

**터미널과 VS Code를 오가며 Claude Code를 쓰고 있다면, 이제 어느 쪽에서 입력하든 `ultrathink`의 effort 상승과 표시 방식이 동일하다는 점을 믿고 써도 됩니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

## 개발자 워크플로우 팁

### SSL 인증서 오류 메시지가 이제 가능한 원인까지 짚어줍니다 (v2.1.316)

**SSL 인증서 오류가 발생하면, 서버가 중간 인증서(intermediate certificate)를 빠뜨렸을 가능성처럼 흔한 원인들을 구체적으로 짚어주고 각각의 해결 방법까지 안내하도록 개선됐습니다.** 지금까지는 `UNABLE_TO_VERIFY_LEAF_SIGNATURE` 같은 오류 코드만 보고 원인을 직접 추측해야 하는 경우가 많았습니다.

**사내 프록시나 자체 발급 인증서를 쓰는 환경에서 Claude Code의 네트워크 요청이 SSL 오류로 막힌 적이 있다면, v2.1.316부터는 오류 메시지만 읽어도 어디부터 점검해야 할지 바로 알 수 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### `/model <id>`로 인식되지 않는 모델을 쓰면 이제 경고가 뜹니다 (v2.1.316)

**이 버전에서 인식하지 못하는 모델 ID를 `/model`로 지정하면, auto-compact가 컨텍스트 창을 200K 토큰으로 간주한다는 경고가 이제 함께 표시됩니다.** 지금까지는 커스텀 배포명이나 오래된 모델 ID를 지정해도 아무 경고 없이 넘어가, 실제 컨텍스트 창과 다른 가정으로 압축 시점이 결정되는 경우가 있었습니다.

**LLM 게이트웨이나 자체 배포 환경에서 커스텀 모델 ID를 `/model`로 직접 지정해 쓰고 있다면, 이 경고가 뜨는지부터 확인해 auto-compact가 실제 컨텍스트 창 크기와 다른 가정으로 동작하고 있지 않은지 점검해볼 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### Windows에서 Grep·Glob이 타임아웃된 뒤 영원히 응답하지 않던 문제가 수정됐습니다 (v2.1.316)

**검색 프로세스가 타임아웃으로 강제 종료됐지만 실제로는 바로 끝나지 않는 경우, Grep과 Glob이 응답을 영원히 기다리던 문제가 Windows 환경에서 수정됐습니다.** 지금까지는 대형 저장소에서 검색이 타임아웃에 걸리면 도구 호출 자체가 멈춘 것처럼 보여, 세션을 중단해야 하는 경우가 있었습니다.

**Windows에서 대형 모노레포를 다루며 Grep·Glob이 가끔 응답 없이 멈추는 경험을 했다면, v2.1.316으로 올려 이 문제가 해소됐는지 확인해볼 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### PowerShell 훅이 종료 코드 2로 막아야 할 명령 일부를 그냥 통과시키던 결함이 수정됐습니다 (v2.1.316)

**명령이 타입 캐스트, `param`, `using` 또는 속성(attribute)으로 시작할 때, PowerShell 훅이 종료 코드 2를 돌려줘도 그 명령을 막지 못하던 문제가 수정됐습니다.** 지금까지는 PreToolUse 훅으로 특정 명령 패턴을 차단하도록 설정해뒀어도, 명령이 이런 구문으로 시작하면 차단이 조용히 무시될 수 있었습니다.

**PowerShell 훅으로 위험한 명령을 막는 안전장치를 운영하고 있다면, v2.1.316 이전 버전에서는 이런 구문으로 시작하는 명령이 차단을 우회했을 수 있다는 점을 염두에 두고 업그레이드를 서두를 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### `--restricted` 세션이 작업 디렉터리 밖 파일을 업로드하던 결함이 수정됐습니다 (v2.1.316)

**`--restricted` 플래그로 세션을 제한해도, Read 허용 규칙이 작업 디렉터리 밖 경로를 포함하고 있으면 그 경로의 파일이 업로드되던 문제가 수정됐습니다.** 지금까지는 `--restricted`로 업로드 범위를 작업 디렉터리 안으로 좁혀뒀다고 생각해도, Read 규칙 설정에 따라 그 경계가 실제로는 지켜지지 않는 경우가 있었습니다.

**민감한 저장소를 다루며 `--restricted`로 업로드 범위를 제한하고 있다면, v2.1.316으로 올린 뒤 Read 허용 규칙이 작업 디렉터리 밖 경로를 포함하고 있지 않은지도 함께 점검해볼 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

## 알아두면 좋은 소소한 변경사항

아래는 모두 **v2.1.316**(10/31) 항목입니다.

- **Claude apps gateway가 요청에 담긴 모델명을 `availableModels`·`deniedModels`·`models`와 항상 대조하지 않던 문제가 수정**돼, 차단된 모델명을 요청하면 이제 어떤 필드 때문인지 밝히는 400 오류를 돌려줍니다.
- **managed settings가 Claude apps gateway를 요구하는 환경에서 `claude auth login`이 거부되던 문제가 수정**돼, 터미널에서 게이트웨이 로그인 화면이 뜹니다.
- **보이지 않는 문자가 섞인 프롬프트가 Enter를 두 번 눌러야 전송되던 문제가 수정**돼, 평문 프롬프트는 정리된 채 한 번에 전송됩니다.
- **백그라운드 작업이나 메시지로 깨어난 서브에이전트가 부모 서브에이전트의 모델을 상속했다가 메인 모델로 바뀌던 문제가 수정**됐습니다.
- **SDK의 `register_repo_root` 컨트롤 요청이 작업 디렉터리 밖 디렉터리의 CLAUDE.md를 불러오지 못하던 문제가 수정**됐습니다(`CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1`).
- **[VSCode] 모델 설정에 `[1m]` 태그가 붙으면(예: `opus[1m]`) Effort 슬라이더·Ultracode 스위치·모델 이름이 사라지던 문제가 수정**됐습니다.
- **[Cloud sessions] 전환해 돌아간 클라우드·Remote Control 세션의 메시지가 아직 최신화되는 중이면 "Catching up…" 줄이 표시**됩니다.
