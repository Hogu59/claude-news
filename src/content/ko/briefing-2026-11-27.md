## 개발자 워크플로우 팁

### Google Cloud·Microsoft Foundry의 sonnet·opus 별칭이 5.5로 바뀌고, Foundry 기본 모델도 Sonnet 5.5가 됐습니다 (v2.1.332)

**지금까지 Google Cloud의 Agent Platform과 Microsoft Foundry에서 `sonnet`·`opus` 별칭을 쓰면 세대가 섞여 어떤 모델이 실제로 호출되는지 플랫폼마다 달랐는데, 이번 릴리스부터 두 플랫폼의 `sonnet` 별칭은 Sonnet 5.5, Foundry의 `opus` 별칭은 Opus 5.5로 통일됐습니다.** 다만 Amazon Bedrock의 `sonnet` 별칭은 그대로 Sonnet 4.5를 가리키므로 플랫폼 간 동작이 달라졌다는 점에 유의해야 합니다. Microsoft Foundry의 기본 모델도 Sonnet 5.5로 바뀌어, 직접 배포한 모델을 쓰려면 `claude-sonnet-5-5`를 배포하거나 `ANTHROPIC_DEFAULT_SONNET_MODEL`을 원하는 모델로 설정해야 합니다. Google Cloud의 Agent Platform에서는 `sonnet`과 백그라운드 요청이 이제 `VERTEX_REGION_CLAUDE_5_5_SONNET` 환경변수를 읽고, 이 값 없이 `_4_5` 변수만 설정돼 있으면 `CLOUD_ML_REGION`이나 `us-east5`로 넘어갑니다. 더불어 Bedrock Mantle·Agent Platform·Foundry에서 Sonnet 5나 5.5로 옮겨간 터미널·VS Code 세션은 별도 모드가 지정돼 있지 않으면 이제 auto 모드로 시작합니다.

```bash
# Microsoft Foundry에서 Sonnet 5.5가 아닌 특정 배포 모델을 기본값으로 쓰려면
export ANTHROPIC_DEFAULT_SONNET_MODEL="my-deployed-model-name"

# Bedrock Mantle·Agent Platform·Foundry에서 auto 모드 자동 시작을 끄려면
# settings.json에 아래 설정 추가
{ "disableAutoMode": "disable" }
```

**Google Cloud나 Microsoft Foundry에서 `sonnet`·`opus` 별칭이나 Foundry 기본 모델에 의존해 Claude Code를 운영하고 있다면, 이번 변경으로 실제 호출되는 모델 세대가 바뀌었을 수 있으니 `VERTEX_REGION_CLAUDE_5_5_SONNET`·`ANTHROPIC_DEFAULT_SONNET_MODEL` 설정을 점검하고, auto 모드로 자동 전환되는 게 싫다면 `disableAutoMode`를 미리 꺼둘 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### VS Code·Desktop에 세션 일부 저장 실패·이전 메시지 미로드 경고가 추가됐습니다 (v2.1.332)

**지금까지 VS Code나 Desktop의 Code 탭에서 세션 일부가 저장되지 않거나, 다시 열었을 때 터미널에서는 보이던 이전 메시지가 빠진 채로 로드돼도 별다른 안내가 없었는데, 이번 릴리스부터 두 경우 모두 화면에 경고가 뜹니다.** 저장 실패 경고에는 `/compact`로 지금이라도 저장하는 방법이 함께 안내되고, 메시지 미로드 경고는 터미널이 이미 보여주던 정보를 VS Code·Desktop에도 똑같이 띄워주는 것입니다.

**VS Code나 Desktop의 Code 탭으로 긴 대화를 이어 쓰다가 이유 없이 맥락이 끊긴 느낌을 받은 적이 있었다면, v2.1.332부터는 그 원인이 저장 실패인지 메시지 미로드인지 화면 경고로 바로 구분하고 `/compact`로 대응할 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### 플랜 모드가 안전성을 판단할 수 없는 명령에 거부 대신 승인을 요청하도록 바뀌었습니다 (v2.1.332)

**지금까지 Desktop의 Code 탭과 VS Code에서 플랜 모드 중 auto 모드의 안전성 검사기가 어떤 명령이 안전한지 판단할 수 없으면 그 명령을 그냥 거부했는데, 이번 릴리스부터는 Manual이나 Accept edits에서 들어간 플랜에 대해서는 거부 대신 승인을 요청하도록 바뀌었습니다.** 안전성 판단이 애매한 명령을 무조건 막는 대신, 최종 판단을 사람에게 넘기는 쪽으로 기본 동작이 바뀐 셈입니다.

**Desktop이나 VS Code에서 플랜 모드로 작업하다가 안전성 판단이 불확실한 명령이 그냥 거부돼 흐름이 끊겼던 경험이 있었다면, v2.1.332부터는 그 자리에서 승인 여부를 직접 고를 수 있으니 거부된 명령이 실제로 위험한지부터 판단해볼 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

**지금까지 AI 에이전트가 Gmail·Drive·Calendar 같은 Google Workspace 데이터에 접근할 때는 REST API를 직접 호출해도 아무 제약이 없었는데, Google이 11/24 Workspace MCP 서버 8개를 정식 출시하면서 "Workspace AI Tools Addendum" 약관을 함께 추가해 2027년 2월 1일부터 AI 에이전트나 AI 모델이 구동하는 도구의 REST 직접 호출에 제약을 걸기로 했습니다.** 그 날짜 이후 REST를 직접 호출하는 에이전트는 유료 등급을 쓰고 있어도 무료 Standard 등급 할당량(프로젝트당 하루 5,000 MCP 요청, Gmail 검색 1회는 10회분으로 계산)이 강제 적용되며, 호출 자체는 동작하지만 약관 위반 상태가 됩니다. AI를 쓰지 않는 야간 백업이나 CRM 동기화 같은 결정론적 스크립트는 별도 OAuth 클라이언트를 쓰면 이 제약을 피할 수 있습니다. 가장 눈에 띄는 공백은 Gmail로, 공개 MCP 서버는 검색·읽기·초안 생성·라벨 관리만 지원하고 발송·답장·전달·초안 수정은 여전히 파트너 전용이며 첨부파일 다운로드와 필터 관리도 빠져 있습니다. Drive는 이동·공유·이름 변경을 지원하지 않고, Calendar·Chat은 캘린더나 스페이스 생성·관리를 지원하지 않습니다. 유료 Scaled 등급은 2027년 4월 1일부터 Gmail·Calendar·Drive에 과금하는데 MCP는 첫 요청부터 과금되는 반면 REST에는 대규모 무료 할당량이 남아 있어, 가격 정책 자체가 MCP 전환을 유도하는 모양새입니다. **MCP로 Gmail·Drive·Calendar 등 Google Workspace에 연결해 쓰는 Claude Code 에이전트나 자체 자동화를 운영하고 있다면, 2027년 2월 1일 이후 REST 직접 호출은 무료 할당량으로 강제 전환되니 지금부터 공식 MCP 서버로 전환 계획을 세우고 메일 발송처럼 아직 파트너 전용으로 막힌 기능은 SMTP 같은 대안을 미리 확인해둘 만합니다.** [원문](https://techstackups.com/articles/google-workspace-ai-agents-mcp/) · [GeekNews](https://news.hada.io/topic?id=37919)
