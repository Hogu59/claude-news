### OTel `tool_decision` 이벤트가 auto mode classifier 판단과 권한 규칙을 구분합니다 (v2.1.301)

**`tool_decision` OpenTelemetry 이벤트에 `classifier_verdict`와 `permission_mode`가 추가되어, auto mode의 classifier가 내린 판단과 permission 규칙에 따른 결정을 더 이상 하나로 섞어 볼 필요가 없어졌습니다.** `OTEL_LOG_TOOL_DETAILS=1`을 켜면 `classifier_category`까지 함께 기록되어, classifier가 어떤 내장 규칙에 걸려 도구 호출을 막았는지도 이름으로 확인할 수 있습니다.

```bash
# 도구 결정 이벤트에 classifier가 매칭한 내장 규칙 이름까지 포함
export OTEL_LOG_TOOL_DETAILS=1
```

**auto mode로 Claude Code를 운영하면서 OpenTelemetry로 도구 호출을 모니터링하고 있다면, 이번 필드 추가로 classifier가 막은 호출과 조직의 permission 규칙이 막은 호출을 분리해서 집계할 수 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

## 개발자 워크플로우 팁

### CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS — 무인 재시도가 영원히 기다리지 않게 하기 (v2.1.301)

**새 환경변수 `CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS`를 설정하면, 무인 재시도 모드(`CLAUDE_CODE_RETRY_WATCHDOG`)가 사용량 한도에 걸렸을 때 그 한도가 리셋되는 시점이 너무 멀리 있으면 기다리는 대신 요청을 종료합니다.** 지금까지는 한도 리셋까지 몇 시간이 남았든 워치독이 그대로 대기했기 때문에, 밤새 돌리던 무인 작업이 다음 날 아침까지도 멈춰 있는 경우가 있었습니다.

```bash
# 사용량 한도 리셋이 30분 이상 남으면 대기 대신 요청을 종료
export CLAUDE_CODE_RETRY_WATCHDOG=1
export CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS=1800000
```

**CI나 스케줄러로 Claude Code를 무인 실행하고 있다면, 이 변수로 최대 대기 시간을 짧게 잡아두면 한도 리셋을 하염없이 기다리다 작업 전체가 지연되는 대신 다음 스케줄에서 바로 재시도하도록 설계할 수 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### claude-api 스킬에 OpenTelemetry 트레이싱 가이드가 추가됐습니다 (v2.1.301)

**`claude-api` 스킬에 OpenTelemetry 트레이싱을 설정하는 가이드가 추가되어, `ant` CLI로 트레이스 목적지를 구성하는 방법까지 안내받을 수 있습니다.** 지금까지는 OTel 트레이싱을 자체 Agent SDK 애플리케이션에 붙이려면 외부 문서를 따로 찾아봐야 했는데, 이제는 스킬 안에서 바로 설정 과정을 확인할 수 있습니다.

**Claude API나 Agent SDK로 만든 애플리케이션에 트레이싱을 새로 붙이려 한다면, `claude-api` 스킬을 불러와 트레이스 목적지 설정 단계부터 따라가 보는 것이 가장 빠른 시작점입니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)
