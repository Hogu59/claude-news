## 개발자 워크플로우 팁

### MCP 서버 설정을 커맨드라인에 남기지 않고 stdin으로 넘기는 `claude mcp add-json <name> -`가 추가됐습니다 (v2.1.327)

**지금까지 `claude mcp add-json`으로 MCP 서버를 등록하려면 JSON 설정을 커맨드라인 인자로 직접 넘겨야 해서, 그 안에 토큰이나 API 키가 들어 있으면 셸 히스토리나 프로세스 목록에 그대로 노출될 위험이 있었습니다.** 이제 JSON 뒤에 `-`를 붙이면 stdin으로 같은 내용을 읽어, 민감한 값을 커맨드라인에 노출하지 않을 수 있습니다. 다만 Claude Code 세션 내부(Bash 도구 등)에서는 이 입력 방식을 쓸 수 없습니다.

```bash
# MCP 서버 설정을 토큰을 노출하지 않고 등록하고 싶을 때
cat server-config.json | claude mcp add-json my-server -
```

**CI 스크립트나 셸 함수로 MCP 서버를 자동 등록하면서 토큰이 담긴 JSON을 커맨드라인 인자로 그대로 넘기고 있었다면, v2.1.327부터는 이 stdin 입력 방식으로 바꿔 셸 히스토리에 토큰이 남는 것을 막을 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### `/status`가 깨진 agent·skill·command·hook 설정을 한눈에 모아 보여줍니다 (v2.1.327)

**`/status`에 깨진 agent·skill·command·output style 파일, 키바인딩 오류, 사용할 수 없는 샌드박스, 무시된 permission 설정, 그리고 한 번도 매칭되지 않는 hook matcher까지 한 번에 모아서 보여주는 목록이 추가됐습니다.** 지금까지는 이런 설정 오류들이 흩어진 채로만 드러나거나, 조용히 무시돼 원인을 찾기 어려웠습니다.

```text
/status 실행 → 깨진 agent·skill·command·output style 파일 / 키바인딩 오류 /
사용 불가능한 샌드박스 / 무시된 permission 설정 / 매칭되지 않는 hook matcher를 한 목록에서 확인
```

**여러 skill·agent·hook을 설정해 쓰면서 어느 설정이 조용히 무시되고 있는지 알아내기 어려웠다면, v2.1.327 업그레이드 뒤 `/status`를 한 번 실행해 이 진단 목록부터 확인해볼 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### 세션 첫 Bash 명령의 속도가 빨라졌습니다 — 끄고 싶다면 `CLAUDE_CODE_DISABLE_SHELL_HEAD_START` (v2.1.327)

**셸의 시작 파일(예: `.bashrc`, `.zshrc`)이 이제 명령이 승인되기 전에 먼저 실행될 수 있게 바뀌어, 세션의 첫 Bash 명령이 더 빠르게 시작됩니다.** 이는 명령 자체가 거부되는 경우에도 마찬가지로 적용되므로, 셸 시작 파일이 승인 여부와 무관하게 먼저 돌아갈 수 있다는 점은 알아두어야 합니다. 이전처럼 승인 후에만 시작 파일이 실행되길 원한다면 아래 환경변수로 끌 수 있습니다.

```bash
# 셸 시작 파일이 승인 전에 먼저 실행되는 속도 개선을 끄고 싶을 때
export CLAUDE_CODE_DISABLE_SHELL_HEAD_START=1
```

**셸 시작 파일에 무거운 초기화 스크립트를 두고 있어서 Claude Code의 첫 Bash 명령이 느리게 느껴졌다면, v2.1.327부터는 별도 설정 없이도 빨라진 속도를 바로 체감할 수 있습니다. 다만 시작 파일 안에 승인 전에 실행돼서는 안 되는 민감한 로직이 있다면 위 환경변수로 이전 동작으로 되돌려두는 편이 안전합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

**최근 며칠 사이 claude.ai나 Claude iOS 앱에서 Apple 계정으로 로그인이 안 됐다면 11/17의 이 인시던트 때문일 가능성이 크며, 이미 해결됐으므로 다시 시도해도 됩니다. Claude Code CLI 자체는 이번 인시던트와 무관하게 평소대로 쓸 수 있습니다.** [Claude Status](https://status.claude.com)

### v2.1.327에 심볼릭 링크·PowerShell·Bash 변수 확장을 둘러싼 권한 검사 강화가 포함됐습니다

**쓰기 가능한 경로를 가리는 일부 심볼릭 링크를 그대로 인정해주던 경로 검사가 더 엄격해져, 이제 그런 링크로의 쓰기를 거부합니다.** 또한 `permissions.blockReadsOutsideWorkingDirectories`가 bypass·auto 모드에서 더 많은 Bash 명령에 확인을 묻거나 일부를 거부하도록 바뀌었고, `Read`나 `Edit` deny 규칙이 걸린 경로를 가리키는 Bash 명령도 지금까지는 확인만 물었지만 이제 더 많은 경우에 거부됩니다. 변수가 아주 긴 텍스트로 확장되는 Bash 명령도 이제 거부되는데, 짧은 값이나 파일을 쓰라는 안내가 함께 표시됩니다. PowerShell 도구는 특정 명령을 허용하는 규칙이 있어도 한 번 더 확인을 묻도록 바뀌었고, 아무도 답할 수 없는 상황에서는 전체 허용 규칙·auto 모드·bypass permissions 모드가 아니면 거부됩니다.

**샌드박스나 auto·bypass 모드로 Claude Code를 자동화 파이프라인에 연결해 두고 있다면, v2.1.327 업그레이드 뒤 지금까지 조용히 통과되던 일부 명령이 새로 확인을 요구하거나 거부될 수 있다는 점을 감안해둘 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

## 알아두면 좋은 소소한 변경사항

아래는 모두 **v2.1.327**(11/17) 항목입니다.

- **`/tui classic`이라는 이름이 추가**돼, `/tui default`와 함께 비전체화면 렌더러를 가리킬 수 있습니다.
- **`/export`가 기존 파일을 묻지 않고 덮어쓰던 문제가 수정**돼, 이제 먼저 확인을 묻고 `/export <name>`은 파일을 유지한 채 `/export`를 다시 실행하라고 안내합니다.
- **`/plugin`에서 클릭 직후 Enter를 누르면 의도치 않게 플러그인이 설치되거나 비활성화되던 문제가 수정**됐습니다.
- **Grep이 `head_limit`과 `offset`으로 페이징할 때 결과를 중복 표시하거나 건너뛰던 문제가 수정**돼, 이제 파일 경로 기준으로 정렬됩니다.
- **Read 도구가 10MB 이상이라 전체를 읽을 수 없는 파일의 크기를 실제 크기 대신 512KB로 잘못 보고하던 문제가 수정**됐습니다.
- **VS Code 탐색기의 우클릭 메뉴에 선택한 파일·폴더를 채팅에 바로 @-mention하는 Claude Code: Add to Chat이 추가**됐습니다.
- **auto 모드가 결제형 classifier 요청으로 폴백할 때 뜨는 안내에, 다음 릴리스에서 이 폴백 자체가 제거될 예정이라는 문구가 추가**됐습니다.
