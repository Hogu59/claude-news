## 주요 신규 기능 & 실전 활용

### Claude apps gateway에 과거 지출을 조회하는 Cost Report Admin API가 추가됐습니다 (v2.1.317)

**Claude apps gateway 관리자 API에 `GET /v1/organizations/analytics/cost`가 추가돼, 지정한 날짜 범위의 과거 지출을 전체 합계·개발자별·일별·IdP 그룹별로 조회할 수 있습니다.** 이와 함께 `admin:`이 설정된 Claude apps gateway에서 각 개발자의 IdP 그룹을 매일 기록해 `admin.identity_retention_days` 기간만큼 보관하며, cost report는 이 기록을 바탕으로 그룹별 집계를 제공합니다. OTel 메트릭·이벤트·스팬에도 `anthropic.plan`, `anthropic.seat_type`, `anthropic.provider`, `anthropic.custom_base_url`이 추가돼 지출 분석과 함께 교차 참조할 수 있습니다.

```bash
# 지정 기간의 지출을 IdP 그룹별로 조회하는 예시
curl -H "Authorization: Bearer $ADMIN_API_KEY" \
  "https://<gateway-host>/v1/organizations/analytics/cost?start_date=2026-10-01&end_date=2026-10-31&group_by=idp_group"
```

**Claude apps gateway로 여러 팀의 Claude 사용을 관리하고 있다면, 지금까지 수작업으로 추정하던 팀별·기간별 지출을 이 API로 직접 조회해 pooled budget 설정이나 예산 보고에 바로 활용할 수 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### 클라우드 세션에 MCP 서버가 요청하는 링크를 열거나 거절하는 카드가 추가됐습니다 (v2.1.317)

**MCP 서버가 클라우드 세션에서 특정 URL을 방문해달라고 요청하면, 이제 그 요청을 열거나 거절할 수 있는 링크 카드가 화면에 표시됩니다.** 지금까지는 터미널과 달리 클라우드 세션에서는 이런 요청이 눈에 보이지 않은 채 그대로 지나가는 경우가 있었습니다.

**OAuth 인증이나 추가 승인을 위해 외부 링크 방문을 요구하는 MCP 서버를 클라우드 세션에서 쓰고 있다면, v2.1.317부터는 그 요청을 놓치지 않고 바로 확인·처리할 수 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

## 개발자 워크플로우 팁

### self-hosted runner에서 `claude -p`가 바깥 세션의 ID와 transcript를 그대로 쓰게 하는 환경변수가 추가됐습니다 (v2.1.317)

**`CLAUDE_CODE_DISABLE_NESTED_SESSION_ID`를 `1`로 설정하면, self-hosted runner에서 세션 안에 실행된 `claude -p`가 그 세션의 ID와 transcript를 그대로 쓰도록 이전 버전과 같은 동작으로 되돌릴 수 있습니다.** 최근 버전에서는 중첩 실행된 `claude -p`가 자신만의 세션 ID를 쓰고 독자적인 제목을 생성해 바깥 세션으로 보내던 동작으로 바뀌었는데, 기존 파이프라인이 이 변경에 영향을 받는다면 이 환경변수로 이전 동작을 유지할 수 있습니다.

```bash
# self-hosted runner에서 중첩 claude -p가 바깥 세션 ID를 그대로 쓰도록 설정
export CLAUDE_CODE_DISABLE_NESTED_SESSION_ID=1
```

**self-hosted runner 위에서 세션 내부에 `claude -p`를 중첩 실행하는 자동화를 운영하고 있는데 최근 버전에서 세션 ID나 transcript 처리가 달라졌다고 느꼈다면, 이 환경변수로 이전 동작으로 되돌려 파이프라인을 다시 맞춰볼 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### 종료 시 보여주는 재개 안내가 실행할 때 쓴 플래그를 그대로 기억합니다 (v2.1.317)

**Claude Code를 종료할 때 뜨는 "Resume this session with" 안내가 이제 `--chrome --debug`처럼 세션을 시작할 때 쓴 플래그를 `--resume` 앞에 그대로 붙여서 보여줍니다.** 지금까지는 이 안내가 `--resume`만 보여줘서, 특정 플래그를 붙여 시작한 세션을 재개할 때 그 플래그를 다시 기억해내 직접 입력해야 하는 경우가 있었습니다.

**`--chrome`, `--debug`처럼 특정 플래그를 붙여 세션을 자주 시작한다면, 종료할 때 뜨는 안내를 그대로 복사해 붙여넣는 것만으로 같은 조건의 세션을 다시 열 수 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### `/design-sync`가 디자인 시스템이 이미 Claude로 옮겨간 경우 업로드를 시작하기 전에 미리 알려줍니다 (v2.1.317)

**조직의 디자인 시스템이 이미 Claude 쪽으로 이전된 상태라면, `/design-sync`가 이를 작업을 시작하기 전에 먼저 알려주고 빌드에 들어가지 않습니다.** 지금까지는 이런 상태에서 업로드 단계까지 진행한 뒤에야 실패하는 경우가 있어, 어디서 멈춰야 하는지 미리 알기 어려웠습니다.

**여러 사람이 같은 조직에서 `/design-sync`를 쓰고 있다면, 누군가 먼저 디자인 시스템을 옮긴 뒤에도 다른 사람이 같은 작업을 반복하다 업로드 단계에서 실패를 마주하는 일이 줄어듭니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

## 보안/제한 이슈

### Claude 서비스 현황 — 10/31~11/3 모두 인시던트 없이 전체 정상입니다

**공식 status.claude.com을 직접 확인한 결과, 10/31부터 11/3까지 모두 "No incidents reported"로 표시돼 있으며, claude.ai·Claude API·Claude Code·Claude Console·Claude Cowork·Claude for Government 전체가 "All Systems Operational"로 정상 상태입니다.** 가장 최근 인시던트는 10/28에 해결된 Google Calendar·Gmail 커넥터 오류였습니다.

**최근 며칠 사이 서비스 오류를 겪었다면 이미 모두 해소된 상태이니, 오늘 문제가 발생한다면 로컬 설정이나 네트워크 쪽을 먼저 점검해보는 것이 합리적입니다.** [Claude Status](https://status.claude.com)

### `/schedule`이 예상치 못한 커넥터가 붙은 클라우드 예약 작업을 만들 때 경고합니다 (v2.1.317)

**새 클라우드 예약 작업을 만들 때 요청하지 않은 커넥터가 함께 붙으면, `/schedule`이 이를 경고하고 그 커넥터를 제거하는 방법까지 함께 안내합니다.** 지금까지는 예약 작업에 어떤 커넥터가 연결됐는지 명확히 드러나지 않아, 의도하지 않은 범위로 작업이 실행될 가능성이 있었습니다.

**클라우드 예약 작업으로 이메일·캘린더 같은 커넥터에 접근하는 자동화를 여러 개 운영하고 있다면, v2.1.317부터는 새로 만드는 예약 작업에 원치 않는 커넥터가 끼어 있는지 이 경고로 바로 확인할 수 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### 웹·셸 도구 호출이 계정 이메일을 네트워크로 보내기 전에 확인을 거칩니다 (v2.1.317)

**웹이나 셸 도구 호출이 사용자의 계정 이메일 주소를 네트워크로 전송하려 하면, 이제 그 전에 확인을 거치는 절차가 추가됐습니다.** 지금까지는 이런 전송이 눈에 띄지 않게 일어날 수 있어, 의도치 않게 계정 이메일이 외부로 나가는 경우를 사용자가 알기 어려웠습니다.

**WebFetch나 Bash 도구로 외부 서비스와 연동하는 워크플로를 쓰고 있다면, 계정 이메일이 네트워크로 나가는 순간을 이제 명시적으로 확인할 수 있다는 점을 안심하고 반영해도 됩니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

## 알아두면 좋은 소소한 변경사항

아래는 모두 **v2.1.317**(11/3) 항목입니다.

- **디스크 가득 찼거나 할당량 초과로 transcript나 `~/.claude.json` 쓰기가 실패했을 때, `claude -p`가 exit code 0으로 조용히 끝나던 문제가 수정**돼, 이제 오류를 출력하고 text·json 출력 모두에서 exit 1로 끝납니다(일부 전체 NFS export 환경은 여전히 놓칠 수 있습니다).
- **PDF 자체 메타데이터가 Read 도구와 @-mention의 페이지 수를 실제보다 적게 세게 만들던 문제가 수정**됐습니다.
- **리전·네트워크 차단(HTTP 403)이 로그인 실패처럼 보이던 문제가 수정**돼, 이제 오류 메시지가 차단 상황임을 설명합니다.
- **`DISABLE_PROMPT_CACHING_OPUS`·`DISABLE_PROMPT_CACHING_SONNET`이 `[1m]`, 다른 리전, 날짜 없는 기본 모델 표기에는 적용되지 않던 문제가 수정**됐습니다.
- **입력창의 텍스트를 지우려고 Ctrl+C를 눌렀을 때 실행 중인 백그라운드 에이전트가 전부 멈춰버리던 문제가 수정**됐습니다.
- **본인 소유 아티팩트가 200개 이상이면 `/artifacts`와 Artifact 도구의 공유 목록에 공유된 아티팩트가 보이지 않던 문제가 수정**됐습니다.
- **[Windows] 네이티브 경로 조회가 실패하는 일부 볼륨에서 모든 도구 호출이 거부되던 문제가 수정**돼, 이제 작업 디렉터리 확인이 폴더 식별자를 비교하는 방식으로 바뀌었습니다.
- **[Gateway] 그룹의 pooled budget이 소진된 뒤, 개발자 본인의 지출 한도가 100% 소진으로 잘못 표시되던 문제가 상태 표시줄과 `/usage`에서 수정**됐습니다.
