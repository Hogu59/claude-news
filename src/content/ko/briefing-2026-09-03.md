## 주요 신규 기능 & 실전 활용

### `managedMcpServers` — 조직이 모든 사용자에게 MCP 서버를 일괄 배포합니다 (v2.1.259)

**v2.1.259에 `managedMcpServers` 관리형 설정이 추가**되어, **조직이 HTTP/SSE MCP 서버를 모든 사용자에게 동일하게 제공**할 수 있습니다. **항목 형식은 `.mcp.json`과 같으며, 실행할 커맨드를 이름으로 지정하는 항목은 보안상 건너뜁니다.**

```json
// managed-settings.json
{
  "managedMcpServers": {
    "internal-docs": {
      "type": "sse",
      "url": "https://mcp.internal.example.com/docs"
    }
  }
}
```

**여러 팀에 동일한 사내 MCP 서버(문서 검색, 사내 API 등)를 배포하려고 사용자마다 `.mcp.json`을 따로 나눠주던 조직이라면, 이제 관리형 설정 한 곳에서 일괄 배포**할 수 있습니다. [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

## 개발자 워크플로우 팁

### `--permission-prompts none` — 무인 헤드리스 호스트에서 확인 프롬프트를 전부 자동 거부합니다 (v2.1.259)

**무인으로 돌아가는 헤드리스 호스트를 위해 `--permission-prompts none` 플래그가 추가**됐습니다. **확인을 요구했을 모든 작업이 자동으로 거부되며, auto mode를 포함해 활성 권한 모드는 계속 판단을 이어갑니다.**

```bash
claude -p "빌드 로그를 분석해줘" --permission-prompts none
# 승인이 필요한 작업은 전부 거부되고, 나머지는 현재 권한 모드가 그대로 판단합니다
```

**CI 파이프라인이나 사람이 없는 배치 작업에서 Claude Code를 돌릴 때, 프롬프트가 뜬 채로 무한 대기하는 대신 즉시 거부하고 다음으로 넘어가게 만들 수 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### 에이전트 메모리는 파이프라인이 아니라 파일 형식이어야 합니다 — Memoryfield (9/2)

**기존 에이전트 메모리 시스템은 특정 하네스에 종속되거나 별도 LLM과 데이터베이스를 얽은 복잡한 파이프라인이 되기 쉬우므로, 메모리를 단순하고 이식 가능한 데이터 형식으로 다뤄야 한다는 제안**입니다. **Memoryfield는 에이전트가 직접 작성한 짧은 Markdown 문서와 선택적 YAML 메타데이터만으로 메모리를 구성**합니다.

**Claude Code의 `CLAUDE.md`나 메모리 파일을 설계할 때도 같은 원칙을 적용할 만합니다.** 특정 하네스나 벤더에 묶이지 않는 순수 Markdown+YAML 형식으로 메모리를 쌓아두면, 다른 도구로 옮기거나 여러 에이전트가 같은 메모리를 공유하기가 훨씬 쉬워집니다. [GeekNews](https://news.hada.io/topic?id=33135)

## 보안/제한 이슈

### 관리형 설정 파싱 실패 시 조용히 무시되던 문제 — 이제 Claude Code가 시작을 거부합니다 (v2.1.259)

**관리형 설정 파일, drop-in, MDM plist, HKLM 값 중 하나라도 파싱에 실패하면 그 설정이 조용히 적용되지 않은 채 넘어가던 문제가 수정**됐습니다. **이제 파싱에 실패하면 Claude Code가 시작 자체를 거부하고 어떤 소스가 문제인지 이름을 알려줍니다.**

**조직 정책을 관리형 설정으로 강제하고 있다면, 설정 파일의 오타나 형식 오류가 정책을 무력화한 채 조용히 통과되던 위험이 이번 릴리스로 사라집니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### Bash `Read()` deny 규칙이 옵션 값·git diff 피연산자·복합 명령까지 커버합니다 (v2.1.259)

**`--ignore-revs-file=.env`, `-f.env`, `@file`처럼 옵션 값으로 넘겨진 파일, `git diff`·`git grep`의 파일 피연산자, `cd DIR && cat FILE` 같은 복합 명령이 `Read()` deny 규칙을 우회하던 문제가 수정**됐습니다. **차단된 파일을 담은 디렉터리를 대상으로 한 `grep -r`·`cp -r`도 이제 확인을 요구**합니다.

**`.env` 같은 민감 파일을 deny 규칙으로 막아뒀다면, 지금까지는 옵션 값이나 복합 명령으로 우회될 여지가 있었습니다. 업데이트하면 이 경로들이 함께 막힙니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)
