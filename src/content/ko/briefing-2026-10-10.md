## 주요 신규 기능 & 실전 활용

### 서브에이전트 전용 autoCompactWindow — 메인 세션보다 먼저 압축되게 설정하기 (v2.1.296)

**서브에이전트 frontmatter와 `--agents` 정의에 `autoCompactWindow`가 추가되어, 서브에이전트가 메인 대화의 컨텍스트 윈도우보다 더 일찍 자동 압축(auto-compact)되도록 개별 설정할 수 있게 됐습니다.** 지금까지는 서브에이전트도 메인 세션과 같은 압축 임계값을 공유해, 짧고 반복적인 작업을 도는 서브에이전트가 불필요하게 큰 컨텍스트를 들고 있다가 늦게 압축되는 경우가 있었습니다.

```yaml
---
name: file-scanner
autoCompactWindow: 20000
---
```

**파일 검색이나 로그 요약처럼 가벼운 작업을 반복하는 서브에이전트를 쓰고 있다면, `autoCompactWindow`를 메인 세션보다 작게 잡아 서브에이전트가 스스로 더 일찍 압축하게 만들면 토큰 낭비를 줄일 수 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### Read 도구에 allow_large 옵션 추가 — 큰 파일을 한 번에 통째로 읽기 (v2.1.296)

**Read 도구에 `allow_large` 옵션이 추가되어, 컨텍스트에 여유가 있고 파일 전체가 필요한 경우 기존 크기 제한을 넘는 텍스트 파일도 한 번의 호출로 전부 읽을 수 있게 됐습니다.** 지금까지는 큰 파일을 여러 번에 걸쳐 나눠 읽어야 했는데, 파일 전체의 맥락이 한 번에 필요한 작업에서는 이 과정이 오히려 번거로웠습니다.

**대형 설정 파일이나 로그 전체를 한눈에 봐야 하는 작업을 맡길 때, 컨텍스트 여유가 있다는 전제로 프롬프트에 "파일 전체를 한 번에 읽어줘"라고 명시해두면 분할 읽기 때문에 맥락이 끊기는 것을 피할 수 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

## 개발자 워크플로우 팁

### CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL — 워크플로 전체를 한 모델로 통일하기 (v2.1.296)

**새 환경변수 `CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL`을 설정하면, Workflow 도구가 띄우는 모든 에이전트가 이 변수가 지정한 모델로 통일되어 실행되고, 그 밖의 일반 서브에이전트는 원래 지정된 모델을 그대로 씁니다.**

```bash
# Workflow 안의 모든 에이전트를 Haiku 5.5로 통일 실행
export CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL=claude-haiku-5-5
```

**여러 단계로 구성된 Workflow 스크립트에서 단계마다 다른 모델이 뒤섞여 비용과 속도를 예측하기 어려웠다면, 이 환경변수로 워크플로 전용 모델을 하나로 고정해두면 비용 추정과 디버깅이 한결 쉬워집니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

## 알아두면 좋은 소소한 변경사항

아래는 모두 **v2.1.296**(10/9) 항목입니다.

- **Sonnet 5.5 캐시 읽기 가격이 100만 토큰당 $0.20에서 $0.10으로 절반 인하**돼, `/cost`·상태표시줄·`--max-budget-usd`·SDK 비용 수치에 모두 반영됩니다.
- **MCP 도구 설명과 서버 instructions를 처음부터 프롬프트에 올리는 기본 글자 제한이 2,048자에서 4,096자로 늘었습니다.**
- **[VSCode] Claude in Chrome이 `@browser`로 연결한 세션을 포함해 모든 세션에서 브라우저 액션 전에 승인을 묻도록 바뀌었고**, 세션 안에서 한 사이트를 허용하면 반복해서 묻지 않습니다.
- **Windows: PowerShell 명령이 약 1KB를 넘으면 항상 권한을 묻던 문제가 수정**돼, 허용 규칙과 읽기 전용 감지가 32KB까지 적용됩니다.
- **`claude self-hosted-runner`가 러너 등록이 거부됐을 때 어떤 조직 관리자 설정이 원인인지, 재시작된 온디맨드 러너라면 새 작업 지시가 필요한지 구체적으로 알려주도록 개선**됐습니다.
- **`/plugin`이 같은 이름의 다른 플러그인이 이미 활성화돼 훅이 제외된 플러그인에 대해 안내 문구를 표시합니다.**
