### Computer Use·Browser Use Tool·Skills API·Files API로 프로덕션 에이전트 구축하기 (8/22)

8/20 GA로 전환된 **Computer Use, Browser Use Tool, Skills API, Files API**를 어떻게 하나의 파이프라인으로 엮는지 다룬 실전 가이드입니다(8/22 브리핑이 다룬 GA 발표의 후속). **소프트웨어를 직접 조작하는 Computer Use, 페이지 구조를 읽어 특정 필드·버튼을 조작하는 새 Browser Use Tool, 조직 지식을 담은 Skills, 완성된 파일을 반환하는 Files API를 연결하면 웹 작업 자동화부터 산출물 저장까지 하나의 에이전트 흐름으로 구성**할 수 있다는 것이 핵심입니다.

**실무로 옮기면**: 별도 셀프호스티드 인프라 없이 Claude Platform 하나로 브라우저 자동화·조직 지식 적용·파일 산출까지 이어지는 파이프라인을 시험해 볼 수 있습니다. [GeekNews](https://news.hada.io/topic?id=32754)

### Labor0 — 에이전트 세션이 늘어날수록 병목은 사람의 조율로 옮겨갑니다 (8/22)

**AI 에이전트 세션이 늘어나면 실행 자체보다 사람이 모든 진행 상황을 확인하고 조율하는 일이 병목이 된다는 문제의식에서 출발한 작업 체계**입니다. **큰 작업을 작은 PR 단위로 나누고, CI 실패 수정·머지 충돌 해결·리뷰 반영·자동 코드 리뷰가 모두 끝난 뒤에만 사람이 확인하도록 설계**해 사람의 개입 지점을 최소화합니다.

**Claude Code로 여러 에이전트 세션을 동시에 돌리는 팀이라면, "사람은 언제 개입해야 하는가"를 미리 정의해 두는 이 접근이 8/16~8/22 브리핑이 반복해서 다뤄온 완료 조건 설계 논의에 구체적인 실무 사례를 더해줍니다.** [GeekNews](https://news.hada.io/topic?id=32769)

### Anthropic, Claude Code의 추론 노력 수준 축소를 A/B 테스트하는 것으로 보입니다 (8/23)

**서버 측 실험으로 Claude Code 2.1.236 이상의 일부 Fable 5 세션에서 추론 노력(reasoning effort) 척도가 낮아져, 같은 버전을 쓰는 사용자 사이에서도 체감 성능이 달라질 수 있는 것으로 파악**됩니다. **이전 Claude Code 버전과 Opus 5는 실험 대상에서 제외**되며, **클라이언트 버전이 실험 등록 조건으로 쓰이는 것으로 보입니다.**
