## 주요 신규 기능 & 실전 활용

### GitLab MR을 `--worktree` 플래그로 바로 엽니다 (v2.1.233)

**GitLab merge request URL을 `--worktree` 플래그와 `claude agents` 뷰에서 지원**합니다. **`claude agents` 뷰에서는 MR이 `!N` 형태로 표시**됩니다.

```bash
claude --worktree https://gitlab.com/group/project/-/merge_requests/123
```

8/14 브리핑이 다룬 **GitLab 전면 지원**(시크릿 리댁션·마켓플레이스 bare URL 클론)의 연장선입니다 — **worktree 워크플로까지 GitHub와 대등해지면서, GitLab에서 이슈·MR 단위로 작업 트리를 오가는 습관을 그대로 옮겨 쓸 수 있게 됐습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### Bash 도구에 opt-in 메모리 상한을 걸 수 있습니다 — 폭주 빌드가 세션을 막지 못하게 (v2.1.233)

**Linux에서 Bash 도구가 실행하는 명령에 cgroup 기반 메모리 상한을 옵트인으로 걸 수 있는 `CLAUDE_CODE_TOOL_MEMORY_LIMIT` 환경변수**가 추가됐습니다. **메모리를 과도하게 먹는 빌드나 스크립트 하나가 세션 전체를 멈춰 세우는 상황을 막는 것**이 목적입니다.

```bash
# Linux에서 Bash 도구 명령의 메모리 상한을 cgroup으로 제한합니다(opt-in)
export CLAUDE_CODE_TOOL_MEMORY_LIMIT=<값>
```

**CI 러너나 셀프호스티드 러너처럼 에이전트가 무인으로 빌드·테스트를 오래 돌리는 환경**이라면, **메모리 누수가 있는 빌드 스크립트 하나 때문에 세션 자체가 응답 불능에 빠지는 사고를 이 옵션으로 예방**할 수 있습니다. 정확한 값 형식은 공식 문서에서 확인하는 편이 안전합니다. [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### WebFetch 캐시 TTL을 직접 조정합니다 (v2.1.233)

**`CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS` 환경변수로 WebFetch 세션 URL 캐시의 TTL을 설정**할 수 있게 됐습니다. **기본값은 기존과 동일한 15분(900000ms)**입니다.

```bash
# WebFetch 캐시 TTL을 30분으로 늘리는 예시
export CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS=1800000
```

**같은 URL을 세션 안에서 반복해 확인하는 조사·리서치 워크플로**라면 TTL을 늘려 재요청 비용을 줄일 수 있고, 반대로 **자주 바뀌는 페이지(상태 페이지, 실시간 대시보드 등)를 다루는 세션**이라면 TTL을 줄여 최신 데이터를 더 자주 받아오게 조정할 만합니다. [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

## 개발자 워크플로우 팁

### TaskCreate·TodoWrite가 신형 모델에서 기본적으로 사라졌습니다 — `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`로 복원 (v2.1.233)

**Opus 4.8, Sonnet 5, Fable 5, Mythos 5를 비롯한 신형 모델에서 작업추적 도구(TaskCreate·TaskGet·TaskUpdate·TaskList, TodoWrite)가 기본적으로 더 이상 제공되지 않습니다.** 이전처럼 계속 쓰려면 환경변수를 켜야 합니다.

```bash
export CLAUDE_CODE_ENABLE_TODO_TOOLS=1
```

- **왜 바뀌었는지는 체인지로그에 명시돼 있지 않지만**, 신형 모델이 별도 도구 없이도 작업을 스스로 구조화하는 능력이 충분하다고 판단했을 가능성이 있습니다.
- **실무로 옮기면**: 지금까지 CLAUDE.md나 팀 워크플로에서 "작업을 TaskCreate로 쪼개서 진행하라"는 지시를 명시해 뒀다면, **신형 모델 세션에서는 그 지시가 조용히 무시될 수 있습니다.** 작업추적 도구에 의존하는 워크플로(진행 상황을 도구 목록으로 확인하는 습관 등)가 있다면, **오늘 `/model`로 어떤 모델을 쓰고 있는지 먼저 확인하고, 필요하면 환경변수를 세션 설정에 추가**해 두는 편이 안전합니다.

### Windows auto mode 회귀 수정 — 평범한 명령에도 반복 승인을 요구하던 문제 (v2.1.233)

8/9~8/14 브리핑이 D-3부터 다뤄 온 **auto mode 기본 전환이 정작 시행된 8/14 당일, Windows에서 부작용이 있었습니다.** **`cd <dir> && <command> > file`처럼 지극히 평범한 Bash 명령에도 auto mode가 반복적으로 수동 승인을 요구하던 문제**가 확인됐고, **v2.1.232에서 생긴 회귀(regression)**로 밝혀져 v2.1.233에서 수정됐습니다.

**auto mode가 승인 없이 진행되는 게 핵심 가치인데, 오히려 승인을 더 자주 요구하는 방향으로 회귀가 났다는 점이 아이러니합니다.** Windows에서 auto mode를 8/14부터 켜 뒀는데 **평범한 명령마다 승인 프롬프트가 계속 뜬다면, v2.1.233으로 업데이트했는지부터 확인해 볼 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### v2.1.233 보안 수정 두 건 — Windows NTLM 유출 벡터, 스킬 인자 재확장 방지

- **Windows NT 경로 검증 우회(NTLM 자격증명 유출 벡터) 수정**: **NT의 `\??\` 디바이스 프리픽스로 표기된 Windows 경로가 UNC 경로 검증을 우회**하던 문제가 막혔습니다. 이런 경로를 통해 **NTLM 자격증명이 유출될 수 있는 경로가 이번 수정으로 닫혔습니다.**
- **스킬/명령 인자 치환 재확장 방지**: **스킬이나 명령에 전달된 인자 값이 템플릿 마커로 다시 확장(re-expand)되는 것을 방지**하도록 인자 치환 로직이 수정됐습니다. 외부에서 전달된 인자 값이 의도치 않게 다시 해석되는 경로를 줄이는 조치입니다.

**8/11~8/14에 걸쳐 반복해 다룬 권한·경로 검증 하드닝의 연장선**입니다. Windows에서 Claude Code를 셀프호스팅하거나 조직 배포 중이라면, **이번 두 수정이 포함된 v2.1.233으로 업데이트를 권장**합니다. [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

**보안 강화가 실사용 워크플로를 너무 많이 막아 되돌려진 경우**로 보입니다 — 위에서 다룬 **Windows auto mode 회귀**와 함께 놓고 보면, **v2.1.232의 Windows용 권한 강화가 여러 방향에서 부작용을 냈고, v2.1.233은 그 부작용을 수습하는 릴리스에 가깝습니다.** Windows에서 Git Bash나 Cygwin 스타일 도구를 쓰는 워크플로가 있다면, **이 경계가 다음 릴리스에서 다시 좁아질 수 있다는 점을 염두**에 두는 편이 좋습니다. ### MCP가 Stateless해집니다 — 이번 릴리스의 스트림 재접속 버그와 같은 문제를 가리킵니다 (8/14)

**MCP 2026-07-28 스펙이 출시 이후 가장 큰 규모로 개정**됐습니다. 핵심은 **프로토콜 코어가 stateful한 양방향 연결 구조에서 stateless한 request/response 구조로 전환**된다는 점입니다.

**흥미로운 지점은, 오늘 다룬 v2.1.233의 버그 수정 하나가 정확히 이 문제를 겨눈다는 것입니다** — **"서버리스 호스트처럼 고정된 타임아웃으로 장기 스트림을 끊는 서버를 상대로, MCP v2 연결이 subscriptions/listen 스트림을 끝없이 재접속하려 하던 문제"가 v2.1.233에서 수정**됐습니다. **stateful한 장기 연결이 서버리스 환경과 근본적으로 궁합이 안 맞는다는 문제의식이, 스펙 쪽(stateless 전환)과 구현 쪽(재접속 루프 버그 수정) 양쪽에서 동시에 나타난 셈**입니다.

**서버리스 환경에 MCP 서버를 올려 두고 있다면**, 이번 v2.1.233 업데이트와 함께 **MCP 스펙의 stateless 전환이 여러분의 서버 구현에 어떤 마이그레이션을 요구하는지 확인해 볼 만한 타이밍**입니다. [GeekNews](https://news.hada.io/topic?id=32492)
