## 개발자 워크플로우 팁

### 검색·복붙에서 에이전트 위임으로 — 코드 리뷰보다 QA와 제약조건을 먼저 생각하게 됐습니다 (10/18)

**한 개발자가 자신의 업무 방식이 검색과 코드 복사/붙여넣기에서 에이전트에 작업을 맡기는 방식으로 바뀌었고, 최근에는 완성된 코드를 리뷰하기보다 QA와 결과가 지켜야 할 제약조건을 먼저 떠올리는 단계로 옮겨갔다고 돌아봅니다.** 초기에는 익숙하지 않은 언어로 코드를 작성하거나 특정 분야 프로젝트를 돕는 보조 도구였지만, 지금은 작업을 맡기기 전에 무엇이 맞는 결과인지부터 정의하는 역할이 커졌습니다.

**Claude Code에 작업을 맡기는 빈도가 늘고 있다면, 코드를 짠 뒤 리뷰하는 습관 대신 작업을 맡기기 전에 QA 기준과 제약조건을 먼저 정리해두는 쪽으로 워크플로를 옮겨보는 것이 이 글이 제안하는 방향입니다.** [GeekNews](https://news.hada.io/topic?id=35541)

### AI가 쏟아내는 코드가 쌓일수록, 비정합성(decoherence)이 변경 비용을 끌어올립니다 (10/17)

**개별적으로는 타당하지만 서로 호환되지 않거나 중복되는 모델이 시스템에 쌓이는 현상을 비정합성(decoherence)이라 부르며, 모델 사이를 오가고 의도치 않은 부작용을 막는 일이 변경 비용의 대부분을 차지하게 된다고 짚는 글입니다.** 비정합성은 시간이 지난다고 저절로 커지는 것이 아니라 시스템에 가해지는 변경의 양에 비례해 커진다는 점이 핵심입니다.

**Claude Code로 여러 세션이나 서브에이전트를 동시에 돌려 코드를 빠르게 늘리고 있다면, 코드량 자체보다 서로 호환되지 않는 모델과 패턴이 쌓이고 있는지를 리뷰 기준에 포함시켜두는 것이 이 글이 경고하는 비정합성의 함정을 피하는 방법입니다.** [GeekNews](https://news.hada.io/topic?id=35526)

**전문 업무용 에이전트에 Claude Code나 Claude API를 쓰고 있다면, 이런 특화 오픈 모델이 비용 대비 품질에서 어느 지점까지 따라왔는지 벤치마크 결과를 참고해볼 만합니다.** [GeekNews](https://news.hada.io/topic?id=35519)

**Claude Code로 Deno 기반 프로젝트를 유지보수하고 있다면, 독립 런타임 투자 축소가 장기 지원이나 생태계 활력에 어떤 영향을 줄지 이번 소식을 계기로 미리 점검해볼 만합니다.** [GeekNews](https://news.hada.io/topic?id=35533)

## 알아두면 좋은 소소한 변경사항

아래는 모두 **v2.1.302**(10/16) 항목 중 전날 브리핑에서 다루지 않은 것들입니다.

- **플러그인을 많이 설치한 환경의 시작 시간이 개선**돼, 플러그인 명령·에이전트 파일을 불러오는 데 필요한 파일시스템 호출이 크게 줄었습니다. Windows에서 효과가 가장 큽니다.
- **조직 정책으로 `/feedback`이 꺼졌을 때 안내 문구가 변경**돼, 조직 관리자 대신 GitHub 이슈를 안내합니다.
- **`claude plugin details <name>@builtin`이 플러그인을 찾지 못했을 때의 안내가 수정**돼, 빌트인 플러그인을 보여주지 않는 `claude plugin list` 대신 `/plugin`을 안내합니다.
- **[Cloud sessions] 루틴 페이지에 마지막 실행이 시작되지 않은 이유를 보여주는 배너가 추가**돼, 조직의 동시 cloud session 한도 도달 같은 원인을 바로 확인할 수 있습니다.
- **[Cloud sessions] cloud session에서 가장 최근 메시지를 제외한 모든 메시지에 대해 Rewind to here가 실패하던 문제가 수정**됐습니다(셀프 호스티드 러너는 v2.1.246 이상 필요).
