## 개발자 워크플로우 팁

### 서브에이전트 응답이 출력 토큰 제한에 걸려 잘리면, 이제 전체를 더 짧게 다시 요청합니다 (v2.1.325)

**지금까지는 서브에이전트의 응답이 출력 토큰 제한에 걸려 잘리면 끝부분만 반환돼 정작 필요한 앞부분 내용을 통째로 잃어버리는 경우가 있었는데, 이제는 잘린 경우 서브에이전트에게 전체 답변을 더 간결하게 다시 작성해 달라고 자동으로 요청합니다.** 별도 설정이 필요 없는 변경입니다.

**여러 서브에이전트에게 긴 분석 리포트나 코드 리뷰 결과를 한 번에 받아오게 하면서, 응답이 끝부분만 남고 잘려 처음부터 다시 물어봐야 했던 경험이 있다면, v2.1.325로 올린 뒤에는 이 자동 재요청이 그 번거로움을 대신 처리해주는지 확인해볼 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### 상대 경로로 쓴 deny 권한 규칙이 cd 이후와 --add-dir로 추가한 디렉터리에도 그대로 적용됩니다 (v2.1.325)

**`Read(./.env)`처럼 상대 경로로 쓴 deny·ask 권한 규칙이, 세션 중 `cd`로 디렉터리를 옮기거나 `--add-dir`로 다른 폴더를 추가한 뒤에는 더 이상 보호 대상을 벗어나던 문제가 수정돼, 이제 프로젝트와 추가된 디렉터리 모두에 그대로 적용됩니다.**

```json
{
  "permissions": {
    "deny": ["Read(./.env)", "Read(./secrets/**)"]
  }
}
```

**모노레포나 여러 저장소를 `--add-dir`로 함께 열어두고 작업하면서 `.env` 같은 민감 파일을 상대 경로 deny 규칙으로 막아뒀다면, 지금까지는 디렉터리를 옮기거나 폴더를 추가한 뒤에도 그 규칙이 계속 적용되는지 의심할 이유가 있었지만, v2.1.325부터는 이를 신뢰하고 그대로 써도 됩니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

**Claude Code의 Edit 도구가 macOS에서 대상 경로의 심볼릭 링크를 검사한 뒤 그 결과를 디렉터리 inode나 파일 디스크립터에 고정하지 않아, 검사와 실제 쓰기 사이의 틈을 노려 샌드박스 안에서 실행되는 공격자 코드가 작업공간 상위 디렉터리를 심볼릭 링크로 바꿔치기해 작업공간 밖의 사용자 쓰기 가능 파일을 덮어쓸 수 있는 취약점(CVE-2026-88968, CVSS 3.1 기준 8.8)이 공개됐습니다.** 악성 저장소를 열거나 의존성 설치 스크립트를 실행해 샌드박스 안에서 공격자 코드가 먼저 돌아가야 악용할 수 있는 조건부 취약점이며, v2.1.251부터 이미 수정됐습니다. 자동 업데이트를 쓰고 있다면 이미 수정판을 받았을 것이고, 지금 최신 버전은 이보다 훨씬 최신인 v2.1.325입니다.

**Claude Code를 자동 업데이트 없이 특정 버전에 고정해 쓰고 있거나 수동으로 업데이트를 관리하고 있다면 v2.1.251 이상인지 지금 확인해볼 만하며, 낯선 저장소를 열거나 의존성 설치 스크립트를 돌릴 때는 버전과 상관없이 주의하는 편이 안전합니다.** [GitLab Advisory Database](https://advisories.gitlab.com/npm/@anthropic-ai/claude-code/CVE-2026-88968/)

**Claude Code를 포함한 Anthropic 제품을 조직 차원에서 쓰고 있다면, 핵심 인프라 공급사인 Nvidia·Alphabet이 동시에 주주로 들어오는 이번 구조를 Anthropic의 컴퓨팅 공급 안정성을 가늠하는 신호로 참고할 만합니다.** [원문](https://cryptobriefing.com/nvidia-alphabet-anthropic-ipo-private-placement/)
