## 주요 신규 기능 & 실전 활용

### maxProseWidth 설정 추가 — 넓은 터미널에서 응답 줄 너비를 직접 제어합니다 (v2.1.282)

**초대형 모니터나 넓은 tmux pane에서 Claude Code를 쓰면 설명문(prose)이 화면 전체 너비로 늘어나 오히려 읽기 불편했는데, 이제 이 폭을 별도로 지정할 수 있습니다.** **표와 코드 블록은 이 설정과 무관하게 기존처럼 화면 전체 너비를 그대로 씁니다.**

```json
{
  "maxProseWidth": 100
}
```

**넓은 화면에서 Claude Code를 상시 띄워두는 개발자라면, 이 설정으로 설명문만 적당한 폭으로 줄이고 표·코드는 그대로 넓게 볼 수 있어 가독성을 손쉽게 끌어올릴 수 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### Claude 앱 게이트웨이에 readiness_grace_seconds 추가 — 짧은 DB 장애에도 준비 상태를 유지합니다 (v2.1.282)

**자체 호스팅 Claude 앱 게이트웨이 설정에 `store.readiness_grace_seconds`를 지정하면, Postgres 페일오버 같은 짧은 데이터베이스 장애가 발생해도 `/readyz` 헬스체크가 곧바로 준비 안 됨 상태로 바뀌지 않고 설정한 유예 시간만큼 준비 상태를 유지합니다.**

```json
{
  "store": {
    "readiness_grace_seconds": 30
  }
}
```

**쿠버네티스 등에서 `/readyz`를 기준으로 트래픽을 라우팅하는 자체 호스팅 게이트웨이 운영팀이라면, DB 페일오버 몇 초 만에 파드 전체가 unready 처리되면서 트래픽이 끊기는 일을 이 옵션으로 막을 수 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

## 개발자 워크플로우 팁

### 플러그인 hook에서 CLAUDE_PLUGIN_ROOT는 반드시 따옴표로 감싸세요 (v2.1.282)

**`claude plugin validate`가 이제 shell-form hook에서 `${CLAUDE_PLUGIN_ROOT}`를 따옴표 없이 쓴 경우 경고를 표시합니다.** **공백이 포함된 경로에 플러그인이 설치되면 따옴표 없는 참조가 조용히 깨질 수 있기 때문입니다.**

```json
{
  "hooks": {
    "PreToolUse": [
      { "hooks": [{ "type": "command", "command": "\"${CLAUDE_PLUGIN_ROOT}/scripts/check.sh\"" }] }
    ]
  }
}
```

**사내 플러그인을 배포하기 전에 `claude plugin validate`를 실행하는 습관을 들이면, macOS나 Windows 사용자 이름에 공백이 섞여 있어도 hook이 깨지지 않는지 미리 잡아낼 수 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### sandbox.network.allowLocalBinding — macOS 샌드박스에서 로컬 개발 서버가 멈출 때 (v2.1.282)

**macOS 샌드박스 환경에서 로컬 개발 서버가 포트를 바인딩하지 못해 멈추면, Claude가 이제 원인이 될 수 있는 설정으로 `sandbox.network.allowLocalBinding`을 직접 안내합니다.**

```json
{
  "sandbox": {
    "network": {
      "allowLocalBinding": true
    }
  }
}
```

**샌드박스를 켠 채로 `npm run dev`나 로컬 API 서버를 자주 띄우는 팀이라면, 매번 원인을 찾아 헤매는 대신 이 설정을 CLAUDE.md나 프로젝트 settings.json에 미리 문서화해두는 편이 좋습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### macOS 심볼릭링크로 네트워크 마운트까지 읽히던 문제 등 권한 관련 보안 수정 다발 (v2.1.282)

**시작 시 CLAUDE.md와 rules 파일을 읽는 과정에서, 저장소 안의 심볼릭링크가 `..`나 `/.vol` 형태의 커널 경로를 거쳐 macOS의 `/Network`(네트워크 마운트)에 닿거나, macOS의 `/home`을 가리키는 rules 링크가 그대로 나열되던 문제가 수정됐습니다.** **권한 규칙에 NUL 바이트가 섞여 있으면 와일드카드처럼 모든 것에 매칭되던 문제도 고쳐져, 이제 그런 규칙은 아무것도 매칭하지 않습니다.**

**관리형 설정에서도 `disableClaudeAiConnectors`나 `allowManagedPermissionRulesOnly`처럼 boolean으로 잠그는 키에 오타 섞인 값이 들어가면 잠금 자체가 무시되던 문제, 그리고 `permissions`·`autoMode`·`worktree`·`attribution` 설정 중 하나만 잘못돼도 블록 전체가 무시되던 문제도 함께 수정돼, 이제 오타는 시작 시 이름과 함께 경고되고 나머지 유효한 설정은 그대로 적용됩니다. 또한 프로젝트·로컬 설정 파일은 더 이상 `CLAUDE_CODE_ENABLE_TELEMETRY`나 `OTEL_LOG_*` 같은 텔레메트리 활성화·엔드포인트·콘텐츠 캡처 변수를 지정할 수 없게 바뀌었고, 어떤 변수가 이렇게 무시됐는지는 시작 알림과 `/status`, `claude doctor`에서 확인할 수 있습니다.**

**저장소를 여러 사람이 공유하거나 외부 저장소를 클론해 쓰는 조직이라면, 심볼릭링크나 손상된 권한 규칙을 통한 우회 경로가 이번 릴리스로 상당수 막힌 만큼 최신 버전으로 업데이트해둘 필요가 있습니다. 조직 관리형 설정으로 텔레메트리나 권한을 엄격히 통제하고 있었다면, 오타 때문에 잠금이 조용히 풀려 있지 않았는지도 이번 기회에 점검해볼 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)
