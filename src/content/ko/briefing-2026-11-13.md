# Claude Code 데일리 브리핑 - 2026-11-13

## 최신 릴리스 요약

| 버전 | 날짜 | 핵심 변경 |
|------|------|----------|
| **v2.1.323** | 11/12 | 실험적 opt-in 기능 Code Mode 추가, `plugin.json`의 `engines["claude-code"]`로 버전 범위 강제, 심볼릭 링크 쓰기 우회·`cp`/`mv` 대상 누락 등 Bash sandbox 보안 수정 다수 등 300여 건 |
| v2.1.322 | 11/10 | Vertex AI의 global·us·eu 리전에서 fast mode 사용 가능 (11/11 브리핑에서 다룸) |

**v2.1.322(11/10) 이후 이틀 만인 11/12에 v2.1.323이 나왔습니다.** Claude가 도구 호출을 JavaScript로 묶어 실행하는 실험 기능 Code Mode가 처음 추가됐고, 플러그인 생태계의 버전 호환성을 강제하는 `engines` 필드, 그리고 샌드박스 보안 수정이 유난히 많이 포함된 비중 있는 릴리스입니다.

## 주요 신규 기능 & 실전 활용

### Claude가 도구를 하나씩 호출하는 대신 JavaScript로 묶어 호출하는 실험 기능 Code Mode가 추가됐습니다 (v2.1.323)

**지금까지 Claude Code는 도구를 하나 호출할 때마다 모델에게 되돌아가 다음 행동을 다시 물어봐야 했는데, Code Mode를 켜면 Claude가 여러 도구 호출을 묶은 JavaScript 코드를 작성해 한 번에 실행할 수 있습니다.** 아직 실험적 opt-in 기능이라 기본값은 꺼져 있고, 조직 단위로 켜거나 끌 수 있습니다. Docker의 agent runtime이나 OpenCode에 이미 있는 같은 이름의 기능이 여러 단계를 거치는 작업에서 모델과의 왕복 횟수를 줄이는 방식으로 동작한다는 점을 고려하면, Claude Code의 Code Mode도 비슷한 효과를 노린 것으로 보입니다.

**여러 도구를 연쇄적으로 호출하는 복잡한 작업에서 매번 모델에게 되돌아가는 왕복 지연이나 토큰 비용이 부담스러웠다면, [공식 문서](https://code.claude.com/docs/en/code-mode)를 보고 이 실험 기능을 켜볼 만합니다. 다만 아직 실험 단계이니 중요한 워크플로에 바로 적용하기보다는 영향이 적은 작업에서 먼저 동작을 확인하는 편이 안전합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

## 개발자 워크플로우 팁

### 서브에이전트 진행 상황 요약이 부담스럽다면 `CLAUDE_CODE_DISABLE_AGENT_PROGRESS_SUMMARIES`로 끌 수 있습니다 (v2.1.323)

**2.1.318부터 동작은 하고 있었지만 이번에 처음 문서화된 이 환경변수를 `1`로 설정하면, 서브에이전트의 진행 상황을 요약하는 동작과 그 요약을 쓰기 위한 별도 요청 자체가 꺼집니다.**

```bash
# 서브에이전트 진행 상황 요약과 그 요청을 끄고 싶을 때
export CLAUDE_CODE_DISABLE_AGENT_PROGRESS_SUMMARIES=1
```

**여러 서브에이전트를 동시에 띄워 작업하면서 진행 상황 요약 때문에 생기는 추가 요청과 토큰 비용이 아깝다고 느꼈다면, 이 환경변수로 요약 기능 자체를 꺼서 비용을 아낄 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### 낯선 모델 ID의 컨텍스트 창 추정치가 200K에서 1M으로 바뀌어, 서드파티 모델을 쓸 때는 함정이 될 수 있습니다 (v2.1.323)

**Claude Code가 인식하지 못하는 모델 ID로 세션을 열면, 이제 컨텍스트 창을 200K가 아니라 1M 토큰으로 가정합니다.** 실제로는 더 작은 컨텍스트 창을 가진 서드파티 모델을 LLM 게이트웨이 뒤에서 쓰고 있다면, Claude Code는 실제보다 훨씬 큰 창이 남아 있다고 착각해 압축 시점을 놓치고, 세션이 꽉 찬 뒤로는 `/clear` 전까지 매 턴이 계속 실패할 수 있습니다.

```bash
# 이전처럼 200K로 고정해서 쓰고 싶을 때
export CLAUDE_CODE_DISABLE_1M_CONTEXT=1
```

**Claude 외의 모델을 게이트웨이로 연결해 Claude Code를 쓰고 있고 그 모델의 실제 컨텍스트 창이 1M보다 작다면, v2.1.323 업그레이드 뒤 세션이 가득 차기 전에 `/autocompact`로 미리 압축하거나 위 환경변수로 이전 동작을 선택해 두는 편이 안전합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### Claude Code 내부의 git·ripgrep 호출이 로그인 토큰 없이 실행되도록 바뀌어, 일부 git hook이 동작하지 않을 수 있습니다 (v2.1.323)

**Claude Code 자신이 내부적으로 실행하는 ripgrep과 대부분의 git 명령이 이제 대부분의 로그인 토큰·API 키 없이 실행됩니다.** 그 결과 이런 내부 git 명령 아래에서 돌아가는 credential helper나 git hook이 지금까지 Claude Code의 로그인 정보를 활용했다면, 이제는 그 정보를 찾지 못합니다.

**git hook이나 credential helper를 커스터마이즈해 Claude Code의 세션 토큰에 의존하는 자동화를 만들어 뒀다면, v2.1.323부터는 그 토큰에 더 이상 접근할 수 없다는 점을 염두에 두고 동작을 다시 확인해볼 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### `plugin.json`의 `engines["claude-code"]` 필드로 플러그인 버전 호환성이 강제됩니다 (v2.1.323)

**플러그인이 `plugin.json`에 지원하는 Claude Code 버전 범위를 `engines["claude-code"]`로 선언하면, 그 범위 밖의 Claude Code에는 설치·업데이트·로드되지 않고, 설치와 업데이트는 그 범위에 맞는 가장 최신 버전을 고릅니다.** 지금까지는 플러그인이 특정 Claude Code 버전에서만 동작하도록 설계됐어도 이를 강제할 방법이 없어, 호환되지 않는 버전에서 설치된 뒤 알 수 없는 오류로 이어지는 경우가 있었습니다. 같은 릴리스에서 `claude plugin validate`도 플러그인의 TypeScript hooks 모듈에 타입 검사를 추가해, `--strict` 옵션으로 실행하면 이런 문제를 미리 걸러낼 수 있습니다.

**Claude Code용 플러그인을 만들어 배포하고 있다면, `plugin.json`에 `engines["claude-code"]`로 지원 버전 범위를 명시해 사용자가 호환되지 않는 버전에서 플러그인을 설치해 겪는 오류를 미리 막을 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)
