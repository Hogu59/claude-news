### Claude Fable 5.2·Mythos 5.2가 정식 공개됐고, 과학 연구 전용 모델 Mythos가 처음 등장했습니다 (11/11)

**지난 11/10 브리핑에서는 v2.1.321이 Fable 5.2를 기본 Fable 모델로 추가하고 Artificial Analysis 지능 지수에서 65점을 받았다는 소식만 다뤘는데, Anthropic이 직접 공개한 공식 발표에는 그보다 훨씬 구체적인 내용과 처음 소개되는 Mythos 5.2가 담겨 있습니다.** 두 모델은 같은 기반 모델에서 나왔지만 접근 범위가 다릅니다. Fable 5.2는 사이버보안·생물학 안전장치를 갖추고 일반에 공개됐고, Mythos 5.2는 보안·생명과학 연구를 하는 검증된 기관에만 제공됩니다. Anthropic은 대부분의 코딩·지식 작업은 Opus 5.5로 시작하고, 복잡도가 높은 작업에만 Fable·Mythos로 전환하라고 권장합니다.

```bash
# 가격: 입력 100만 토큰당 8달러, 출력 100만 토큰당 40달러 (5.1보다 낮음)
# fast mode: 가격 2배(입력 16달러/출력 80달러)로 최대 2.5배 빠른 토큰 생성
/model claude-fable-5-2
```

Anthropic은 Fable 5.2 에이전트가 약 30시간 만에 Fermat의 마지막 정리를 Lean으로 형식화했다고 밝혔는데, 이는 전담 하네스와 사람의 지도가 필요했던 이전 내부 시도의 11일에서 크게 줄어든 것입니다. 또 1,000개가 넘는 서브에이전트를 8일간 조율해 운영체제 시제품을 만든 사례, 한 문단짜리 요청만으로 완성한 전자제품 3종이 전기적 수정 없이 바로 동작한 사례도 소개합니다. Mythos 5.2는 아데노연관바이러스(AAV) 캡시드 구조 예측 방법을 개발해 34개 중 28개 사례를 정확히 모델링했습니다.

**복잡한 수학 증명, 과학 연구, 하드웨어 설계처럼 깊은 추론이 필요한 작업에 Claude를 쓰고 있다면, 모든 작업을 Fable로 돌리기보다 Opus 5.5로 먼저 시도하고 난이도가 높은 작업만 Fable·Mythos로 넘기는 Anthropic의 권장 순서를 따라볼 만합니다.** [Anthropic 공식 발표](https://www.anthropic.com/claude-fable-and-mythos-5-2) · [GeekNews](https://news.hada.io/topic?id=36896)

### Claude Whiteboards·Sheets가 베타로 추가됐고, Claude Data가 정식 출시됐습니다 (11/11)

**팀 협업 보드 Claude Whiteboards와 스프레드시트 Claude Sheets가 베타로 공개됐고, 10월에 베타로 시작했던 Claude Dashboards가 Claude Data로 정식 출시됐습니다.** Whiteboards는 Claude와 팀원이 실시간으로 함께 쓰는 보드로, 러프한 계획을 담당자·일정이 붙은 타임라인으로 바꾸거나 회의록에서 할 일을 뽑아낼 수 있고, 완성한 보드는 문서·프레젠테이션으로 바꾸거나 Lucid·Miro·Vani by Zoho로 내보낼 수 있습니다. Sheets는 프롬프트로 탭·수식·서식·드롭다운이 있는 스프레드시트를 만들고 Claude가 바꾼 셀을 표시해 변경 추적이 가능하며, 완전한 기능이 필요하면 .xlsx·CSV로 내보내면 됩니다. Data는 Redshift·BigQuery·ClickHouse 같은 데이터 소스에 질문할 수 있고, 팀이 공통 지표 정의를 인증하는 certified queries(베타), 승인된 조회 결과만 보여주는 live sharing(베타) 같은 기능이 추가됐습니다.

```text
Team 플랜         → 세 기능 모두 기본 켜짐
Enterprise 플랜   → Whiteboards·Sheets는 기본 꺼짐, Data는 11/19부터 기본 켜짐
설정 변경 위치     → Organization settings > Artifacts
```

**조직 차원에서 Claude를 쓰면서 화이트보드나 스프레드시트, 데이터 분석을 각각 다른 SaaS로 넘나들고 있었다면, 이번 공개로 가벼운 작업은 Claude 안에서 바로 끝내고 본격적인 편집이 필요할 때만 Lucid·Miro·엑셀 같은 전문 도구로 넘기는 흐름을 만들어볼 만합니다.** [Claude 공식 소개](https://claude.com/resources/articles/sheets-whiteboards-data) · [GeekNews](https://news.hada.io/topic?id=36958)

### GoogleChrome의 modern-web-guidance 스킬로 Claude Code의 평가 통과율을 57%에서 88%로 끌어올린 사례입니다 (11/11)

**이 스킬은 코딩 에이전트가 학습 데이터에 쌓인 낡은 JavaScript 패턴 대신 최신 웹 플랫폼 기능을 쓰도록, 약 250개 웹 기능과 203개 활용 사례를 담은 가이드를 CLI로 검색해 컨텍스트에 넣어줍니다.** 네트워크 호출이나 API 키 없이 오프라인 임베딩과 BM25로 검색하며, Baseline 데이터로 브라우저 지원 현황에 맞춰 대체 구현을 제안합니다. Playwright 채점기로 가이드 사용 전후를 비교한 결과, Claude Code의 통과율은 57%에서 88%로, Codex CLI는 54%에서 82%로, Antigravity CLI는 58%에서 94%로 올랐습니다.

```bash
# 프로젝트에 modern-web-guidance 스킬 설치
npx modern-web-guidance
```

**Claude Code가 오래된 폴리필이나 불필요하게 무거운 JavaScript를 짜는 것이 신경 쓰였다면, 이 스킬을 설치해 최신 CSS·DOM·접근성 기능으로 먼저 유도해보고 실제로 통과율이 올라가는지 직접 확인해볼 만합니다.** [GeekNews](https://news.hada.io/topic?id=36964)

### 커뮤니티 skill을 프로젝트에 들일 때는 keep·bind·rewrite·drop·review로 판단 근거를 남기세요 (11/10)

**GitHub에서 가져온 Claude Code·Codex skill은 원작자의 프로젝트를 기준으로 쓰여 있어 내 프로젝트에 없는 도구를 요구하거나 테스트 명령이 달라 그대로 쓰기 어려운 경우가 많은데, skilladopt는 문단마다 keep(유지)·bind(연결)·rewrite(재작성)·drop(삭제)·review(검토 필요) 판단과 그 근거를 기록해 이 문제를 풉니다.** 프로젝트가 바뀌면 영향받은 줄만 짚어주고, skill 안의 파일은 실행하지 않고 고정된 커밋만 읽으며, 판단을 맡는 에이전트는 읽기 전용 샌드박스에서 돌아갑니다.

```bash
npx skilladopt setup
npx skilladopt anthropics/skills frontend-design
npx skilladopt impact   # 프로젝트 변경 후 다시 확인할 줄만 보기
```

**다른 사람이 만든 skill을 손으로 고쳐 쓰다가 팀원이 테스트 명령이나 규칙을 바꿀 때마다 어느 줄을 다시 봐야 할지 몰라 헤맸다면, 이 도구로 판단 근거와 영향받는 줄을 추적 가능하게 만들어볼 만합니다.** [GeekNews](https://news.hada.io/topic?id=36942)

## 생태계 & 플러그인

### Show GN: Herdr CKD — Claude Code용 MCP 도구 13종을 포함한 오픈소스 AI 코딩 오케스트레이터 (11/11)

**코딩 에이전트가 빌드 오류나 빠진 요구사항이 남아 있는데도 작업을 완료했다고 선언하는 문제를, 프롬프트 지시가 아니라 물리적인 권한 분리와 git worktree 격리로 막는 오케스트레이터입니다.** 파일을 직접 고치거나 명령을 실행할 수 없는 고정된 조정자(Core C)가 작업을 배정하고 최종 PASS·FAIL을 판정하며, 구현 스레드(A1~An)는 각자의 worktree에서 작업하고, 감사 스레드(B1~Bn)는 구현자의 설명이 아니라 `git status`·`git diff --stat` 결과만으로 읽기 전용 검토를 합니다. 감사자가 구현자의 자기 설명을 보지 않는 구조라 자기 정당화로 통과되는 경우를 줄이는 것이 핵심이며, 조정자는 Claude 같은 클라우드 모델을, 구현·감사 스레드는 LM Studio·Ollama의 로컬 모델을 섞어 쓰는 하이브리드 라우팅도 지원합니다.

```text
Core C(조정자, 읽기·쓰기 불가) → A1~An(worktree별 구현) → B1~Bn(git diff 기반 읽기 전용 감사) → PASS/FAIL
```

**Claude Code에 accept-edits나 auto mode를 걸어두고 여러 에이전트를 동시에 돌리면서, 에이전트의 "다 됐다"는 보고를 그대로 믿기 어려웠다면, 이 구조로 구현과 감사를 물리적으로 분리해볼 만합니다.** [GeekNews](https://news.hada.io/topic?id=36946)

**Val Town은 11/10부터 과금을 멈추고, 12/10에는 읽기 전용으로 전환되며(sqlite·blob storage 제외), 2027/1/10에 모든 서비스가 완전히 종료됩니다.** 2027년 2월 1일에는 소스가 오픈소스로 공개될 예정입니다. 운영사는 Cloudflare·Vercel·Netlify·Render로의 마이그레이션 가이드를 함께 공개했는데, 현재의 LLM이 이런 마이그레이션 작업을 잘 처리한다는 점을 전제로 사용자들이 AI의 도움을 받아 앱을 옮길 것으로 기대한다고 밝혔습니다.

**Val Town으로 만든 앱을 운영하고 있다면 2027년 1월 10일 전에 마이그레이션을 마쳐야 하며, 이 기회에 Claude Code로 다른 호스팅 환경으로의 이전 작업 자체를 자동화해보는 것도 고려할 만합니다.** [GeekNews](https://news.hada.io/topic?id=36961)
