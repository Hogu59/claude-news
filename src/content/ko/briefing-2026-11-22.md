## 개발자 워크플로우 팁

### Anthropic이 상시 작동(always-on) 에이전트를 짜는 여섯 가지 구성 요소를 공개했습니다 (11/13)

**지금까지 에이전트는 대부분 요청 한 번에 응답 한 번으로 끝나는 세션 단위로 동작했는데, Anthropic이 공식 가이드에서 세션이 끝나도 맥락을 유지하며 사용자 감독 없이 이벤트가 생길 때마다 움직이는 "상시 작동 에이전트"를 짜는 구조를 공개했습니다.** 핵심 에이전트 루프 자체는 기존과 같고, 그 주변 구조가 상시 작동 경험을 만든다고 설명합니다. 이벤트 수신함(사용자 메시지·웹훅·예약 작업을 영속 큐에 쌓고, 수신함당 워커를 하나로 제한해 중복 실행을 막음), 타이머(후속 확인과 반복 일정을 예약), 메모리(사용자 지시·메모·과거 메시지·작업 진행 상황 네 유형을 워커가 사라져도 남도록 영속 저장), 컨텍스트 관리(길어지면 압축하거나 새 세션을 시작하되 중요한 내용은 미리 메모리에 저장), 권한(무인 실행이 사용자 권한으로 움직이므로 자격 증명은 외부 프록시가 주입하고, 승인이 필요한 호출은 세션을 보류한 채 답을 기다림), 발신함(알림이 너무 잦으면 소음이 되므로 처음엔 조용하게 시작)이 여섯 구성 요소입니다. 배경으로는 장기 코딩 벤치마크에서 Opus 5.5가 해결 작업당 비용을 Opus 5보다 78% 낮췄다는 수치를 들어, 이런 구현이 이제야 비용 면에서 현실적이 됐다고 짚습니다.

```text
이벤트(사용자 메시지·웹훅·예약 작업) → 영속 큐에 쌓임 → 수신함당 워커 1개가 처리
  → 메모리(지시·메모·과거 메시지·진행 상황)를 참조해 실행
  → 승인이 필요한 호출은 세션을 보류하고 답을 기다림
  → 타이머가 후속 확인을 예약하거나 발신함으로 결과 전달 → 다음 이벤트까지 대기
```

**세션 사이 맥락을 유지하며 스스로 움직이는 자동화 에이전트를 설계하려 한다면, 이벤트를 영속 큐에 쌓고 수신함당 워커를 하나로 제한해 중복·덮어쓰기를 막는 구조와, 무인 권한의 자격 증명을 외부 프록시가 주입하게 해 위험을 분리하는 설계를 그대로 참고할 만합니다.** [Anthropic 공식 가이드](https://claude.com/ko/resources/articles/building-always-on-agents) · [GeekNews](https://news.hada.io/topic?id=37550)

### VS Code에 실행 중인 워크플로를 한눈에 보여주는 `/workflows` 명령이 추가됐습니다 (v2.1.330)

**지금까지 VS Code에서 여러 워크플로를 동시에 돌리면 어떤 에이전트가 어떤 작업을 진행 중인지 한눈에 확인하기 어려웠는데, 이번 릴리스부터 `/workflows` 명령으로 실행 중인 워크플로를 보여주는 에이전트 맵을 바로 열 수 있습니다.**

```bash
# VS Code에서 실행 중인 워크플로를 한눈에 보고 싶을 때
/workflows
```

**VS Code로 여러 에이전트·워크플로를 동시에 돌리면서 진행 상황을 추적하기 번거로웠다면, v2.1.330부터는 `/workflows` 하나로 에이전트 맵을 띄워 확인해볼 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

## 알아두면 좋은 소소한 변경사항

- **WebFetch가 일부 페이지에서 몇 분씩 세션을 멈추거나 빈 결과를 돌려주던 문제가 수정**됐습니다.
