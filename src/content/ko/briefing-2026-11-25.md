## 주요 신규 기능 & 실전 활용

### Claude Ship — PR 리뷰·수정·승인까지 맡기는 베타 기능이 공개됐습니다 (11/23)

**지금까지 Claude Code로 코드를 짜고 나면 PR을 올리고 리뷰를 받고 CI 실패와 머지 충돌을 직접 처리하는 과정은 여전히 사람이 챙겨야 했는데, Anthropic이 공식 블로그에서 이 흐름 전체를 맡기는 베타 기능 Claude Ship을 공개했습니다.** Code Review(정식 출시)는 PR을 여러 관점에서 검토하고 발견한 내용을 검증·분류해 PR에 남기며 저장소별로 Quick·Standard·Deep 리뷰 강도를 고를 수 있습니다. PR Steward(베타)는 실패한 CI, 머지 충돌, 리뷰 피드백에 대응해 PR을 계속 통과 상태로 유지하면서 푸시마다 무엇을 바꿨고 어떻게 되돌릴 수 있는지 댓글로 남기지만, 스스로 승인하거나 머지하지는 않습니다. Claude Approvals(베타)는 저장소에 파일로 적어둔 승인 정책에 따라 사소한 변경은 자동 승인하고 특정 경우에는 사람의 서명을 요구하며, Anthropic은 처음에는 관찰 전용 모드로 시작한 뒤 브랜치 보호 규칙에 적용하라고 권장합니다. Team·Enterprise 플랜에서 GitHub 저장소에 쓸 수 있고, Zero Data Retention·HIPAA 설정·고객 관리 암호화 키를 쓰는 조직에는 아직 제공되지 않습니다.

```bash
# 개발자가 변경을 만든 뒤
/ship
# → Claude가 변경을 푸시하고 PR을 연 뒤, 스스로 리뷰하고
#   피드백과 실패한 체크에 대응합니다 (머지 여부는 권한·브랜치 규칙에 따름)
```

**PR을 올린 뒤에도 CI 실패나 리뷰 피드백을 직접 챙기느라 맥락 전환이 잦았다면, Team·Enterprise 플랜에서 GitHub 저장소를 쓰는 경우 `/ship` 한 번으로 리뷰부터 수정까지 맡기고, 자동 승인 범위는 관찰 전용 모드로 먼저 검증해볼 만합니다.** [Anthropic 공식 블로그](https://claude.com/resources/articles/introducing-claude-ship)

### MCP 서버가 skill 배포·백그라운드 작업·중간 확인 요청·파일 업로드까지 지원하도록 확장됐습니다 (11/24)

**지금까지 MCP 서버는 주로 Claude가 호출하는 도구(tool)만 제공했는데, Anthropic이 공식 블로그에서 서버가 Claude를 "다른 에이전트처럼" 다룰 수 있도록 네 가지 기능을 공개했습니다.** Skills over MCP(공개 베타)는 서버가 다단계 작업 가이드나 조직별 플레이북을 skill로 함께 배포해, Claude가 필요할 때만 불러오고 서버 업데이트에 따라 자동으로 최신화됩니다. Tasks(정식 출시)는 시간이 오래 걸리는 작업이나 전체 에이전트 루프를 서버가 백그라운드에서 돌리는 동안 Claude가 다른 일을 계속하게 해주고, Elicitation(정식 출시)은 서버가 호출 중간에 멈춰 폼이나 링크로 사용자 확인(비용 승인, 위험한 작업 승인 등)을 받은 뒤 이어갈 수 있게 합니다. 파일 업로드(곧 출시)는 PDF·스프레드시트·이미지를 컨텍스트 창을 거치지 않고 서버로 바로 보냅니다. Skills over MCP는 Pro·Max·Ultra에서 기본 켜짐이고 Team은 관리자가 켜야 하며 Enterprise는 곧 지원됩니다.

**MCP 서버를 직접 운영하거나 Claude Code에 여러 MCP 서버를 연결해 쓰고 있다면, 서버 쪽에 skill을 함께 배포해 별도 설치 없이 가이드를 전달하거나, 비용 승인처럼 위험한 동작 앞에 Elicitation으로 확인 단계를 넣는 설계를 검토해볼 만합니다.** [Anthropic 공식 블로그](https://claude.com/resources/articles/skills-over-mcp-tasks-and-more)

### Claude Code를 조직 전체에 안전하게 확장하는 방법을 정리한 엔터프라이즈 가이드가 공개됐습니다 (11/23)

**지금까지 보안·기술 리더가 Claude Code를 조직 규모로 확장할 때 어떤 통제를 어디에 둬야 하는지는 각자 따로 정리해야 했는데, Anthropic이 공식 가이드에서 위험을 없애는 대신 "눈에 보이고 한계가 분명한" 상태로 만드는 3단계 통제 구조를 제시했습니다.** 판단 레이어(정렬 학습, 프롬프트 인젝션 탐지, 의도와 행동을 대조하는 auto 모드 분류기, 되돌리기 어려운 작업에 대한 사람의 승인)와, 고정 경계 레이어(선순위 deny 규칙, Bash 명령을 토큰 단위로 쪼개 검사하는 분석, 커밋에 포함된 비밀 정보를 막는 PreToolUse 훅, OS 수준으로 격리하는 로컬 샌드박스, 매 작업마다 새로 뜨는 디스포저블 VM인 클라우드 세션), 정책 레이어(기본값을 확장 가능한 baseline과 중앙에서 강제하는 locked로 나누고, `allowManagedDomainsOnly`·`allowManagedMcpServersOnly`·`disableBypassPermissionsMode` 같은 설정으로 잠그는 방식)로 구성됩니다. 자격 증명 유출, 검증되지 않은 MCP 서버·플러그인·skill·`CLAUDE.md`, 데이터 유출, 프롬프트 인젝션을 핵심 위험으로 짚으며, 민감도가 낮은 저장소에서 2주 파일럿을 돌려 분류기 차단·샌드박스 차단·거부된 네트워크 접근을 검토하라고 권장합니다.

```text
판단 레이어(정렬 학습·인젝션 탐지·auto 모드 분류기·사람 승인)
  → 고정 경계 레이어(권한 규칙·Bash 분석·훅·로컬 샌드박스·클라우드 세션)
  → 정책 레이어(baseline vs locked 설정, 중앙 강제)
  → 감사 가능성(세션 트랜스크립트·OpenTelemetry·감사 API)
```

**조직 차원에서 Claude Code 도입 범위를 넓히면서 어떤 통제를 먼저 잠그고 어떤 건 개발자 재량에 맡겨야 할지 고민하고 있었다면, 민감도 낮은 저장소에서 2주 파일럿을 돌려 분류기·샌드박스·네트워크 차단 로그부터 검토하는 이 가이드의 출발점을 그대로 따라볼 만합니다.** [Anthropic 공식 가이드](https://claude.com/resources/articles/enterprise-guide-to-securing-coding-agents)

### 평가(eval)는 AI 엔지니어링에서 가장 과소평가된 역량이라는 실전 기법이 공개됐습니다 (11/24)

**지금까지 모델이나 프롬프트를 바꾼 뒤 개선됐는지는 지표 하나로 판단하기 쉬웠는데, 이 글은 지표보다 먼저 프로덕션의 실패 사례 100개 이상을 직접 읽고 분류하는 데서 시작해야 한다고 강조합니다.** 프롬프트는 버려지고 모델은 몇 달마다 바뀌지만, 쌓인 실패 사례 라이브러리는 그 가치가 계속 남는다는 것이 핵심 논거입니다. 스키마 검증·정규식·테스트용 DB에 대한 SQL 실행처럼 코드로 확인 가능한 항목은 결정적 검사로 먼저 거르고, 코드로 확인할 수 없는 부분만 LLM 판정에 맡기라고 권하며, RAG는 검색(recall@k, MRR, nDCG)과 생성(근거 충실도)을 따로 측정해야 어느 단계가 실패하는지 드러난다고 짚습니다. 에이전트는 모든 도구 호출을 로그로 남겨 정밀도·재현율·인자 정확도·단계 수를 확인하고(3단계면 될 일을 14번 호출한 사례 언급), 매 실행이 성공해야 하는 pass^k는 매 실행 80% 성공률에서도 5회 연속 성공률이 약 33%에 그친다는 점을 수치로 제시합니다. LLM 판정을 쓸 때는 100개 이상을 직접 라벨링해 train·dev·test로 나누고, 100개 샘플 80% 정확도의 95% 신뢰구간이 ±8포인트 정도라는 점을 들어 83%로의 변화가 잡음일 수 있다고 경고합니다.

**Claude Code나 자체 에이전트의 성능 개선을 지표 하나로 판단하고 있었다면, 실패 사례부터 쌓아 결정적 검사와 LLM 판정을 구분하고, pass@k가 아니라 pass^k로 신뢰성을 따지며, 작은 샘플의 정확도 차이를 신뢰구간 없이 개선으로 단정하지 않는 이 글의 방법론을 그대로 적용해볼 만합니다.** [GeekNews](https://news.hada.io/topic?id=37745)

### Zero Data Retention을 적용한 Enterprise Frontier Safeguards가 공개 베타로 전환됐습니다 (11/23)

**지금까지 엔터프라이즈 고객이 안전장치와 데이터 비보관(Zero Data Retention)을 동시에 받으려면 비공개 베타 신청을 거쳐야 했는데, Anthropic이 공식 블로그에서 헬스케어·금융·법률 분야를 포함한 100곳 넘는 비공개 베타 고객을 거쳐 공개 베타로 전환했다고 밝혔습니다.** 기존 ZDR이 요청 하나 단위로만 위험을 막았다면, Enterprise Frontier Safeguards(EFS)는 여러 요청에 걸쳐 쪼개진 악용 패턴까지 탐지하면서도 고객이 직접 관리하는 클라우드 스토리지(Amazon S3 또는 Google Cloud Storage)에 모니터링 데이터를 저장해 Anthropic이나 클라우드 제공사가 데이터를 보관하지 않는다고 설명합니다. Claude Platform, AWS 위의 Claude Platform, Amazon Bedrock, Google Cloud에서 쓸 수 있고 Microsoft Foundry 지원은 "곧 제공"으로 안내됐습니다. 위험이 감지되면 고객의 클라우드 스토리지나 API에서 읽을 수 있는 Safety Case가 생성되는데, 여기에는 실제 입력·출력 내용은 포함되지 않고 Anthropic 쪽의 사람이 직접 들여다보는 검토 절차도 없다고 강조합니다.

**헬스케어·금융·법률처럼 민감한 데이터를 다루면서 안전장치 때문에 데이터 비보관 혜택을 포기해야 했다면, 공개 베타로 전환된 EFS가 고객 관리 스토리지에 비용을 지불하는 대신 둘을 동시에 받을 수 있는 선택지가 됐다는 점을 검토해볼 만하며, Microsoft Foundry 환경이라면 아직 지원 전이라는 점은 감안해야 합니다.** [Anthropic 공식 블로그](https://claude.com/resources/articles/zero-data-retention-with-enterprise-frontier-safeguards)
