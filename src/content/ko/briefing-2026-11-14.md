## 개발자 워크플로우 팁

### 샌드박스로 실행되는 Bash 명령이 이제 기본적으로 권한 확인을 거칩니다 (v2.1.325)

**지금까지는 샌드박스 안에서 실행되는 Bash 명령이 승인 없이 곧바로 실행됐는데, 이 버전부터는 그런 명령도 일반적인 권한 확인 흐름을 따르도록 바뀌었습니다.** 샌드박스가 명령의 영향 범위를 제한해주는 것은 그대로지만, 그 안에서 실행되는 것만으로 더 이상 승인을 자동으로 건너뛰지는 않습니다. 이전처럼 프롬프트 없이 계속 실행하고 싶다면 설정을 바꿔야 합니다.

```json
{
  "sandbox": {
    "autoAllowBashIfSandboxed": true
  }
}
```

**managed settings로 샌드박스를 강제로 켜둔 조직이라면, 이 값을 가장 우선순위가 높은 managed 설정 소스에 넣어야 명령이 계속 프롬프트 없이 실행됩니다.**

**샌드박스 모드로 Claude Code를 운영하면서 승인 없이 명령이 바로 실행되는 것을 전제로 워크플로를 짜뒀다면, v2.1.325 업그레이드 뒤 갑자기 권한 프롬프트가 늘어난 이유가 바로 이 변경 때문이라는 점을 알아두고, 필요한 경우에만 위 설정으로 이전 동작을 되돌릴 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### 신뢰하지 않는 저장소의 읽기 전용 git 명령도 이제 확인을 거칩니다 (v2.1.325)

**프로젝트 자신의 저장소도 아니고 따로 신뢰하지도 않은 저장소에서는, 읽기 전용 git 명령조차 이제 먼저 확인을 묻습니다.** 이런 저장소를 프롬프트 없이 계속 다루고 싶다면, `additionalDirectories` 설정이 아니라 `--add-dir`로 그 폴더를 직접 이름 붙여 넘겨야 합니다.

```bash
# 신뢰하지 않은 다른 저장소의 git 명령을 프롬프트 없이 실행하고 싶을 때
claude --add-dir ../other-repo
```

**모노레포 밖의 다른 저장소를 함께 열어두고 git log나 git diff 같은 읍기 명령을 수시로 돌리고 있었다면, v2.1.325부터는 그 저장소를 `--add-dir`로 명시해야 매번 뜨는 확인 프롬프트를 피할 수 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### 예약된 작업·`/loop`이 unattended skill을 실행하기 전에 이제 확인을 묻습니다 (v2.1.325)

**`allowed-tools`나 hooks를 선언한 skill을 scheduled task나 `/loop`이 실행하려 하면, 이제 먼저 확인을 묻도록 바뀌었습니다.** 사람 없이 무인으로 계속 돌리고 싶다면 그 skill을 명시적으로 허용 목록에 추가해야 합니다.

```text
permissions.allow에 Skill(스킬이름) 추가 → 확인 없이 무인 실행
```

**scheduled task나 self-paced `/loop`에 hooks가 있는 skill을 연결해 밤새 돌려두고 있었다면, v2.1.325 업그레이드 뒤 이 설정을 미리 추가해두지 않으면 다음 실행에서 확인을 기다리다 멈춰 있을 수 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

## 알아두면 좋은 소소한 변경사항

아래는 모두 **v2.1.325**(11/13) 항목입니다.

- **Claude Code on the web(클라우드 세션)의 MCP 도구 설명 글자 제한이 4,096자에서 16,384자로 늘어, 다른 Claude Code 세션과 같아졌습니다.**
- **Claude가 자신이 만든 artifact나 그 데이터를 읽을 때 더 이상 권한을 묻지 않도록 바뀌었습니다.**
- **`/cost`, `$.session.usage()`, `--max-budget-usd` 같은 비용·토큰 지표가 mod의 `$.model.complete`·`$.model.classify` 호출도 함께 집계하도록 바뀌었습니다.**
- **VS Code에 API 키를 만들지 않는 Console 로그인 방식이 추가**됐습니다.
- **`claude -p`가 로그인 캐시 데이터가 없을 때 그 데이터를 기다린 뒤 첫 요청을 보내도록 바뀌어, 깨끗한 환경에서의 첫 실행이 몇 초 늦게 시작될 수 있습니다.**
