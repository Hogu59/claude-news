## 주요 신규 기능 & 실전 활용

### MCP 서버의 작업(task)을 터미널에서 자동으로 백그라운드 처리합니다 (v2.1.319)

**MCP 서버가 도구 호출을 작업(task)으로 실행하면, Claude Code가 터미널에서도 그 작업을 바로 백그라운드로 옮기고 끝나면 결과를 Claude에게 알려주도록 바뀌었습니다.** 지금까지는 오래 걸리는 MCP 작업이 끝날 때까지 턴 전체가 멈춰 있어야 하는 경우가 있었습니다. 작업이 끝나기 전에 Claude가 직접 결과를 기다리게 하고 싶다면 환경변수로 이전 동작을 유지할 수 있습니다.

```bash
# MCP 작업을 백그라운드로 옮기지 않고 도구 호출 안에서 그대로 기다리게 함
export CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND=1
```

**오래 걸리는 MCP 작업(대용량 데이터 조회, 외부 API 배치 처리 등)을 자주 호출한다면, v2.1.319부터는 그 작업이 끝나기를 기다리는 동안 세션이 멈춰 있지 않고 다른 일을 계속할 수 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### 권한 프롬프트 대신 자동으로 거부하는 `permissions.denyInsteadOfPrompting` 설정이 추가됐습니다 (v2.1.319)

**이 설정을 켜면, 권한 프롬프트를 기다려야 하는 도구 호출이 터미널 세션·서브에이전트·팀원(teammate) 모두에서 승인 대기 없이 곧바로 거부되고 턴은 계속 진행됩니다.** 지금까지는 무인 환경이나 서브에이전트가 승인이 필요한 명령을 만나면 그 자리에서 멈춰버려, 사람이 없으면 작업 전체가 중단되는 경우가 있었습니다.

```json
{
  "permissions": {
    "denyInsteadOfPrompting": true
  }
}
```

**승인해줄 사람이 상시 대기하지 않는 백그라운드 작업이나 CI 파이프라인에서 Claude Code를 돌리고 있다면, 이 설정으로 권한이 필요한 호출을 조용히 거부하고 나머지 작업을 이어가게 만들 수 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### `/claude-api latency-optimize`로 내 Claude API 코드의 지연 구간을 찾을 수 있습니다 (v2.1.319)

**`/claude-api latency-optimize`는 내가 만든 Claude API 코드에서 사람을 기다리게 만드는 지점을 찾아내고, 직접 만든 eval을 기준으로 더 빠른 설정을 시도해봅니다.** 지금까지는 API 응답이 느리다고 느껴도 어느 호출, 어느 설정이 지연을 만드는지 직접 하나씩 바꿔가며 확인해야 하는 경우가 많았습니다.

```bash
/claude-api latency-optimize
```

**Claude API로 사용자 응답 시간이 중요한 기능을 만들고 있다면, 이 명령으로 지연 구간을 먼저 자동으로 찾아낸 뒤 그 지점부터 최적화를 시작하는 편이 효율적입니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

## 개발자 워크플로우 팁

### 애매한 사례만 Opus로 재검토해 비용을 4분의 1로 줄인 Hightouch의 사례입니다 (11/6)

**고객 기록이 같은 사람인지 판별하는 작업에서, Hightouch는 저렴한 모델 Jev가 먼저 모든 사례를 판단하고 신뢰도가 애매한 구간(약 30~90%)에 속한 사례만 Opus로 재검토하는 하이브리드 방식을 시험했습니다.** 쉬운 테스트에서는 전체의 22%만 Opus로 넘겨 정확도 98.8%(Opus 단독 99.0%)를 유지하면서 1,000건당 비용을 3.86달러에서 0.88달러로 줄였고, 어려운 테스트에서도 정확도 95.3%(Opus 단독 95.1%)를 유지하며 비용을 5.39달러에서 2.94달러로 줄였습니다.

```text
confidence < 30%   → 저렴한 모델의 판정을 그대로 채택
30% ≤ confidence ≤ 90% → Opus로 재검토
confidence > 90%   → 저렴한 모델의 판정을 그대로 채택
```

**분류·판별처럼 신뢰도 점수를 낼 수 있는 작업을 Claude 모델로 자동화하고 있다면, 모든 사례를 Opus로 돌리는 대신 애매한 구간만 선별해 올리는 이 방식으로 정확도를 거의 그대로 유지하면서 비용을 크게 줄여볼 만합니다.** [GeekNews](https://news.hada.io/topic?id=36725)

### Claude apps gateway 사용자라면 `/usage`에서 오늘·이번 주·이번 달 지출을 바로 확인할 수 있습니다 (v2.1.319)

**Claude apps gateway 뒤에서 작업하면서 별도 지출 한도가 없는 개발자에게, 게이트웨이가 이 버전 이상으로 돌아간다면 `/usage`에 오늘·이번 주·이번 달 지출이 함께 표시됩니다.** 지금까지는 한도가 없는 개발자는 자신이 얼마나 쓰고 있는지 확인할 방법이 마땅치 않았습니다.

```bash
/usage
```

**조직의 Claude apps gateway를 통해 Claude Code를 쓰면서 본인의 사용 추이를 직접 가늠해보고 싶었다면, 게이트웨이 버전만 맞다면 별도 설정 없이 `/usage`로 바로 확인할 수 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### `/tasks`의 "Earlier in this session" 항목으로 끝난 서브에이전트를 다시 열어 메시지를 보낼 수 있습니다 (v2.1.319)

**`/tasks`에 완료된 서브에이전트를 모아 보여주는 "Earlier in this session" 줄이 추가돼, 목록에서 사라졌거나 세션을 재시작한 뒤에도 그 서브에이전트를 다시 열어 메시지를 보낼 수 있습니다.** 지금까지는 서브에이전트가 작업을 끝내고 목록에서 빠지면, 그 결과에 대해 추가 질문을 하려 해도 다시 접근할 방법이 없었습니다.

**여러 서브에이전트를 동시에 돌리다 끝난 작업의 결과를 나중에 다시 확인하거나 추가로 물어보고 싶었던 적이 있다면, v2.1.319부터는 `/tasks`에서 그 서브에이전트를 다시 찾아 이어서 대화할 수 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

**공식 status.claude.com을 직접 확인한 결과, 11/4부터 11/7(오늘)까지 모두 "No incidents reported"로 표시돼 있으며, claude.ai·Claude API·Claude Code·Claude Console·Claude Cowork·Claude for Government 전체가 "All Systems Operational"로 정상 상태입니다.** 가장 최근 인시던트는 10/28에 해결된 Google Calendar·Gmail 커넥터 오류입니다.

**최근 며칠 사이 서비스 오류를 겪었다면 이미 모두 해소된 상태이니, 오늘 문제가 발생한다면 로컬 설정이나 네트워크 쪽을 먼저 점검해보는 것이 합리적입니다.** [Claude Status](https://status.claude.com)

### worktree 생성 시 발생하던 sandbox escape가 수정됐습니다 (v2.1.319)

**새 worktree를 만드는 과정에서 샌드박스를 벗어날 수 있는 결함이 이 버전에서 수정됐습니다.** 릴리스 노트는 구체적인 재현 경로를 공개하지 않았지만, 샌드박스는 Claude Code가 승인 없이 실행하는 명령의 영향 범위를 제한하는 핵심 안전장치이므로 이를 벗어나는 경로가 있었다는 사실 자체가 비중 있는 보안 수정입니다.

**샌드박스 모드로 Claude Code를 운영하며 worktree를 자주 만든다면, v2.1.319로 올려 이 문제가 해소된 버전을 쓰고 있는지부터 확인할 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### 조작된 환경변수 접두사로 Bash 권한 검사를 피해가던 결함이 수정됐습니다 (v2.1.319)

**명령 앞에 특정 방식으로 조작된 환경변수 접두사를 붙이면 그 명령의 일부가 권한 검사에서 가려지던 Bash 권한 우회 결함이 수정됐습니다.** 지금까지는 이런 방식으로 작성된 명령이 deny·ask 규칙의 눈을 피해 실행될 가능성이 있었습니다.

**Bash 명령에 deny·ask 규칙을 걸어 위험한 작업을 막고 있다면, v2.1.319 이전 버전에서는 환경변수 접두사를 이용한 명령이 이 방어를 우회했을 수 있다는 점을 염두에 두고 업그레이드를 서두를 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### accept-edits·auto mode에서 `sed` 명령이 권한 검사를 건너뛰던 문제가 수정됐습니다 (v2.1.319)

**accept-edits 모드와 auto mode에서 특정 형태의 `sed` 명령이 권한 검사를 건너뛸 수 있었던 문제가 수정됐습니다.** `sed`는 파일을 직접 수정할 수 있는 명령인 만큼, 이 검사가 건너뛰어지면 의도치 않은 파일 변경이 승인 없이 일어날 수 있었습니다.

**accept-edits나 auto mode로 Claude Code를 자주 돌린다면, v2.1.319로 올려 `sed` 명령에 대한 권한 검사가 제대로 동작하는 버전을 쓰고 있는지 확인해볼 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

## 알아두면 좋은 소소한 변경사항

아래는 모두 **v2.1.319**(11/6) 항목입니다.

- **`CLAUDE_CODE_DISABLE_FEATURE_FLAGS` 환경변수가 추가**돼, 텔레메트리는 끄지 않고 feature flag만 가져오지 않게 할 수 있습니다. 이때 모든 flag는 내장 기본값을 씁니다.
- **`/context`가 터미널에서 Claude에게 매 턴마다 전체 비주얼 그리드를 보내던 문제가 수정**돼, 이제 Claude는 테이블만 읽습니다.
- **안전성 검사를 받을 수 없어 작업이 거부됐는데도 `claude -p`가 auto mode에서 exit code 0으로 끝나던 문제가 수정**돼, 텍스트·JSON 출력 모두 이제 exit 1로 끝납니다.
- **권한 프롬프트가 열려 있는 동안 노트북 내용이 바뀌면 `NotebookEdit`이 잘못된 셀을 바꾸던 문제가 수정**됐습니다.
- **`/model` 모델 피커에서 오래된 모델들이 현재 모델들 뒤에 길게 나열되던 방식이 바뀌어, 이제 "More models" 행으로 따로 묶여 표시**됩니다.
- **[VSCode] 플러그인 마켓플레이스를 제거할 때 뜨는 확인창이 그 시점에 실제로 설치된 플러그인을 다시 확인하도록 개선**됐습니다.
- **[Claude Tag] Claude Tag가 연결된 Enterprise 조직의 Models admin 페이지에 Claude Tag 행이 추가**돼, 모델 기본값을 관리하는 곳으로 바로 연결됩니다.
