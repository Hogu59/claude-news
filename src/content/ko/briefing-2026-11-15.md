## 개발자 워크플로우 팁

### Anthropic이 Fable 5.2로 1,000개 에이전트 팀을 안전하게 굴린 설계를 공개했습니다 (11/14)

**Anthropic 연구팀이 정식 출시 전 Fable 5.2로 리드 에이전트 1개와 보조 에이전트 999개를 동시에 돌려, Fermat의 마지막 정리를 Lean으로 형식화하는 "토이 실험"을 28.7시간에 끝냈습니다.** 지난 9월 실험(연구자가 수십 개 에이전트를 직접 지휘하며 11일 소요)과 비교하면 출력 토큰은 3분의 1, 증명 길이는 7분의 1로 줄었습니다. 별도 협업 도구 없이 에이전트마다 자신의 git 브랜치를 쓰고, 모두가 공유하는 Postgres 데이터베이스에 리드가 10분 만에 Announce·Assign·Notes·Subtasks·Landed 다섯 개 테이블을 만들어 조율했습니다.

안전장치는 세 겹입니다. 각 에이전트는 네트워크가 없는 경량 VM에서 돌아가고 sudo는 제거됐으며 샌드박스 안에는 API 키가 들어가지 않습니다. SQL 문은 5초로 시간을 제한했고, 모든 셸 명령과 파일 수정은 실행 전에 LLM 분류기가 fail-closed 방식으로 먼저 검사했습니다. 100만 건이 넘는 도구 호출 중 차단 기준에 걸린 사례는 하나도 없었습니다.

```text
격리 VM(네트워크 없음, sudo 제거, API 키 없음)
  → SQL 5초 제한
  → 모든 셸·파일 수정 명령을 LLM 분류기가 fail-closed로 사전 검사
  → git 브랜치별 작업 + 공유 Postgres로 조율
```

**Claude Code로 여러 서브에이전트를 동시에 띄워 복잡한 작업을 맡기면서 조율 수단을 고민하고 있었다면, 거창한 오케스트레이션 도구 없이도 git 브랜치와 공유 데이터베이스만으로 충분하다는 이 설계를, 특히 승인 없이 돌리는 에이전트의 셸 명령·파일 수정을 사전에 걸러내는 fail-closed 분류기 아이디어는 그대로 참고할 만합니다.** [Anthropic 공식 블로그](https://claude.dev/blog/safely-scaling-multi-agent-teams-with-fable-5-2/) · [GeekNews](https://news.hada.io/topic?id=37159)

### 패키지를 설치하기 전에 PyPI의 새 보안 증명 신호를 확인하세요 (11/13)

**PyPI가 프로젝트 페이지에 보안 탭을 새로 만들어, 어떤 워크플로가 파일을 게시했는지와 빌드 증명이 있다면 어느 소스 커밋에서 빌드됐는지를 보여주도록 개편했습니다.** 모든 파일에 증명이 있으면 Full Provenance, 하나도 없으면 No Provenance로 표시되고, 일부 파일만 증명이 있거나 저장소·워크플로가 바뀌거나 증명이 갑자기 사라진 경우에는 경고가 뜹니다. No Provenance가 악성이라는 뜻은 아니지만, 계정 탈취나 빌드 파이프라인 침해로 패키지 내용이 바뀐 상황을 설치 전에 알아챌 수 있는 신호입니다.

**Claude Code로 MCP 서버나 의존성을 설치할 때 pip 패키지 이름만 보고 그대로 설치하고 있었다면, 이제는 PyPI 프로젝트 페이지의 보안 탭에서 출처 상태와 경고를 먼저 확인하는 습관을 들일 만합니다.** [PyPI 공식 블로그](https://blog.pypi.org/posts/2026-11-06-ui-updates-complete/) · [GeekNews](https://news.hada.io/topic?id=37178)
