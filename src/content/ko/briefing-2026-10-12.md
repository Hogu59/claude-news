## 주요 신규 기능 & 실전 활용

### `/code-review` 결과가 클라우드·SDK·IDE에서 읽기 쉬운 리스트로 출력됩니다 (v2.1.296)

**지금까지 cloud sessions, Agent SDK, IDE 통합 환경에서 `/code-review`를 실행하면 결과가 가공되지 않은 JSON 배열로 그대로 끝나버리는 경우가 있었는데, v2.1.296에서 이 문제가 수정되어 findings가 번호 매긴 리스트로 출력됩니다.** 터미널 세션에서는 원래 문제가 없었지만, CI 파이프라인이나 IDE 패널에서 리뷰 결과를 확인하던 팀에게는 가독성에 바로 영향을 주는 변경입니다.

**IDE나 SDK를 통해 `/code-review`를 돌리는 자동화를 운영하고 있다면, 이번 수정으로 리뷰 결과 파싱이나 화면 표시 로직을 따로 손볼 필요 없이 바로 깔끔한 리스트를 받게 됩니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### Edit·NotebookEdit이 비-UTF8 파일을 깨뜨리는 대신 편집을 거부합니다 (v2.1.296)

**Windows-1252, Shift-JIS, GBK처럼 UTF-8이 아닌 인코딩으로 저장된 파일을 Edit나 NotebookEdit으로 편집하면 파일 안의 모든 비-ASCII 문자가 깨져버리던 문제가 수정되어, 이제는 그런 편집 자체가 거부됩니다.** 조용히 데이터가 깨지는 대신 거부로 바뀐 것이어서, 오래된 레거시 인코딩 파일을 다루는 작업에서 눈치채지 못한 손상을 막아줍니다.

**레거시 시스템에서 넘어온 비-UTF8 인코딩 파일(과거 한글·일본어 윈도우 환경 파일 포함)을 Claude Code로 직접 편집할 일이 있다면, 거부 메시지가 뜨는 즉시 파일을 UTF-8로 먼저 변환한 뒤 다시 편집을 맡기는 것이 안전합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### PATH에 틸드(~)를 따옴표로 묶으면 확장되지 않습니다 (10/12)

**`export PATH="$PATH:~/.local/bin/"`처럼 따옴표 안에 `~`를 넣으면 셸이 이를 홈 디렉터리로 확장하지 않고 문자 그대로 PATH에 남기는데, 그 결과 이 항목은 홈 디렉터리가 아니라 현재 작업 디렉터리를 기준으로 한 `./~/.local/bin/` 경로를 가리키게 됩니다.** 평소에는 조용히 무시되다가, 마침 그 디렉터리 이름의 폴더가 현재 위치에 있을 때만 예기치 않게 동작해 디버깅이 까다로워지는 함정입니다.

**Claude Code에게 셸 설정 스크립트나 PATH 관련 환경변수 작업을 맡길 때, `~`가 들어간 경로는 따옴표 밖에 두거나 `$HOME`으로 바꿔 쓰도록 지시해두면 이런 식으로 조용히 깨지는 PATH 항목을 사전에 막을 수 있습니다.** [GeekNews](https://news.hada.io/topic?id=35184)

### v2.1.296 보안 수정 — BASH_ARGV0 악용과 Windows rm -rf 권한 우회가 막혔습니다 (v2.1.296)

**v2.1.296에는 지금까지 브리핑에서 다루지 않은 권한 우회 수정 두 건이 포함돼 있습니다.** 하나는 BASH_ARGV0 셸 변수를 지정해 명령이 다른 이름으로 보이게 만든 뒤 그 변수를 실제로 사용하는 명령이 권한 프롬프트 없이 자동 승인되던 문제로, 이제는 승인을 묻도록 고쳐졌습니다. 다른 하나는 Windows Git Bash에서 bypass permissions 모드일 때 `rm -rf /c/Users/<name>`처럼 사용자 홈 폴더를 지우는 명령이 별도 확인 없이 실행되던 문제입니다.

**Bash 명령의 이름 매칭만으로 위험한 동작을 걸러내려는 가드레일을 운영하고 있거나 Windows에서 bypass permissions 모드를 쓰고 있다면, v2.1.296으로 업데이트해 이번에 막힌 두 우회 경로를 적용해두는 것이 안전합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### v2.1.296, 공유 로그에서 시크릿 마스킹이 누락되던 문제도 수정했습니다 (v2.1.296)

**키 뒤에 값이 없는 형태로, 특히 셸 문자열 안에 쓰인 JSON에서, 시크릿 리덕션이 일부 값을 가려내지 못하던 문제가 v2.1.296에서 수정됐습니다.** 공유된 transcript나 디버그 로그를 다른 사람과 주고받는 과정에서 이런 패턴의 값이 마스킹되지 않고 그대로 노출될 수 있었던 셈입니다.

**디버그 로그나 세션 transcript를 팀원이나 외부에 공유하는 일이 있다면, v2.1.296 이전 버전에서 내보낸 로그에 이 패턴의 미마스킹 값이 남아있을 가능성이 있으니 과거 공유 로그도 한 번 점검해볼 필요가 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)
