## 주요 신규 기능 & 실전 활용

### Linked billing — API 키 공유 없이 고객이 직접 결제하게 하는 베타 기능이 Claude Platform에 공개됐습니다 (11/17)

**지금까지 자사 SaaS에 Claude API를 재판매하는 플랫폼은 고객에게 API 키를 공유하거나 사용료를 직접 재청구해야 했는데, Anthropic이 공식 블로그에서 고객이 자신의 Claude Platform 조직으로 사용료를 직접 결제하게 하는 베타 기능 Linked billing을 공개했습니다.** Anthropic에 선결제 크레딧이나 인보이스로 직접 결제하는 Claude Platform 조직만 신청할 수 있고, 고객은 연동할 플랫폼을 승인하고 지출 한도를 설정하며 언제든 연동을 해지할 수 있습니다. 요청이 실행되는 위치 자체는 바뀌지 않지만, IP 허용 목록이나 암호화 키 같은 조직 단위 설정은 연동된 플랫폼의 요청에는 적용되지 않습니다. 출시 당일 ClickHouse가 자사 Agents·AI Functions의 Claude API 사용료를 고객의 기존 약정 조건으로 바로 청구하는 식으로 이 기능을 적용한 사례를 공개했습니다.

**자사 제품에 Claude API를 재판매하면서 API 키 공유나 수동 재청구 때문에 번거로웠던 플랫폼이라면, 고객이 자신의 Claude Platform 조직으로 직접 결제하게 만드는 이 베타 기능을 검토해볼 만하며, HIPAA·FERPA 적용이 필요한 고객에게는 아직 권장되지 않는다는 점은 유의해야 합니다.** [Anthropic 공식 블로그](https://claude.com/blog/linked-billing-on-claude-platform)

## 개발자 워크플로우 팁

### Claude에게 직접 chaos engineering을 맡겨 Claude Docs 출시를 검증한 사례가 공개됐습니다 (11/17)

**Anthropic 엔지니어링팀은 지난 9월 출시한 공동 문서 편집기 Claude Docs를 내놓기 전, 2주 동안 스테이징 환경에서 Claude 에이전트가 스스로 시스템에 장애를 일으키고 고치는 "chaos loop"를 돌렸다고 공식 블로그에 밝혔습니다.** 테스트 하네스가 부하 시나리오(일 1,000만 문서 생성, 연결 2만2,000개 동시 재연결 등)를 고르면 Claude가 Datadog MCP로 텔레메트리를 읽고 원인과 선택지를 제시한 뒤, 되돌리기 쉬운 수정은 직접 작성해 스테이징에 배포하고 재테스트했습니다. 스키마 변경처럼 되돌리기 어려운 결정만 사람이 승인했습니다. 이 과정에서 문서 하나가 쓰던 메모리를 약 3GB에서 180MB로 줄여 필요한 pod 수를 500개 이상에서 약 50개로 줄였고, 실제 출시 후 9월 22일까지 460만 개 이상의 문서, 약 20억 건의 요청을 처리하면서도 서버 오류는 60건, 롤백은 0회에 그쳤습니다. 스테이징에서 미리 겪은 10개 장애 시나리오 중 7개가 실제 프로덕션에서도 똑같이 발생했습니다.

```text
테스트 하네스가 부하 시나리오 선택 → Claude가 Datadog MCP로 텔레메트리 확인
  → 선택지·추천안 제시 → 되돌리기 쉬운 수정은 Claude가 작성해 스테이징 배포·재테스트
  → 스키마 변경 등 되돌리기 어려운 결정은 사람이 승인
```

**새 기능을 출시하기 전에 사람이 일일이 장애 시나리오를 설계하고 복구하는 데 시간을 쏟고 있었다면, Claude에 옵저버빌리티 MCP 서버를 연결해 실제 트래픽의 몇 배 부하와 장애를 스테이징에서 스스로 일으키고 고치게 하는 이 설계를, 특히 되돌리기 어려운 변경만 사람이 승인하도록 선을 긋는 부분을 그대로 참고할 만합니다.** [claude.dev 공식 블로그](https://claude.dev/blog/chaos-loop-claude-docs-launch/)

### `/code-review`가 버그·CLAUDE.md 위반만 보고하도록 범위가 좁아졌습니다 — 재사용·단순화는 `/simplify`로 분리 (v2.1.328)

**지금까지 `/code-review`는 버그뿐 아니라 재사용 가능한 코드, 단순화, 효율성 개선까지 한 번에 쏟아내 어떤 지적이 정말 고쳐야 할 문제인지 가려내기 번거로웠는데, 이번 릴리스부터 대부분의 모델에서 버그와 CLAUDE.md 위반만 보고하도록 범위가 좁혀졌습니다.** 재사용·단순화·효율성 개선을 보고 싶다면 별도로 `/simplify`를 실행해야 합니다. 각 발견 항목은 Important·Pre-existing·Nit 중 하나로 표시되고 요약 끝에 제안하는 수정 방법이 함께 붙으며, 문제가 없는 리뷰는 이제 "Code review found no issues."라고 말합니다.

```bash
# 버그·CLAUDE.md 위반만 보고 싶을 때
/code-review

# 재사용·단순화·효율성 개선을 따로 보고 싶을 때
/simplify
```

**`/code-review`를 돌릴 때마다 진짜 버그 지적과 스타일 제안이 뒤섞여 우선순위를 가리기 번거로웠다면, v2.1.328부터는 두 명령을 용도에 맞게 나눠 쓰는 편이 리뷰 결과를 더 빠르게 소화하는 데 도움이 됩니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### Opus 4.6·Sonnet 4.6도 Bedrock·GCP·Foundry·Claude apps 게이트웨이에서 기본적으로 auto 모드로 시작합니다 (v2.1.328)

**지금까지 auto 모드(권한 판단을 세션이 자동으로 처리하는 모드)는 주로 최신 모델에서만 기본 적용됐는데, 이번 릴리스부터 Amazon Bedrock·Google Cloud의 Agent Platform·Microsoft Foundry·Claude apps 게이트웨이에서 Opus 4.6과 Sonnet 4.6을 쓰는 세션도 추가됐습니다.** 별도로 permission 모드를 지정하지 않은 대화형 세션은 이제 이 네 플랫폼에서도 자동으로 auto 모드로 시작합니다.

```json
// 프로젝트의 .claude/settings.json 등 적용 범위에 맞는 설정 파일에 추가하면
// auto 모드로 자동 시작되는 것을 막을 수 있습니다
{
  "disableAutoMode": true
}
```

**Bedrock이나 Foundry 등에서 Opus 4.6·Sonnet 4.6을 쓰면서 permission 모드를 따로 지정하지 않고 있었다면, v2.1.328 업그레이드 뒤 세션이 조용히 auto 모드로 시작될 수 있다는 점을 감안해, 기존처럼 매 단계 확인받고 싶다면 `disableAutoMode`로 꺼둘 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)
