## 개발자 워크플로우 팁

### Code Mode가 Bedrock·GCP Agent Platform·Microsoft Foundry·AWS Claude Platform의 터미널 세션까지 확장됐습니다 (v2.1.331)

**지금까지 Code Mode(Claude가 도구 호출을 코드로 작성해 실행하는 모드)는 주로 Claude Platform의 표준 환경에서만 쓸 수 있었는데, 이번 릴리스부터 Amazon Bedrock·Google Cloud의 Agent Platform·Microsoft Foundry·AWS 위의 Claude Platform에서 열린 터미널 세션에서도 Code Mode를 쓸 수 있습니다.** 같은 릴리스에서 Code Mode 안의 `gen_ai.usage.*`·`gen_ai.response.model`·`gen_ai.operation.name` 트레이스 스팬이 OpenTelemetry로도 함께 노출되도록 개선돼, 어느 플랫폼에서 돌리든 토큰 사용량과 모델 정보를 같은 방식으로 관찰할 수 있습니다.

**조직 정책상 Bedrock이나 Foundry, AWS 위의 Claude Platform처럼 표준 환경이 아닌 곳에서 Claude Code를 운영하면서 Code Mode를 못 썼다면, v2.1.331 업그레이드 뒤에는 같은 플랫폼에서도 Code Mode의 속도와 토큰 절감 효과를 그대로 누릴 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### `claude doctor`가 API 연결 상태를 바로 보여주는 진단 항목을 갖췄습니다 (v2.1.331)

**지금까지 Claude Code가 API에 접속하지 못할 때 원인이 네트워크인지, 프록시인지, 자격 증명인지 가늠하려면 로그를 직접 뒤져야 했는데, 이번 릴리스부터 `claude doctor`에 API 연결 상태 섹션이 추가돼 API에 도달할 수 있는지, 도달하지 못했다면 HTTP 상태나 오류가 무엇인지, 혹은 왜 테스트하지 못했는지를 바로 보여줍니다.**

```bash
claude doctor
# → "API connectivity" 섹션에서 연결 가능 여부·HTTP 상태·오류 원인을 바로 확인
```

**사내 프록시나 게이트웨이를 거쳐 Claude Code를 쓰다가 연결 문제가 생기면 매번 사용자에게 로그를 요청해 원인을 추적했다면, v2.1.331부터는 `claude doctor` 한 번으로 연결 실패 지점을 먼저 좁혀볼 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### VS Code에 오류를 바로 고치는 Fix with Claude Code와 병합 충돌 해결 버튼이 추가됐습니다 (v2.1.331)

**지금까지 VS Code에서 오류나 실패한 테스트를 Claude에게 고쳐 달라고 하려면 내용을 직접 복사해 채팅창에 붙여넣어야 했는데, 이번 릴리스부터 오류·경고와 테스트 결과 보기(Test Results)·실패 테스트 미리보기의 빠른 수정(Quick Fix) 메뉴에 Fix with Claude Code가 추가돼 문제 내용이 채팅창에 바로 들어갑니다.** 병합 충돌이 있는 파일의 에디터 제목 표시줄과 소스 제어의 Merge Changes 그룹에는 Resolve Merge Conflicts 버튼도 새로 생겼습니다. 그 밖에도 변경된 파일의 우클릭 메뉴에 Add to Chat이, 노트북 셀 메뉴에 출력·오류까지 함께 붙여 넣는 Add Cell to Chat이 추가됐습니다.

**VS Code에서 에디터의 오류 밑줄이나 실패한 테스트를 볼 때마다 내용을 복사해 Claude에게 따로 설명해야 했다면, v2.1.331부터는 Quick Fix 메뉴의 Fix with Claude Code나 병합 충돌 파일의 Resolve Merge Conflicts 버튼을 눌러 바로 채팅으로 넘길 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

**지금까지 managed 설정의 `extraKnownMarketplaces`에 등록된 플러그인 마켓플레이스는 자동 업데이트 여부가 별도로 정해져 있지 않았는데, 이번 릴리스 공지에 따르면 2026년 11월 30일 이후의 릴리스부터는 이런 마켓플레이스가 기본적으로 자동 업데이트되도록 바뀝니다.** 자동 업데이트를 원하지 않는 마켓플레이스가 있다면 그 항목에 `autoUpdate: false`를 직접 설정해야 합니다.

```json
// managed 설정의 extraKnownMarketplaces 항목에서
// 특정 마켓플레이스의 자동 업데이트를 막고 싶을 때
{
  "extraKnownMarketplaces": {
    "my-marketplace": {
      "autoUpdate": false
    }
  }
}
```

**조직 차원에서 managed 설정으로 `extraKnownMarketplaces`를 등록해 플러그인 마켓플레이스를 운영하고 있다면, 11월 30일 이후 릴리스부터 의도치 않게 자동 업데이트가 켜질 수 있으니 버전을 고정해야 하는 마켓플레이스가 있다면 지금 `autoUpdate: false`를 미리 설정해둘 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

## 알아두면 좋은 소소한 변경사항

아래는 모두 **v2.1.331**(11/23) 항목 중 위에서 다루지 않은 것들입니다.

- **Claude apps 게이트웨이에 `oidc.groups_jsonpath`가 추가**돼, RFC 9535의 일부 JSONPath 문법으로 객체 목록에서 그룹 정보를 읽어올 수 있습니다.
- **압축된 응답을 중간에 끊어버리는 프록시 뒤에서 비압축 응답을 요청하는 `CLAUDE_CODE_DISABLE_RESPONSE_COMPRESSION` 환경변수가 추가**됐습니다. 다만 self-hosted runner나 Remote Control에는 아직 권장되지 않습니다.
- **`oidc.use_proxy: true`를 쓰는 환경에서 `NO_PROXY`가 설정돼 있어도 로그인 요청이 IdP 호스트명을 프록시에 그대로 전달하게 하는 `CLAUDE_GATEWAY_IDP_CONNECT_BY_HOSTNAME=1` 환경변수가 추가**됐습니다.
- **플러그인 매니페스트에 `optionalDependencies`가 추가**돼, 설치하는 플러그인이 목록에 올려둔 선택적 의존 플러그인을 개별적으로 끄거나 지울 수 있게 됐습니다.
- **로컬이나 WebSocket MCP 서버의 일부 잘못된 응답 때문에 MCP 도구 호출이 최대 30분씩 멈추던 문제가 수정**됐습니다.
- **플러그인 업데이트가 중단되거나 실패했을 때 스킬 등 일부 구성 요소가 빠진 채로 남은 플러그인 폴더가 다음에도 그대로 로드되던 문제가 수정**됐습니다 (anthropics/claude-code#102186).
