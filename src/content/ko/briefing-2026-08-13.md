## 주요 신규 기능 & 실전 활용

### 플러그인 마켓플레이스 `command` 소스 — 로컬 명령이 플러그인 디렉터리를 매 세션 재해석합니다 (v2.1.229)

**플러그인 마켓플레이스에 `command` 소스**가 추가됐습니다. **로컬 명령(예: IDE)이 플러그인 디렉터리를 출력**하면, 이 경로가 **매 세션마다 다시 해석되고 재시작 없이 바로 적용**됩니다. **`mode: "link"`**를 쓰면 그 디렉터리를 그 자리에서 그대로 사용합니다.

```jsonc
// 마켓플레이스 정의에서 command 소스를 지정하는 형태입니다.
// 로컬 명령이 stdout으로 플러그인 디렉터리 경로를 출력해야 합니다.
{
  "source": "command",
  "command": "my-ide-plugin-path",
  "mode": "link"
}
```

**8/8의 `archive` 소스(zip 하나로 오프라인 배포), 8/6의 `owner/*` 와일드카드에 이어 플러그인 배포 경로가 또 하나 늘었습니다.** 이번 것의 특징은 **정적 파일이 아니라 실행 중인 로컬 명령이 소스가 된다는 점**입니다 — IDE나 사내 도구가 **현재 활성화된 플러그인 세트를 동적으로 알려주고, 그 값이 세션마다 다시 평가**되므로, 개발 중인 플러그인을 재시작 없이 계속 바꿔가며 테스트하는 워크플로에 맞습니다. [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### VSCode 사이드바 세션 그룹 — 여러 세션을 묶어서 관리합니다 (v2.1.229)

**VSCode 확장의 사이드바에 세션 그룹**이 추가됐습니다. **우클릭으로 그룹을 만들고 이름을 바꾸고 삭제**할 수 있으며, **Cmd/Ctrl-클릭이나 Shift-클릭으로 여러 세션을 한 번에 다른 그룹으로 옮길 수** 있습니다.

**여러 세션을 동시에 띄워 두고 작업하는 습관이 있다면 바로 체감되는 변화입니다.** 지금까지는 세션이 늘어날수록 사이드바가 한 줄로 쭉 늘어서기만 했는데, **프로젝트별·작업별로 세션을 묶어 두면 어느 세션이 무슨 목적이었는지 더 빨리 찾을 수 있습니다.** 8/8의 셀프호스티드 러너, 8/9의 크로스세션 메시징처럼 **한 사람이 동시에 여러 세션을 굴리는 워크플로가 계속 늘어나는 흐름과 맞닿아 있는 UI 개선**입니다. [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### 워크플로 fan-out 스태거링 — 같은 프리픽스 형제 에이전트가 캐시를 재사용합니다 (v2.1.229)

**워크플로 fan-out에서 같은 프롬프트 프리픽스를 공유하는 형제 에이전트들의 시작 시점을 살짝 어긋나게(stagger) 만들어**, **뒤이어 시작하는 에이전트가 캐시된 프롬프트 프리픽스를 그대로 읽고 다시 비용을 치르지 않도록** 개선됐습니다. **`CLAUDE_CODE_WORKFLOW_PREFIX_STAGGER_MS=0`**으로 끌 수 있습니다.

**Workflow 도구로 수십 개 에이전트를 동시에 fan-out하는 작업을 자주 돌린다면, 별도 설정 없이도 토큰 비용이 조금 줄어들 가능성**이 있습니다. 다만 **정확히 동시에 시작해야 하는 벤치마크성 작업이라면 이 스태거링이 타이밍을 살짝 어긋나게 만들 수 있으니**, 그런 경우엔 환경변수로 꺼두는 편이 안전합니다. [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

**지금까지는 이 명령이 자동승인 규칙 안에 있으면, 강제 푸시나 커밋 수정처럼 되돌리기 어려운 작업도 별도 확인 없이 통과될 여지**가 있었습니다. 8/8 브리핑이 다룬 **인간 승인 정확도 연구(파괴 명령 누락률 11.7%)**, 8/9의 **auto mode classifier 논쟁**과 같은 방향의 수정입니다 — **되돌릴 수 없는 작업일수록, 자동승인 규칙에 걸리더라도 별도의 명시적 확인을 한 겹 더 끼워 넣는 쪽**을 택했습니다. `/commit-push-pr`을 자동승인 목록에 넣어 둔 팀이라면, **이번 변경으로 위험 플래그가 포함된 호출은 다시 확인을 거치게 된다는 점을 알아 둘 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

## 알아두면 좋은 소소한 변경사항

아래는 모두 **v2.1.229** 항목입니다.

- **긴 응답이 스트리밍 중 일부 사라지거나 터미널에 두 번 출력되던 문제**가 수정됐습니다.
- **도구 호출의 `glob`·`file_path`·`command` 값이 문자열이 아닐 때 에러 화면으로 크래시하던 문제**가 수정됐습니다 — `--resume`으로 해당 세션을 다시 열 때도 동일하게 크래시했던 부분까지 포함합니다.
- **아주 좁은 터미널 창에서 진행률 표시줄이나 마크다운 표가 렌더링될 때 RangeError로 크래시하던 문제**가 수정됐습니다 — `claude --continue`/`--resume` 시작 시점의 크래시도 함께 해결됐습니다.
- **Windows에서 확장 길이(`\\?\`)나 UNC 경로로 참조된 파일을 다루면 크래시하던 문제**가 수정됐습니다.
- **MCP OAuth가 엄격한 인증 서버에서 실패하던 문제**: 리다이렉트 URI에 `localhost` 대신 **`127.0.0.1`**을 쓰도록 바뀌었습니다.
- **대화 메시지만으로 API의 32MB 요청 한도를 넘긴 경우, 압축을 계속 재시도하던 문제**가 수정됐습니다 — 이미지·문서를 지울 게 없으면 이제 **한 번 실패하고 명확한 메시지**를 보여줍니다.
- **파일 원자적 교체 후 파일-워처 핸들이 새던 문제**와 **Windows에서 예약 작업 워처가 네트워크·가상 파일시스템에서 실패할 때 처리되지 않던 오류**가 수정됐습니다.
- **[VSCode] "문제 신고"와 `/bug`가 이제 폐지된 설문 링크 대신 내장 피드백 대화상자를 엽니다.**
- **셀프호스티드 러너가 Windows에서 시작하려면 이제 `--base-dir`를 명시해야 합니다** — Windows에는 기본 체크아웃 디렉터리가 없습니다.
- **8월 마감 캘린더 4종**: **8/14**(D-1) auto mode 기본 전환 / **8/17**(D-4) 레거시 Workbench + 실험적 prompt tools API 3종 은퇴 / **8/19**(D-6) Claude Code 주간 사용량 50% 부스트 종료 예정 / **8/31**(D-18) Sonnet 5 도입가 종료(9/1부터 +50%).
