## 주요 신규 기능 & 실전 활용

### [VSCode] Bookmarks — Claude의 답변을 저장해 한곳에서 모아봅니다 (v2.1.286)

**Claude의 응답을 저장해 전용 Bookmarks 사이드 패널에서 계속 확인할 수 있는 기능이 추가됐습니다.** 대화가 길어지면 스크롤로 과거 답변을 다시 찾기 번거로운데, 중요한 설계 결정이나 코드 스니펫이 담긴 응답을 북마크해두면 세션이 길어져도 바로 꺼내볼 수 있습니다.

**긴 리팩터링이나 설계 논의 세션에서 특정 응답을 자주 다시 참조해야 했다면, 매번 스크롤하거나 검색하는 대신 북마크 패널 하나로 핵심 응답만 모아 관리할 수 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### [VSCode] Questions 행 — Claude가 던진 질문과 내 답변이 대화 기록에 남습니다 (v2.1.286)

**질문 카드에 답하면 그 질문과 선택한 답이 Questions 행으로 대화에 추가되어, 나중에도 어떤 질문에 어떻게 답했는지 한눈에 되짚어볼 수 있습니다.** 선택지 미리보기 기능도 함께 추가돼, 강조된 선택지의 목업이나 코드 스니펫이 선택지 옆이나 아래에 바로 표시됩니다.

**Claude가 구현 방향을 묻는 질문을 여러 번 던지는 작업에서, 과거에 어떤 선택을 했는지 기억이 가물가물할 때 대화를 거슬러 올라가지 않고도 Questions 행만 훑어 복기할 수 있습니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

## 개발자 워크플로우 팁

### 텍스트 분류를 위한 언어 모델: Bag-of-Words에서 Jev까지 (10/1)

**Bag-of-Words와 로지스틱 회귀에서 출발해 RNN, CNN, 사전학습 Transformer를 거쳐 범용 분류 모델 Jev로 이어지는 텍스트 분류 기법의 계보를 정리한 글입니다.** Jev는 작업마다 별도 분류기를 파인튜닝하지 않고도 다양한 텍스트 분류·의사결정을 수행하며, 대형 생성형 LLM보다 빠르고 저렴한 처리를 지향합니다.

**9/19일 이후 이 브리핑에서 계속 다뤄온 Jev·Jeff·Ollaya 등 System 1 판단형 모델 흐름의 기술적 배경을 정리한 글로, Claude Code 파이프라인에 분류·라우팅 단계를 끼워 넣을 때 왜 무거운 생성형 호출 대신 이런 경량 판단 모델을 쓰는지 근거를 확인할 수 있습니다.** [GeekNews](https://news.hada.io/topic?id=34551)

### SQL 쿼리 빌더의 두 가지 유형 (10/1)

**쿼리 빌더는 비슷한 파이프라인 인터페이스를 제공해도, 데이터 처리 결과를 정의하는 방식과 SQL 구문 트리를 조립하는 방식으로 나뉘며 연산 순서를 바꿨을 때 동작이 달라집니다.** FunSQL, EF/LINQ, dbplyr는 실제 처리 순서를 그대로 반영하는 방식이라, 필터링 전에 정렬·집계를 먼저 써도 의도한 대로 동작합니다.

**Claude Code에게 ORM이나 쿼리 빌더 코드를 생성·리뷰하게 할 때 어떤 라이브러리가 어느 쪽 모델을 따르는지 미리 알아두면, 연산 순서를 바꾼 리팩터링이 실제로 같은 쿼리를 내는지 검증하는 기준으로 쓸 수 있습니다.** [GeekNews](https://news.hada.io/topic?id=34562)

## 알아두면 좋은 소소한 변경사항

아래는 모두 **v2.1.286**(9/30) 항목입니다.

- **권한 프롬프트에 "2 of 5" 같은 카운트가 추가**돼, 여러 권한 요청이 쌓였을 때 몇 번째 요청인지 바로 확인할 수 있습니다.

- **기본 모델이나 모델 별칭이 가리키는 모델을 API가 거부할 때, 같은 등급의 이전 모델로 한 번 자동 재시도**하도록 바뀌었습니다.
- **조직 정책이 Remote Control을 끄면, 이미 연결돼 있던 Remote Control 세션(`claude remote-control` 포함)도 알림과 함께 바로 연결이 끊어집니다.**
- **`claude auth status`가 Console 로그인으로 저장된 API 키를 `claude.ai`로 잘못 보고하던 문제가 수정**돼, 이제 `api_key`로 정확히 표시됩니다.
- **macOS에서 다른 Claude Code 창에서 `/login`에 성공해도 "Not logged in"으로 남아 있던 문제가 수정**됩니다(남아 있던 `~/.claude/.credentials.json` 때문).
