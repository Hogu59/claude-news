## 개발자 워크플로우 팁

### Code Mode에서 스크립트가 수천 번 도구를 호출해도 터미널이 거의 멈추지 않게 됐습니다 (v2.1.330)

**지금까지 Code Mode에서 스크립트가 수천 번씩 도구를 호출하면 터미널이 한동안 멈춰버렸는데, 이번 릴리스부터 그 멈춤 시간이 크게 줄었습니다.** 더불어 Claude가 Code Mode 안에서 이미지와 PDF를 어떻게 들여다봐야 하는지 안내받도록 개선됐고, Esc로 중단한 명령은 빨간 오류 대신 "Interrupted"로 표시됩니다.

```text
Code Mode 스크립트가 수백~수천 개 파일을 순회하며 도구를 반복 호출하는 대량 작업
  (예: 일괄 리팩터링, 대량 API 점검 등)
  → v2.1.330부터 터미널 멈춤이 크게 줄어듦
```

**Code Mode로 대량 파일을 순회하는 스크립트를 돌릴 때마다 터미널이 한동안 먹통이 됐었다면, v2.1.330 업그레이드 뒤에는 같은 작업에서 훨씬 쾌적해진 체감을 느낄 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### `/ultrareview`가 Team·Enterprise 플랜에서 남은 월 지출 한도를 미리 보여줍니다 (v2.1.330)

**지금까지 `/ultrareview`의 비용 확인 창은 이번 리뷰 1회의 예상 비용만 보여줘서, 팀 전체의 월 지출 한도 안에서 얼마나 여유가 있는지는 따로 확인해야 했는데, 이번 릴리스부터 Team·Enterprise 플랜에서는 남은 월 지출 한도가 리뷰 1회 비용보다 적을 때 그 수치를 함께 보여줍니다.**

```bash
/ultrareview
# → 확인 창에 "이번 리뷰 예상 비용"뿐 아니라
#    남은 월 지출 한도가 더 적을 때는 그 한도도 함께 표시
```

**팀 단위로 `/ultrareview`를 자주 돌리면서 월 지출 한도를 넘기지 않을지 매번 따로 확인했다면, v2.1.330부터는 확인 창 한 번으로 바로 판단할 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

### `claude --teleport`가 일부 환경에서 브랜치를 자동 전환하지 않고 git 명령만 보여주도록 바뀌었습니다 (v2.1.330)

**지금까지 일부 설정에서 `claude --teleport`는 선택한 세션의 브랜치로 알아서 전환했는데, 이번 릴리스부터는 브랜치를 바꾸는 git 명령어만 화면에 보여주고 실제 전환은 직접 하도록 바뀌었습니다.** `-p` 모드에서는 브랜치를 바꾸기 전까지 종료 코드 1을 반환합니다.

```bash
claude --teleport
# → 브랜치 전환 git 명령을 보여주기만 함 (직접 실행 필요)
claude -p --teleport ...
# → 브랜치를 바꾸기 전까지는 종료 코드 1 반환
```

**`--teleport`를 자동화 스크립트에 넣어 브랜치 전환까지 맡기고 있었다면, v2.1.330 업그레이드 뒤에는 git 명령 실행 단계를 스크립트에 직접 추가해야 그대로 동작한다는 점을 감안해둘 만합니다.** [전체 릴리스 노트](https://github.com/anthropics/claude-code/releases)

**Dragos의 최고연구책임자 HD Moore가 빈 계정에 연결된 AWS 키, SSH 등 서비스 비밀번호, 고유 URL·DNS 이름, 비공개 git 저장소 참조 같은 추적용 비밀 정보를 약 200만 건의 AI 프롬프트 각각에 하나씩 심어 어느 단계에서 유출되는지 추적한 실험입니다.** 그 결과 최소 3곳의 AI 호스팅 업체가 침해된 정황이 드러났고, 공격자들은 탈취한 키를 몇 시간 안에 시험해보고 S3·Secrets Manager를 뒤져 추가 자격 증명을 찾았습니다. 한 중국 AI 랩은 "데이터 수집 안 함(ZDR)"으로 표시된 요청의 약 3분의 2를 포함해 7~10월 요청의 절반 넘는 비밀 URL에 실제로 접근했고, 일부 리셀러는 낮은 가격을 내세우면서 몰래 요청 로깅을 켜 둔 것으로 나타났습니다. OpenRouter 같은 AI 라우터는 중계마다 프롬프트를 평문으로 복호화하기 때문에 여러 당사자가 내용을 들여다볼 수 있다는 점도 함께 지적됐습니다. 이번 실험에서 Anthropic이나 Claude가 직접 침해 사례로 지목되지는 않았지만, ZDR·비수집 설정이 실제로는 지켜지지 않을 수 있다는 점을 실측으로 보여준 사례입니다.

**Claude나 다른 모델에 요청을 보낼 때 API 키를 직접 쓰지 않고 리셀러나 AI 라우터를 거치고 있다면, "데이터 수집 안 함" 같은 표시만 믿기보다 실제로 요청을 처리하는 주체가 누구인지 확인해두는 편이 안전하다는 근거로 참고할 만합니다.** [Ars Technica](https://arstechnica.com/security/2026/11/a-leaky-ai-supply-chain-is-exposing-secret-user-data-at-an-alarming-rate/) · [GeekNews](https://news.hada.io/topic?id=37675)

## 알아두면 좋은 소소한 변경사항

- **Anthropic의 Enterprise Admin Console이 관리하는 조직으로 로그인하는 기능이 추가**돼, `claude auth login` 이후 조직의 설정과 클라우드 제공사·게이트웨이가 그대로 적용됩니다.
